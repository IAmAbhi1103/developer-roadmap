00 · Master roadmap — becoming a strong Java full-stack developer

Where you are and where this takes you

You already have the right stack: Java, Spring Boot and SQL. With about 12 months of steady study, you can become a job-ready Java full-stack developer.

Right now you know the basics of all three, but not deeply. That is normal and a good place to start. This plan makes those three strong first, then adds one new layer at a time.

By the end of this roadmap you will be able to:

  • Solve easy and medium DSA problems in Java and clear online coding rounds.
  • Build a secure, tested REST API with Spring Boot, JPA and PostgreSQL or MySQL.
  • Build a React frontend that talks to your own API.
  • Use Git and GitHub the way real teams do: branches, pull requests and code review.
  • Package apps with Docker, test them automatically with CI/CD, and deploy them to the cloud.
  • Answer low-level and high-level system design questions in interviews.
  • Show three solid, deployed projects on GitHub and a one-page resume.

Assumption: about 4 hours of study on weekdays and 6–8 hours on weekend days. With about 2 hours a day, plan for 18–20 months; the order stays the same.

The big picture: what a good developer knows

Start at layer 1, where you are now. Each box names the topic tab that holds its full index, resources and practice plan.

The learning order and why

Learn in this order: Git, then strong Java and SQL, then Spring Boot, then frontend, then DevOps, then system design. DSA runs every day in parallel, from week 1 to the end.

Why this order: each layer uses the one before it. Spring Boot is Java plus a framework, so weak Java makes Spring feel like magic. System design only makes sense after you have built and deployed real apps. DSA runs in parallel because it grows slowly, through daily practice over months, not one big push.

Do not move to the next phase until you pass its "move on when" test:

  1. Phase 0 — Setup and Git (weeks 1–2). Install JDK, IntelliJ IDEA, VS Code, Git and PostgreSQL or MySQL. Learn the daily Git commands.
    • Move on when: you push all practice code to GitHub without looking up commands.
  2. Phase 1 — Strong Core Java and SQL (months 1–2). OOP, collections, exceptions, generics, Java 8+ features (lambdas, streams), basic multithreading. SQL joins, GROUP BY, subqueries, indexes.
    • Move on when: you can build a 300-line console app with classes, collections and a database, and solve the easy and medium questions of LeetCode SQL 50.
  3. Phase 2 — Spring Boot backend (months 3–5). REST APIs, Spring Data JPA, validation, exception handling, Spring Security with JWT, tests with JUnit and Mockito.
    • Move on when: you have a complete CRUD API with login, tests and a README on GitHub.
  4. Phase 3 — Frontend and full-stack (months 6–7). HTML, CSS, JavaScript, then React.
    • Move on when: your React app logs in and works with your own Spring Boot API.
  5. Phase 4 — DevOps and deployment (month 8). Linux basics, Docker, GitHub Actions, deployment to a cloud server.
    • Move on when: a push to the main branch tests and deploys your app automatically.
  6. Phase 5 — System design and advanced backend (months 9–10). LLD (SOLID, design patterns), HLD (scaling, caching, queues), Redis, Kafka basics, microservices basics.
    • Move on when: you can design a URL shortener or a parking lot system out loud for 45 minutes.
  7. Phase 6 — Interview prep and job search (months 11–12). Revise DSA patterns and CS fundamentals, do mock interviews, apply widely.
    • Start applying for internships after Phase 3. You do not need to finish everything first.

DSA in parallel, 1–1.5 hours a day: basics in months 1–3, core patterns in months 4–6, trees, graphs and DP in months 7–9, then revision and contests. Target about 300 well-understood problems by month 12.

Phase-by-phase timeline

Each main phase feeds a project. By month 8 you have three projects, one of them live on the internet, and you start applying.

How to study: methods that actually work

Spend at most 30% of your time watching or reading, and at least 70% writing code yourself. That one rule keeps you out of tutorial hell.

  • Watch, close, rebuild. After each lesson, close the video and write the same code from memory. Where you get stuck is exactly what you did not understand.
  • One main resource per topic. Pick one course or playlist and finish it. Jumping between five YouTubers feels productive but slows you down.
  • Build something every week. Even one small feature. Projects teach how the pieces connect; tutorials do not.
  • Read docs and error messages. Working developers live in official docs, stack traces and Stack Overflow. Practise this from week 1.
  • Short notes in your own words. One page per topic. Revise them after 1 day, 7 days and 30 days.
  • DSA: struggle 20–30 minutes, then look. If stuck, read only the hint or the approach, then code it yourself. Solve it again after 3 days and after 2 weeks.
  • Teach it. Explain a concept to a friend or write a short LinkedIn post. If you cannot explain it simply, revise it.
  • Use AI as a tutor, not an answer machine. Ask it to explain an error, quiz you, or review code you wrote. Write the code yourself first; interviews and real bugs need your own understanding.
  • Commit to GitHub every day. Your contribution graph becomes visible proof of consistency.

Sign you are in tutorial hell: you have watched three courses on a topic but cannot build a small app alone. The fix: stop watching, pick a tiny project, build it badly, then improve it.

Resume, GitHub profile and job search

Start applying for internships after Phase 3 (around month 7) and for full-time roles from month 10. A one-page resume with 2–3 deployed projects is what gets you interviews.

  • Resume. One page. Sections: Education, Skills, Projects, Experience, Achievements. Each project gets 2 bullet points with the tech, a number and a link, for example: "Cut API response time from 800 ms to 120 ms with Redis caching." The free "Jake's Resume" template on Overleaf is a popular clean format.
  • GitHub. Pin your 3–4 best repos, each with a good README. Add a short profile README. Leave half-finished tutorial copies unpinned.
  • LinkedIn. Headline like "Java Backend Developer | Spring Boot | React". Post once a week about what you built or learned.
  • Where to apply. LinkedIn Jobs, Naukri, Wellfound, Instahyre, Cutshort, company career pages and off-campus drives. Referrals from people you know get the best response.
  • Interview rounds to expect. Online test (2–3 DSA problems), technical rounds (DSA, Java, Spring Boot, SQL, your projects), design rounds (mostly for experienced roles), then HR.
  • Mock interviews. Practise with friends: one asks, one solves out loud. Practise explaining each project in 2 minutes.

Company types differ: service companies test aptitude and basics, product companies test DSA and design hard, and startups care most about projects and practical skills.

Common mistakes to avoid

The biggest mistake is trying to learn everything at once; one main focus plus daily DSA is enough.

  • Too many languages. Use Java for DSA and backend, JavaScript only for frontend. No C++, Python and Go on the side.
  • Skipping the base. Jumping to microservices or Kubernetes with weak Java makes everything harder.
  • Only DSA or only development. Product-company interviews need both. Do a little of each daily.
  • Solving many problems without revising. 300 problems you understand beat 1,000 you rushed.
  • Copy-pasting from AI or tutorials. If you cannot explain a line, you do not own it yet.
  • Waiting to feel 100% ready. Nobody does. Apply once Phase 3 is done.
  • Comparing yourself on LinkedIn. Compare with yourself from last month.
  • Burnout cycles. Twelve-hour days for a week, then nothing for a month, loses to 4 steady hours a day for a year.

01 · Git & GitHub

Learn Git in your first two weeks, then use it every day. About 15 hours of focused study covers what a job needs; daily use does the rest.

How Git moves your code

Once this picture is clear, almost every Git command makes sense: it moves changes between these four places.

Topic index

Four levels, in order. Tick each item when you can do it without looking it up.

Level 1 — Daily basics (week 1, about 6 hours)

  • What version control is and why every team uses it
  • Install Git; set your name and email with git config --global
  • Start a repo with git init, or copy one with git clone
  • The three local areas: working folder, staging area, repository
  • The daily loop: git status, git add, git commit -m, git log --oneline
  • See what changed: git diff and git diff --staged
  • Keep junk out with .gitignore (target/, .idea/, .env)
  • Undo safely: git restore, git restore --staged, git commit --amend

Level 2 — GitHub and remotes (weeks 1–2, about 4 hours)

  • GitHub account with SSH key or personal access token
  • Remotes: git remote add origin, git push -u origin main, git pull, git fetch
  • Write a clear README in Markdown
  • Fork vs clone, and when to use each

Level 3 — Branches and teamwork (week 2, about 5 hours)

  • Branches: git switch -c feature/login, git branch, git switch main
  • Merge: git merge, fast-forward vs merge commit
  • Resolve a merge conflict by hand
  • Pull requests: open, review, request changes, merge
  • Good commit messages: short, present tense, one change each ("Add login endpoint")
  • GitHub flow: main branch plus short-lived feature branches

Level 4 — Professional level (later, when needed)

  • git rebase vs git merge, and interactive rebase to tidy commits
  • git stash to park unfinished work
  • git cherry-pick to copy one commit to another branch
  • git revert vs git reset (soft, mixed, hard), and why reset --hard is risky
  • git reflog to recover "lost" commits
  • Tags and releases with semantic versions (v1.2.0)
  • GitHub extras: Issues, Projects board, branch protection, Actions (tab 07)

How much and how to study

Levels 1–3 are a must before you start any project. Level 4 can wait until you work in a team or an interview asks for it.

LevelPriorityTime
1 · Daily basicsMust, week 1about 6 h
2 · GitHub and remotesMust, weeks 1–2about 4 h
3 · Branches and teamworkMust, week 2about 5 h

How to study it:

  • Use the terminal first. IDE Git buttons hide what is happening. Once the commands make sense, use whichever you like.
  • Break things on purpose. In a practice repo, create conflicts, delete files and reset commits, then recover them.
  • Everything goes on GitHub from day 1. DSA solutions, Java practice, projects: all of it.
  • Branch and pull request for every feature, even when you work alone. It builds the team habit companies expect.
  • Keep a one-page cheat sheet of the commands you actually use.

Common interview questions: merge vs rebase, fetch vs pull, reset vs revert, and how you resolve a conflict.

Practice and the "done when" test

Do these eight exercises in a practice repo, in order:

  1. Create a repo java-practice, add a Java .gitignore, commit, and push it to GitHub.
  2. Make 5 small commits with clear messages, then read them with git log --oneline --graph.
  3. Create a branch feature/calculator, add code, open a pull request, and merge it.
  4. Create a merge conflict on purpose (same line, two branches), merge, and fix it by hand.
  5. Commit a mistake, then undo it three ways: git commit --amend, git revert, git reset --soft HEAD~1.
  6. Delete a branch that has commits, then bring it back with git reflog.
  7. Fork a beginner-friendly open-source repo, fix a typo in its docs, and open a real pull request.
  8. Finish the Main and Remote sections of Learn Git Branching.

You are done when:

  • You use add, commit, push, pull and branches daily without looking anything up
  • You can resolve a merge conflict calmly
  • You can explain merge vs rebase, fetch vs pull, and reset vs revert
  • Your GitHub graph shows commits on most days

02 · Core Java

Strengthen Core Java in months 1–2 (about 8 weeks). It is the base for DSA, Spring Boot and every Java interview.

Topic index

Eight modules, in order. Since you know some Java already, move fast through module 1 and slow down at OOP and collections.

1 — Basics and syntax (revise fast, about 1 week)

  • JDK vs JRE vs JVM; how javac and java run your code
  • Data types, variables, operators, type casting
  • if/else, switch (including switch expressions), loops
  • Methods, parameters, return types, overloading
  • Arrays (1D and 2D) and the Arrays class
  • Strings: immutability, the String pool, StringBuilder, common methods
  • Input with Scanner and BufferedReader; formatted output

2 — Object-oriented programming (the most important module, about 2 weeks)

  • Classes, objects, constructors, this, static
  • Encapsulation: access modifiers, getters and setters
  • Inheritance: extends, super, method overriding
  • Polymorphism: compile-time vs runtime, dynamic method dispatch
  • Abstraction: abstract classes vs interfaces, default and static interface methods
  • The final keyword; Object methods: equals, hashCode, toString
  • Composition vs inheritance
  • Packages and imports; enums; records for simple data classes

3 — Exceptions and files (about 3 days)

  • Checked vs unchecked exceptions and the exception hierarchy
  • try / catch / finally and try-with-resources
  • throw vs throws; writing custom exceptions
  • Reading and writing files with java.nio.file.Files

4 — Collections and generics (about 1.5 weeks)

  • List: ArrayList vs LinkedList
  • Set: HashSet, LinkedHashSet, TreeSet
  • Map: HashMap, LinkedHashMap, TreeMap; how HashMap works inside (hashing, buckets, collisions)
  • Queue and Deque: ArrayDeque, PriorityQueue
  • Iterator; Comparable vs Comparator
  • The Collections utility class; immutable collections with List.of
  • Generics: generic classes and methods, bounded types, wildcards (? extends, ? super)

5 — Modern and functional Java (about 1 week)

  • Lambdas and functional interfaces: Predicate, Function, Consumer, Supplier
  • Method references
  • Streams: filter, map, sorted, collect, groupingBy, reduce
  • Optional and avoiding NullPointerException
  • Date and time API: LocalDate, LocalDateTime
  • Newer features: var, text blocks, switch expressions, pattern matching for instanceof, sealed classes

6 — Multithreading and concurrency (basics now, depth in months 9–10)

  • Process vs thread; Thread and Runnable; thread lifecycle
  • Race conditions; synchronized, volatile, AtomicInteger
  • ExecutorService and thread pools; Callable and Future
  • CompletableFuture basics
  • ConcurrentHashMap and other concurrent collections
  • Deadlock: causes and prevention
  • Virtual threads (Java 21): what problem they solve

7 — JVM and memory (interview level, about 3 days)

  • Stack vs heap; where objects and references live
  • Garbage collection basics
  • Class loading basics
  • == vs equals, and why hashCode must agree with equals

8 — Tools every Java developer uses (about 3 days)

  • IntelliJ debugger: breakpoints, step over and step into, watches
  • Maven: pom.xml, dependencies, mvn clean install; Gradle basics
  • JUnit 5: write a test for a method (more in tab 04)
  • JDBC: connect to a database, PreparedStatement, avoid SQL injection
  • Logging with SLF4J instead of System.out.println

How much and how to study

Modules 1–5 and 8 are must-know now. Learn the basics of module 6 now and go deeper in months 9–10. Module 7 is mostly for interviews.

Can wait until you need them: the Java module system, reflection, annotation processing, and JVM tuning.

03 · SQL & Databases

Learn SQL properly in months 1–2, add database design and transactions alongside Spring Boot in months 3–5, and pick up Redis and NoSQL basics in month 9.

Topic index

Six modules. Modules 1–3 are pure SQL; modules 4–6 are how databases are designed and how they work inside.

1 — SQL basics (months 1–2, about 1 week)

  • Relational databases: tables, rows, columns, primary keys
  • Install PostgreSQL or MySQL, plus a client such as pgAdmin, DBeaver or MySQL Workbench
  • SELECT, WHERE, ORDER BY, LIMIT, DISTINCT
  • Filters: AND, OR, IN, BETWEEN, LIKE, IS NULL
  • INSERT, UPDATE, DELETE
  • CREATE TABLE, ALTER TABLE, DROP, data types
  • Constraints: PRIMARY KEY, FOREIGN KEY, UNIQUE, NOT NULL, CHECK, DEFAULT

2 — Intermediate SQL (months 1–2, about 1.5 weeks)

  • Aggregates: COUNT, SUM, AVG, MIN, MAX
  • GROUP BY and HAVING, and how HAVING differs from WHERE
  • Joins: inner, left, right, full, self join, cross join
  • Subqueries, correlated subqueries, EXISTS
  • UNION vs UNION ALL; CASE WHEN
  • String and date functions
  • Logical order: FROM, WHERE, GROUP BY, HAVING, SELECT, ORDER BY, LIMIT

3 — Advanced SQL (month 2, revise in month 11)

  • Common table expressions (WITH) and recursive CTEs
  • Window functions: ROW_NUMBER, RANK, DENSE_RANK, LAG, LEAD, running totals with OVER (PARTITION BY ...)
  • Views; what stored procedures and triggers are
  • Classic interview queries: Nth highest salary, duplicates, top N per group, consecutive days

4 — Database design (months 3–5, alongside Spring Boot)

  • ER diagrams: entities, attributes, relationships
  • One-to-one, one-to-many, many-to-many (join tables)
  • Keys: primary, foreign, candidate, composite; surrogate vs natural keys
  • Normalization: 1NF, 2NF, 3NF, BCNF, and when to denormalize
  • Naming conventions and choosing data types

5 — How databases work inside (months 3–5)

  • Indexes: B-tree basics, when an index helps reads and slows writes
  • Composite indexes and the leftmost-prefix rule
  • Reading query plans with EXPLAIN and EXPLAIN ANALYZE
  • Transactions and ACID
  • Isolation levels and the problems they prevent: dirty, non-repeatable and phantom reads
  • Locking; optimistic vs pessimistic locking
  • Connection pooling (HikariCP in Spring Boot)
  • The N+1 query problem (you will meet it in JPA)

6 — Beyond relational (month 9)

  • SQL vs NoSQL, and when to use each
  • Redis: key-value store, TTL, data types, caching patterns
  • MongoDB basics: documents, collections, queries
  • CAP theorem in simple words
  • Replication and sharding (concepts; more in tab 08)
  • Schema migrations with Flyway or Liquibase

Practice and the "done when" test

Exercises, in order:

  1. Build a college database: students, courses, teachers, enrollments. Insert 50+ rows of sample data.
  2. Write 30 queries on it: every join type, GROUP BY with HAVING, subqueries, CTEs and window functions.

05 · Data structures & algorithms (DSA)

Practise DSA in Java for 1–1.5 hours every day for 12 months. Aim for about 300 well-understood problems, organised by pattern.

Topic index

Four stages, about 300 problems in total. The number after each topic is a target count of problems, not a limit.

Stage 1 — Foundations (months 1–3, about 90 problems)

  • Time and space complexity: Big-O, analysing loops and recursion
  • Java for DSA: ArrayList, HashMap, HashSet, ArrayDeque, PriorityQueue, Arrays.sort, StringBuilder
  • Basic maths: primes and the sieve, GCD, modulo, digit tricks (5)
  • Arrays: prefix sums, Kadane's algorithm, rotation, in-place tricks (20)
  • Strings: palindromes, anagrams, frequency counting (12)
  • Hashing: counting with maps and sets, the two-sum idea (12)
  • Sorting: understand the simple sorts, implement merge sort and quick sort, custom comparators (8)
  • Binary search: on arrays and on the answer space (15)
  • Recursion: base case, call stack, recursion trees, subsets and permutations (12)
  • Bit manipulation basics: AND, OR, XOR tricks (6)

Stage 2 — Core patterns (months 4–6, about 100 problems)

  • Two pointers (12)
  • Sliding window, fixed and variable size (12)
  • Linked lists: reverse, fast and slow pointers, merge, cycle detection (12)
  • Stacks: valid parentheses, next greater element, monotonic stack (12)
  • Queues and deques: BFS basics, sliding window maximum (6)
  • Binary trees: traversals (recursive and iterative), height, diameter, LCA, views (20)
  • Binary search trees: insert, delete, validate, kth smallest (8)
  • Heaps: top K elements, merge K sorted lists, median of a stream (10)
  • Intervals: merge, insert, meeting rooms (6)
  • Matrix: spiral order, rotate, search (6)

Stage 3 — Advanced (months 7–9, about 90 problems)

  • Backtracking: subsets, permutations, combination sum, N-Queens, word search (12)
  • Greedy: activity selection, jump game, gas station (10)
  • Graph basics: adjacency lists, BFS, DFS, connected components, cycle detection (15)
  • Graph algorithms: topological sort, Dijkstra, union-find, minimum spanning tree; know Bellman-Ford and Floyd-Warshall (15)
  • Dynamic programming: 1D, grids, 0/1 and unbounded knapsack, LCS, LIS, DP on strings (35)
  • Tries: insert, search, prefix problems (5)

Stage 4 — Polish (months 10–12)

  • Re-solve every problem marked "needed help" in your log
  • Company-tagged questions for the companies you target
  • Weekly LeetCode contests; Codeforces or CodeChef only if you enjoy it
  • Optional, for top product companies: segment tree and Fenwick tree

How to study DSA

Solve problems by pattern, not at random. Stay stuck for at most 30 minutes, learn the approach, code it yourself, and solve it again after 3 days and after 2 weeks.

The method for every problem:

  1. Read it twice. Write down inputs, outputs and constraints. Constraints hint at the speed you need: n up to 100,000 usually means O(n log n) or better.
  2. Work through 1–2 examples by hand on paper.
  3. State the brute-force idea and its complexity first.
  4. Look for the pattern:
    • sorted input: binary search or two pointers
    • subarray or substring: sliding window or prefix sums
    • "all combinations": backtracking
    • overlapping subproblems: dynamic programming
    • dependencies or connections: graphs
  5. Write clean Java with clear variable names.
  6. Test edge cases: empty input, one element, duplicates, negatives, very large values.
  7. Stuck after 25–30 minutes? Read only the hint or approach, never the code, then write it yourself.
  8. Log it: problem, pattern, key trick, mistake, and whether you needed help.

How many: about 300 problems you truly understand, roughly 30% easy, 60% medium, 10% hard. 300 understood problems beat 1,000 rushed ones.

Your 1.5 hours a day: 10 minutes reviewing yesterday's log, 60–70 minutes on 1–2 new problems, 10–15 minutes re-solving an old one.

For interviews, practise thinking out loud, stating complexity, and sometimes coding without autocomplete.

How much and how to study

Freshers are mostly asked LLD and basic HLD; deep HLD matters more after 1–2 years of experience. Learning HLD now still makes you a better backend developer and sharpens your project discussions.

PartWeeksPriority
LLD: principles, patterns, problems3Must for freshers
HLD: fundamentals and building blocks3Must at concept level
HLD: distributed patterns and practice2Good to know now; must for experienced roles

The method for any HLD question, in about 45 minutes:

  1. Requirements (5 min). What it must do, plus scale, speed and availability. Ask questions before drawing.
  2. Estimates (5 min). Users, requests per second, storage per year.
  3. High-level design (10–15 min). API endpoints, main components and how data flows.
  4. Data model (5 min). Tables or documents, and why SQL or NoSQL.
  5. Deep dive (10–15 min). Bottlenecks, caching, sharding, queues, failures.
  6. Trade-offs (5 min). Say what you chose and what you gave up.

For LLD (45–60 minutes): clarify requirements, list entities, draw the class diagram, code the core classes, name the patterns you used, then handle edge cases and concurrency.

How to study it:

  • For every building block ask two things: what problem does it solve, and what does it cost?
  • Build what you learn into Project 4. A real cache and queue let you speak from experience.
  • Read engineering blogs from companies such as Netflix, Uber, Swiggy and Flipkart.
  • Practise out loud with a friend on a whiteboard or Excalidraw.
  • Remember building blocks and trade-offs, not whole memorised solutions.

Practice and the "done when" test

Solve these in order. Write real Java code for LLD; draw and explain out loud for HLD.

LLD problems (code them)

  • Parking lot — classes, enums, Strategy for pricing
  • Tic-tac-toe or Snake and Ladder — game state and turns
  • Library management — entities and relationships
  • Vending machine — State pattern
  • Elevator system — scheduling logic
  • LRU cache — HashMap plus doubly linked list
  • Splitwise — balances and settling debts
  • BookMyShow — seat booking without double booking
  • Rate limiter — token bucket
  • Food delivery order flow — Observer for status updates

HLD problems (draw and explain)

  • URL shortener — ID generation, caching, redirects
  • Pastebin — object storage, expiry
  • Distributed rate limiter — Redis counters
  • Notification system — queues, retries, multiple channels
  • Chat app like WhatsApp — WebSockets, message delivery, online status
  • News feed like Instagram — fan-out, caching, pagination
  • Food delivery like Swiggy — location, order states, partner matching
  • Ride sharing like Uber or Ola — geospatial search, real-time updates
  • Video streaming like YouTube — upload pipeline, CDN, encoding
  • Payments or e-commerce checkout — idempotency, consistency

You are done when:

  • You can explain SOLID and at least 6 design patterns with Java code
  • You can design and code a parking lot or BookMyShow in 60 minutes
  • You can explain caching, load balancing, replication, sharding and queues, and when to use each
  • You can design a URL shortener end to end, out loud, in 45 minutes
  • Project 4 uses a cache and a queue that you can discuss in depth
