CSS turns plain HTML into a designed, responsive interface. It looks easy — a few colours and fonts — and then layout, specificity and "why will this not centre?" take the first week. The good news: CSS has a small number of core ideas (the cascade, the box model, Flexbox, Grid, positioning, media queries). Learn those properly and the rest is looking things up.

This module follows the order in which problems appear: how rules are written and which one wins, how every element is a box, how to size things, how to lay out rows (Flexbox) and grids (Grid), how to position and layer, how to adapt to phones, and how to animate. Then comes Tailwind CSS, the utility-first approach you will meet in many React projects. Module 2 gave you the HTML; in Module 5 you will apply these skills to React components.

Adding CSS to a page and the anatomy of a rule

CSS is a list of rules, each a selector plus declarations in braces; add it with an external stylesheet linked in the head — inline styles and style tags exist but are for special cases.

Anatomy of a rule

/* selector   { property: value; } */
.card {
  background-color: white;     /* a declaration: property + value */
  padding: 1rem;
  border-radius: 8px;
}
  • The selector (.card) chooses which elements the rule applies to.
  • The declaration block is everything inside { }. Each declaration is property: value; — end every one with a semicolon.
  • A property is something you can style (color, margin); the value is what you set it to.
  • Comments are /* … */. There is no // comment in CSS.
  • An at-rule starts with @: @media, @keyframes, @font-face, @import, @layer.

CSS ignores what it does not understand. A misspelt property (colour: red) or an invalid value is silently dropped, and the rest of the rule still works — there is no error message. DevTools shows invalid declarations with a warning icon and a line through them.

Three ways to add CSS

WayWhereUse it for
External stylesheet<link rel="stylesheet" href="styles.css"> in the headAlmost everything. Cached by the browser, shared across pages, separate from HTML
<style> elementInside the headTiny demos, critical above-the-fold CSS, HTML emails
Inline style attribute<p style="color: red">Values computed by JavaScript (a progress bar width); quick tests
 
<head>
  <link rel="stylesheet" href="css/styles.css">
</head>

Inline styles have very high specificity (they beat any selector except !important) and cannot use media queries, hover states or pseudo-elements. That makes them hard to override and maintain. In React you will see style={{ width: "40%" }} for dynamic values; for everything else use classes.

An @import inside a CSS file loads another stylesheet, but it makes the browser download files one after the other (slow). In a Vite project you can import CSS from JavaScript (import "./styles.css") and the tool bundles it.

Where CSS fits in the page lifecycle

The browser downloads the HTML, finds the <link>, downloads the CSS, builds the CSSOM and only then paints (How the browser renders a page). Hence: keep the stylesheet in the head, keep it small, and split rarely used CSS out. A relative path in href is resolved against the page URL, so css/styles.css from /blog/post.html means /blog/css/styles.css — a classic cause of "my CSS does not load" (check the Network tab for a 404).

Rule: every declaration ends with a semicolon

A missing semicolon makes the browser merge that line with the next one, and both are dropped as invalid. This silent failure causes endless confusion; Prettier and the VS Code CSS validation catch it.

Conventions

  • One external stylesheet (or a few) linked in the head; no inline styles except for computed values.
  • One declaration per line, two-space indent, a space after the colon, lowercase hex colours; class names lowercase with hyphens (.product-card).
  • Group related properties: layout, box, typography, colour, effects.

Edge cases

  • If two stylesheets set the same property with equal strength, the one linked later wins.
  • A stylesheet is cached. After editing, the browser may still use the old file; hard reload or "Disable cache" in DevTools. Vite adds a hash to file names in production to avoid this.
  • Web servers must send Content-Type: text/css; Spring Boot's static resource handler does this for files in static/.

Interview angle

  • "Inline vs internal vs external CSS?" — external is preferred: cacheable, reusable, separation of concerns.
  • "What happens with an invalid declaration?" — the browser ignores just that declaration, silently.

Selectors: choosing the elements to style

A selector describes which elements a rule applies to — by tag, class, id, attribute, relationship to other elements, state (pseudo-class) or a part of an element (pseudo-element).

Selectors are CSS's query language, comparable to a WHERE clause in SQL: they filter the DOM. The same selector syntax also works in JavaScript's document.querySelectorAll().

Pseudo-classes: states and positions

A pseudo-class starts with one colon and selects an element in a certain state or position.

Pseudo-classMatches

Pseudo-elements: parts of an element

A pseudo-element uses two colons and styles a part of an element or adds generated content.

/* Add a decoration before each required label (content is mandatory) */
label.required::after {
  content: " *";
  color: #b00020;
}

input::placeholder {
  color: #6b7280;
}

p::first-line { font-weight: 600; }
::selection { background: #fde68a; }     /* text highlighted by the user */

::before and ::after insert a child box at the start or end of an element, and do nothing unless you set content (even content: ""). They are decorations — icons, quotes, badges — never real content, since screen readers may or may not read them and users cannot select the text.

Putting selectors to work

/* Reset link look in the nav, then show state */
nav a {
  color: inherit;
  text-decoration: none;
}
nav a:hover,
nav a:focus-visible {
  text-decoration: underline;
}

/* Zebra rows */
tbody tr:nth-child(even) { background: #f6f6f6; }

/* Space between list items, none after the last */
.tags li:not(:last-child) { margin-right: 0.5rem; }

/* External links get an arrow */
a[href^="http"]::after { content: " ↗"; }

/* A paragraph directly after a heading has no top margin */
h2 + p { margin-top: 0; }

You can test a selector quickly: type $$(".card > .title") in the DevTools Console to see which elements it finds.

Conventions

  • Style with classes. IDs are too strong (see specificity) and cannot repeat; reserve them for anchors and JavaScript hooks.
  • Avoid styling bare tags too deeply (div ul li a); long chains are fragile and slow to read. Two levels at most.
  • Name classes after what things are (.product-card), not how they look (.red-text).
  • Do not style by position in the HTML when a class would do — the markup will change.

Edge cases

  • Within a selector list, one invalid selector used to invalidate the whole rule: a:hover, b::unknown { } may apply to nothing. :is() and :where() forgive invalid items.
  • :nth-child(2) counts all siblings, regardless of type; p:nth-child(2) matches only if the second child is a p. Use :nth-of-type to count among the same tag.
  • :hover does not exist on touch screens in the same way (a tap simulates it and it may stick). Never hide essential content behind hover.
  • Class names are case-sensitive in standards mode; tag names are not.

Mistake: a space where there should be none

Wrong: looks for a .primary inside a button

button .primary { background: blue; }

Right: a button with the class primary

button.primary { background: blue; }

Interview angle

  • "Pseudo-class vs pseudo-element?" — a state or position (:hover) versus a part of an element (::before).
  • "Descendant vs child selector?" — space matches any depth, > only direct children.
  • "What does .a .b vs .a.b mean?" — inside versus same element.

Specificity, the cascade and inheritance

When several rules set the same property on one element, the browser picks the winner by importance and origin first, then specificity (inline, then ids, then classes, then tags), and finally by order — the later rule wins a tie.

"Why does my style not apply?" is the most common CSS question, and the answer is nearly always this article. The "C" in CSS stands for Cascading: the algorithm that decides, for every property of every element, which of the competing declarations wins. Think of it as conflict resolution, like Spring choosing between multiple beans (with @Primary and @Order) — except with a precise points system.

The order of decision

  1. Importance and origin. Declarations marked !important beat normal ones. Among normal ones, your author styles beat the browser's default styles (the "user agent" stylesheet that makes h1 big and links blue).
  2. Specificity. The more specific selector wins.
  3. Order of appearance. If still tied, the declaration that comes last in the source wins.

(Modern CSS also has @layer, which sits between importance and specificity: a later layer beats an earlier one regardless of specificity. Frameworks use it to let your styles override theirs easily; you only need to know it exists.)

Calculating specificity

Specificity is like a three-part score (IDs, classes, tags), compared left to right like a version number, not added as one decimal number. Inline styles sit above all three.

What countsColumnExamples
Inline style="…"Beats all selectors<p style="color:red">
ID selectors1st (hundreds)#nav
Classes, attribute selectors, pseudo-classes2nd (tens).card, [type="text"], :hover, :nth-child()
Type selectors, pseudo-elements3rd (ones)p, ::before
Universal *, combinators, :where()Nothing*, >, +

Worked examples (written as ID-class-tag):

p                      { }   /* 0-0-1 */
.card                  { }   /* 0-1-0 */
p.card                 { }   /* 0-1-1 */
nav ul li a            { }   /* 0-0-4 */
.nav a:hover           { }   /* 0-2-1  (.nav, :hover, a) */
#main .card p          { }   /* 1-1-1 */
#main                  { }   /* 1-0-0 */
:not(.a)               { }   /* 0-1-0  (:not counts its argument) */
:where(.a, .b)         { }   /* 0-0-0 */

Because the columns are compared in order, one class beats any number of tag selectors (0-1-0 beats 0-0-9), and one ID beats any number of classes. Now a real puzzle:

<p class="note" id="intro">Hello</p>
p          { color: red; }      /* 0-0-1 */
.note      { color: green; }    /* 0-1-0 */
p.note     { color: blue; }     /* 0-1-1 */
#intro     { color: purple; }   /* 1-0-0  <-- wins */
p.note     { color: orange; }   /* 0-1-1, but #intro still wins */

The text is purple. Remove the #intro rule and the last p.note (orange) wins over the blue one, because they tie on specificity and orange comes later.

!important

color: red !important; jumps over specificity. Only another !important with equal or higher specificity can beat it. It "works", which is the danger: the next developer needs an !important to override yours, and soon the stylesheet is a war. Avoid it. Acceptable uses: utility classes that must always win (Tailwind's ! modifier), and overriding third-party CSS you cannot edit. For ordinary cases, fix the specificity: lower the strong selector, or add a class.

Inheritance

Some properties are passed from parent to child automatically. If you set font-family on body, every paragraph uses it without any further rule.

  • Inherited by default (mostly text): color, font-family, font-size, font-weight, line-height, text-align, visibility, cursor, list-style.
  • Not inherited (mostly boxes): margin, padding, border, background, width, height, display, position, overflow. If a border inherited, nesting would draw boxes inside boxes.

An inherited value is the weakest of all: any rule that directly targets the element beats it, whatever the specificity. This is why links stay blue after you set color on body — the browser's own a rule targets the link directly.

KeywordMeaningExample
inheritTake the parent's computed valuea { color: inherit; } — links look like surrounding text
initialUse the property's default from the CSS specdisplay: initial (becomes inline)
unsetinherit if the property is inherited, else initialall: unset on a button to remove all styling
revertGo back to the browser's default stylerevert undoes your own rules

currentColor is a related keyword: it equals the element's current color value, so a border or an SVG icon can follow the text colour: border: 1px solid currentColor;.

A debugging recipe: "my style does not apply"

  1. Inspect the element. In Styles, is your declaration there? If not, the selector is wrong or the CSS file did not load (Network tab, 404).
  2. Is it struck through? Another rule won. Scroll up in the Styles list to find the winning rule: it has a stronger selector, or comes later.
  3. Is there a warning icon? The property or value is invalid (typo, wrong unit).
  4. Is it greyed out and not struck through? The property has no effect here (for example width on an inline element, or top on a static element).
  5. Check Computed to see the final value and which rule supplied it.

Rule: specificity is calculated per selector, not per rule

In h1, .title { } the two selectors have different specificity (0-0-1 and 0-1-0); for an element matching both, the higher one is used. Order matters only when specificity is equal.

Conventions to keep specificity low and predictable

  • Style with single classes (0-1-0) so any later single class can override them.
  • Write general rules first (reset, base elements), then components, then utilities and overrides.
  • Do not use ID selectors for styling and do not chain more than two or three selectors.
  • To win over a rule, match its specificity and place yours later; do not escalate with !important.

Edge cases

  • Rules are applied per property. A losing rule still contributes the properties that the winner does not set. The cascade merges rules, not replaces them.
  • The order of :link, :visited, :hover, :active rules matters because they have equal specificity: remember LoVe HAte.
  • Order is by the position of the rule in the final combined CSS, so the order of your <link> tags (or imports) changes the result.
  • CSS-in-JS and component libraries inject styles at runtime; the injection order can change who wins. Check "Styles" in DevTools, not just the source.

Mistake: fighting specificity with ever longer selectors

Wrong: escalating

#page .content div.card p.text { color: red !important; }

Right: flat and simple

.card-text { color: red; }

Interview angle: "How does CSS decide which rule applies?"

  • Importance/origin → specificity (inline > ID > class/attribute/pseudo-class > tag) → source order.
  • Calculate a score for a given selector, e.g. #a .b p is 1-1-1.
  • Which properties inherit (text-related) and which do not (box-related)?
  • Why you avoid !important.

Colours, typography and CSS variables

Colours come as hex, rgb() or hsl() values; set font-family, font-size, line-height and font-weight on body so text inherits them; and define colours, spacing and fonts once as custom properties (--name) used with var().

Colour formats

FormatExampleNotes
Keywordtomato, transparent, currentColorAbout 140 named colours
Hex#1a56db, #fff, #1a56db80Red-green-blue in hex; 3-digit shorthand; 4th pair is opacity
rgb()rgb(26 86 219), rgb(26 86 219 / 50%)Channels 0–255; the older comma form rgba(26, 86, 219, 0.5) also works
hsl()hsl(220 79% 48%)Hue (0–360 degrees on a colour wheel), saturation, lightness. Easiest to adjust by hand

HSL is friendly: to make a hover colour, lower the lightness; to make a tint, raise it. The same hue keeps the shades consistent. Newer colour spaces like oklch() exist; you can ignore them for now. opacity: 0.5 fades the whole element and its children, while a transparent colour (rgb(0 0 0 / 50%)) fades only that colour — use it for overlays so the text on top stays solid.

Foreground colour is color; the fill behind is background-color; the box outline colour is in border. Check contrast (at least 4.5:1 for body text, see Accessibility): DevTools' colour picker shows the ratio.

Backgrounds and borders in brief

.hero {
  background: #0f172a url("images/hero.jpg") center / cover no-repeat;
  /* colour (fallback) + image + position / size + repeat */
}
.card {
  border: 1px solid #e5e7eb;
  border-radius: 12px;                         /* rounded corners; 50% makes a circle */
  box-shadow: 0 2px 8px rgb(0 0 0 / 0.12);     /* x y blur colour */
}
.avatar { border-radius: 50%; object-fit: cover; }  /* crop an image without squashing */
.banner {
  background: linear-gradient(135deg, #1a56db, #7c3aed);
}

Typography

Set the base text once on body; everything inherits it.

body {
  font-family: system-ui, -apple-system, "Segoe UI", Roboto, sans-serif;
  font-size: 1rem;          /* 16px by default; respects the user's browser setting */
  line-height: 1.6;         /* unitless: 1.6 x the element's own font size */
  color: #1f2937;
}
h1, h2, h3 { line-height: 1.2; font-weight: 700; }
code { font-family: ui-monospace, "Cascadia Code", Consolas, monospace; }
p { max-width: 65ch; }      /* comfortable line length: about 65 characters */
font-family
A font stack: the browser uses the first installed font and falls back to the next. Always end with a generic family (sans-serif, serif, monospace). Quote names with spaces. system-ui uses the operating system's font: fast and familiar.
font-size
Use rem so text scales with the user's settings (Units). Do not set the root size to a fixed px.
font-weight
400 normal, 700 bold; keywords normal and bold. Variable fonts accept any value from 100 to 900.
line-height
Space between lines. Use a unitless number: 1.5–1.7 for body text, 1.1–1.3 for headings. With a unit like 24px, children inherit the fixed value, which clips big text.
Other
font-style: italic, text-align, text-decoration, text-transform: uppercase, letter-spacing, white-space, text-overflow: ellipsis (needs overflow: hidden; white-space: nowrap), and font as a shorthand.
Web fonts (brief)

To use a font that users do not have installed, load it. The easy route is Google Fonts: add its <link> and use the family name. Self-hosting gives better privacy and speed:

@font-face {
  font-family: "Inter";
  src: url("/fonts/inter-var.woff2") format("woff2");
  font-weight: 100 900;        /* a variable font */
  font-display: swap;          /* show fallback text first, swap when loaded */
}
body { font-family: "Inter", system-ui, sans-serif; }

Use WOFF2, load only the weights you need (each adds download size), and keep a good fallback in the stack. Fonts for Hindi and other Indian scripts need the proper subset (Devanagari, Tamil…); otherwise the browser falls back to a system font for those characters.

CSS custom properties (variables)

A custom property is a value you name once and reuse everywhere. The name starts with two dashes; you read it with var(). Declare shared ones on :root.

:root {
  --color-primary: #1a56db;
  --color-text: #1f2937;
  --color-bg: #ffffff;
  --space: 1rem;
  --radius: 8px;
}

.button {
  background: var(--color-primary);
  padding: calc(var(--space) / 2) var(--space);
  border-radius: var(--radius);
  color: var(--color-bg);
}

.card {
  padding: var(--space);
  color: var(--color-text, black);   /* second argument: fallback value */
}

Unlike Sass variables (compiled away), custom properties are live: they live in the browser, follow the cascade and inheritance, and can be changed by JavaScript or overridden inside any element. That makes theming easy.

:root {
  --bg: #ffffff;
  --text: #111827;
}

@media (prefers-color-scheme: dark) {
  :root {
    --bg: #0b1020;
    --text: #e5e7eb;
  }
}

/* Or a manual switch: <html data-theme="dark"> */
:root[data-theme="dark"] {
  --bg: #0b1020;
  --text: #e5e7eb;
}

body { background: var(--bg); color: var(--text); }
document.documentElement.dataset.theme = "dark";             // switch theme
document.documentElement.style.setProperty("--space", "2rem"); // change one variable
getComputedStyle(document.documentElement).getPropertyValue("--space"); // read it

Rule: a custom property name is case-sensitive and works only in values

--Color and --color are different. You cannot use a variable as a property name or inside a media-query condition. If a variable is undefined and has no fallback, the declaration becomes invalid at computed time and the property falls back to inherit/initial.

Conventions

  • Define design tokens (colours, spacing, radii, font sizes) as variables on :root with meaningful names (--color-primary, not --blue).
  • Set typography on body; use unitless line-height and rem font sizes.
  • Never use colour as the only signal, and keep text contrast at WCAG AA or better.

Edge cases

  • The shorthand font: 1rem/1.6 Inter, sans-serif resets everything not listed (weight, style) to defaults — easy to overwrite by accident. Order: style weight size/line-height family.
  • The #rrggbbaa and rgb(r g b / a) forms are supported in current browsers.
  • Fonts blocked by CORS (a font on another domain without the right header) fail silently; see the Console.

Interview angle

  • "What are CSS variables and how are they different from Sass variables?" — runtime, cascading and inheritable, changeable by JS; Sass variables are compile-time.
  • "Why unitless line-height?" — it scales with each element's own font size when inherited.
