CSS Grid: rows and columns together

Grid lays out items in two dimensions — you define columns and rows on the container (with fr, repeat() and minmax()) and the items fill or are placed into the cells; auto-fit with minmax() gives a responsive card grid with no media queries.

CSS Grid is the layout system for two dimensions: rows and columns at once. Where Flexbox lays items along one line and lets content decide, Grid lets you define the structure first (a table-like skeleton) and then put items into it. Use it for page layouts (header, sidebar, content, footer), dashboards, galleries and card grids.

A first grid

.grid {
  display: grid;
  grid-template-columns: 200px 1fr 1fr;   /* three columns: fixed, flexible, flexible */
  gap: 1rem;                              /* space between rows and columns */
}

Direct children are placed automatically, left to right, filling each row and then starting the next one. The number of rows follows from the number of items. The vocabulary:

Grid container / grid item
The element with display: grid and its direct children.
Grid line
The dividing lines, numbered from 1. Three columns have four vertical lines (1 to 4). Negative numbers count from the end: -1 is the last line.
Track
A row or column (the space between two lines).
Cell
One unit where a row and a column cross.
Area
A rectangle of one or more cells.

Defining tracks: fr, repeat() and minmax()

grid-template-columns: 1fr 2fr 1fr;          /* shares: 25% / 50% / 25% of free space */
grid-template-columns: repeat(3, 1fr);       /* three equal columns */
grid-template-columns: repeat(4, 100px);     /* four fixed columns */
grid-template-columns: 250px 1fr;            /* sidebar + flexible content */
grid-template-columns: minmax(200px, 1fr) 3fr; /* at least 200px, else flexible */
grid-template-rows: auto 1fr auto;           /* header, stretchy middle, footer */
grid-auto-rows: minmax(100px, auto);         /* rows created automatically */
  • fr ("fraction") divides the free space left after fixed tracks and gaps: 1fr 2fr gives the second column twice the first. 1fr is really minmax(auto, 1fr), so a long word can still push the column wider than its share; use minmax(0, 1fr) to force an exact share.
  • repeat(count, size) avoids repeating yourself.
  • minmax(min, max) sets a range for a track.
  • Content-based keywords: auto (fit content, stretch if space is left), min-content (the narrowest the content can be), max-content (the widest it wants).

Implicit vs explicit grid

The tracks you declare with grid-template-* form the explicit grid. If there are more items than cells, the browser adds extra rows (or columns) on its own — the implicit grid. Control their size with grid-auto-rows and grid-auto-columns, and the filling order with grid-auto-flow (row by default, column, or dense to back-fill gaps).

Responsive card grid with no media queries

.cards {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(250px, 1fr));
  gap: 1rem;
}

Read it aloud: "make as many columns as fit, each at least 250px wide, and share the leftover equally". On a 1,000px container you get three columns (3 × 250 = 750, the rest shared); on a 600px tablet two; on a 350px phone one. It is the single most useful Grid line. Unlike the Flexbox card row, all rows keep the same column widths.

auto-fill vs auto-fit

Both create as many tracks as fit. The difference shows when there are fewer items than tracks. auto-fill keeps the empty tracks, so three cards on a wide screen stay at their minimum-ish size, with empty columns on the right. auto-fit collapses the empty tracks to zero, so the existing cards stretch to fill the row. With many items, both look the same. Choose auto-fit when you want cards to stretch, auto-fill when you want a steady column rhythm.

A caution: minmax(250px, 1fr) overflows on screens narrower than 250px. For tiny screens use minmax(min(250px, 100%), 1fr).

Placing items: lines and span

.featured {
  grid-column: 1 / 3;        /* from line 1 to line 3 (spans two columns) */
  grid-row: 1 / 3;           /* spans two rows */
}
.wide    { grid-column: span 2; }       /* span two columns from wherever it lands */
.fullrow { grid-column: 1 / -1; }       /* from first to last line: the whole row */
.pinned  { grid-column: 3; grid-row: 2; }  /* a single cell */

grid-column: 1 / 3 is short for grid-column-start: 1; grid-column-end: 3. Items can overlap if you place them in the same cells; combine with z-index for layered designs.

Named areas: layout by drawing

For page layouts, grid-template-areas is the most readable way. You draw the layout with names:

.page {
  display: grid;
  grid-template-columns: 220px 1fr;
  grid-template-rows: auto 1fr auto;
  grid-template-areas:
    "header  header"
    "sidebar main"
    "footer  footer";
  min-height: 100dvh;
  gap: 1rem;
}
.page header  { grid-area: header; }
.page aside   { grid-area: sidebar; }
.page main    { grid-area: main; }
.page footer  { grid-area: footer; }

@media (max-width: 700px) {
  .page {
    grid-template-columns: 1fr;
    grid-template-areas:
      "header"
      "main"
      "sidebar"
      "footer";
  }
}

Each string is a row; use a dot (.) for an empty cell. Areas must be rectangles. The responsive version just redraws the picture — a major advantage over Flexbox for page structure. (Rearranging a layout visually does not change the DOM order, so keep the HTML in a sensible reading order.)

A dashboard example

.dashboard {
  display: grid;
  grid-template-columns: repeat(12, 1fr);   /* a 12-column system like Bootstrap */
  gap: 1rem;
}
.kpi    { grid-column: span 3; }            /* four KPI tiles in a row */
.chart  { grid-column: span 8; }
.recent { grid-column: span 4; }

@media (max-width: 800px) {
  .kpi, .chart, .recent { grid-column: 1 / -1; }   /* each takes a full row */
}

Flexbox or Grid?

FlexboxGrid
DimensionsOne (row or column)Two (rows and columns)
Starts fromContent: items decide their size, the container fits themLayout: you define tracks, items fit in
Best forNavbars, toolbars, button rows, centring, small components, a row of unequal itemsPage layouts, galleries, dashboards, forms with aligned labels, anything with aligned rows and columns
WrappingWrapped lines are independent (items of different lines do not align)Columns stay aligned across rows
OverlapNeeds positioningNatural: place items in the same cell

A good rule: Grid for the page, Flexbox for the parts. Real pages use both — a grid for the page structure, flex rows inside the header, cards and buttons. If you find yourself fighting wrap behaviour or aligning columns across rows with Flexbox, switch to Grid. If you only need items in a line, Flexbox is simpler.

Subgrid (grid-template-columns: subgrid) lets nested grids align to the parent's tracks, useful for card content that must line up across cards; it is supported in current browsers.

Rule: only direct children are grid items

Like Flexbox, setting display: grid affects direct children only. Grandchildren need their own grid or flex container (or subgrid).

Conventions

  • Use gap instead of margins between items; use fr and minmax() instead of percentages (percentages plus a gap overflow).
  • Use repeat(auto-fit, minmax(…, 1fr)) for card grids, and grid-template-areas for page layouts.
  • Name areas after their purpose, matching the semantic elements.

Edge cases

  • Grid items have min-width: auto like flex items, so wide content stretches a 1fr column. Add min-width: 0 or use minmax(0, 1fr).
  • Items that are position: absolute inside a grid are positioned against the grid area if the container is positioned.
  • An unplaced item skips cells already occupied by explicit placements, which can create holes; grid-auto-flow: dense fills them at the cost of the visual order differing from the DOM.
  • Margins on grid items do not collapse.

Mistake: using percentages with gaps

Wrong: 3 × 33.33% + 2 gaps overflows

.grid { display: grid; gap: 1rem;
        grid-template-columns: 33.33% 33.33% 33.33%; }

Right: fr subtracts the gaps for you

.grid { display: grid; gap: 1rem;
        grid-template-columns: repeat(3, 1fr); }

Interview angle

  • "Flexbox vs Grid?" — one-dimensional content-first versus two-dimensional layout-first; Grid for the page, Flexbox for components.
  • "What does repeat(auto-fit, minmax(250px, 1fr)) do?" — responsive columns without media queries.
  • "What is fr?" — a fraction of the free space.
  • "auto-fit vs auto-fill?" — whether empty tracks collapse.

Positioning and stacking: relative, absolute, fixed, sticky and z-index

The position property takes an element out of or adjusts it within normal flow — absolute elements sit relative to the nearest positioned ancestor, fixed to the viewport, sticky switches between relative and fixed while scrolling, and z-index orders overlapping elements within stacking contexts.

Flexbox and Grid handle most layout now. position is for special cases: badges on cards, dropdown menus, modals, sticky headers, tooltips. You must understand it, because these are everywhere and the failure modes are confusing.

ValueIn normal flow?Positioned relative toTypical use
staticYes— (default; top/left/z-index are ignored)Normal elements
relativeYes (its original space stays)Its own normal positionSmall nudges; anchor for absolute children
absoluteNo (space removed)Nearest ancestor that is positioned (not static); else the page (initial containing block)Badges, icons in inputs, dropdowns, overlays
fixedNoThe viewportFixed headers, floating buttons, cookie banners
stickyYesNormal position until a scroll threshold, then sticks to its scroll containerSticky headers, table headings, sidebars

The offset properties top, right, bottom, left (and the shorthand inset) move a positioned element. inset: 0 means all four are 0.

relative

A relative element stays where it is in the flow, but top/left shift its drawing from that spot; the space it originally took is kept and other elements do not move. Its real power: it becomes the reference box for absolutely positioned children, even with no offsets at all.

absolute

An absolute element is removed from the flow (siblings act as if it is not there) and placed using its offsets inside its containing block: the padding box of the nearest ancestor with position other than static. If no ancestor is positioned, it uses the page itself — which is why an absolute badge "flies" to the top-left corner of the page when you forget to make the card relative.

.product-card {
  position: relative;          /* makes the card the anchor */
}
.product-card .badge {
  position: absolute;
  top: 0.5rem;
  right: 0.5rem;               /* 8px from the card's top-right corner */
  background: #dc2626;
  color: white;
  padding: 0.2rem 0.5rem;
  border-radius: 4px;
}

/* Cover the parent entirely: overlay */
.overlay { position: absolute; inset: 0; background: rgb(0 0 0 / 0.5); }

/* Centre an absolute element */
.modal {
  position: absolute;
  top: 50%;
  left: 50%;
  transform: translate(-50%, -50%);   /* shift back by half its own size */
}

Absolute elements do not take up space, so the parent can collapse in height, and they can overlap the content. A dropdown menu is the classic case: the wrapper is relative, the menu is absolute; top: 100%; left: 0.

fixed

A fixed element is positioned against the viewport and stays on screen when the page scrolls. Because it leaves the flow, other content slides under it; add padding or margin at the top of the page equal to the header height. A fixed element can be fooled into acting like absolute if an ancestor has a transform, filter or perspective (that ancestor becomes its containing block).

.top-bar {
  position: fixed;
  top: 0;
  left: 0;
  right: 0;                   /* full width */
  height: 3.5rem;
  z-index: 100;
}
body { padding-top: 3.5rem; } /* leave room so the content is not hidden */

.chat-button { position: fixed; bottom: 1rem; right: 1rem; }

sticky

Sticky is a hybrid: the element scrolls normally until it would pass a threshold you set with top (or another offset), and then it sticks — staying within its parent's bounds. Perfect for a table header or a section heading.

.site-header {
  position: sticky;
  top: 0;                      /* required: without a threshold, nothing happens */
  background: white;
  z-index: 50;
}
thead th { position: sticky; top: 0; background: #f3f4f6; }
Why sticky "does not work"
  1. No threshold. You need at least one of top, bottom, left, right.
  2. An ancestor has overflow set (hidden, auto, scroll). Sticky sticks to the nearest ancestor that scrolls, and that ancestor does not scroll vertically. Check every parent in DevTools and remove the overflow.
  3. The parent is too short. A sticky element can move only inside its parent. If the parent is the same height as the element, there is nowhere to stick.
  4. A flex or grid parent stretches the item to the full height. Add align-self: flex-start to the sticky sidebar.
  5. No background, so content shows through, which looks like it is not working — add a background and z-index.

z-index and stacking contexts

When positioned elements overlap, z-index decides who is on top: a higher number is in front. It applies to positioned elements (anything except static) and to flex and grid items. Without it, later elements in the HTML paint over earlier ones.

The gotcha is that z-index is only comparable inside the same stacking context. A stacking context is like a separate deck of cards: the elements inside it are ordered among themselves, and the whole deck sits at one position among the cards of its parent. A new stacking context is created by: the root element; a positioned element with a z-index other than auto; position: fixed or sticky; opacity below 1; transform, filter, perspective, clip-path, mask; isolation: isolate; and flex or grid items with a z-index.

That is why "I set z-index: 9999 and it is still behind" happens: an ancestor created a context with a lower z-index. Fixes: move the element (render modals at the end of body, which is what React portals do), or remove the thing that created the context (often an accidental transform or opacity), or give the ancestor a higher z-index. In DevTools, the Layers view or an extension can show contexts.

Floats (legacy)

float: left was the old layout tool and is now used only to wrap text around an image. You will meet it in older code; replace it with Flexbox or Grid.

Rule: absolute needs a positioned parent

Whenever you write position: absolute on a child, decide which parent is the anchor and set position: relative on it. Make this a habit, and the "flying badge" bug disappears.

Conventions

  • Use Flexbox/Grid for layout; use positioning only for overlays, badges and sticky or fixed UI.
  • Keep a small, named scale of z-index values (CSS variables: --z-dropdown: 100; --z-modal: 1000) rather than random large numbers.
  • Always provide a background for sticky and fixed bars.

Edge cases

  • An absolute element with both left and right (and no width) stretches between them.
  • position: fixed misbehaves with iOS keyboards and mobile address bars; test on a device.
  • A sticky element inside a table works on th cells; thead and tr sticky support has varied. Use th.
  • Negative z-index can push an element behind its parent's background if the parent has none and creates no context.

Mistake: using position: absolute for page layout

Absolute elements do not affect each other or their parent's height, so everything breaks at another screen size or with longer text. Layout belongs to Flexbox and Grid.

Interview angle

  • "Explain the position values." — static, relative, absolute (nearest positioned ancestor), fixed (viewport), sticky (hybrid, needs an offset).
  • "Why doesn't my z-index work?" — stacking contexts; the element is not positioned; or an ancestor creates a lower context.
  • "Why doesn't sticky work?" — missing top, an ancestor with overflow, or a parent that is too short.

Responsive design: mobile-first, media queries and fluid layouts

Responsive design makes one page work on every screen: add the viewport meta tag, write the mobile layout first, add min-width media queries for larger screens, keep images fluid, and use clamp() and Grid auto-fit to reduce the number of breakpoints.

Most Indian users browse on phones, on screens from 360px to tablets and 1920px desktops. Responsive web design means a single codebase that adapts to all of them. It rests on three ideas: a flexible layout (percentages, Flexbox, Grid), flexible media (images that scale) and media queries (apply different CSS depending on the screen).

Step 1: the viewport meta tag

<meta name="viewport" content="width=device-width, initial-scale=1">

Without it, a phone shows your page at about 980px wide, zoomed out, and media queries never see a small width. This line goes in every page's head (see the boilerplate).

Step 2: write mobile-first

Mobile-first means your base CSS (no media query) is the phone layout; you then add @media (min-width: …) blocks that enhance the layout as the screen gets wider. This is simpler because a phone layout is usually a single column (the browser's natural flow), and the CSS the phone has to download and parse is the smallest.

/* Base: phone. One column, stacked. */
.layout { display: grid; gap: 1rem; }
.nav-links { display: none; }          /* hidden behind a menu button on phones */

/* Tablet and up */
@media (min-width: 768px) {
  .layout { grid-template-columns: 1fr 1fr; }
}

/* Desktop and up */
@media (min-width: 1024px) {
  .layout { grid-template-columns: 240px 1fr; }
  .nav-links { display: flex; gap: 1.5rem; }
}

The opposite, desktop-first, uses max-width queries to take features away for smaller screens. It works, but you end up undoing styles, and phones carry the heaviest CSS. Prefer min-width. Do not mix both styles in one stylesheet.

Media query syntax

@media (min-width: 768px) { … }                      /* width of 768px or more */
@media (max-width: 767.98px) { … }                   /* narrower than 768px */
@media (min-width: 600px) and (max-width: 900px) { … }
@media (orientation: landscape) { … }
@media (prefers-color-scheme: dark) { … }            /* user chose dark mode */
@media (prefers-reduced-motion: reduce) { … }        /* user wants less animation */
@media (hover: hover) { a:hover { … } }              /* devices that can really hover */
@media print { nav { display: none; } }              /* styles for printing */
@media (width >= 768px) { … }                        /* modern range syntax, same meaning */

Breakpoints

A breakpoint is a width where the layout changes. Do not chase device models; set breakpoints where your content starts to look bad (drag the DevTools device toolbar wider until it breaks). As a starting point, the common values are:

Namemin-widthTypical device
Base (no query)0Phones, 360–480px wide
sm640pxLarge phones, landscape
md768pxTablets
lg1024pxSmall laptops
xl1280pxDesktops

(Tailwind's defaults are 640, 768, 1024, 1280 and 1536px; Bootstrap uses 576, 768, 992, 1200 and 1400px.) Keep to three or four, and define them as a team convention.

Flexible media

img, video, svg {
  max-width: 100%;      /* never wider than the parent */
  height: auto;         /* keep the proportions */
}
.thumb { aspect-ratio: 16 / 9; object-fit: cover; width: 100%; }  /* uniform crops */

Use srcset to serve smaller image files to phones (Images). Wide tables get an overflow-x: auto wrapper.

Fewer breakpoints with modern tools

  • Grid auto-fit gives a column count that adapts to the width on its own (Grid).
  • Flex wrap with flex: 1 1 250px similarly (Flexbox layouts).
  • clamp() makes type and spacing fluid between a minimum and maximum:
h1      { font-size: clamp(1.75rem, 1.2rem + 2.5vw, 3rem); }
section { padding-block: clamp(2rem, 6vw, 5rem); }
.container { width: min(100% - 2rem, 70rem); margin-inline: auto; }

Container queries (brief)

A media query looks at the screen. A container query looks at the width of the component's own container, so a card can switch between a stacked and a side-by-side layout depending on the space it gets, wherever you place it (a wide main area or a narrow sidebar). This suits reusable React components. It is supported in current browsers.

.card-wrapper { container-type: inline-size; }

.card { display: grid; gap: 0.5rem; }
@container (min-width: 480px) {
  .card { grid-template-columns: 160px 1fr; }
}

Responsive navigation: the typical pattern

On phones the link list is hidden behind a button; on larger screens it shows inline. A no-JavaScript version can use a checkbox or the <details> element; in React you toggle a state variable and a class. Make sure the toggle is a real <button> with aria-expanded and aria-controls, and that the menu can be used with a keyboard (Accessibility).

Testing

  1. DevTools device toolbar (Ctrl+Shift+M): pick a phone, then drag the width through every size — not only the preset devices.
  2. Rotate to landscape. Zoom the browser to 200%. Increase the browser's default font size.
  3. Throttle the network to Slow 4G and check the loading experience.
  4. Open the page on a real phone on the same network (use your computer's IP address and Vite's --host option).
  5. Check there is no horizontal scrollbar at 320px width.

Rules

  • Always include the viewport meta tag.
  • Use min-width queries (mobile-first) consistently.
  • Never disable zoom; touch targets about 44 × 44 pixels.

Conventions

  • Set breakpoints from your content; keep them in one place (or use framework defaults); put each component's queries beside the component's CSS.
  • Do not hide important content on mobile; a smaller screen needs the same information, arranged differently.
  • Use relative units so text and spacing follow the user's settings.

Edge cases

  • Media queries cannot use CSS variables in the condition (@media (min-width: var(--md)) is invalid). Tailwind and Sass generate the values for you.
  • A max-width: 768px query and a min-width: 768px query both match at exactly 768px. Use 767.98px for the max, or the range syntax (width < 768px).
  • Hover-only features break on touch; use @media (hover: hover) and provide a tap alternative.
  • The DevTools emulator does not reproduce real mobile performance or the address-bar behaviour.

Mistakes

  • Forgetting the viewport meta tag, then wondering why media queries "do not work" on the phone.
  • Fixed pixel widths (width: 1200px) instead of max-width.
  • Designing only at 1920px and 375px; the in-between widths are where layouts break.

Interview angle

  • "What is responsive design?" — one codebase adapting to all screens via fluid layout, flexible media, media queries.
  • "Mobile-first vs desktop-first?" — base styles for small screens and min-width enhancements versus the reverse.
  • "How do you make images responsive?" — max-width: 100%; height: auto, srcset.
  • "How do you test?" — DevTools device mode, real devices, throttling.
