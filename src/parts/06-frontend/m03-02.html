The box model, display and overflow

Every element is a rectangular box made of content, padding, border and margin; with box-sizing: border-box the width you set includes padding and border, which is why every project resets it.

The browser's layout engine thinks only in boxes. A paragraph, an image, a button, even a line of text inside a paragraph — all boxes. Layout is the art of sizing and placing boxes, so this is the most important concept in CSS. Think of a framed photo on a wall: the photo is the content, the white mat inside the frame is the padding, the frame is the border, and the gap to the next frame is the margin.

Content
The area for text or children. width and height set its size (by default).
Padding
Space between the content and the border. The element's background colour fills it. Negative values are not allowed.
Border
A line around the padding: border: 1px solid #ddd (width, style, colour). Without a style there is no border.
Margin
Space outside the border, separating the element from its neighbours. It is always transparent and may be negative. margin: 0 auto centres a block element that has a width.

Shorthands

.box {
  padding: 16px;                 /* all four sides */
  padding: 8px 16px;             /* vertical | horizontal */
  padding: 8px 16px 12px;        /* top | horizontal | bottom */
  padding: 8px 16px 12px 4px;    /* top | right | bottom | left (clockwise) */
  margin-inline: auto;           /* left and right (logical property) */
  margin-block: 2rem;            /* top and bottom */
  border-bottom: 2px solid currentColor;
}

Remember the clockwise order T-R-B-L ("trouble"). Logical properties (margin-inline, padding-block) follow the writing direction, so they also work for right-to-left languages.

box-sizing: the setting that decides what "width" means

By default (content-box), width sets only the content width; padding and border are added on top. So width: 300px with padding: 20px and border: 2px gives a box that is 344px wide (300 + 40 + 4). Add width: 100% to that and the box overflows its parent. With border-box, width includes padding and border, and the content shrinks to fit: the box is exactly 300px.

*,
*::before,
*::after {
  box-sizing: border-box;
}
width: 300px; padding: 20px; border: 2pxcontent-box (default)border-box

Put this reset at the top of every stylesheet. Tailwind and Bootstrap include it. The sizes you write now match what you see — and percentages plus padding no longer overflow.

The display property

ValueBehaviour

inlineFlows within text; ignores width/height and vertical margin (span, a)
inline-blockFlows like text but accepts width, height and all margins (buttons, icons)

contentsThe element's own box disappears; its children take part in the parent's layout

Two different "hide" tools: display: none removes the element completely (no space, not read by screen readers); visibility: hidden hides it but keeps the space; opacity: 0 makes it invisible but it still takes space and can be clicked and focused.

width, height and max-width

  • A block element's default width is auto: it fills its parent. Do not write width: 100% on blocks — it is the default, and with content-box plus padding it overflows.
  • height: auto (the default) lets content decide. Fixing a height invites overflowing text; prefer min-height.
  • max-width is the key to fluid layouts: max-width: 1100px; margin-inline: auto; makes a centred column that is never wider than 1100px but shrinks on phones. min-width and min-height set lower limits.
  • Images: max-width: 100%; height: auto; keeps them inside the parent without distortion.

Overflow

When content is bigger than its box, it overflows. The overflow property decides what happens.

ValueResult
visible (default)Content spills outside the box
hiddenClipped; no scroll bar (also used to contain floats and rounded-corner images)
scrollAlways shows scroll bars
autoScroll bars only when needed — the usual choice

overflow-x and overflow-y control each axis. A horizontal scroll bar on the whole page on a phone is a bug: find the element that is too wide using DevTools (hover the elements) and fix it.

Margin collapsing

This surprises everyone once. Vertical margins of adjacent blocks collapse: when one block's bottom margin touches the next block's top margin, they do not add up — the larger one wins.

.a { margin-bottom: 30px; }
.b { margin-top: 20px; }
/* The gap between .a and .b is 30px, not 50px. */
  • A parent's top margin and its first child's top margin also merge, if nothing (padding, border, content) separates them — so the child's margin seems to "leak out" and push the parent down.
  • An empty block's own top and bottom margins collapse together.
  • Margins do not collapse in flex or grid containers, between floated or absolutely positioned elements, with inline-block boxes, or when a parent has padding, a border or overflow other than visible. Horizontal margins never collapse.

Many teams avoid the surprise by using margin in one direction only (for example only margin-bottom), or by spacing items with gap in flex/grid.

Seeing the box model

In DevTools, select an element and look at the box-model diagram in the Styles or Computed pane; hover each layer to highlight it on the page. Margins are shown orange, borders yellow, padding green, content blue.

Rule: start every stylesheet with the border-box reset

Without it, adding a padding or a border changes an element's total size and breaks layouts that were calculated with percentages.

Conventions

  • Use padding for space inside a component and margin (or gap) for space between components.
  • Use rem for padding and margin so spacing scales with text size.
  • Prefer max-width over fixed width for containers.

Edge cases

  • Percentage padding and margin are relative to the parent's width, even for top and bottom.
  • margin: auto centres horizontally only for blocks with a defined width, and does not centre vertically in normal flow (but does in flex and grid).
  • An inline element's vertical padding and border draw but do not push other lines away.
  • height: 100% works only if the parent has a definite height; use min-height: 100vh or flex instead.

Mistake: a mysterious horizontal scrollbar

Usually caused by width: 100% plus padding or border in a content-box element, by an image or table wider than the screen, or by 100vw (which includes the scrollbar width). Reset box-sizing, and find the culprit by deleting elements in DevTools until the scrollbar goes away.

Interview angle

  • "Explain the box model." — content, padding, border, margin; draw it.
  • "content-box vs border-box?" — what width includes; work out a 300px example.
  • "What is margin collapsing?" — adjacent vertical margins merge to the larger one; not in flex/grid.
  • "display: none vs visibility: hidden vs opacity: 0?"

CSS units: px, %, em, rem, vw, vh and more

Use rem for font sizes and spacing so they follow the user's settings, % and fr for flexible widths, vw/vh/dvh for viewport-relative sizes, px for hairlines, and calc(), min(), max() and clamp() to combine them.

A CSS length is a number plus a unit — 16px, 1.5rem, 50%. Zero needs no unit (margin: 0); any other number without a unit is invalid for lengths (but fine for line-height and flex). Units fall into two groups: absolute (fixed size) and relative (depends on something else).

remThe root (html) font size, 16px by defaultFont sizes, margins, paddings, media queries
vw, vh1% of the viewport width / heightFull-screen sections, fluid type
dvh, svh, lvhDynamic / small / large viewport heightFixes mobile address-bar problems with vh

px vs rem — and why rem wins for text

The browser's default root font size is 16px, so 1rem = 16px, 1.5rem = 24px. Many people raise it in the browser settings for readability. Text sized in px ignores that setting; text sized in rem grows with it. That is an accessibility requirement, not a style choice. So size text and spacing in rem; keep html { font-size: 100% } (or leave it) rather than html { font-size: 16px }.

A once-popular trick, html { font-size: 62.5% } (so 1rem = 10px for easy sums), still respects the user's setting but needs you to restore the body size; many teams skip it and use a calculator or calc(). Convert rem to px by multiplying by 16.

em vs rem

.menu    { font-size: 1.2em; }   /* 1.2 x parent */
.menu li { font-size: 1.2em; }   /* 1.2 x 1.2 x parent = 1.44 x parent */

.menu    { font-size: 1.2rem; }  /* always 1.2 x root */
.menu li { font-size: 1.2rem; }  /* the same size: no surprise */

.btn { font-size: 1rem; padding: 0.5em 1em; }
/* padding follows this button's own font size: a bigger button gets more padding */

em in nested elements multiplies at each level, which is confusing for font sizes. Use rem for font sizes and em only where you want a value to follow the element's own text size.

Percentages

A percentage is always a share of something, and what depends on the property: width: 50% is half the parent's content width; height: 50% is half the parent's height (only if the parent's height is set); padding and margin use the parent's width; font-size: 120% uses the parent's font size; for an absolutely positioned element, left: 10% uses the containing block.

Viewport units

100vw is the full width and 100vh the full height of the window. Two traps:

  • 100vw includes the vertical scrollbar's width, so width: 100vw on a page with a scrollbar creates a horizontal scrollbar. Prefer width: 100% for page-wide blocks.
  • On mobile browsers, the address bar slides away while scrolling, so 100vh is taller than the visible area and the bottom of a full-screen section gets cut off. Use 100dvh (dynamic viewport height, current visible size) or 100svh (smallest). Provide 100vh first as a fallback for old browsers.
.hero {
  min-height: 100vh;     /* fallback */
  min-height: 100dvh;    /* modern browsers: the actually visible height */
}

calc(), min(), max(), clamp()

Math functions let you mix units that the browser can only resolve at layout time.

.sidebar { width: calc(100% - 280px); }       /* spaces around + - are required */
.hero    { height: calc(100vh - 4rem); }      /* full screen minus a 4rem header */

.container { width: min(100% - 2rem, 1100px); margin-inline: auto; }
/* the smaller of "full width minus gutters" and 1100px */

h1 { font-size: clamp(1.75rem, 1.2rem + 2.5vw, 3rem); }
/* clamp(minimum, preferred, maximum): grows with the screen between 28px and 48px */

.panel { padding: max(1rem, 3vw); }           /* the larger of the two */

clamp(min, preferred, max) is the tool for fluid typography and spacing: no media queries needed. Always include a rem part in the preferred value (1.2rem + 2.5vw), not only vw, so zoom and browser font settings still work.

Which unit when?

NeedUse

Rule: always write a unit for lengths (except 0)

margin: 10 is invalid and silently ignored (except in quirks mode, another reason for the doctype). Unitless values are valid only where the property expects a number: line-height: 1.5, flex: 1, opacity: 0.5, z-index: 10.

Convention: rem for type and space, px for hairlines, fr and clamp for flexible layout

Do not size text in px or with vw alone. Test by changing the browser's default font size to "Very large" and zooming to 200%.

Edge cases

  • Media queries using em/rem are based on the browser's default size, not your CSS html font size.
  • In calc(), + and - must have spaces (calc(100% -2rem) is invalid), while * and / do not need them.
  • A percentage height inside an auto-height parent behaves like auto.

Interview angle

  • "em vs rem?" — own/parent font size (compounds) versus root (predictable). Prefer rem.
  • "Why not 100vh on mobile?" — address-bar problem; use dvh.
  • "What does clamp(1rem, 2vw, 2rem) do?" — value between 1rem and 2rem following 2vw.

Flexbox: container and item properties

Flexbox lays out items in one direction (a row or a column) and lets you align them, space them and make them grow or shrink — you control the main axis with justify-content and the cross axis with align-items.

Flexbox (Flexible Box Layout) is the tool you will use every day: navbars, button groups, card rows, form rows, centring anything. It is made for one-dimensional layout — items along a single line (that may wrap onto more lines). Think of it as a smart row (or column) of boxes that shares leftover space and aligns itself. It replaced the old float hacks completely.

Turn it on

.toolbar {
  display: flex;      /* .toolbar is the flex container; its direct children are flex items */
}

Only the direct children become flex items; grandchildren are not affected (they can be flex containers themselves — nesting is normal). By default items sit in a row, stretch to the container's height, do not wrap, and shrink if they do not fit.

Main axis and cross axis

Everything in Flexbox depends on two axes. The main axis is the direction items flow; the cross axis is perpendicular. With flex-direction: row the main axis is horizontal; with column it turns vertical, and the roles of the properties swap.

justify-content in pictures

space-between: the first item touches the start, the last touches the end, equal gaps between. space-around: equal space around every item (half-size gaps at the ends). space-evenly: all gaps, including the ends, are equal.

The flex shorthand

You writeIt meansUse for
flex: 11 1 0Equal shares: items split the whole space equally regardless of content
flex: auto1 1 autoStart from content size, then share the leftover
flex: none0 0 autoFixed: never grows or shrinks
flex: 0 0 200pxExactly 200pxA fixed-width sidebar
flex: 2 and flex: 1Grow 2 and 1A 2:1 split of the space

How the algorithm works: (1) every item starts at its flex-basis; (2) if the total is smaller than the container, the free space is shared in the ratio of the flex-grow values; (3) if the total is bigger, the overflow is taken from items in the ratio of flex-shrink times their basis. A worked example: a 900px container with three items of basis 100px and grow values 1, 1, 2 has 600px free; it is shared 150 / 150 / 300, so the widths are 250, 250 and 400.

.layout { display: flex; gap: 1rem; }
.layout .left  { flex: 1; }   /* 1 share */
.layout .right { flex: 2; }   /* 2 shares: twice as wide */

The minimum-size trap

A flex item cannot shrink below its content by default (min-width: auto). A long word, a wide image or a long line of code then overflows instead of shrinking. Fix with min-width: 0 on the item (and overflow-wrap: anywhere or overflow: hidden as needed). This is the cause of the common "my flex child will not shrink / text overflows" problem.

Auto margins

In a flex container, margin-left: auto on an item pushes it (and everything after it) to the far end — the standard way to put a logo on the left and a login button on the right in a navbar. margin: auto centres an item on both axes.

Rule: justify = main axis, align = cross axis

If justify-content seems to do nothing, check the direction. In flex-direction: column, justify-content is vertical. Also remember align-items needs spare cross-axis room to show an effect: a row container that is exactly as tall as its items cannot centre anything vertically — give it a height or min-height.

Conventions

  • Use gap for spacing between items instead of margins on the items.
  • Use flex: 1 to share space, flex: none for fixed-size items.
  • Write flex-wrap: wrap on rows that must work on small screens.
  • Use Flexbox for components and one-dimensional rows or columns; use Grid for two-dimensional page structure.

Edge cases

  • Floats, clear, vertical-align, and column-* properties have no effect on flex items. Margins of flex items do not collapse.
  • Absolutely positioned children of a flex container are taken out of the flex layout.
  • Children that are plain text nodes become anonymous flex items.
  • align-content does nothing on a single-line container (no wrap); align-items is what you need.
  • Images as flex items stretch to the cross size and distort; add align-self: flex-start or object-fit: cover.
  • With flex-basis and width both set, flex-basis wins (unless it is auto).

Mistake: putting flex properties on the wrong element

Wrong: the item has justify-content, the container has flex: 1

.card   { justify-content: center; }  /* no effect: card is not a flex container */
.nav    { flex: 1; }                   /* no effect: .nav is not a flex item */

Right: container properties on the parent, item properties on children

.nav       { display: flex; justify-content: space-between; }
.nav .logo { flex: 1; }

Interview angle

  • "Explain Flexbox." — one-dimensional layout; container and items; main vs cross axis.
  • "justify-content vs align-items?" — main versus cross axis.
  • "What does flex: 1 mean?" — flex: 1 1 0: grow, shrink, basis 0.
  • "flex-basis vs width?" — basis is the starting size along the main axis and wins over width in a flex item.

Common Flexbox layouts, ready to copy

Five layouts cover most daily needs: a navbar, centring anything, a wrapping card row, a sticky footer and a sidebar with content.

Learn these patterns by heart. In each, the HTML is short, and the CSS shows the flex idea that does the job. Try them in a scratch file and open the Flexbox overlay in DevTools (click the "flex" badge in Elements).

1. Navbar: logo left, links right

<header class="site-header">
  <a class="logo" href="/">MyShop</a>
  <nav>
    <ul class="nav-links">
      <li><a href="/products">Products</a></li>
      <li><a href="/cart">Cart</a></li>
      <li><a href="/login">Login</a></li>
    </ul>
  </nav>
</header>
.site-header {
  display: flex;
  justify-content: space-between;   /* logo at one end, nav at the other */
  align-items: center;              /* vertically centred */
  padding: 0.75rem 1.5rem;
  background: #0f172a;
}
.nav-links {
  display: flex;                    /* the ul is a flex container too */
  gap: 1.5rem;
  list-style: none;                 /* remove bullets */
  margin: 0;
  padding: 0;
}
.site-header a { color: white; text-decoration: none; }

Two flex containers are nested: the header (logo vs nav) and the ul (the links in a row). A variation: put margin-left: auto on the nav and drop space-between to push everything after the logo to the right.

2. Centre anything, horizontally and vertically

.center-screen {
  display: flex;
  justify-content: center;   /* horizontal */
  align-items: center;       /* vertical */
  min-height: 100dvh;        /* gives the container room to centre in */
}

/* Alternative with grid, shortest of all */
.center-grid { display: grid; place-items: center; min-height: 100dvh; }

This replaces the old tricks with negative margins and absolute positioning. The most common failure is the missing container height: without min-height, the container is only as tall as its content, so there is nothing to centre inside. Another is to forget that the centring properties go on the parent of the thing being centred.

3. A row of cards that wraps

.cards {
  display: flex;
  flex-wrap: wrap;
  gap: 1rem;
}
.card {
  flex: 1 1 250px;          /* grow, shrink, start at 250px */
  border: 1px solid #e5e7eb;
  border-radius: 12px;
  padding: 1rem;
}

Each card wants to be at least 250px wide; when the row cannot fit another, the next card wraps and the cards on each line share the space. On a phone you get one card per line; on a laptop three or four. No media query. One catch: the last row's cards also stretch to fill the line, so a final single card becomes very wide. If you need uniform columns (a real grid), use CSS Grid. Alternatively cap the width with max-width: 400px.

4. Sticky footer: footer at the bottom even on short pages

<body>
  <header>…</header>
  <main>…short content…</main>
  <footer>…</footer>
</body>
body {
  min-height: 100dvh;
  display: flex;
  flex-direction: column;     /* stack header, main, footer */
  margin: 0;
}
main {
  flex: 1;                    /* main takes all the free vertical space */
}

If the content is short, main grows and pushes the footer to the bottom of the screen; if the content is long, the page simply scrolls and the footer follows the content. (This is different from position: sticky, which keeps something fixed on screen while scrolling.)

5. Sidebar and content

<div class="layout">
  <aside class="sidebar">Menu</aside>
  <main class="content">Article text…</main>
</div>
.layout {
  display: flex;
  gap: 1.5rem;
  align-items: flex-start;    /* sidebar keeps its own height instead of stretching */
}
.sidebar {
  flex: 0 0 240px;            /* fixed 240px: no grow, no shrink */
}
.content {
  flex: 1;                    /* takes the rest */
  min-width: 0;               /* lets long code lines shrink instead of overflowing */
}

@media (max-width: 700px) {
  .layout { flex-direction: column; }   /* stack on phones */
}

6. Other quick patterns

/* Button with icon + text */
.btn { display: inline-flex; align-items: center; gap: 0.5rem; }

/* Media object: image beside text */
.media { display: flex; gap: 1rem; align-items: flex-start; }
.media img { flex: none; width: 64px; height: 64px; border-radius: 50%; }

/* Equal-height cards with the button pinned to the bottom */
.card { display: flex; flex-direction: column; }
.card .actions { margin-top: auto; }     /* pushes the actions down */

/* Tag chips that wrap */
.tags { display: flex; flex-wrap: wrap; gap: 0.5rem; }

Rule: give the container room before you align

Vertical centring and bottom-pinning need a container taller than its content (min-height, a flex-column parent, or a parent with defined height). Otherwise there is no free space to distribute.

Convention: mobile-first flex

Start with a column (or a wrapping row) on small screens and switch to a row in a min-width media query, as shown in Responsive design.

Edge cases

  • An ul that is a flex container keeps its padding-left (the browser default) and bullets; reset them as in the navbar example.
  • Safari had bugs with gap in flexbox in very old versions; all current browsers support it.
  • The centred element's own margin still counts; margin: auto centres, margin-top offsets.

In real projects

React components often render a flex container with a few classes (className="flex items-center gap-4" in Tailwind). These patterns are exactly what those utility classes express; once you know them, reading Tailwind is trivial. Practise on Flexbox Froggy (flexboxfroggy.com) — see the Practice list.

Interview angle

  • "How do you centre a div?" — flex with justify-content and align-items: center (or grid place-items: center) plus a container height; also mention margin: auto for horizontal centring of a block with width.
  • "How do you make a sticky footer?" — flex column on body with min-height: 100dvh and flex: 1 on main.
