Interview questions — JavaScript

How is JavaScript different from Java?

JavaScript is dynamically typed (values have types, variables do not), has one number type, treats functions as values, creates objects without classes (classes are syntax over prototypes), decides this at call time, and runs on a single thread with an event loop instead of many threads. It is interpreted and JIT-compiled from source by an engine such as V8. The two languages share only C-style syntax. See JavaScript for Java developers.

What is the difference between var, let and const?

var is function-scoped, hoisted as undefined, and can be re-declared. let and const are block-scoped, hoisted but unusable before the declaration (temporal dead zone, ReferenceError), and cannot be re-declared in the same scope. const also forbids re-assignment, but it does not freeze an object: const cart = []; cart.push(1) works. Use const by default, let when you must reassign, and never var.

What is the difference between == and ===? List the falsy values.

=== compares type and value with no conversion. == converts types first, which gives surprises such as 0 == "" and "0" == false both being true. Use ===; the only common exception is x == null to check for null or undefined. Falsy values: false, 0, -0, 0n, "", null, undefined, NaN. Everything else is truthy, including [], {} and "0".

What does this print? console.log(0.1 + 0.2 === 0.3, typeof null, [] + [], "5" - 3, "5" + 3)

false object "" 2 "53". Numbers are binary floating point, so 0.1 + 0.2 is 0.30000000000000004. typeof null is "object" because of an old bug. Two empty arrays become empty strings and are joined. The - operator always converts to numbers; + joins when one side is a string.

What is hoisting? Predict the output of: console.log(a); var a = 1; console.log(b); let b = 2;

Declarations are registered before the code in their scope runs. var a exists with the value undefined, so the first line prints undefined. let b is hoisted but uninitialised, so the second console.log(b) throws ReferenceError: Cannot access 'b' before initialization. Function declarations are hoisted completely and can be called early; function expressions and arrow functions follow their variable's rules. See scope and hoisting.

What is a closure? Why does a var loop with setTimeout print the same number?

A closure is a function plus the variables of the scope where it was created; it keeps using them after the outer function returns. Example: makeCounter returns a function that increments a private count. In for (var i = 0; i < 3; i++) setTimeout(() => console.log(i)) all callbacks share one i, which is 3 when they run, so it prints 3 three times. With let each iteration has its own i, so it prints 0, 1, 2. Uses: private state, factories, memoization, debounce. See closures.

How is the value of this decided? How do arrow functions differ?

For normal functions, by the call: new gives the new object; call/apply/bind give the object you pass; obj.method() gives obj; a plain call gives undefined in strict mode (window in sloppy mode). Arrow functions have no own this; they use the this of the code where they are written, and this cannot be changed. That is why a detached method (setTimeout(obj.method)) loses this, and why an arrow function is a bad object method but a good callback inside a method.

map vs forEach vs filter vs reduce, and how do you sort numbers?

map returns a new array of the same length by transforming each item. filter returns a new array with the items that pass a test. reduce folds the array into one value using an accumulator (always give the start value). forEach returns nothing and is for side effects. sort() compares as strings by default, so numbers need a comparator: arr.sort((a, b) => a - b). sort changes the array in place; toSorted or [...arr].sort() does not.

const total = cart.reduce((sum, i) => sum + i.price * i.qty, 0);
Shallow copy vs deep copy: how do you copy objects and arrays?

Assignment copies only the reference. Spread ([...a], { ...o }) and slice make a shallow copy: the top level is new, but nested objects are shared, so changing copy.address.city also changes the original. structuredClone(x) makes a deep copy of plain data, dates, maps and sets (it throws for functions). JSON.parse(JSON.stringify(x)) is an older trick that loses functions, undefined and dates. In React you update nested state by spreading each level.

Explain the event loop. In what order does this print? console.log(1); setTimeout(() => console.log(2), 0); Promise.resolve().then(() => console.log(3)); console.log(4);

JavaScript runs on one thread with a call stack. Timers, network and events are handled by the host (Web APIs); when they finish their callback goes into a queue. When the stack is empty, the event loop runs all microtasks (promise callbacks), then takes one macrotask (timer, event). So the output is 1, 4, 3, 2: synchronous code first, then the promise callback, then the timer. See the event loop.

Promises vs async/await: what does an async function return, and how do you run calls in parallel?

A promise represents a future value (pending, fulfilled or rejected). async/await is syntax over promises: an async function always returns a promise, and await pauses only that function until the promise settles (it does not block the thread). Errors are handled with try/catch. Sequential awaits run one after another; for independent calls start them together: const [a, b] = await Promise.all([getA(), getB()]). Promise.allSettled never rejects, race returns the first to settle, any the first to fulfil.

Does fetch reject on a 404 or 500? How do you handle errors, send JSON and a JWT?

No. The promise rejects only for network-level failures (offline, DNS, CORS, abort). An HTTP error is a normal response with response.ok === false, so you check response.ok or status and throw yourself. To send JSON: method, header Content-Type: application/json, and body: JSON.stringify(data). For a JWT: header Authorization: Bearer <token>. Add a timeout with AbortSignal.timeout() or an AbortController. See fetch.

textContent vs innerHTML, and what is event delegation?

textContent sets plain text, so it is safe. innerHTML parses its value as HTML, so putting user data in it allows XSS (for example an img tag with onerror). Use textContent or createElement. Event delegation puts one listener on a parent and uses event.target.closest(selector) to find which child was clicked; it needs fewer listeners and works for items added later because events bubble up the tree.

What are prototypes? Are JavaScript classes the same as Java classes?

Every object has a hidden link to a prototype object; reading a missing property walks the prototype chain up to null. Methods of a class live once on the prototype and are shared by all instances. The class keyword (constructor, extends, super, static, #private) is syntax over this; typeof a class is "function". Unlike Java there are no interfaces or abstract classes, no overloading, and a class is not a fixed blueprint (you can add to a prototype at runtime).

localStorage vs sessionStorage vs cookies, and is it safe to keep a JWT in localStorage?

localStorage lasts until cleared, sessionStorage until the tab closes; both are about 5 MB, string-only and never sent to the server. Cookies are about 4 KB and are sent with each request; the server can make them HttpOnly so scripts cannot read them. Store objects with JSON.stringify/parse. A JWT in localStorage can be stolen by any XSS bug or malicious package; an HttpOnly Secure SameSite cookie avoids XSS theft but needs CSRF protection. Never store passwords or card data in web storage. See Module 6.

Cheat sheet — JavaScript

  • Declare const first, let if reassigned, never var; const freezes the binding, not the object.
  • Types string, number, bigint, boolean, undefined, null, symbol + object; typeof null is "object"; arrays: Array.isArray.
  • Numbers one 64-bit float; 0.1 + 0.2 !== 0.3; use integer paise; Number.isNaN; safe integer up to 253 − 1.
  • Equality always ===; objects compare by reference; x == null is the one OK use of ==.
  • Falsy false 0 -0 0n "" null undefined NaN; [] and {} are truthy.
  • Defaults a ?? b only for null/undefined; a || b for any falsy; obj?.x?.y safe access; x ??= 1.
  • Convert Number("42"), parseInt(s, 10), String(x), +"3"; form inputs are always strings.
  • Functions declaration (hoisted), expression, arrow (a) => a * 2; arrows have no own this/arguments; wrap object results in ( ).
  • Parameters defaults (a = 1), rest (...args), no overloading; pass the function, do not call it: onClick={fn}.
  • Scope block (let/const) vs function (var); lookup walks the scope chain; var hoists as undefined, let/const sit in the TDZ.
  • Closure a function remembers the variables where it was created; gives private state, factories, memoize; let in loops fixes the callback bug.
  • Arrays mutate: push pop shift unshift splice sort reverse; copy: slice concat map filter toSorted [...a].
  • sort default is string order; numbers need (a, b) => a - b.
  • Array methods map transform, filter keep, reduce(fn, start) fold, find first match, some/every yes/no; remove: filter(x => x.id !== id).
  • Objects { a, b } shorthand, [key] computed, Object.keys/values/entries, { ...o, k: v } immutable update, Object.freeze is shallow.
  • JSON JSON.stringify(v, null, 2) / JSON.parse(s); drops functions and undefined, dates become strings, throws on BigInt and cycles.
  • Destructuring const { a, b: x = 1 } = obj, const [h, ...t] = arr, swap [a, b] = [b, a]; spread expands, rest collects.
  • Templates `Hi ${name}`, multi-line; they do not escape HTML.
  • DOM querySelector(All), textContent (safe) not innerHTML (XSS), classList, dataset, createElement + append.
  • Events addEventListener; event.target vs currentTarget; bubbling; delegation with closest; preventDefault on form submit.
  • this new > call/apply/bind > obj.method() > plain call (undefined in strict); arrows use outer this.
  • Classes constructor, #private, static, get, extends + super(); syntax over prototypes; new is required.
  • Event loop sync code → all microtasks (promises, await) → one macrotask (timers, events); long loops freeze the page.
  • Promises pending/fulfilled/rejected; then returns a new promise; Promise.all fail-fast, allSettled never rejects, race, any.
  • async/await async returns a promise; await in try/catch; independent calls with Promise.all; never await in forEach.
  • fetch check response.ok; await res.json(); POST needs Content-Type + JSON.stringify; Authorization: Bearer; AbortSignal.timeout(ms).
  • Modules export named / export default one; import { a } from "./x.js"; type="module"; module scope is private.
  • npm package.json, npm install / npm ci / npm run dev, ^ minor+patch, ~ patch; commit the lock file, not node_modules.
  • Storage strings only: JSON.stringify/parse; localStorage persists, sessionStorage per tab; no secrets (XSS can read it).
  • Errors try/catch/finally, throw new Error(), class X extends Error; catch does not see later async errors; log with console.error.
  • Debug console (table, time, trace), breakpoints, debugger;, Network tab for API calls.

Practice — JavaScript

  1. Output prediction (30 minutes). Without running them, write down the output of the hoisting puzzles in scope and hoisting, the loop bug in closures and the ordering puzzle in the event loop. Then run them in the console. Done when all your predictions match, and you can explain every difference out loud.
  2. Array workout. Given a list of 10 products (id, name, price, category, qty) write one-line solutions: names of products over ₹500; the cart total; the most expensive product; items grouped by category with reduce; products sorted by price descending without changing the original; a list with one product removed by id. Done when no for loop is needed and the original array is never mutated (check with console.log).
  3. Closures and functions. Write makeCounter(step) with increment, reset and value that keep the count private; a memoize(fn) that logs "cache hit"; and a debounce(fn, ms). Done when counter.count is undefined, memoize logs the hit on the second call, and debounce runs once after a burst of five calls.
  4. To-do list saved in local storage (roadmap build). Start from the to-do example. Load tasks from localStorage on start, save after every add, toggle and delete, compute the next id from the highest stored id, and add a filter (All / Active / Done) plus a "Clear completed" button. Done when tasks survive a page reload, bad JSON in storage does not crash the page (wrap in try/catch), and a task named <b>hi</b> is displayed as text.
  5. Quiz app (roadmap build). Keep 8 questions in an array of objects (question, options, answerIndex). Show one question at a time with option buttons (use event delegation), mark the answer right or wrong, keep the score, show a final result with a "Play again" button, and store the best score in localStorage. Done when the whole flow works with only keyboard and mouse, with no global variables outside one module, and the best score stays after a reload.
  6. Calculator (roadmap build). Build a calculator with digit, operator, decimal point, clear and equals buttons, driven by one delegated click listener and data- attributes. Do not use eval. Handle division by zero (show "Cannot divide by 0"), repeated operators, and the 0.1 + 0.2 display (round to 10 decimal places). Add keyboard support with keydown. Done when 7 ÷ 2 shows 3.5, 0.1 + 0.2 shows 0.3 and no input crashes it.
  7. GitHub profile finder (roadmap build, async). A form takes a username and calls https://api.github.com/users/{username}, then shows avatar, name, bio, followers, public repos and the five most recently updated repositories from the /repos endpoint (load both with Promise.all). Show "Loading…" while waiting, a friendly message for 404 (user not found) and for network errors, disable the button during the request, and cancel the previous request with AbortController if the user searches again. Use textContent for all text. Done when every error path shows a message and the page never throws in the console. (A weather app with a public weather API is an equally good alternative.)
  8. Your own apiClient. Create apiClient.js (see fetch) as an ES module and use it against the Spring Boot REST API you built earlier: list, create, update and delete one resource, with a login that stores the JWT. Handle 401 by clearing the token and showing the login form. Done when each call works from a page served by a dev server (or Vite), CORS is configured on the Spring side, and you can show the failing request in the Network tab for a wrong password and for a stopped server and explain the difference.
  9. Review and explain. Without notes, answer the 13 questions in the interview article aloud in under two minutes each, then rebuild the event-delegation delete button from memory. Done when you can explain this, closures, the event loop and fetch error handling to someone who only knows Java.
