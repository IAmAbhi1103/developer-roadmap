TanStack Query for server data

TanStack Query manages server state for you: useQuery fetches and caches data by a query key with loading and error states, and useMutation sends changes and invalidates the cache so the UI refreshes.

Good to know

Server state is different

Data like "the list of employees" is not owned by your app. It lives on the server, can change without you knowing, can be shared by many screens, and can be out of date the moment you receive it. With useEffect you would have to build caching, deduplication, retries, background refresh, loading flags and invalidation yourself. TanStack Query (formerly React Query) does all of it. Install: npm install @tanstack/react-query. The current major version is v5; the examples use its object-style API.

Setup

import { QueryClient, QueryClientProvider } from '@tanstack/react-query';

const queryClient = new QueryClient({
  defaultOptions: {
    queries: {
      staleTime: 30_000,        // data counts as fresh for 30 s: no refetch in that window
      retry: 1,                 // retry failed requests once
    },
  },
});

createRoot(document.getElementById('root')).render(
  <StrictMode>
    <QueryClientProvider client={queryClient}>
      <App />
    </QueryClientProvider>
  </StrictMode>,
);

useQuery: reading data

You give useQuery a query key (an array that identifies the data) and a query function that returns a Promise (and throws on failure). The key is the cache key: same key, same cached data, shared by all components.

export async function fetchEmployees(page = 0) {
  const res = await fetch(`http://localhost:8080/api/employees?page=${page}&size=10`);
  if (!res.ok) throw new Error(`HTTP ${res.status}`);   // a thrown error becomes `error`
  return res.json();
}
import { keepPreviousData, useQuery } from '@tanstack/react-query';
import { fetchEmployees } from './employeeApi.js';

function EmployeeListPage() {
  const [page, setPage] = useState(0);

  const { data, isPending, isError, error, isFetching } = useQuery({
    queryKey: ['employees', { page }],         // changes with page -> new fetch, own cache entry
    queryFn: () => fetchEmployees(page),
    placeholderData: keepPreviousData,         // keep showing old page while the next loads
  });

  if (isPending) return <p>Loading…</p>;
  if (isError) return <p role="alert">Error: {error.message}</p>;

  return (
    <>
      <ul>{data.content.map((e) => <li key={e.id}>{e.name}</li>)}</ul>
      {isFetching && <small>Updating…</small>}
      <button disabled={page === 0} onClick={() => setPage((p) => p - 1)}>Prev</button>
      <button disabled={data.last} onClick={() => setPage((p) => p + 1)}>Next</button>
    </>
  );
}

Compare this with the 30-line effect in fetching data: no loading state, no cleanup, no race conditions, and the result is cached. Key fields returned:

Field / optionMeaning

isPendingNo data yet (first load)
isFetchingA request is running, including background refetches
isError / errorThe query function threw
refetch()Fetch again on demand

Fresh, stale and refetching

Cached data is fresh for staleTime, then stale. Showing stale data instantly while fetching a new copy in the background ("stale-while-revalidate") is the default behaviour. A stale query is refetched when a component mounts, the window regains focus, or the network reconnects. That is why your list refreshes when you come back to the tab. With staleTime: 0 (the default) this happens a lot; raise it for data that rarely changes.

Query keys

Keys are arrays, compared by value. Put everything the function depends on into the key, as you would with an effect's dependencies: ['employee', id], ['employees', { page, q }]. The key structure is hierarchical, so invalidating ['employees'] also matches ['employees', { page: 2 }].

useMutation: changing data

Writes (POST, PUT, DELETE) use useMutation. After a successful mutation you invalidate the affected queries, which marks them stale and refetches the ones on screen.

import { useMutation, useQueryClient } from '@tanstack/react-query';

async function createEmployee(newEmployee) {
  const res = await fetch('http://localhost:8080/api/employees', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(newEmployee),
  });
  if (!res.ok) throw new Error(`HTTP ${res.status}`);
  return res.json();
}

function AddEmployee() {
  const queryClient = useQueryClient();

  const mutation = useMutation({
    mutationFn: createEmployee,
    onSuccess: () => {
      queryClient.invalidateQueries({ queryKey: ['employees'] });   // list refetches
    },
  });

  return (
    <button
      disabled={mutation.isPending}
      onClick={() => mutation.mutate({ name: 'Meera Iyer', email: 'meera@corp.in' })}
    >
      {mutation.isPending ? 'Saving…' : 'Add employee'}
      {mutation.isError && <span role="alert"> Failed: {mutation.error.message}</span>}
    </button>
  );
}

Wrap it in custom hooks

import { useMutation, useQuery, useQueryClient } from '@tanstack/react-query';
import { createEmployee, fetchEmployee, fetchEmployees } from './employeeApi.js';

export const employeeKeys = {
  all: ['employees'],
  list: (page) => ['employees', { page }],
  detail: (id) => ['employee', id],
};

export function useEmployees(page) {
  return useQuery({ queryKey: employeeKeys.list(page), queryFn: () => fetchEmployees(page) });
}

export function useEmployee(id) {
  return useQuery({
    queryKey: employeeKeys.detail(id),
    queryFn: () => fetchEmployee(id),
    enabled: Boolean(id),
  });
}

export function useCreateEmployee() {
  const qc = useQueryClient();
  return useMutation({
    mutationFn: createEmployee,
    onSuccess: () => qc.invalidateQueries({ queryKey: employeeKeys.all }),
  });
}

Rules

  • The query function must return a Promise and throw on HTTP errors. With fetch check res.ok; Axios already throws for 4xx/5xx.
  • Everything the request depends on goes in the query key.
  • Do not copy data into useState; read it from the query.
  • Use queries for reads and mutations for writes.

Edge cases

  • In v5, isLoading means "first fetch is running" (isFetching && isPending); isPending is "no data yet". In v4 the names were different (isLoading meant "no data"). Check which version tutorials use.
  • The default retry is 3 attempts with backoff. A 401 or 404 that retries three times just delays the error; set retry: false for those or handle them in one place.
  • Install the optional @tanstack/react-query-devtools to see the cache live.

In real projects

A common stack for a Spring Boot backend: Axios instance (Module 6) as the queryFn transport, TanStack Query for all GET/POST/PUT/DELETE calls, React Router for pages, Context only for auth and theme, and React Hook Form for forms.

Interview: "Why TanStack Query instead of useEffect and Redux?"

  • Server state is async, shared, cached and can go stale; it needs a cache layer, not just setState.
  • The query key identifies cached data; staleTime controls freshness; mutations plus invalidateQueries keep the UI in sync after writes.
  • It removes boilerplate and race conditions, and leaves Redux/Zustand for true client state.

React DevTools and common React errors

Use the React DevTools browser extension to inspect the component tree, props, state and renders, and learn to read the handful of error messages you will see every week.

React DevTools

Install the React Developer Tools extension for Chrome, Edge or Firefox. Open the browser DevTools; two new tabs appear:

  • Components: the component tree. Click a component to see its props, state, hooks and context on the right. You can edit state and props live, jump to the DOM node, and search by component name. Use it to answer "what value did this component really receive?".
  • Profiler: record an interaction, then see which components rendered, how long each took, and (with "Record why each component rendered" enabled in settings) why. Use it before adding memo/useMemo. The "Highlight updates when components render" option flashes every re-rendering component.

Combine it with the other DevTools tabs you know from Module 4: the Network tab for requests and the Console for errors. TanStack Query also has its own devtools panel.

A debugging routine

  1. Read the first error in the Console and click the file and line in the stack trace; later errors are often a consequence.
  2. In the Components tab, check the props and state of the failing component. Is the value what you expected?
  3. In the Network tab, check the request URL, status, response body and headers. Is it a 404, a 401, a CORS failure, or the wrong JSON shape?
  4. Add console.log or a debugger statement; remember StrictMode runs renders twice in development, so logs appear doubled.
  5. Reduce the problem: comment out parts until it works, then add them back.

Tip: error boundaries

A rendering error in any component unmounts the whole tree and leaves a white page. An error boundary catches errors in its children and shows a fallback. It must be a class component, so most apps use the small react-error-boundary library: <ErrorBoundary fallback={<p>Something broke</p>}>. Boundaries do not catch errors in event handlers or async code; handle those with try/catch.

Interview: "How do you debug a React app?"

  • Console error and stack trace first; React DevTools Components for props/state; Profiler for slow renders; Network tab for API problems.
  • Know the usual suspects: keys, too many re-renders, stale closures, undefined data before loading, wrong hook order.

Interview questions — React

What is React, and how is it different from a framework like Angular?

React is a library for building UIs from components. It handles rendering and state only; routing, forms, HTTP and global state come from separate libraries you choose. Angular is a full framework with its own router, forms, HTTP client and dependency injection, written in TypeScript. React is declarative: you describe the UI for the current state, and React updates the DOM.

What is the virtual DOM and how does reconciliation work?

Components return React elements, plain objects that describe the UI. After a state change React renders again, diffs the new tree with the previous one and commits only the differences to the real DOM. It assumes elements of different types produce different trees, and uses key to match list items, which gives roughly O(n) comparison. Several updates are batched into one render.

What is the difference between props and state?

Props are inputs from the parent and are read-only. State is data the component owns and changes through a setter, which triggers a re-render. State persists across renders; props change when the parent re-renders. Data flows down as props, and child-to-parent communication happens by calling functions passed as props.

Why must you not mutate state directly?

React detects changes by comparing references. If you mutate an array or object and pass the same reference to the setter, React sees no change and the UI is stale. Create a new value with spread, map or filter. Immutability also keeps DevTools, memoisation and time-travel debugging reliable.

After setCount(count + 1) three times in a handler, count only goes up by 1. Why, and how do you fix it?

State is a snapshot: in that render count is a constant, so all three calls schedule "count = old + 1". Use the functional form setCount(c => c + 1); React passes the latest pending value to each updater, and the result is +3 in one batched render.

Explain useEffect and its dependency array.

It runs after the render is committed, to synchronise with an external system. No array: after every render. []: once after mount. [a, b]: when a or b change. The returned cleanup runs before the next run and on unmount. List every reactive value you use, or you get stale closures. Unstable object or function dependencies cause extra runs or infinite loops.

How do you fetch data in a component and avoid race conditions?

Fetch inside useEffect with the inputs (such as id) in the dependency array. Keep loading, error and data state, and check res.ok. Return a cleanup that aborts with AbortController or sets an ignore flag so an older, slower response cannot overwrite a newer one. In real projects use TanStack Query.

Why do I see my effect (and API call) run twice in development?

StrictMode deliberately mounts, unmounts and mounts again in development to check that your effect has correct cleanup. It does not happen in production. Fix the effect rather than removing StrictMode.

Why do lists need keys? Is the array index a good key?

Keys let React match items between renders to reuse, move or remove the correct element and keep its state. Use a stable unique id. Index keys break when the list is reordered, filtered or has inserts or deletes, because state and DOM nodes attach to the wrong item. A random key per render recreates every item.

Controlled vs uncontrolled components?

A controlled input's value comes from state (value + onChange), so React is the source of truth and you can validate or transform on each change. An uncontrolled input keeps its value in the DOM; you read it with a ref or FormData. File inputs are always uncontrolled; React Hook Form uses uncontrolled inputs for performance.

What is prop drilling and how do you avoid it?

Passing props through intermediate components that do not need them. Avoid it with composition (pass children or JSX), with Context for rarely changing global values like the user or theme, or with a state library. Context re-renders all consumers when the value changes, so it is not for fast-changing data.

What are the rules of hooks, and why do they exist?

Call hooks only at the top level (not in conditions, loops or nested functions) and only in function components or custom hooks. React stores hook state in an ordered list per component, so the calls must happen in the same order every render. Breaking the rule gives "Rendered more hooks than during the previous render" or silently wrong state.

When would you use useMemo, useCallback and React.memo?

useMemo caches an expensive computed value; useCallback caches a function reference; React.memo skips re-rendering a component when its props are shallow-equal. Together they help when a memoised child receives stable props, or a value is an effect dependency. Measure with the Profiler first; unnecessary memoisation adds complexity without benefit.

Why TanStack Query instead of fetching in useEffect?

Server data needs caching, deduplication, background refetching, retries, loading and error states and invalidation after writes. TanStack Query provides these through query keys, staleTime, useQuery, useMutation and invalidateQueries, and removes race-condition boilerplate. Client-only state still belongs in useState or Context.

Practice — React

  1. Counter and toggles. Create a Vite React project. Build a counter with +, − and reset, using functional updates, and a button that shows/hides a panel. Done when clicking + three times in one handler adds 3 and no console warnings appear.
  2. Todo list. Add, toggle and delete todos stored in state with immutable updates, a filter (all/done/pending) derived during render, and ids as keys. Done when you can delete the first item without any text in other rows moving.
  3. Form with validation. Build a registration form (name, email, password, role select, terms checkbox) with controlled inputs, one handleChange, errors under each field and a disabled button while "submitting" (use a fake 1-second promise). Rebuild it with React Hook Form + Zod.
  4. Movie search or expense tracker. Pick one. Movie search: call a public movie API from an effect with a debounced search box, loading/error/empty states, AbortController and results as cards. Expense tracker: add/edit/delete expenses, totals by category derived in render, persisted with a useLocalStorage hook. Done when a fast typist never sees stale results.
  5. Add routing and Context. Extend that app with React Router: a list page, a detail page (/:id), a 404 page, a shared layout with NavLinks, and filters in search params. Add a ThemeContext (light/dark) and a favourites list in Context.
  6. Rebuild the Module 4 apps. Take your DOM and async apps from Module 4 (for example the weather or GitHub-user search) and rebuild them in React with routing. Compare how many lines handle "update the screen".
  7. Custom hooks. Write and use useFetch, useDebounce and useLocalStorage. Open StrictMode's double effect in the Network tab and prove your cleanup works.
  8. Switch to TanStack Query. Replace a hand-written fetch with useQuery, add a create form with useMutation and invalidateQueries. Done when the list updates after saving without a manual refetch.
  9. Break and debug on purpose. Trigger "Each child in a list should have a unique key", "Too many re-renders", and "Objects are not valid as a React child". Find each in the Console and fix it. Record a Profiler session and find one avoidable re-render.
