Arrays: creating, changing, looping and copying

A JavaScript array is a resizable list of any values (like an ArrayList<Object>); know which methods change the array and which return a new one, remember that sort() compares as strings, and copy with spread or structuredClone.

In Java you choose between a fixed-size array int[] and an ArrayList<T>. JavaScript has just one thing: the array. It grows and shrinks on its own, holds values of mixed types, and comes with dozens of built-in methods. It is an object, so typeof [] is "object"; test with Array.isArray(). Indexes start at 0, and arr.length is a property, not a method.

Creating arrays

const cart = ["Rice", "Dal", "Ghee"];        // literal — the normal way
const empty = [];
const mixed = [1, "two", true, null, { id: 4 }];   // allowed, but avoid it

console.log(cart.length);       // 3
console.log(cart[0], cart[2]);  // Rice Ghee
console.log(cart[10]);          // undefined — no ArrayIndexOutOfBoundsException
console.log(cart.at(-1));       // "Ghee" — negative index counts from the end

const zeros = new Array(3).fill(0);               // [0, 0, 0]
const range = Array.from({ length: 5 }, (_, i) => i + 1);  // [1, 2, 3, 4, 5]
const letters = Array.from("abc");                // ["a", "b", "c"]
const fromSet = [...new Set([1, 2, 2, 3])];       // [1, 2, 3] — remove duplicates
console.log(Array.of(7));       // [7]  (new Array(7) would make 7 empty slots)

Reading a missing index gives undefined, and writing past the end grows the array and leaves empty holes: cart[5] = "Tea" makes length 6 with empty slots in between. Avoid this.

Note the pairs that confuse: slice (copies, safe) vs splice (edits, dangerous), and push (returns the new length, not the array).

sort() sorts as strings by default

Without a function, sort() converts items to strings and compares them in alphabetical (UTF-16) order. For numbers this is wrong. Pass a comparator: a function (a, b) that returns a negative number if a comes first, positive if b comes first, and 0 if equal. It works just like Java's Comparator.compare.

const marks = [100, 25, 9, 1000];
console.log(marks.sort());                 // [100, 1000, 25, 9]  — string order!

marks.sort((a, b) => a - b);               // ascending
console.log(marks);                        // [9, 25, 100, 1000]
marks.sort((a, b) => b - a);               // descending
console.log(marks);                        // [1000, 100, 25, 9]

const products = [
  { name: "Mouse", price: 499 },
  { name: "Cable", price: 199 },
  { name: "Bag",   price: 1299 },
];
products.sort((a, b) => a.price - b.price);          // by number
products.sort((a, b) => a.name.localeCompare(b.name)); // by text, language-aware
console.log(products.map(p => p.name));   // ["Bag","Cable","Mouse"]

// Newer, keeps the original untouched
const sorted = products.toSorted((a, b) => b.price - a.price);

sort() is stable (equal items keep their order) in all current engines, and it changes the array in place. To keep the original, copy first: [...marks].sort(...) or use toSorted().

Looping: for, for...of, for...in, forEach

const cities = ["Pune", "Delhi", "Goa"];

for (let i = 0; i < cities.length; i++) console.log(i, cities[i]);  // classic

for (const city of cities) console.log(city);          // values — preferred

for (const [i, city] of cities.entries()) console.log(i, city);  // index + value

cities.forEach((city, i) => console.log(i, city));   // callback style

for (const key in cities) console.log(key);            // "0", "1", "2" — STRINGS

Copying: reference, shallow, deep

Like in Java, const b = a copies the reference: both names point to one array. To copy, use spread. A shallow copy copies the top level only; nested objects are still shared. A deep copy duplicates everything.

const a = [{ name: "Rice", qty: 1 }, { name: "Dal", qty: 2 }];

const same = a;              // same array
const shallow = [...a];      // new array, same item objects (also a.slice())
const deep = structuredClone(a);   // new array AND new item objects

shallow[0].qty = 99;         // changes the shared object
console.log(a[0].qty);       // 99 — the original changed!
console.log(deep[0].qty);    // 1  — unaffected

shallow.push({ name: "Tea", qty: 1 });
console.log(a.length, shallow.length); // 2 3 — the arrays are separate

structuredClone() (available in current browsers and Node 17+) copies plain data, dates, maps, sets and nested arrays; it throws DataCloneError for functions. The old trick JSON.parse(JSON.stringify(x)) loses dates, undefined and functions (see objects and JSON).

Convention: do not mutate shared arrays

Prefer map, filter, spread and toSorted over push, splice and sort on data that other code also uses, especially React state. setItems([...items, newItem]) instead of items.push(newItem).

Edge cases

  • indexOf and includes compare with strict equality, so they cannot find an object by its content: [{a:1}].includes({a:1}) is false. Use some or find.
  • [1, 2, 3].includes(NaN) is false, but [NaN].includes(NaN) is true; indexOf(NaN) is always −1.
  • Setting arr.length = 0 empties the array; setting a smaller length cuts it.
  • new Array(3) makes holes, and map skips holes. Use Array.from({ length: 3 }) or .fill().
  • forEach over an empty array does nothing; reduce on an empty array without an initial value throws TypeError: Reduce of empty array with no initial value.

Common mistake: default sort on numbers and mutating while sorting a copy

Wrong: string order, and edits state

const ranked = prices.sort();     // [100, 25, 9]...
// prices itself was reordered too

Right: comparator on a copy

const ranked = [...prices].sort((a, b) => a - b);
// or prices.toSorted((a, b) => a - b)

Interview angle

  • "slice vs splice?" slice returns a copy of a part; splice removes/inserts in place.
  • "Why does [10, 9, 1].sort() give [1, 10, 9]?" Default sort compares strings. Use (a, b) => a - b.
  • "for…in vs for…of?" keys vs values; for…of for arrays.
  • "Shallow vs deep copy?" Spread copies one level; structuredClone copies all levels.
  • "How do you check for an array?" Array.isArray(x).

map, filter, reduce, find and friends

Replace most hand-written loops with array methods: map transforms each item, filter keeps some, reduce folds the array into one value, find/some/every search, and you can chain them like Java streams — without any stream() or collect().

These methods take a callback and call it for every item. They are the daily tools of React code, where lists are turned into UI with map. If you know Java streams (stream().map().filter().collect()), you already know the ideas; in JavaScript the methods work directly on the array and return an array.

Callbacks receive up to three arguments: (item, index, array). Most of the time you write only the first.

map: transform every item

const cart = [
  { id: 1, name: "Paneer", price: 240, qty: 2, category: "dairy" },
  { id: 2, name: "Rice",   price: 650, qty: 1, category: "grocery" },
  { id: 3, name: "Curd",   price: 60,  qty: 4, category: "dairy" },
  { id: 4, name: "Atta",   price: 380, qty: 1, category: "grocery" },
];

const names = cart.map(item => item.name);
console.log(names);   // ["Paneer", "Rice", "Curd", "Atta"]

const lines = cart.map(({ name, price, qty }) => ({ name, lineTotal: price * qty }));
console.log(lines[0]); // { name: 'Paneer', lineTotal: 480 }

// In React you turn data into elements the same way:
// cart.map(item => <li key={item.id}>{item.name}</li>)

map always returns an array of the same length. If you do not use the returned array, you wanted forEach.

filter: keep what matches

const dairy = cart.filter(item => item.category === "dairy");
console.log(dairy.map(i => i.name));   // ["Paneer", "Curd"]

const expensive = cart.filter(i => i.price > 300);   // Rice and Atta
const cleaned = ["a", "", null, "b", undefined].filter(Boolean);  // ["a", "b"]
const withoutItem2 = cart.filter(i => i.id !== 2);     // "delete" without mutating

filter(i => i.id !== id) is the standard way to remove an item from a list in React state.

reduce: fold into one value

reduce goes through the array with an accumulator (the running result). Your callback receives (accumulator, item) and returns the next accumulator. The second argument is the starting value. Always pass it.

// Cart total
const total = cart.reduce((sum, i) => sum + i.price * i.qty, 0);
console.log(total);   // 480 + 650 + 240 + 380 = 1750

// Count items per category
const countByCategory = cart.reduce((acc, i) => {
  acc[i.category] = (acc[i.category] ?? 0) + 1;
  return acc;
}, {});
console.log(countByCategory);   // { dairy: 2, grocery: 2 }

// Group items by category (like Collectors.groupingBy)
const grouped = cart.reduce((acc, i) => {
  (acc[i.category] ??= []).push(i.name);
  return acc;
}, {});
console.log(grouped);   // { dairy: [ 'Paneer', 'Curd' ], grocery: [ 'Rice', 'Atta' ] }

// Max price
const maxPrice = cart.reduce((m, i) => Math.max(m, i.price), 0);   // 650
// Newer: Object.groupBy(cart, i => i.category) does grouping directly (Node 21+, recent browsers)

Newer helpers

Object.groupBy(), toSorted() and findLast() exist in current browsers and recent Node versions, but not in old ones. Check MDN browser compatibility before relying on them in a project that supports older browsers.

find, findIndex, some, every

const rice = cart.find(i => i.name === "Rice");
console.log(rice?.price);                  // 650
console.log(cart.find(i => i.id === 99)); // undefined — no exception, check it
console.log(cart.findIndex(i => i.id === 3));   // 2
console.log(cart.some(i => i.qty > 3));         // true  — at least one
console.log(cart.every(i => i.price > 50));     // true  — all of them
console.log([].every(x => false), [].some(x => true)); // true false (empty array)

find returns the first match and stops. It returns the item itself (a reference, not a copy), so changing it changes the original array. filter(...)[0] does the same job but needlessly checks every item.

Chaining

Because map and filter return arrays, you can chain them. Read from top to bottom like a pipeline.

const dairyBill = cart
  .filter(i => i.category === "dairy")
  .map(i => i.price * i.qty)
  .reduce((sum, x) => sum + x, 0);
console.log(dairyBill);   // 480 + 240 = 720

const summary = cart
  .toSorted((a, b) => b.price - a.price)
  .slice(0, 2)
  .map(i => `${i.name}: ₹${i.price}`)
  .join(", ");
console.log(summary);     // Rice: ₹650, Atta: ₹380

Differences from Java streams: arrays are eager — each step builds a full intermediate array right away, while streams are lazy and process one element at a time. For typical UI data this does not matter. There is also no terminal operation to remember: the result is already an array.

Which one do I use?

  1. Need a new array of the same size with changed items? map.
  2. Need fewer items? filter.
  3. Need one value (total, object, map, string)? reduce (or a loop if it reads better).
  4. Need one item? find. Need yes/no? some or every.
  5. Need a side effect only (log, change the DOM)? forEach or for…of.

Edge cases

  • A map callback with a block body must return; forgetting it gives an array of undefined.
  • find compares nothing by itself: the callback must return a boolean. cart.find(i => i.id = 2) (assignment) is a bug that returns the first item.
  • These methods skip empty holes of sparse arrays and never wait for promises: arr.map(async x => …) returns an array of promises.
  • Changing the array inside a callback (pushing while iterating) leads to confusing results. Do not.

Common mistake: map for side effects, reduce without a start value

Wrong

cart.map(i => console.log(i.name));   // builds a useless array
[].reduce((a, b) => a + b);           // TypeError: Reduce of empty
                                      // array with no initial value

Right

cart.forEach(i => console.log(i.name));
[].reduce((a, b) => a + b, 0);        // 0

Interview angle

  • "map vs forEach?" map returns a new array; forEach returns undefined and is for side effects.
  • "Write a function that groups or totals with reduce." Show the cart total and grouping above; always pass the initial value.
  • "What does find return if nothing matches?" undefined (filter returns [], findIndex returns −1).
  • "Remove an item without mutating." list.filter(x => x.id !== id).
  • "Implement your own map." A loop that pushes fn(item, i, arr) into a result array.

Objects and JSON

A JavaScript object is a bag of key-value pairs you can create without a class; read it with dot or bracket access, loop with Object.keys/values/entries, and exchange it with servers as JSON using JSON.stringify and JSON.parse — remembering that functions, undefined and dates do not survive.

In Java, to hold a name and an age you first write a class. In JavaScript you write an object literal: curly braces with key: value pairs. The keys are strings (or symbols), the values can be anything, including functions and other objects. The same shape, written as text, is the format of nearly every web API, which is why objects and JSON go together.

const student = {
  name: "Asha",
  age: 21,
  skills: ["Java", "SQL"],
  address: { city: "Pune", pin: "411001" },
  greet() {                       // method shorthand
    return `Hi, I am ${this.name}`;
  },
};

console.log(student.name);            // dot access
console.log(student["age"]);          // bracket access: the key is a string
const field = "city";
console.log(student.address[field]);  // bracket access with a variable: "Pune"
console.log(student.greet());         // "Hi, I am Asha"
console.log(student.phone);           // undefined — missing key, no exception

student.email = "asha@example.com";   // add a property
student.age = 22;                     // change
delete student.skills;                // remove
console.log("age" in student);        // true
console.log(student.hasOwnProperty("name")); // true  (Object.hasOwn(student, "name") is newer)

Use dot access when you know the name; use brackets when the key is in a variable or contains characters like a dash (headers["Content-Type"]).

Shorthand and computed keys

const name = "Rice";
const price = 650;
const item = { name, price };                 // same as { name: name, price: price }
console.log(item);                             // { name: 'Rice', price: 650 }

const field2 = "qty";
const row = { [field2]: 3, [`${field2}Max`]: 10 };   // computed keys
console.log(row);                              // { qty: 3, qtyMax: 10 }

// Updating one field of a form: the pattern behind most React handlers
function updateField(form, key, value) {
  return { ...form, [key]: value };            // new object, one key changed
}
console.log(updateField({ name: "A", city: "X" }, "city", "Goa")); // { name: 'A', city: 'Goa' }

Looping over an object

const stock = { rice: 10, dal: 0, tea: 25 };

console.log(Object.keys(stock));     // ["rice", "dal", "tea"]
console.log(Object.values(stock));   // [10, 0, 25]
console.log(Object.entries(stock));  // [["rice",10], ["dal",0], ["tea",25]]

for (const [item, qty] of Object.entries(stock)) {
  console.log(`${item}: ${qty}`);
}
const inStock = Object.fromEntries(
  Object.entries(stock).filter(([, qty]) => qty > 0)
);
console.log(inStock);   // { rice: 10, tea: 25 }
console.log(Object.assign({}, stock, { dal: 5 })); // { rice: 10, dal: 5, tea: 25 }

Property order: integer-like keys first in ascending order, then the other keys in the order they were added. Do not depend on it for important logic.

Object.freeze and copying

Object.freeze(obj) makes the object's own properties read-only (shallow). Object.isFrozen(obj) checks. Copy an object with spread ({ ...obj }, shallow) or structuredClone(obj) (deep), as for arrays in arrays. Object.freeze on a const is how you make real constants, as shown in let, const and var.

Optional chaining on objects

Data from an API often has missing branches. order.customer?.address?.city ?? "Unknown" reads three levels without throwing (see operators).

JSON: the exchange format

JSON (JavaScript Object Notation) is a text format for data: objects, arrays, strings, numbers, booleans and null. It looks like a JavaScript object literal, but it is stricter: keys and strings must use double quotes, there are no comments, no trailing commas, and no functions or undefined. Spring Boot's Jackson produces and reads exactly this.

  • JSON.stringify(value) turns a value into a JSON string (like Jackson's writeValueAsString). JSON.stringify(value, null, 2) pretty-prints with 2 spaces.
  • JSON.parse(text) turns a JSON string into a value (like readValue). It throws SyntaxError on invalid JSON.
const order = {
  id: 1042,
  customer: "Asha",
  paid: true,
  note: undefined,                      // dropped
  total: NaN,                           // becomes null
  placedAt: new Date("2026-11-10T09:30:00Z"),   // becomes a string
  pay() { return true; },               // dropped
};

const text = JSON.stringify(order);
console.log(text);
// {"id":1042,"customer":"Asha","paid":true,"total":null,"placedAt":"2026-11-10T09:30:00.000Z"}

const back = JSON.parse(text);
console.log(typeof back.placedAt);   // "string" — not a Date any more
console.log(back.placedAt === order.placedAt); // false
console.log(new Date(back.placedAt).getFullYear()); // 2026

try {
  JSON.parse("{ 'id': 1 }");         // single quotes are invalid JSON
} catch (e) {
  console.log(e.name);               // "SyntaxError"
}
console.log(JSON.stringify({ a: 1, b: [1, 2] }, null, 2));
{
  "a": 1,
  "b": [
    1,
    2
  ]
}

Map and Set vs plain objects

Objects work as dictionaries for simple string keys, but Map is closer to Java's HashMap and Set to HashSet.

Edge cases

  • Keys are always strings: { 1: "a" }[1] works because 1 becomes "1".
  • Methods written as arrow functions inside an object do not get this from the object (see this).
  • JSON.parse("") and JSON.parse(undefined) throw SyntaxError. When a Spring endpoint returns no body (204), calling response.json() fails the same way.
  • A key named __proto__ in data from the outside can be a security risk (prototype pollution); validate or use Map.

Common mistake: expecting objects to compare or copy by value

Wrong

const a = { id: 1 };
const b = a;           // same object
b.id = 2;
console.log(a.id);     // 2
console.log({ id: 1 } === { id: 1 }); // false

Right

const b = { ...a };    // copy
b.id = 2;
console.log(a.id);     // 1
const same = JSON.stringify(x) === JSON.stringify(y);
// quick compare for plain data; key order matters

Interview angle

  • "What does JSON.stringify drop?" Functions, undefined, symbols; it changes dates to strings, NaN to null, and throws for BigInt and cycles.
  • "Dot vs bracket notation?" Same result; brackets accept variables and unusual names.
  • "Object vs Map?" Map allows any key type, has size, and keeps insertion order.
  • "Is JSON the same as a JavaScript object?" No: JSON is text with strict rules; an object is an in-memory value.
  • "How do you iterate an object?" Object.entries() with for…of.

Destructuring, spread, rest and template literals

Destructuring unpacks arrays and objects into variables in one line, spread (...) copies or merges them, rest (...) gathers the remainder, and template literals (backticks) build strings with ${expression} — all four appear in every React file.

These four features are only syntax, but they make modern JavaScript short and readable. Java has no direct equivalent (records and string templates are the nearest ideas). The three-dot ... means two different things depending on position: spread when it expands something into pieces, rest when it collects pieces into one thing.

Object destructuring

Destructuring pulls values out of an object or array into separate variables. For objects you match by property name, using braces on the left side.

const user = {
  id: 7,
  name: "Asha",
  address: { city: "Pune", pin: "411001" },
  roles: ["USER", "ADMIN"],
};

const { name, id } = user;                 // name = "Asha", id = 7
const { name: fullName } = user;           // rename: variable fullName
const { phone = "not given" } = user;      // default when undefined
const { address: { city } } = user;        // nested: city = "Pune"
const { roles: [firstRole] } = user;       // object + array: "USER"
const { id: userId, ...others } = user;    // rest: others has name, address, roles

console.log(name, id, fullName, phone, city, firstRole);
// Asha 7 Asha not given Pune USER
console.log(Object.keys(others));          // [ 'name', 'address', 'roles' ]

If the value is null or undefined, destructuring throws TypeError: Cannot destructure property 'name' of 'user' as it is undefined. Give a default: const { name } = user ?? {}.

Array destructuring

For arrays you match by position, using square brackets.

const [first, second] = ["Rice", "Dal", "Ghee"];
const [, , third] = ["Rice", "Dal", "Ghee"];     // skip with commas
const [head, ...tail] = [1, 2, 3, 4];             // rest: tail = [2, 3, 4]
const [a = 10, b = 20] = [5];                     // a = 5, b = 20 (default)

let x = 1, y = 2;
[x, y] = [y, x];                                  // swap without a temp variable
console.log(first, second, third, head, tail, a, b, x, y);
// Rice Dal Ghee 1 [ 2, 3, 4 ] 5 20 2 1

// Functions that return pairs: React's useState returns an array
function minMax(list) { return [Math.min(...list), Math.max(...list)]; }
const [low, high] = minMax([4, 9, 2]);            // 2 9
const [count, setCount] = useState(0);            // React, Module 5

Destructuring in function parameters

This is how React components receive props, and it is a clean way to write "named arguments" in a language without them.

function printOrder({ id, items = [], paid = false }) {
  console.log(`#${id}: ${items.length} items, paid: ${paid}`);
}
printOrder({ id: 1042, items: ["a", "b"] });   // #1042: 2 items, paid: false

function createUser({ name, role = "USER", active = true } = {}) {
  return { name, role, active };               // "= {}" lets you call createUser()
}
console.log(createUser({ name: "Ravi" }));     // { name: 'Ravi', role: 'USER', active: true }

[["a", 1], ["b", 2]].forEach(([key, value]) => console.log(key, value));
// Destructure while looping: for (const { id, name } of users) { ... }

Spread: expand into pieces

const veg = ["Onion", "Tomato"];
const dairy = ["Milk"];
const all = [...veg, "Salt", ...dairy];        // [Onion, Tomato, Salt, Milk]
const copy = [...veg];                          // shallow copy

console.log(Math.max(...[4, 9, 2]));            // 9 — array becomes separate arguments

const defaults = { theme: "light", lang: "en", notify: true };
const mine = { lang: "hi", notify: false };
const settings = { ...defaults, ...mine };      // later keys win
console.log(settings);                          // { theme: 'light', lang: 'hi', notify: false }

// Immutable updates — the React way
const state = { user: { name: "Asha", city: "Pune" }, count: 1 };
const next = { ...state, user: { ...state.user, city: "Goa" }, count: state.count + 1 };
console.log(state.user.city, next.user.city);   // Pune Goa

console.log([..."हिंदी"].length, [..."abc"]);   // string spread; [ 'a', 'b', 'c' ]

Spread makes a shallow copy: nested objects are still shared, so update nested levels by spreading each level (as in the user line above). Spreading an object with the same key twice keeps the last one. Spread of null/undefined into an object is fine ({ ...null } is {}), but spread of null into an array or function call throws TypeError.

Rest: gather the remainder

Rest appears in a function's parameter list (function f(a, ...others)) and at the end of a destructuring pattern, as shown above. It always collects into a real array (or, for objects, a new object) and must be the last element.

Template literals

A template literal uses backticks. It can span several lines, and ${...} inserts the result of any expression. It replaces Java's + joining, String.format and text blocks.

const name = "Asha";
const total = 1497;
console.log(`Hello ${name}, your total is ₹${total * 1.18}`);
// Hello Asha, your total is ₹1766.46
console.log(`Status: ${total > 1000 ? "FREE delivery" : "Delivery ₹40"}`);

const html = `
  <li class="item">
    <strong>${name}</strong>
  </li>`;                                // multi-line, keeps the line breaks
console.log(html.trim().split("\n").length);  // 3

console.log(`Price: ${total.toFixed(2)} \`INR\``);   // escape a backtick with \

// Tagged template (brief): a function called with the text parts and the values
function bold(strings, ...values) {
  return strings.reduce((out, s, i) => out + s + (values[i] !== undefined ? `*${values[i]}*` : ""), "");
}
console.log(bold`Order ${1042} for ${name}`);   // Order *1042* for *Asha*

Tagged templates are what libraries such as styled-components and GraphQL's gql use. You only need to recognise them.

Rule: never put user input into HTML templates unescaped

A template literal does not escape anything. If you build HTML with `<p>${comment}</p>` and assign it to innerHTML, a user comment containing a script tag becomes an attack (see the DOM). The same applies to SQL: never build SQL strings this way; use parameters.

Edge cases

  • Starting a statement with a destructuring pattern needs brackets: ({ a, b } = obj);, otherwise { is read as a block.
  • Defaults apply only for undefined, not null: const { x = 5 } = { x: null } gives null.
  • ${obj} calls toString(), giving "[object Object]"; use JSON.stringify(obj). A Symbol inside ${ } throws TypeError.
  • Rest in an object pattern copies only own enumerable properties.

Common mistake: mutating state instead of spreading

Wrong: edits the original

const updated = state;
updated.count = 5;          // state.count is 5 too
items.push(newItem);        // React will not re-render

Right: new object and array

const updated = { ...state, count: 5 };
const newItems = [...items, newItem];

Interview angle

  • "Spread vs rest?" Same ... symbol: spread expands, rest collects; position decides.
  • "How do you merge two objects?" { ...a, ...b }; the later wins. It is a shallow merge.
  • "Swap two variables without a temp?" [a, b] = [b, a].
  • "Destructure a nested object with a default and a rename." const { address: { city: town = "NA" } = {} } = user;
