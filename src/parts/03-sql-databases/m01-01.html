Almost every Java application you will build keeps its data in a relational database: users, orders, payments, bookings. Spring Boot, JPA and Hibernate sit on top of it, but underneath they all send SQL to the database. If you understand SQL well, you can write correct queries, debug slow or wrong results, read what Hibernate generates and answer the SQL round that almost every Java interview has.

This module covers the core: how relational databases organise data, how to install PostgreSQL (or MySQL) and a client tool, how to read data with SELECT, filters, sorting and paging, how to change data with INSERT, UPDATE and DELETE, and how to define tables with the right data types and constraints. Every example runs on one sample database (a small company plus a small online shop) that you create in The sample database; Modules 2 and 3 use the same tables. PostgreSQL syntax is the default and MySQL differences are noted where they matter. Database design is in Module 4, and indexes and transactions inside the engine are in Module 5. The same tables are used from Java in Spring Boot · Module 3.

Relational databases: tables, rows, columns and keys

A relational database stores data in tables. Each row is one record, each column is one attribute with a fixed data type, and a primary key gives every row a unique identity that other tables can point to with foreign keys.

Database, DBMS and RDBMS

A database is an organised collection of data that programs can store and find again later. A DBMS (database management system) is the software that manages it. It writes the data to disk, answers queries, lets hundreds of users work at the same time, and keeps the data safe when the machine crashes. An RDBMS (relational DBMS) is a DBMS that organises data as tables and is queried with SQL. PostgreSQL, MySQL, MariaDB, Oracle Database, Microsoft SQL Server and SQLite are all RDBMSs. Databases that do not use tables (MongoDB, Redis, Cassandra) are called NoSQL databases; they are covered in Module 6.

Why not just write the data to files from your Java code? Because the DBMS solves problems you would otherwise have to solve yourself, badly:

Tables, rows and columns

A table holds data about one kind of thing: departments, employees, orders. A column is one attribute of that thing (name, location) and has a fixed data type, so every value in the column is of that type. A row is one record: one department, one employee. The set of columns and their types is the table's schema (its structure); the rows are its data.

The theory behind this comes from Edgar F. Codd's relational model (1970). In that theory a table is called a relation, which is why these are "relational" databases. You will meet the formal words in interviews and in DBMS courses:

Relation
A table.
Tuple
A row.
Attribute
A column.
Domain
The set of values a column may hold (its data type plus its constraints).
Degree
The number of columns in a table.
Cardinality
The number of rows in a table. (The same word also describes relationships: one-to-many, many-to-many.)

A relation has a few properties that matter every day:

  • Every row has the same columns. You cannot add a column to just one row.
  • Each cell holds one value (atomic). A list such as 'java,sql,react' in one column breaks this rule and makes queries painful (see first normal form in Module 4).
  • Rows have no order. A table is a set, not a list. When you query without ORDER BY, the database may return rows in any order, and the order can change after an update or a new index.
  • Rows should be distinguishable. That is the job of the primary key.

Primary keys

A primary key (PK) is a column, or a set of columns, whose value uniquely identifies one row. The database enforces two things for it: the value must be unique and it must be NOT NULL. A table has at most one primary key, and the database builds an index on it automatically, so looking up a row by its key is fast.

  • A natural key is a real-world value that is already unique: an email address, a PAN number, an ISBN.
  • A surrogate key is a value the database generates only to identify the row: an auto-incrementing number or a UUID. It has no business meaning, so it never needs to change.
  • A composite key uses two or more columns together. In the sample database, employee_projects uses (emp_id, project_id): one employee can be on many projects and one project has many employees, but the same pair appears only once.

Any column set that could serve as the primary key is a candidate key; the one you choose is the primary key and the others usually get a UNIQUE constraint.

Foreign keys and relationships

A foreign key (FK) is a column whose value must match a key value in another table (or in the same table). employees.dept_id points to departments.dept_id: the database refuses an employee row with dept_id = 99 if department 99 does not exist. This guarantee is called referential integrity. Foreign keys create the relationships between tables:

  • One-to-many: one department has many employees. The FK lives on the "many" side (employees.dept_id).
  • Many-to-many: employees and projects. You need a third table (a junction table, here employee_projects) with an FK to each side.
  • One-to-one: an FK that is also unique, for example a user_profiles row per user.

Where tables live: server, database, schema

In PostgreSQL one server (called a cluster) holds many databases. Each database holds one or more schemas, which are namespaces for tables; the default schema is public, so the full name of a table is public.employees. A connection always belongs to one database, and a query cannot simply join tables from two databases. In MySQL the words database and schema mean the same thing, and one query can read shop.orders and hr.employees together.

Rule: every table gets a primary key

Without one, duplicate rows can appear, you cannot reliably update or delete one specific row, and tools depend on it: JPA entities need an @Id, and replication and many admin tools expect a key.

Convention: surrogate primary key plus unique natural key

Most Java projects use a generated BIGINT or UUID as the primary key and add a UNIQUE constraint on natural identifiers such as email. Emails and phone numbers change; a surrogate key never has to.

Edge cases

  • SQL itself allows a table without a primary key. The table then behaves like a bag of rows and can hold exact duplicates. MySQL's InnoDB engine quietly uses the first UNIQUE NOT NULL index as the clustered key, or creates a hidden row id if there is none.
  • A foreign key column may be NULL unless you declare it NOT NULL. A NULL FK means "no related row", for example an employee not yet assigned to a department.
  • A foreign key may point to the same table: employees.manager_id refers to employees.emp_id. This is a self-reference.

Mistake: trusting the order of rows

"It always comes back sorted by id" is luck, not a guarantee. After updates, deletes, a new index or a parallel plan, the order changes. If the order matters, write ORDER BY.

Interview angle

  • Primary key vs unique key: both reject duplicates; a primary key also rejects NULL and there is only one per table, while a table can have many unique keys and a unique column can usually hold NULLs.
  • Can a table have two primary keys? No. It can have one primary key made of two columns (a composite key).
  • Can a foreign key be NULL? Yes, unless the column is NOT NULL.
  • Candidate key vs primary key vs super key: a super key is any column set that is unique; a candidate key is a minimal super key; the primary key is the candidate key you pick.

SQL: a declarative language and its sublanguages

In SQL you describe the result you want, not the steps to get it; the database's planner chooses how. SQL statements fall into five groups: DDL, DML, DQL, DCL and TCL.

What "declarative" means

SQL (Structured Query Language, said "ess-queue-ell" or "sequel") is the standard language for relational databases. It is declarative: you state what you want, and the database decides how to get it. Java is imperative: you write every step. Compare finding Sales employees who earn more than ₹1,00,000, highest paid first:

// You decide HOW: loop, test, collect, sort
List<Employee> result = new ArrayList<>();
for (Employee e : allEmployees) {
    if (e.getDeptId() == 2 && e.getSalary().compareTo(new BigDecimal("100000")) > 0) {
        result.add(e);
    }
}
result.sort(Comparator.comparing(Employee::getSalary).reversed());
-- You say WHAT you want; the database picks the method
SELECT first_name, salary
FROM employees
WHERE dept_id = 2
  AND salary > 100000
ORDER BY salary DESC;
 first_name |  salary
------------+-----------
 Karan      | 160000.00
 Ananya     | 150000.00
(2 rows)

The SQL version does not say whether to scan the whole table or use an index, or which sort algorithm to use. The database's query planner (also called the optimizer) looks at table sizes, indexes and statistics and picks the cheapest plan. The same query can run differently on a table of 10 rows and a table of 10 crore rows, and you do not change a word. This is also why you can ask the database to explain its plan with EXPLAIN (covered in Module 5).

Standard SQL and dialects

SQL is an ISO/ANSI standard (first published in 1986; the current edition is SQL:2023). Every database implements most of the core and adds its own extensions, so each has a dialect. The basics (SELECT, WHERE, JOIN, GROUP BY, INSERT) are the same everywhere. Differences show up in details: paging (LIMIT vs FETCH FIRST vs SQL Server's TOP), auto-generated ids, string functions, date functions and upserts. PostgreSQL follows the standard closely; MySQL is more lenient and has more non-standard behaviour. Learn one dialect well and the others take days, not months.

The five sublanguages

SQL statements are grouped by what they do. Interviewers like this classification.

GroupFull namePurposeStatements
DDLData Definition LanguageDefine and change structure CREATE, ALTER, DROP, TRUNCATE, COMMENT
DMLData Manipulation LanguageChange the rows INSERT, UPDATE, DELETE, MERGE
DQLData Query LanguageRead rowsSELECT
DCLData Control LanguagePermissions GRANT, REVOKE
TCLTransaction Control LanguageGroup changes into transactions BEGIN / START TRANSACTION, COMMIT, ROLLBACK, SAVEPOINT
 
CREATE TABLE skills (skill_id INT PRIMARY KEY, name VARCHAR(50));   -- DDL
INSERT INTO skills (skill_id, name) VALUES (1, 'Java');             -- DML
SELECT skill_id, name FROM skills;                                  -- DQL
GRANT SELECT ON skills TO report_user;                              -- DCL
BEGIN;                                                              -- TCL
UPDATE skills SET name = 'Java 21' WHERE skill_id = 1;              -- DML
COMMIT;                                                             -- TCL

Note: textbooks disagree on the boxes

Many books put SELECT inside DML and have only four groups. TRUNCATE removes rows but is classed as DDL, because it works on the whole table rather than row by row. If an interviewer uses four groups, follow their lead and mention that some sources split out DQL.

Basic syntax rules

  • A statement ends with a semicolon ;. Tools such as psql wait for it before running anything.
  • Keywords are case-insensitive: select, SELECT and Select are the same. Convention is uppercase (see SQL style).
  • String and date literals use single quotes: 'Mumbai', '2026-04-05'. To put a quote inside a string, double it: 'D''Souza'.
  • Double quotes are for identifiers in PostgreSQL ("Order"), not for strings.
  • Whitespace and line breaks do not matter, so format for readability.

Both are excellent, free and fully supported by Spring Boot. Learn PostgreSQL as your default (it is the more common choice for new Java projects and its strictness teaches good habits) and learn the MySQL differences noted throughout these notes, because many service-company projects run MySQL.

Tip: think in sets, not loops

SQL works on whole sets of rows at once. If you catch yourself fetching rows into Java just to filter, count or join them in a loop, the database can almost always do it faster in one query, close to the data.

Mistake: double quotes around strings

Wrong: PostgreSQL reads "Mumbai" as a column name

SELECT name FROM departments WHERE location = "Mumbai";
-- ERROR:  column "Mumbai" does not exist

Right: single quotes for values

SELECT name FROM departments WHERE location = 'Mumbai';

MySQL accepts double-quoted strings by default (unless the ANSI_QUOTES mode is on), which hides this bug until you move to PostgreSQL.

Interview angle

  • Why is SQL declarative? You describe the result; the optimizer chooses the access paths, join order and algorithms.
  • DDL vs DML: DDL changes structure (tables, columns), DML changes rows. In MySQL DDL commits the current transaction automatically; in PostgreSQL most DDL can be rolled back.
  • Is TRUNCATE DDL or DML? DDL. It removes all rows without scanning them one by one.

Install PostgreSQL or MySQL and a client tool

Install a database server (natively or in Docker), connect with the command-line client (psql or mysql) and a GUI such as pgAdmin, DBeaver or MySQL Workbench, then create a database and a non-superuser account for your work.

The pieces

A database has two parts. The server is a background process that owns the data files and listens on a network port (5432 for PostgreSQL, 3306 for MySQL). A client connects to that port, sends SQL and shows the results. Your Spring Boot application is just another client, using a JDBC driver. You can install the server directly on Windows or run it in Docker; either is fine for learning.

PostgreSQL on Windows

  1. Open postgresql.org/download/windows and download the installer (packaged by EDB). Pick the newest version offered.
  2. Run it and keep the default components: PostgreSQL Server, pgAdmin 4 (GUI) and Command Line Tools (psql, pg_dump). Stack Builder is optional.
  3. Set a password for the postgres superuser and write it down. Keep port 5432.
  4. Finish. The server is installed as a Windows service and starts with Windows.
  5. Open a new terminal and run psql --version. If it is not found, add C:\Program Files\PostgreSQL\<version>\bin to your PATH, or use the SQL Shell (psql) shortcut from the Start menu.

PostgreSQL in Docker

If Docker Desktop is installed (see DevOps · Module 3), one command gives you a server, and deleting the container leaves your machine clean:

# Start PostgreSQL 18 in the background, data kept in a named volume
docker run --name pg-learn \
  -e POSTGRES_PASSWORD=change_me \
  -p 5432:5432 \
  -v pgdata:/var/lib/postgresql \
  -d postgres:18

# Open psql inside the container as the postgres superuser
docker exec -it pg-learn psql -U postgres

Version note: Docker volume path

The official image changed its data directory layout in version 18, so mount the volume at /var/lib/postgresql. For images up to 17 the usual mount point is /var/lib/postgresql/data. Check the image's page on Docker Hub when you change versions.

MySQL on Windows or in Docker

From dev.mysql.com/downloads, install MySQL Community Server (the 8.4 LTS release is the safe choice) with its MSI installer, and MySQL Workbench as the GUI. The installer asks for a root password and offers to run MySQL as a Windows service on port 3306. With Docker:

docker run --name mysql-learn \
  -e MYSQL_ROOT_PASSWORD=change_me \
  -p 3306:3306 \
  -v mysqldata:/var/lib/mysql \
  -d mysql:8.4

docker exec -it mysql-learn mysql -u root -p

psql basics

# host, port, user and database are explicit; psql asks for the password
psql -h localhost -p 5432 -U postgres -d postgres

# the same as a connection URI
psql postgresql://postgres@localhost:5432/postgres

Inside psql, lines that start with a backslash are meta-commands: psql handles them itself and they need no semicolon. Everything else is SQL and runs only when you type ;.

Create a database and a user

Do not run your work, or your application, as the superuser. A superuser can drop every database by mistake. Create a normal user that owns one database:

CREATE USER app_user WITH PASSWORD 'change_me';
CREATE DATABASE learn_sql OWNER app_user;

-- Show timestamps in Indian time for every new session on this database
ALTER DATABASE learn_sql SET timezone TO 'Asia/Kolkata';
psql -h localhost -U app_user -d learn_sql
CREATE DATABASE learn_sql;
CREATE USER 'app_user'@'localhost' IDENTIFIED BY 'change_me';
GRANT ALL PRIVILEGES ON learn_sql.* TO 'app_user'@'localhost';

In PostgreSQL, CREATE USER is the same as CREATE ROLE … LOGIN: users and groups are both roles. The timezone setting only changes how timestamps are displayed in each session; you will see why that matters in Dates, times, UUID and JSON types. In MySQL a user is the pair of a name and a host: 'app_user'@'localhost' can connect only from the same machine, while 'app_user'@'%' can connect from anywhere (needed when MySQL runs in Docker and you connect from the host).

Version note: PostgreSQL 15 changed the public schema

Before PostgreSQL 15, every user could create tables in the public schema of any database they could connect to. From 15 on, only the database owner (and roles it grants) can. That is why the example makes app_user the OWNER of learn_sql. If you see ERROR: permission denied for schema public, either make the user the owner or run GRANT CREATE ON SCHEMA public TO app_user; as the owner.

Connecting from Spring Boot

Your application connects with the same details, written as a JDBC URL:

# PostgreSQL (driver dependency: org.postgresql:postgresql)
spring.datasource.url=jdbc:postgresql://localhost:5432/learn_sql
spring.datasource.username=app_user
spring.datasource.password=${DB_PASSWORD}

# MySQL (driver dependency: com.mysql:mysql-connector-j)
# spring.datasource.url=jdbc:mysql://localhost:3306/learn_sql

Keep the password out of the file and read it from an environment variable, as shown. Connection pools, JPA and migrations are in Spring Boot · Module 3.

Common setup problems

  • Nothing happens after Enter in psql: you forgot the ;. The prompt shows -#. Type ; and press Enter.
  • Tables "disappear": you are connected to the default postgres database, not learn_sql. Check with \conninfo.
  • password authentication failed for user: wrong password, or wrong user name (on Windows, psql defaults to your Windows user name if you leave out -U).
  • Port already in use: another PostgreSQL (a second install or a Docker container) holds 5432. Stop one, or map Docker to another port: -p 5433:5432.

In real projects

Teams usually run the database for local development in Docker (often through a docker-compose.yml or Testcontainers in tests), so everyone uses the same version as production. The application connects with a limited user, and only administrators hold the superuser password.

Interview angle

Setup questions are rare, but you may be asked: the default ports (5432 and 3306), how to describe a table from the command line (\d or DESCRIBE), why an application should not use the superuser (least privilege: a bug or SQL injection then cannot drop the whole database), and what a JDBC URL looks like.
