Interview questions — SQL basics

What is the difference between DELETE, TRUNCATE and DROP?

DELETE removes rows one by one, accepts a WHERE, fires row triggers and can be rolled back. TRUNCATE empties the whole table quickly, has no WHERE, resets identity counters if you ask (RESTART IDENTITY) and is transactional in PostgreSQL but commits implicitly in MySQL. DROP TABLE removes the table itself: structure, data, indexes and constraints. DELETE and TRUNCATE keep the table definition; DROP does not.

Why does WHERE salary = NULL return no rows, and what is the fix?

SQL uses three-valued logic: true, false and unknown. Any comparison with NULL, including NULL = NULL, gives unknown, and WHERE keeps only rows that are true. Use IS NULL / IS NOT NULL, or IS DISTINCT FROM when you want a NULL-safe comparison. COALESCE(x, 0) replaces NULL with a default.

What does NOT IN return if the list contains a NULL?

Nothing. x NOT IN (1, 2, NULL) means x <> 1 AND x <> 2 AND x <> NULL; the last part is unknown, so the whole expression is never true. A subquery that returns one NULL empties the result. Use NOT EXISTS, or filter the NULLs out of the subquery (NULL and three-valued logic).

Primary key vs unique key: what is the difference?

A table has at most one primary key; it is unique and cannot be NULL, and it identifies the row (JPA's @Id maps to it). A table may have many unique constraints; their columns may contain NULL, and several NULLs are allowed because NULL is never equal to NULL. Both create a unique index.

Which data type do you use for money, and why not FLOAT?

NUMERIC(p, s) / DECIMAL, mapped to BigDecimal in Java. Floats are binary approximations: 0.1 + 0.2 is not exactly 0.3 in a DOUBLE PRECISION, and errors add up across many rows. Some systems store whole paise in a BIGINT instead.

VARCHAR vs TEXT vs CHAR?

CHAR(n) is fixed length and space padded; avoid it except for fixed codes. VARCHAR(n) holds up to n characters and rejects more, a good way to express a business limit. TEXT has no limit. In PostgreSQL all three perform the same, so the length is only a rule; in MySQL TEXT is a separate family with index restrictions.

What is the difference between TIMESTAMP and TIMESTAMPTZ?

TIMESTAMP stores the date and time you typed, with no zone. TIMESTAMPTZ converts input to UTC, stores that, and shows it in the session time zone, so it always means one exact instant. Use it for event times (created_at). MySQL's equivalents are DATETIME (no conversion) and TIMESTAMP (UTC, limited to the year 2038).

What is the order of rows without ORDER BY, and why does paging need it?

It is unspecified. The database returns rows in whatever order is cheapest, which can change after an update, a vacuum or a different plan. With LIMIT 10 OFFSET 20 and no ORDER BY, a row can appear on two pages or none. Order by a unique column (add the id as a tie-breaker) for stable pages.

Does BETWEEN include its end points? Any trap with dates?

Yes, both ends are included. For a TIMESTAMP column, BETWEEN '2026-04-01' AND '2026-04-30' stops at midnight on the 30th and misses the rest of that day. Use a half-open range instead: >= '2026-04-01' AND < '2026-05-01'.

What happens if you run UPDATE or DELETE without WHERE? How do you work safely?

Every row is changed or removed. Safe workflow: write the SELECT with the same WHERE first and check the rows, run the change inside BEGIN, look at the row count and a verification query, then COMMIT or ROLLBACK. Add RETURNING * in PostgreSQL to see what changed, and take a backup before big changes. MySQL's --safe-updates mode refuses statements without a key in WHERE.

What error do you get when a constraint is violated? Name the four main ones.
  • NOT NULL: null value in column "x" violates not-null constraint (SQLState 23502)
  • UNIQUE / PRIMARY KEY: duplicate key value violates unique constraint "..." (23505)
  • CHECK: new row for relation "t" violates check constraint "..." (23514)
  • FOREIGN KEY: violates foreign key constraint "..." (23503)

In Spring these arrive as DataIntegrityViolationException.

Explain ON DELETE CASCADE, SET NULL and RESTRICT with an example.

They tell the database what to do with child rows when the parent is deleted. CASCADE: deleting an order deletes its order_items. SET NULL: deleting a department sets employees.dept_id to NULL (the column must be nullable). RESTRICT (and the default NO ACTION): deleting a product that was sold fails. Choose cascade only when the child is part of the parent.

How do you insert a row if it does not exist, otherwise update it?

An upsert. PostgreSQL: INSERT ... ON CONFLICT (email) DO UPDATE SET ... (or DO NOTHING). MySQL: INSERT ... ON DUPLICATE KEY UPDATE .... It relies on a unique constraint and is atomic, unlike "select then insert", which breaks when two requests race.

Why avoid SELECT * in application code?

It sends columns you do not use, breaks position-based readers when the table changes, blocks index-only scans, and returns duplicate column names in joins. List the columns you need. It is fine for COUNT(*), EXISTS and exploring in a terminal.

How do you add a NOT NULL column to a large live table?

Adding it as NOT NULL with no default fails if the table has rows. Safe path: add the column nullable (or with a constant default, which is instant in PostgreSQL 11+), backfill existing rows in batches, then ALTER COLUMN ... SET NOT NULL. Do it as a Flyway or Liquibase migration, and be aware of table locks.

Cheat sheet — SQL basics

  • Query order written SELECT … FROM … WHERE … ORDER BY … LIMIT; keywords uppercase, names snake_case.
  • NULL never equals anything; use IS NULL, COALESCE(x, d), NULLIF(a, b), IS DISTINCT FROM.
  • NOT IN + NULL returns no rows; use NOT EXISTS.
  • AND before OR; put parentheses around every OR group.
  • BETWEEN is inclusive on both ends; use >= … AND < … for timestamps.
  • LIKE % any text, _ one character; ILIKE is case-insensitive (PostgreSQL only).
  • Paging ORDER BY id LIMIT n OFFSET m or OFFSET m ROWS FETCH FIRST n ROWS ONLY; always order.
  • DISTINCT removes duplicate rows; DISTINCT ON (col) keeps the first row per group (PostgreSQL).
  • INSERT INSERT INTO t (a, b) VALUES (1, 2), (3, 4) RETURNING id;
  • Upsert ON CONFLICT (key) DO UPDATE SET c = EXCLUDED.c / MySQL ON DUPLICATE KEY UPDATE.
  • UPDATE / DELETE always with WHERE; test with SELECT first, inside BEGIN … ROLLBACK.
  • DELETE vs TRUNCATE vs DROP rows with filter, all rows fast, whole table.
  • Whole numbers SMALLINT 2 bytes, INT 4, BIGINT 8.
  • Money NUMERIC(12,2) → Java BigDecimal; never REAL / DOUBLE.
  • Text VARCHAR(n) for limits, TEXT for free text; ids like phone are text.
  • Time TIMESTAMPTZ for moments, DATE for days; store UTC.
  • Ids INT GENERATED ALWAYS AS IDENTITY (MySQL AUTO_INCREMENT); gaps are normal.
  • DDL CREATE TABLE IF NOT EXISTS, ALTER TABLE … ADD/DROP/RENAME COLUMN, DROP TABLE IF EXISTS … CASCADE.
  • Constraints PRIMARY KEY (unique, not null), UNIQUE (NULLs ok), NOT NULL, CHECK (NULL passes), DEFAULT (only when column omitted), FOREIGN KEY.
  • Error codes 23502 not null, 23505 unique, 23503 foreign key, 23514 check.
  • FK actions NO ACTION (default), RESTRICT, CASCADE, SET NULL, SET DEFAULT.
  • psql \l databases, \c db connect, \dt tables, \d table columns, \q quit.
  • MySQL differences backticks, || is OR, 7/2 = 3.5, no RETURNING, case-insensitive text, DDL auto-commits.

Practice — SQL basics

Run sample_schema.sql first, so you start from known data. Write every query yourself, then compare with the results in the earlier articles.

  1. Warm-up reads. List the first and last name of employees in Engineering (dept 1), highest salary first. Then list products costing between 100 and 1,000, sorted by price. Done when the first query returns five rows, Vikram (220000) first and Divya (90000) last.
  2. NULL hunting. Find employees with no department; find customers with no phone number; list customers with the phone shown as 'unknown' when missing (COALESCE). Done when you get 1 employee (Meera) and 3 customers (Diya, Rohan, Tanvi).
  3. Filters and patterns. Employees hired in 2023 or later whose last name starts with S or G, using parentheses correctly; customers whose email contains "an" (use ILIKE). Explain why the parentheses matter.
  4. Paging. Show employees ordered by salary descending, page size 4: write page 1, 2 and 3. Make the order stable with emp_id as a tie-breaker. Done when no employee appears twice.
  5. Safe change. In a transaction, give everyone in Sales a 10 percent raise. Check with SELECT first, use RETURNING, then ROLLBACK. Then do a failing one: set a salary to -1 and read the exact error and constraint name.
  6. Upsert. Write an upsert into departments keyed on name that updates the location when the name exists (Sales moves to Chennai) and inserts a new row otherwise (Legal in Chennai). Run it twice; the second run must not fail.
  7. Design a table. Create leave_requests as in the notes, then add a column approved_by with a foreign key to employees. Insert one valid row and one row for each constraint violation (bad employee, end before start, unknown status). Record the error text and SQLState of each. Done when you can predict each message before running it.
  8. Foreign key actions. Create reviews (review_id, product_id, customer_id, rating) with rating from 1 to 5, a unique pair (product_id, customer_id), product_id with ON DELETE CASCADE and customer_id with ON DELETE SET NULL. Insert three reviews, delete a product and a customer inside a transaction, and show what remains before rolling back.
  9. Type review. Take a column list from an app you know (user: id, name, phone, balance, created time, is_verified, preferences) and pick a PostgreSQL type, NOT NULL decision and default for each. Justify the money and time columns in one line each.
