Interview questions — Advanced SQL

What is a CTE, and how is it different from a subquery, a view and a temporary table?

A CTE (WITH name AS (…)) is a named result that exists for one statement. Unlike a subquery it has a name and can be used several times; unlike a view it is not stored in the database; unlike a temporary table it holds no data between statements and cannot be indexed. It is mostly a readability tool, and the only way (besides procedural code) to write recursive queries. In PostgreSQL 12+ a CTE used once is inlined like a subquery.

How does a recursive CTE work? How do you stop it looping forever?

An anchor query returns the starting rows. The recursive member joins the CTE to the table to produce the next level, and is repeated on the newest rows until it returns nothing; UNION ALL combines all rounds. Typical uses: org charts, category trees, date series. Protect against cycles with a depth limit, a visited-ids array, PostgreSQL's CYCLE clause, or MySQL's cte_max_recursion_depth.

What is a window function, and how is it different from GROUP BY?

It computes a value over a set of related rows (the window, set by OVER (PARTITION BY … ORDER BY …)) but returns one output row per input row. GROUP BY collapses rows into one per group. Windows let you show row details next to group figures, rank rows, and compare with neighbouring rows.

ROW_NUMBER vs RANK vs DENSE_RANK?

For salaries 300, 220, 150, 150, 120: ROW_NUMBER gives 1, 2, 3, 4, 5 (ties get different numbers); RANK gives 1, 2, 3, 3, 5 (ties share a rank, then a gap); DENSE_RANK gives 1, 2, 3, 3, 4 (no gap). Use DENSE_RANK for the Nth highest value, ROW_NUMBER for exactly N rows or de-duplication.

Why can't you use a window function in WHERE? How do you filter on it?

Window functions are evaluated in the SELECT step, after WHERE, GROUP BY and HAVING. So WHERE ROW_NUMBER() OVER (…) = 1 raises "window functions are not allowed in WHERE". Compute it in a subquery or CTE and filter in the outer query.

Explain window frames. What is the default frame, and why does LAST_VALUE surprise people?

The frame is the set of rows around the current row that the function reads. With an ORDER BY and no frame clause the default is RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW, which includes peers with equal sort values. So LAST_VALUE returns the current row (or its last peer), not the last row of the partition. Add ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING. For running totals, use ROWS and a unique ordering.

Write a query for the second highest salary. What about the Nth?

SELECT MAX(salary) FROM employees WHERE salary < (SELECT MAX(salary) FROM employees), or SELECT DISTINCT salary … ORDER BY salary DESC LIMIT 1 OFFSET 1, or DENSE_RANK() OVER (ORDER BY salary DESC) filtered with = N. The last generalises to N and to "per department", and handles ties. Say what you return if there is no Nth value (NULL).

How do you delete duplicate rows but keep one?

Number the copies with ROW_NUMBER() OVER (PARTITION BY the_columns ORDER BY id) and delete rows with number above 1, or self-join on the same values with a.id > b.id, or delete where id NOT IN (SELECT MIN(id) … GROUP BY the_columns). Then add a unique constraint to stop it recurring. In MySQL, delete through a join because you cannot select from the table being deleted in a subquery.

How do you get the top 3 salaries in each department?

DENSE_RANK() OVER (PARTITION BY dept_id ORDER BY salary DESC) in a CTE, then filter rank <= 3. Ask about ties: DENSE_RANK returns every employee who shares one of the top three salary values (4 rows for Engineering), ROW_NUMBER exactly 3 rows. Alternatives: a correlated count of higher distinct salaries, or a LATERAL join with LIMIT 3.

How do you find users who logged in on consecutive days?

De-duplicate the (user, date) pairs, number them per user with ROW_NUMBER, and compute date - row_number. That value is constant within a run of consecutive dates. Group by user and that value, and use COUNT(*) as the streak length. For exactly "3 in a row" you can also use LEAD(login_date, 2) and test that it equals the date plus 2.

View vs materialized view?

A view is a saved query: no data stored, always current, as fast as the underlying query. A materialized view (PostgreSQL) stores the result, so reads are fast and indexable, but the data is stale until REFRESH MATERIALIZED VIEW (use CONCURRENTLY with a unique index to avoid blocking readers). MySQL has no materialized views; use a summary table.

Stored procedure vs function vs trigger. Would you put business logic in them?

A function returns a value or table and can be used inside a query; a procedure is run with CALL and can commit or roll back; a trigger runs automatically on INSERT, UPDATE or DELETE. They run close to the data and cannot be bypassed, good for audit logs, updated_at, batch jobs. But they are harder to test, version, debug and port, and hide behaviour, so most Spring teams keep business rules in Java services and use triggers sparingly.

How would you compute month-over-month growth?

Aggregate revenue per month in a CTE, then use LAG(revenue) OVER (ORDER BY month) to get the previous month, and compute (revenue - previous) / previous * 100. The first month is NULL; guard the division with NULLIF(previous, 0); fill months without data with a generated calendar (generate_series) so that LAG compares adjacent months.

How do you find the median in SQL?

PostgreSQL: PERCENTILE_CONT(0.5) WITHIN GROUP (ORDER BY col). Elsewhere: number the rows with ROW_NUMBER(), count them with COUNT(*) OVER (), and average the rows where rn IN ((cnt+1)/2, (cnt+2)/2) (integer division), which gives the middle row for an odd count and the average of the two middle rows for an even count.

Cheat sheet — Advanced SQL

  • CTE WITH a AS (…), b AS (… FROM a …) SELECT … FROM b; lives for one statement; later CTEs see earlier ones.
  • Recursive CTE WITH RECURSIVE t AS (anchor UNION ALL recursive-member-using-t); needs a stop condition.
  • Series generate_series(1, 10) or dates with INTERVAL '1 day'; MySQL uses a recursive CTE.
  • Window syntax func() OVER (PARTITION BY a ORDER BY b ROWS BETWEEN … AND …); named with WINDOW w AS (…).
  • Windows keep rows; GROUP BY collapses them. Windows run after WHERE/HAVING.
  • Filter on a window compute in a CTE or subquery, then filter outside; no window functions in WHERE.
  • ROW_NUMBER 1,2,3,4 always unique; add a tie-breaker to make it deterministic.
  • RANK 1,2,2,4 gap after ties. DENSE_RANK 1,2,2,3 no gap. NTILE(n) n equal buckets.
  • LAG / LEAD LAG(col, n, default) previous row, LEAD next row; NULL at the edges.
  • FIRST_VALUE / LAST_VALUE LAST_VALUE needs UNBOUNDED FOLLOWING in the frame.
  • Frames default with ORDER BY is RANGE … UNBOUNDED PRECEDING … CURRENT ROW (peers included); use ROWS for running totals.
  • Running total SUM(x) OVER (PARTITION BY k ORDER BY d, id ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW).
  • Moving average AVG(x) OVER (ORDER BY d ROWS BETWEEN 2 PRECEDING AND CURRENT ROW).
  • Percent of total 100.0 * x / SUM(x) OVER ().
  • View saved query, no data. Materialized view stores data, REFRESH MATERIALIZED VIEW [CONCURRENTLY].
  • WITH CHECK OPTION stops updates through a view that would hide the row.
  • Function returns a value, used in queries. Procedure CALL, can commit. Trigger fires on row changes (NEW, OLD).
  • Nth highest DENSE_RANK() OVER (ORDER BY salary DESC) = N, or DISTINCT … OFFSET N-1.
  • Duplicates find with GROUP BY … HAVING COUNT(*) > 1; delete with ROW_NUMBER() > 1 or a self join; prevent with UNIQUE.
  • Top N per group DENSE_RANK()/ROW_NUMBER() OVER (PARTITION BY g ORDER BY x DESC) <= N in a CTE.
  • Anti-join NOT EXISTS; remember NOT IN fails with NULLs.
  • Consecutive days group by date - ROW_NUMBER() (de-duplicate first).
  • Month-over-month (x - LAG(x) OVER (ORDER BY m)) / NULLIF(LAG(x) OVER (ORDER BY m), 0).
  • Pivot one SUM(CASE WHEN …) or FILTER per output column. Median PERCENTILE_CONT(0.5) WITHIN GROUP (ORDER BY x).

Practice — Advanced SQL

The roadmap exercise is to build a college database and write 30 queries on it. Create it in a new database (college) with the script below: 5 teachers, 8 courses, 15 students and 32 enrollments, 60 rows in all. It has deliberate edge cases: a course without a teacher, a course without students, two students without enrollments, a student without a city, and some enrollments without marks.

DROP TABLE IF EXISTS enrollments, students, courses, teachers CASCADE;

CREATE TABLE teachers (
    teacher_id  INT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name        VARCHAR(50) NOT NULL,
    department  VARCHAR(50) NOT NULL
);
CREATE TABLE courses (
    course_id   INT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    title       VARCHAR(60) NOT NULL UNIQUE,
    credits     SMALLINT    NOT NULL CHECK (credits BETWEEN 1 AND 6),
    teacher_id  INT,
    CONSTRAINT fk_courses_teacher FOREIGN KEY (teacher_id) REFERENCES teachers (teacher_id)
);
CREATE TABLE students (
    student_id    INT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name          VARCHAR(50) NOT NULL,
    city          VARCHAR(50),
    year_of_study SMALLINT    NOT NULL CHECK (year_of_study BETWEEN 1 AND 4),
    joined_on     DATE        NOT NULL
);
CREATE TABLE enrollments (
    student_id  INT NOT NULL,
    course_id   INT NOT NULL,
    marks       SMALLINT CHECK (marks BETWEEN 0 AND 100),
    PRIMARY KEY (student_id, course_id),
    CONSTRAINT fk_enr_student FOREIGN KEY (student_id) REFERENCES students (student_id),
    CONSTRAINT fk_enr_course  FOREIGN KEY (course_id)  REFERENCES courses (course_id)
);

  2. Write these 30 queries. Save them in college_queries.sql. Write each one yourself, then read the result and ask if it matches what you expect:
    • Basics: (1) students from Kolkata, sorted by name; (2) students without a city; (3) courses with 4 or more credits; (4) the distinct cities; (5) students whose name contains a (case-insensitive), first five by name.
    • Joins: (6) each student with the titles of their courses (inner join); (7) every course with its teacher's name, including Ethics (left join); (8) every student with the number of courses they take, including 0; (9) courses nobody takes; (10) students with no enrollment, using NOT EXISTS; (11) a full join of teachers and courses; (12) pairs of students from the same city, each pair once; (13) a cross join of students and courses, and the number of combinations that are not enrolled.
    • Aggregates: (14) average marks per course; (15) courses with an average above 75 (HAVING); (16) cities with at least two students; (17) highest and lowest mark per student; (18) total credits per student; (19) number of different students taught by each teacher.
