JDK, JRE and JVM: how Java code runs

You write source code, javac compiles it to platform-neutral bytecode, and the JVM on each machine loads, verifies and runs that bytecode — interpreting it first and compiling the hot parts to machine code.

Java is both compiled and interpreted. That is the reason one Java program runs on Windows, Linux and macOS without changes. Three names are confused again and again, so learn them precisely.

JVM (Java Virtual Machine)
The program that runs bytecode. It loads classes, checks them, manages memory (including garbage collection) and executes your code. There is a different JVM build for each operating system and CPU, but they all run the same bytecode. When you type java Main, you start a JVM.
JRE (Java Runtime Environment)
The JVM plus the standard class library (java.lang, java.util, java.io, …) — everything needed to run a Java program, but not to compile one.
JDK (Java Development Kit)
The JRE plus the developer tools: the compiler javac, jar, javadoc, jshell, javap, jcmd and more. As a developer, you install a JDK.

Think of it as nesting: JDK ⊃ JRE ⊃ JVM. Since Java 11, vendors such as Eclipse Temurin, Amazon Corretto, Oracle and Microsoft ship only a JDK; a separate JRE download is rare now. To build a small runtime for deployment you can use the jlink tool.

From source to running program

  1. Compile. javac Main.java checks syntax and types, then writes Main.class. This file holds bytecode — instructions for an imaginary machine (the JVM), not for your real CPU. If there is a compile error, no .class file is produced.
  2. Load. The class loader finds Main.class and brings it into memory when it is first needed (details in Class loading).
  3. Verify. The bytecode verifier checks that the bytecode is safe: valid instructions, correct types on the stack, no jumping into the middle of an instruction. This is one reason Java is safer than languages that run raw machine code.
  4. Execute. The interpreter starts running bytecode immediately, one instruction at a time. It is slow but starts fast. The JVM counts how often each method and loop runs.
  5. Optimise. Hot code is handed to the JIT (just-in-time) compiler, which turns it into machine code and keeps it in memory. This is why Java programs get faster after a short warm-up. More in JVM architecture.

Platform independence — "write once, run anywhere"

Bytecode is the same on every platform; only the JVM differs. A .class file compiled on your Windows laptop runs on the Linux server in the cloud, as long as the server has a JVM that is new enough. This is why you can build with Maven on a laptop and deploy a .jar inside a Docker image. Note the limit: the language is portable, but your program can still be non-portable if it hard-codes paths such as C:\data or uses native libraries.

Versions you will meet

Rule: the JVM version must be at least the version you compiled for

Code compiled by a newer javac may fail on an older JVM with UnsupportedClassVersionError ("class file version 65.0, this version of the Java Runtime only recognizes class file versions up to 61.0"). Use javac --release 17 (or Maven's maven.compiler.release) to target an older version safely.

Edge cases and errors

  • 'javac' is not recognized (Windows) means only a JRE is installed or the JDK's bin folder is not on PATH.
  • Error: Could not find or load main class Hello — wrong class name, wrong folder, or you typed java Hello.class.
  • The JVM is not "interpreted only": hot code is compiled to machine code, and that code can even be faster than static C++ for some workloads because the JIT knows the real runtime behaviour.
  • Java is not 100 % platform independent: file separators, line endings and native libraries differ.

Tip: use the single-file launcher and JShell for practice

Interview: "Explain JDK, JRE and JVM. How is Java platform independent?"

  • JVM runs bytecode; JRE = JVM + class libraries; JDK = JRE + tools like javac.
  • javac turns source into bytecode, which is platform neutral; each OS has its own JVM that understands the same bytecode. So bytecode is portable, and the JVM is not.
  • Walk through the pipeline: compile → class loader → verifier → interpreter + JIT → machine code.
  • Mention JIT warm-up and that "Java is compiled and interpreted".

Structure of a Java program, naming and keywords

A Java file holds a package declaration, imports and one or more classes; execution starts at public static void main(String[] args), and every word in that line has a reason.

Java source code is organised into classes, and classes into packages. A typical file has this order: package line, import lines, then the class.

package com.shop;                 // 1. where this class lives (folder: com/shop)

import java.util.List;            // 2. bring other classes into scope
import java.util.ArrayList;

/** Prints a small order summary. */   // 3. documentation comment
public class OrderApp {           // 4. class name = file name (OrderApp.java)

    static final double GST = 0.18;    // a constant (see naming below)

    public static void main(String[] args) {    // 5. program entry point
        List<String> items = new ArrayList<>();
        items.add("Pen");
        items.add("Notebook");
        System.out.println("Items: " + items + ", GST rate: " + GST);
    }
}
Items: [Pen, Notebook], GST rate: 0.18

public static void main(String[] args) — word by word

public
The JVM must be able to call the method from outside the class, so it must be visible everywhere.
static
The method belongs to the class, not to an object. The JVM has no object yet when the program starts, so it must be able to call main without creating one.
void
It returns nothing. To report an exit status, call System.exit(code); 0 means success.
main
The exact name the JVM looks for. Main or MAIN will not work.
String[] args
The command-line arguments as an array of strings. The name args is only a convention; String... args (varargs) also works.

The method does not return a value to the JVM and has no throws restriction: you may write main(String[] args) throws Exception. When main ends and no non-daemon threads are still running, the JVM exits.

Command-line arguments

public class Greet {
    public static void main(String[] args) {
        if (args.length == 0) {
            System.out.println("Usage: java Greet.java <name> [city]");
            return;
        }
        String city = args.length > 1 ? args[1] : "India";
        System.out.println("Hello " + args[0] + " from " + city);
    }
}
$ java Greet.java Asha Pune
Hello Asha from Pune
$ java Greet.java
Usage: java Greet.java <name> [city]

Arguments always arrive as Strings. To use a number, convert it: int age = Integer.parseInt(args[0]);, which throws NumberFormatException for input like "abc". Reading args[0] when no argument was given throws ArrayIndexOutOfBoundsException — always check args.length.

Rules for files and classes

  • A file may contain many classes, but at most one public top-level class, and the file must be named after it. public class OrderApp in Order.java fails with class OrderApp is public, should be declared in a file named OrderApp.java.
  • The package line, if present, must be the first statement. The folder structure should match: package com.shop lives in com/shop/.
  • Classes in java.lang (String, Math, Integer, System) are imported automatically. Everything else needs an import or the full name.
  • import java.util.*; imports all classes of that package (not sub-packages). It is legal, but professional code prefers explicit imports, and IntelliJ manages them for you (Ctrl+Alt+O).
  • import static java.lang.Math.*; imports static members so you can write sqrt(x). Use it sparingly.

Keywords

Java reserves about fifty words. You do not need to memorise them, but know the groups: primitive types (int, boolean, …); control flow (if, else, switch, for, while, do, break, continue, return); OOP (class, interface, extends, implements, new, this, super, abstract, final, static, enum); access (public, protected, private); exceptions (try, catch, finally, throw, throws); others (synchronized, volatile, transient, instanceof, package, import).

  • true, false and null are literals, not keywords, but you cannot use them as names either.
  • goto and const are reserved but unused.
  • var, record, yield, sealed and permits are contextual keywords: special only in certain places, so old code with a variable named record still compiles. var is a reserved type name, not a keyword (rules).

Version note: Java 25 and simpler first programs

Java 25 finalised compact source files and instance main methods: a source file can contain just void main() { ... } without a class declaration, public or static, to make the first program easier for beginners. Older JVMs (8, 11, 17, 21) do not support this as a standard feature, and real projects, Spring Boot included, still use the classic form above. Learn the classic main; you will see it everywhere.

Mistakes with main and file names

  • Writing public void main(String[] args) (no static) or static public void Main. With older Java: Error: Main method not found in class Hello. (static public is fine; only the name, parameter and static matter.)
  • Running java Hello.class instead of java Hello.
  • Naming a class like a library class (String, List) in your package and then wondering why List<String> breaks.

Conventions professionals follow

  • One top-level class per file, named after the file.
  • Names say what a thing is, not how it is stored: customers, not customerList2. Avoid one-letter names except for loop indexes (i, j).
  • Keep main thin: it should create objects and call them. In Spring Boot, main is one line: SpringApplication.run(App.class, args);.

Interview: "Why is main static? Can we overload or omit main?"

  • It is static so the JVM can call it without creating an object of the class.
  • You can overload main (for example main(int x)), but the JVM starts only the String[] version.
  • A class without main compiles fine; it just cannot be started directly (a library class).
  • You can declare main as final or synchronized, and add throws.

Data types, variables, wrappers and var

Java has eight primitive types that hold plain values, reference types that point to objects, wrapper classes (Integer, Double) that bridge the two, and var to let the compiler infer a local variable's type.

Java is statically typed: every variable has a type fixed at compile time, and the compiler checks that you use it correctly. There are two families:

  • Primitive types — eight built-in types that store the value itself (a number, a character, a true/false). They are not objects and have no methods.
  • Reference types — classes, interfaces, arrays, enums, records. The variable stores a reference (an address-like handle) to an object on the heap. null means "no object".

Key facts to remember:

  • Whole-number literals are int by default, decimals are double. Add L for long and f for float: long big = 3_000_000_000L; — without the L the compiler says integer number too large.

Variables and scope

A variable is a named storage location. Declare it with a type, optionally assign a value: int count = 0;. Declared inside a method it is a local variable, alive only in its block { }. Declared in a class it is a field. Use final to forbid reassignment: final int MAX = 5;. You cannot declare two locals with the same name in overlapping scopes — Java does not allow shadowing a local with another local.

Wrapper classes, autoboxing and unboxing

Collections such as List hold objects only, so each primitive has an object twin, a wrapper class in java.lang:

Wrappers are immutable, can be null, and carry useful static methods: Integer.parseInt("42"), Integer.valueOf(42), Integer.toBinaryString(10), Integer.compare(a, b), Double.parseDouble, Character.isDigit(c), Character.isLetter(c), Boolean.parseBoolean. Autoboxing is the compiler converting a primitive to its wrapper automatically; unboxing is the reverse:

List<Integer> marks = new ArrayList<>();
marks.add(85);                 // autoboxing: int -> Integer.valueOf(85)
int first = marks.get(0);      // unboxing:   Integer -> first.intValue()
Integer boxed = 10;            // boxing
int sum = boxed + 5;           // unboxing happens, then int addition

The Integer cache and the == trap

Boxing calls Integer.valueOf(int), which returns a cached object for values from −128 to 127 and creates a new object for others. So == (which compares references for objects) gives surprising answers:

Integer a = 127, b = 127;
Integer c = 128, d = 128;
System.out.println(a == b);        // true  (same cached object)
System.out.println(c == d);        // false (two different objects)
System.out.println(c.equals(d));   // true  (compares the values)
System.out.println(c == 128);      // true  (one side is primitive: c is unboxed)

Integer e = new Integer(5);        // deprecated for removal: do not use
Long l = 10L;
System.out.println(l.equals(10));  // false: 10 is an Integer, not a Long

Rule: compare wrapper objects with equals() (or unbox first), never with ==. The cache exists for Byte, Short, Integer, Long (−128 to 127), Character (0 to 127) and Boolean; Float and Double are not cached. The upper bound of the Integer cache can be raised with a JVM option, so never depend on it.

NullPointerException from unboxing

Map<String, Integer> stock = new HashMap<>();
stock.put("pen", 10);
int pens = stock.get("pen");        // fine: 10
int pencils = stock.get("pencil");  // get returns null -> unboxing null
Exception in thread "main" java.lang.NullPointerException:
  Cannot invoke "java.lang.Integer.intValue()" because the return value of
  "java.util.Map.get(Object)" is null

The fix is to use getOrDefault("pencil", 0) or to keep the value as Integer and check for null. The same happens in a ternary such as cond ? nullInteger : 0, and when a database column that allows NULL is mapped to a primitive int field — use Integer for nullable columns.

var — local variable type inference (Java 10)

With var the compiler infers the type from the right-hand side. The variable is still statically typed; it is not like JavaScript's var.

var count = 10;                       // int
var name = "Ravi";                    // String
var items = new ArrayList<String>();  // ArrayList<String>
for (var item : items) { }            // fine in loops

var x;                                // error: cannot infer type (no initializer)
var n = null;                         // error: cannot infer type for null
var arr = {1, 2, 3};                  // error: array initializer needs an explicit type
var lambda = () -> 5;                 // error: no target type
count = "text";                       // error: count is an int
  • var works only for local variables (also loop variables and try-with-resources), never for fields, parameters or return types.
  • It needs an initializer that gives a clear type. var is not a keyword: you can still name a variable var, but not a class.
  • var x = 10; is int; if you want long write 10L.

Convention: when to use var

Use it when the type is obvious from the right side (var users = new ArrayList<User>();) or very long. Avoid it when it hides information: var result = service.process(request); forces the reader to look up what result is.

Rules to remember

  • Money, IDs and counters that can pass 2.1 billion need long (or BigDecimal for money). Never store money in double.
  • Use int by default for whole numbers, double for decimals, boolean for flags. byte, short and float are for special cases like binary data and large arrays.
  • Local variables must be initialised before use; fields and array elements have defaults.

Common mistakes

  • float f = 3.14; fails: the literal is a double (possible lossy conversion from double to float). Write 3.14f.
  • long big = 3000000000; fails because the literal is read as int first. Write 3000000000L.
  • Using == on Integer or Long values from collections or method results.
  • Using wrappers in hot loops (Long sum = 0L; sum += i; creates millions of objects). Use long.

Interview: "Why does Integer 127 == 127 give true but 128 == 128 give false?"

  • Autoboxing calls Integer.valueOf, which returns cached objects for −128…127. Within the cache both references point to the same object; outside it, two new objects are created.
  • == compares references for objects, so use equals().

Integer arithmetic gotchas

System.out.println(7 / 2);           // 3     integer division drops the fraction
System.out.println(7 / 2.0);         // 3.5   one double operand -> double division
System.out.println(1 / 2 * 3.0);     // 0.0   (1/2) is 0 first
System.out.println(7 % 3);           // 1
System.out.println(-7 % 3);          // -1    sign follows the dividend (left operand)
System.out.println(7 % -3);          // 1
System.out.println(Math.floorMod(-7, 3));   // 2   always non-negative for a positive divisor
System.out.println(5.5 % 2);         // 1.5   % works on decimals too

System.out.println(Integer.MAX_VALUE + 1);          // -2147483648  overflow wraps around
System.out.println(Integer.MAX_VALUE + 1L);         // 2147483648   long arithmetic
System.out.println(Math.abs(Integer.MIN_VALUE));    // -2147483648  no positive counterpart

System.out.println(5 / 0.0);         // Infinity
System.out.println(0.0 / 0.0);       // NaN
System.out.println(5 / 0);           // throws ArithmeticException
Exception in thread "main" java.lang.ArithmeticException: / by zero
  • Integer division truncates toward zero. int percent = marks / total * 100; is almost always wrong (it is 0 unless marks equals total). Multiply first or use a double: marks * 100 / total.
  • Overflow is silent. Integer arithmetic wraps around with no exception. When it matters, use Math.addExact, multiplyExact, toIntExact, which throw ArithmeticException: integer overflow.
  • % is "remainder", not "modulo": the result has the sign of the left operand. For array-index wrap-around use Math.floorMod(index, length).
  • Integer division by zero throws ArithmeticException; floating-point division by zero gives Infinity or NaN. NaN != NaN, so use Double.isNaN(x).

i++ vs ++i

Both add 1 to i. The difference is the value of the expression: i++ (post-increment) gives the old value, then increments; ++i (pre-increment) increments, then gives the new value. As a standalone statement (i++;) they are identical.

int i = 5;
int a = i++;          // a = 5, i = 6
int b = ++i;          // i = 7, b = 7
int j = 5;
int k = j++ + ++j;    // 5 + 7 = 12, j = 7
int x = 5;
x = x++;              // x stays 5: the old value is assigned back
System.out.println(a + " " + b + " " + j + " " + k + " " + x);
5 7 7 12 5

Do not write code like j++ + ++j in real projects — it is only an interview puzzle.

Short-circuit && and || vs & and |

&& stops as soon as the result is known: if the left side is false, the right side is not evaluated. || stops when the left side is true. The single & and | always evaluate both sides.

String name = null;
if (name != null && name.length() > 3) {      // safe: length() is never called
    System.out.println("long name");
}
if (name != null & name.length() > 3) {       // NullPointerException: both sides run
    System.out.println("long name");
}

int calls = 0;
boolean r1 = (calls++ > 0) && (calls++ > 0);   // second part skipped
System.out.println(calls);                         // 1

Use short-circuit to guard: list != null && !list.isEmpty(), divisor != 0 && total / divisor > 5. Put cheap checks first.

Ternary operator

String status = marks >= 40 ? "Pass" : "Fail"; It is an expression (it produces a value), so it can be used inside a println or a return. Nesting is allowed but quickly hard to read. A subtle trap is numeric promotion: both branches are converted to a common type.

System.out.println(true ? 1 : 2.0);        // 1.0   int is promoted to double
Integer n = null;
int r = true ? n : 0;                       // NullPointerException: n is unboxed

Bitwise and shift operators

System.out.println(5 & 3);       // 1    0101 & 0011 = 0001
System.out.println(5 | 3);       // 7    0101 | 0011 = 0111
System.out.println(5 ^ 3);       // 6    XOR: 1 where bits differ = 0110
System.out.println(~5);          // -6   flips all bits: -(5) - 1
System.out.println(5 << 2);      // 20   shift left = multiply by 2^2
System.out.println(-16 >> 2);    // -4   signed shift keeps the sign bit
System.out.println(-16 >>> 28);  // 15   unsigned shift fills with 0
System.out.println(1 << 33);     // 2    int shift count uses only the low 5 bits (33 & 31 = 1)
boolean even = (7 & 1) == 0;     // false: lowest bit tells odd/even

Common uses: checking odd/even (n & 1), flags and permissions packed into one int, fast multiplication by powers of two, and the XOR trick in puzzles ("find the single non-duplicate number": XOR all numbers, pairs cancel out).

Compound assignment has a hidden cast

a += b means a = (T)(a + b) where T is the type of a. The cast is added for you and silently drops information.

byte b = 127;
b += 1;                    // OK: b = (byte)(b + 1)  -> -128, wraps around
b = b + 1;                 // error: incompatible types: possible lossy conversion
                           //        from int to byte

int total = 10;
total += 3.7;              // total = (int)(10 + 3.7) = 13, decimals lost
char c = 'a';
c += 1;                    // 'b'
String s = "Rs ";
s += 500;                  // "Rs 500"

The same rule applies to ++ and --: b++ on a byte compiles. It is a favourite interview question because it looks like it should not compile.

String + and evaluation order

System.out.println(1 + 2 + "A");       // 3A    (1 + 2) first, then join
System.out.println("A" + 1 + 2);       // A12   left to right, already a String
System.out.println("A" + (1 + 2));     // A3
System.out.println('a' + 'b');         // 195   char + char = int
System.out.println("" + 'a' + 'b');    // ab

Rule: operands are evaluated left to right

Java guarantees left-to-right evaluation of operands, unlike C. So i + i++ is well defined. Precedence only says how operands group, not the order in which side effects happen.

Common mistakes

  • Using = instead of == in a condition. if (x = 5) does not compile for int (good), but if (flag = true) compiles for boolean and always passes.
  • Comparing strings and objects with == (see Strings).
  • Computing an average with integer division: sum / count when both are int.
  • Forgetting that && binds tighter than ||: a || b && c is a || (b && c).

Interview: operator puzzles

  • "What does int x = 5; x = x++ + ++x; give?" — 5 + 7 = 12. Explain post vs pre increment and left-to-right evaluation.
  • "Why does byte b = 10; b += 5; compile but b = b + 5; not?" — compound assignment includes an implicit cast; b + 5 is an int.
  • "&& vs &?" — short-circuit vs always evaluate both; & also works bitwise on integers.
  • "What is -7 % 3?" — -1; the result takes the sign of the dividend.
