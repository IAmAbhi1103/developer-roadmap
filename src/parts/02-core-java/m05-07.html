Interview questions — Modern and functional Java

What is a functional interface? Name the four core ones.

A functional interface has exactly one abstract method, so a lambda or method reference can implement it. It may have default and static methods, and @FunctionalInterface makes the compiler check the rule. The core four in java.util.function: Predicate<T> (T → boolean), Function<T,R> (T → R), Consumer<T> (T → void) and Supplier<T> (() → T).

Why must variables used in a lambda be effectively final?

A lambda may run later or on another thread. Local variables live on the stack of the method, and the lambda gets a copy of their value. If the original could change, the copy would be out of date, and sharing a changing local between threads would be unsafe. So the compiler requires that captured locals are never reassigned. Fields and array elements are not copied, so you can change them, but then thread safety is your job.

What are the four kinds of method reference?

Static method: Integer::parseInt is s -> Integer.parseInt(s). Bound instance: System.out::println uses one specific object. Unbound instance: String::length is s -> s.length(), the first argument is the receiver. Constructor: ArrayList::new is () -> new ArrayList<>().

What is a stream? Is it a data structure?

No. A stream is a pipeline that describes computations over a source (collection, array, file). It does not store elements. It is lazy: intermediate operations such as filter and map do nothing until a terminal operation such as collect or count starts the work. A stream can be consumed only once; reusing it throws IllegalStateException: stream has already been operated upon or closed.

map vs flatMap?

map turns each element into exactly one new element. flatMap turns each element into a stream of zero or more elements and flattens all of them into one stream. Example: a list of orders, each with a list of items: orders.stream().flatMap(o -> o.items().stream()) gives one stream of items. With map you would get a stream of lists.

What does this print, and why? 
Stream.of("a", "bb", "ccc", "dddd")
      .filter(s -> { System.out.println("filter " + s); return s.length() > 1; })
      .map(s -> { System.out.println("map " + s); return s.toUpperCase(); })
      .findFirst();

It prints filter a, filter bb, map bb. Elements flow one at a time through the whole pipeline (not stage by stage), and findFirst is short-circuiting, so after "bb" reaches the end nothing else is processed.

toList() vs Collectors.toList()? What happens with duplicate keys in toMap?

Stream.toList() (Java 16) returns an unmodifiable list and allows nulls; Collectors.toList() returns an ArrayList (no promise about the type) that you can modify. Collectors.toMap(keyFn, valueFn) throws IllegalStateException: Duplicate key ... when two elements give the same key. Pass a merge function as a third argument, such as (a, b) -> a, or use groupingBy if you expect many values per key.

When should you NOT use parallel streams?

For small data, for cheap operations, for ordered or stateful operations, for sources that split badly (LinkedList, Stream.iterate), when tasks do blocking I/O, or when lambdas have side effects or touch shared mutable state. Parallel streams use the common ForkJoinPool shared by the whole JVM. Measure first; it is often slower.

orElse vs orElseGet?

orElse(x) evaluates its argument always, even when the Optional has a value. orElseGet(supplier) calls the supplier only when the Optional is empty. If the fallback is costly (a database call or a new object with side effects), use orElseGet. For a constant, orElse is fine.

Where should you use Optional and where not?

Use it as a return type for methods that may have no result (findById). Do not use it for fields, method parameters, collection elements or in JPA entities. Never return null from a method that returns Optional, and do not call get() without checking; prefer orElseThrow, map and ifPresent.

Why is java.util.Date bad, and what replaced it?

Date is mutable (so not thread-safe), its months are zero-based, years start from 1900 in the deprecated getters, and it mixes date and time with no time zone clarity. SimpleDateFormat is also not thread-safe. The java.time package (Java 8) is immutable, thread-safe and clear: LocalDate, LocalDateTime, Instant, ZonedDateTime, Duration, Period and DateTimeFormatter.

What are records, and how do they differ from a normal class with Lombok's @Data?

A record is a final class for immutable data. The compiler generates the constructor, accessors (name(), not getName()), equals, hashCode and toString. All fields are final; records cannot extend other classes but can implement interfaces. They are a language feature with no library needed, they suit DTOs and pattern matching, and they cannot be JPA entities. Lombok's @Data makes mutable classes with setters.

What is new in switch, and what is pattern matching for switch?

Switch expressions (Java 14) return a value, use -> with no fall-through, allow multiple labels per case and need to be exhaustive; yield gives the value from a block. Java 21 added patterns: case Circle c ->, record patterns, when guards and case null. Over a sealed type, no default is needed and the compiler checks that all subtypes are handled.

What is a sealed class and why would you use it?

A sealed class or interface names its allowed direct subtypes with permits. Each subtype must be final, sealed or non-sealed. It models a closed set of alternatives, such as payment results, and combined with a pattern switch it gives compile-time exhaustiveness: add a new subtype and every switch that misses it fails to compile.

What is the difference between LocalDateTime, ZonedDateTime and Instant? What do you store in the database?

LocalDateTime is a date and time on a wall clock with no zone, so it does not identify a moment. ZonedDateTime adds a zone such as Asia/Kolkata. Instant is a point on the UTC timeline. Store timestamps in UTC (an Instant or OffsetDateTime in a timestamptz column) and convert to the user's zone only for display. Use LocalDate for dates without time, such as a birthday.

Cheat sheet — Modern and functional Java

  • Lambda (a, b) -> a + b; implements a functional interface; captured locals must be effectively final.
  • Core interfaces Predicate<T> test, Function<T,R> apply, Consumer<T> accept, Supplier<T> get; plus BiFunction, UnaryOperator, BinaryOperator.
  • Composing and, or, negate; andThen, compose; Function.identity().
  • Method refs Class::static, obj::method, Class::instance, Class::new.
  • Pipeline source → intermediate (lazy) → terminal (starts work). One use only.
  • Intermediate filter, map, flatMap, distinct, sorted, peek, limit, skip, takeWhile, mapToInt, boxed.
  • Terminal forEach, collect, toList(), reduce, count, min/max, anyMatch/allMatch/noneMatch, findFirst, toArray.
  • Primitive streams IntStream.range(0, n), sum(), average() (OptionalDouble), no boxing.
  • Collectors toList, toSet, toMap (duplicate key = IllegalStateException), joining, groupingBy, partitioningBy, counting, summingInt, averagingDouble, mapping.
  • groupingBy groupingBy(classifier, downstream); map type via groupingBy(f, TreeMap::new, downstream).
  • Avoid side effects inside lambdas, reusing a stream, parallel streams on small or I/O work.
  • Optional create with of, ofNullable, empty; read with orElse, orElseGet, orElseThrow; transform with map, flatMap, filter.
  • Optional rules return type only; not for fields or parameters; never get() unchecked; never return null for it.
  • java.time LocalDate, LocalTime, LocalDateTime, ZonedDateTime, Instant; immutable, so plusDays returns a new object.
  • Spans Duration (time-based), Period (date-based), ChronoUnit.DAYS.between(a, b).
  • Formatting DateTimeFormatter.ofPattern("dd-MM-yyyy"); bad input gives DateTimeParseException. Store in UTC.
  • var locals only, needs an initializer, not null, not for fields/parameters; still static typing.
  • Text block """ + newline; closing delimiter sets the indent; \ joins lines; \s keeps a space; formatted().
  • Switch expression case A, B -> value; no fall-through; yield in blocks; must be exhaustive.
  • Pattern instanceof if (o instanceof String s && s.isEmpty()); binding in scope only where matched.
  • Pattern switch (21) type patterns, record patterns, when guards, case null; specific cases before general.
  • Records immutable data carriers; accessors x(); canonical constructor can validate.
  • Sealed sealed ... permits; subclasses final / sealed / non-sealed; exhaustive switch without default.
  • Sequenced (21) getFirst, getLast, addFirst, reversed() (a view) on lists, deques, LinkedHashSet, LinkedHashMap.

  • LTS 8 lambdas/streams, 11 var/HttpClient, 17 records/sealed/text blocks, 21 virtual threads/pattern switch, 25 current LTS.

Practice — Modern and functional Java

  1. Rewrite loops as streams. Take five loops you wrote earlier (sum of even numbers, names in upper case, count of strings longer than 5, first item over 1000, join names with commas). Rewrite each with a stream. Done when the results are identical and you can say, for each, whether the loop or the stream is easier to read.
  2. The streams drill. From a list of employees find the average salary per department, the top 3 earners and the names grouped by first letter. Done when your output matches the sample below and you can explain each collector. 
    import java.util.*;
import java.util.stream.*;

public class EmployeeDrill {
    record Employee(String name, String dept, double salary) { }

    public static void main(String[] args) {
        List<Employee> emps = List.of(
                new Employee("Asha", "IT", 90_000),
                new Employee("Arjun", "HR", 55_000),
                new Employee("Meera", "IT", 120_000),
                new Employee("Ravi", "Sales", 70_000),
                new Employee("Rohit", "IT", 80_000),
                new Employee("Mohan", "HR", 65_000));

        // 1. average salary per department
        Map<String, Double> avg = emps.stream().collect(
                Collectors.groupingBy(Employee::dept,
                        TreeMap::new, Collectors.averagingDouble(Employee::salary)));
        System.out.println(avg);

        // 2. top 3 earners
        List<String> top3 = emps.stream()
                .sorted(Comparator.comparingDouble(Employee::salary).reversed())
                .limit(3)
                .map(Employee::name)
                .toList();
        System.out.println(top3);

        // 3. names grouped by first letter
        Map<Character, List<String>> byLetter = emps.stream().collect(
                Collectors.groupingBy(e -> e.name().charAt(0),
                        TreeMap::new,
                        Collectors.mapping(Employee::name, Collectors.toList())));
        System.out.println(byLetter);
    }
}

  3. Ten stream exercises. Use the same employee list (add two more with duplicate salaries and one with a duplicate name) and solve each in a single pipeline. Done when you have a tested method for every item and you can explain its time cost.
    1. Names of employees earning more than 75,000, sorted alphabetically.
    2. The second-highest salary (use distinct, sorted, skip).
    3. Total salary per department as a Map<String, Double>.
    4. The highest-paid employee in each department (groupingBy with maxBy).
    5. Duplicate names in the list.
    6. A frequency map of the characters in a sentence.
    7. Flatten a List<List<Integer>> into one sorted list without duplicates.
    8. Sort employees by department, then by salary descending (thenComparing).
    9. Partition employees into "salary at least 80,000" and the rest; print the counts.
    10. Join all names into "[Asha, Meera, ...]" using Collectors.joining with prefix and suffix.
  4. Optional and dates. Write Optional<Employee> findByName(String) and use map, orElseGet and orElseThrow on it without calling get(). Then compute the number of days between today and a hard-coded joining date, the date 90 days from now, and format a LocalDate as dd-MMM-yyyy. Done when invalid input produces a DateTimeParseException that you handle with a clear message.
  5. Modernise a class hierarchy. Take an old Shape abstract class with instanceof and casts. Convert it to a sealed interface with records, write area as a pattern switch without default, and add a guard case for a very large circle. Done when adding a new record makes the switch fail to compile until you handle it.
