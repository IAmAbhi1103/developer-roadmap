Type casting, numeric promotion and floating-point precision

Widening conversions are automatic and safe, narrowing casts can lose data silently, arithmetic on small types is promoted to int, and double cannot store 0.1 exactly — so money belongs in BigDecimal.

Widening and narrowing

Java converts between numeric types in two directions. Widening (small to big) is implicit because no information is lost. Narrowing (big to small) needs an explicit cast — your promise to the compiler that you accept the loss.

long to float is allowed implicitly even though a float has only about 7 digits of precision, so it can lose accuracy without any error. boolean cannot be converted to or from any other type.

int i = 100;
long l = i;                    // widening, automatic
double d = i;                  // 100.0

double pi = 3.99;
System.out.println((int) pi);          // 3     truncates, does not round
System.out.println((int) -3.99);       // -3    truncates toward zero
System.out.println((int) Math.round(pi));  // 4  round first if you want rounding
System.out.println((byte) 130);        // -126  130 - 256: only the low 8 bits are kept
System.out.println((int) 3_000_000_000L);  // -1294967296  low 32 bits
System.out.println((int) 1e20);        // 2147483647  saturates at Integer.MAX_VALUE
System.out.println((int) Double.NaN);  // 0

int big = 123456789;
float f = big;                         // allowed, but loses precision
System.out.println((int) f);           // 123456792

Casting an object reference is different: it never changes the object, it only tells the compiler to treat the reference as another type. A wrong cast throws ClassCastException at runtime (see Module 2).

char and int

char c = 'A';
int code = c;                       // 65  (widening)
char next = (char) (c + 1);         // 'B' (c + 1 is an int, so cast back)
char lower = (char) (c + 32);       // 'a'
int digit = '7' - '0';              // 7   classic digit conversion
char fromInt = (char) 97;           // 'a'
c++;                                // 'B' (++ and += include the cast)
System.out.println(code + " " + next + " " + lower + " " + digit + " " + fromInt + " " + c);
65 B a 7 a B

For letters, prefer Character.toUpperCase(c) and Character.isLetter(c) over manual arithmetic.

Numeric promotion in expressions

Before an arithmetic operator runs, Java promotes operands:

  1. If either operand is double, the other becomes double.
  2. Otherwise, if either is float, the other becomes float.
  3. Otherwise, if either is long, the other becomes long.
  4. Otherwise, both become int — including byte, short and char.

The last rule surprises beginners: the result of byte + byte is an int.

byte x = 10, y = 20;
byte z = x + y;            // error: incompatible types: possible lossy conversion
                           //        from int to byte
byte z2 = (byte) (x + y);  // OK
byte k = 10;               // OK: 10 is a constant that fits into byte
final int LIMIT = 50;
byte m = LIMIT;            // OK: LIMIT is a compile-time constant that fits
int a = 5;
byte n = a;                // error: a is not a constant

long total = 1000000 * 1000000;     // -727379968: int * int overflows BEFORE widening
long right = 1000000L * 1000000;    // 1000000000000: one long operand is enough

The last two lines are a famous bug: the multiplication is done in int, overflows, and only the wrong result is widened to long.

Why 0.1 + 0.2 != 0.3

float and double store numbers in binary (IEEE 754). Just as 1/3 has no exact decimal form (0.3333…), 0.1 has no exact binary form (it repeats forever in base 2). The computer stores the nearest value, and tiny errors appear:

System.out.println(0.1 + 0.2);             // 0.30000000000000004
System.out.println(0.1 + 0.2 == 0.3);      // false
System.out.println(1.1 * 3);               // 3.3000000000000003
System.out.println(new java.math.BigDecimal(0.1));
System.out.println(0.5 + 0.25);            // 0.75  (exact in binary)

double a = 0.1 + 0.2, b = 0.3;
System.out.println(Math.abs(a - b) < 1e-9);   // true: compare with a tolerance

Floating point is fine for science, graphics and statistics, where tiny errors do not matter. It is wrong for money, where every paisa must add up. Never compare doubles with ==; compare with a tolerance. Also remember Math.round(2.5) is 3 but Math.round(-2.5) is −2 (it rounds half up toward positive infinity), and it returns a long for a double argument.

BigDecimal for money

java.math.BigDecimal stores an exact decimal number as an unscaled integer plus a scale (digits after the point). It is immutable, so every operation returns a new object.

import java.math.BigDecimal;
import java.math.RoundingMode;

public class Invoice {
    public static void main(String[] args) {
        BigDecimal price = new BigDecimal("499.99");       // from a String, never a double
        BigDecimal total = price.multiply(BigDecimal.valueOf(3));      // 1499.97
        BigDecimal gst = total.multiply(new BigDecimal("0.18"));       // 269.9946
        BigDecimal gstRounded = gst.setScale(2, RoundingMode.HALF_UP); // 269.99
        BigDecimal grand = total.add(gstRounded);

        System.out.println(total + " " + gst + " " + gstRounded + " " + grand);

        BigDecimal third = BigDecimal.ONE.divide(new BigDecimal("3"), 4, RoundingMode.HALF_UP);
        System.out.println(third);                          // 0.3333

        System.out.println(new BigDecimal("2.0").equals(new BigDecimal("2.00")));    // false
        System.out.println(new BigDecimal("2.0").compareTo(new BigDecimal("2.00"))); // 0
        System.out.println(BigDecimal.ONE.divide(new BigDecimal("3")));  // throws
    }
}

  • Construct from a String (new BigDecimal("0.1")) or BigDecimal.valueOf(0.1). new BigDecimal(0.1) keeps the double's error, as shown above.
  • Methods: add, subtract, multiply, divide, negate, abs, pow(int), compareTo, signum, setScale, scale, stripTrailingZeros.

Rule: narrowing needs a cast, and promotion happens before the operator runs

Assigning a bigger type to a smaller one without a cast is a compile error — except for constants that fit (byte b = 10;). Arithmetic on byte, short and char always produces an int.

Edge cases

  • (int) Double.NaN is 0 and out-of-range values saturate; no exception is thrown.
  • Math.abs(Integer.MIN_VALUE) is still negative; Math.toIntExact(long) throws ArithmeticException if the value does not fit.
  • float keeps about 7 digits: 16777217f prints as 1.6777216E7. Prefer double unless memory forces float.
  • 0.0 == -0.0 is true, but Double.valueOf(0.0).equals(-0.0) is false.

Wrong: money in double

double price = 0.10;
double total = 0;
for (int i = 0; i < 10; i++) total += price;
System.out.println(total);   // 0.9999999999999999

Right: BigDecimal from strings

BigDecimal price = new BigDecimal("0.10");
BigDecimal total = BigDecimal.ZERO;
for (int i = 0; i < 10; i++) total = total.add(price);
System.out.println(total);   // 1.00

Interview: "Why not use double for money?" and "What is the output of 0.1 + 0.2?"

  • Binary floating point cannot represent most decimal fractions exactly, so errors accumulate; 0.1 + 0.2 prints 0.30000000000000004.
  • Use BigDecimal built from Strings, with an explicit scale and RoundingMode; or use integer paise.
  • Mention equals vs compareTo on BigDecimal and the divide exception for non-terminating results.
  • Also expect: "byte + byte gives which type?" (int) and "what does (int) 3.99 return?" (3).

Control flow: if, switch, switch expressions and loops

Use if/else for decisions, arrow-form switch for choosing among values, and for, enhanced for, while and do-while for repetition, with labeled break/continue to leave nested loops.

if / else if / else

int marks = 72;
if (marks >= 90) {
    System.out.println("Distinction");
} else if (marks >= 60) {
    System.out.println("First class");
} else if (marks >= 40) {
    System.out.println("Pass");
} else {
    System.out.println("Fail");
}                                   // prints: First class

The condition must be a boolean — Java has no "truthy" values, so if (count) with an int is a compile error. Conditions are checked top to bottom and the first true branch runs; order your ranges from most to least specific. Always use braces, even for one line: a missing brace is the cause of the famous "goto fail" style bugs. Also avoid a stray semicolon: if (x > 5); ends the if with an empty statement.

The classic switch and fall-through

int day = 3;
switch (day) {
    case 1:
        System.out.println("Mon");
        break;
    case 2:
    case 3:                         // 2 and 3 share this code
        System.out.println("Tue or Wed");
    case 4:
        System.out.println("falls into Thu");   // no break above -> also runs
        break;
    default:
        System.out.println("Other");
}
Tue or Wed
falls into Thu

In the colon form, execution continues into the next case until a break — this is fall-through. It is occasionally useful (grouping cases) but mostly a bug source. The switch selector can be byte, short, char, int (and their wrappers), String (Java 7), or an enum — not long, float, double or boolean. Case labels must be constants and unique. A String switch uses equals, is case-sensitive, and throws NullPointerException if the selector is null.

Arrow-form switch and switch expressions (Java 14)

The arrow form case X -> has no fall-through and needs no break. A switch can also be an expression that produces a value; then it must cover all cases (add default, or list every enum constant).

enum Status { PENDING, SHIPPED, DELIVERED, CANCELLED }

public class SwitchExpr {
    static int daysIn(String month) {
        return switch (month) {
            case "Feb" -> 28;
            case "Apr", "Jun", "Sep", "Nov" -> 30;    // several labels in one case
            default -> 31;
        };
    }

    static String describe(Status s) {
        return switch (s) {                            // no default needed: all constants covered
            case PENDING -> "Packing your order";
            case SHIPPED -> "On the way";
            case DELIVERED -> "Delivered";
            case CANCELLED -> "Cancelled";
        };
    }

    static String fee(int amount) {
        return switch (amount / 1000) {
            case 0 -> "Free";
            case 1, 2 -> "Rs 5";
            default -> {                                // block: compute, then yield a value
                int fee = amount / 1000 * 2;
                if (fee > 50) {
                    yield "Rs 50 (capped)";
                }
                yield "Rs " + fee;
            }
        };
    }

    public static void main(String[] args) {
        System.out.println(daysIn("Apr") + " " + daysIn("Jan"));
        System.out.println(describe(Status.SHIPPED));
        System.out.println(fee(500) + ", " + fee(1500) + ", " + fee(8000) + ", " + fee(40000));
    }
}

  • yield returns a value from a block inside a switch expression; return is not allowed there.
  • An enum switch expression without default is checked by the compiler. If you later add an enum constant, every such switch fails to compile — a benefit, because you cannot forget a case.
  • A switch statement may use arrows too (case 1 -> System.out.println("one");). The old colon form can also be used in an expression with yield, but you will rarely see it.
  • Pattern matching in switch (case Circle c ->, guards with when) is covered in Module 5.

break, continue and labels

break leaves the nearest loop (or switch). continue skips the rest of the current pass and goes to the next one. In nested loops, a label lets you name the loop to leave or continue.

// find the first pair (a, b) with a * b == 24 and a < b

    for (int b = a + 1; b < 10; b++) {
        if (a * b == 24) {
            System.out.println(a + " x " + b);
            break outer;                 // leaves BOTH loops
        }
    }
}

for (int i = 1; i <= 5; i++) {
    if (i % 2 == 0) {
        continue;                        // skip even numbers

    System.out.print(i + " ");           // 1 3 5

Two small programs every interview asks

public class FizzBuzzPrime {
    static boolean isPrime(int n) {
        if (n < 2) return false;
        for (int i = 2; (long) i * i <= n; i++) {   // only up to the square root
            if (n % i == 0) return false;
        }
        return true;
    }

    public static void main(String[] args) {
        for (int i = 1; i <= 15; i++) {
            if (i % 15 == 0) System.out.print("FizzBuzz ");
            else if (i % 3 == 0) System.out.print("Fizz ");
            else if (i % 5 == 0) System.out.print("Buzz ");
            else System.out.print(i + " ");
        }
        System.out.println();
        System.out.println(isPrime(29) + " " + isPrime(91));
    }
}

Rules

  • An if/while condition must be boolean.
  • Switch case labels must be compile-time constants and unique; a switch expression must be exhaustive and every arm must produce a value (or throw).
  • Code after break, continue, return or throw in the same block is unreachable and does not compile.
  • A variable declared in one case of a colon-style switch is visible in the following cases (one shared block) — another reason to prefer arrows.

Common mistakes

  • Off-by-one: i <= arr.length instead of i < arr.length throws ArrayIndexOutOfBoundsException.
  • Missing break in an old-style switch, so later cases run too.
  • Semicolon after the header: for (...); or while (x < 5); makes an empty loop body, and a following { } block runs once.
  • Infinite loop because the variable that the condition checks is never updated.
  • Modifying the list inside a for-each loop (ConcurrentModificationException).
  • Comparing strings in a condition with == instead of equals.

Conventions

  • Prefer arrow-form switch (Java 14+) for new code; use default -> throw new IllegalArgumentException(...) to reject unknown values.
  • Prefer the enhanced for when you do not need the index; use streams for filtering and mapping (Module 5).
  • Use early return/continue (guard clauses) to avoid deep nesting.

Interview: "Switch vs if-else? Old switch vs switch expression?"

  • Switch is for one value compared with constants; if-else handles ranges and complex conditions.
  • Old switch falls through without break; arrow switch does not; a switch expression returns a value, is exhaustive and uses yield in blocks.
  • Allowed selector types: integral types up to int and their wrappers, String, enum.
  • "while vs do-while" — the second runs the body at least once.

Methods: parameters, return types, overloading, varargs and recursion

A method is a named, reusable block of code with parameters and a return type; Java picks between overloaded methods at compile time using an order — exact match, widening, boxing, varargs.

A method groups statements under a name so you can call them again and again. It is the basic unit of reuse. Syntax:

//  modifiers   return-type  name   (parameters)         throws
    public static  double    price  (double base, int qty) throws IllegalArgumentException {
        if (qty <= 0) {
            throw new IllegalArgumentException("qty must be positive");
        }
        return base * qty;          // a method with a return type must return on every path
    }
  • The signature is the name plus the parameter types (order matters). The return type and parameter names are not part of it.
  • Parameters are the variables in the declaration; arguments are the values you pass in the call.
  • A void method returns nothing; return; exits early. Any other method must return a value of a compatible type on every path or compilation fails (missing return statement).
  • Calling a method that returns a value and ignoring it is legal but often a bug (for example, calling s.toUpperCase() without using the result).

Static and instance methods (intro)

public class Counter {
    private int count;                          // instance field: one per object

    public void increment() {                   // instance method: works on one object
        count++;
    }

    public static int square(int x) {           // static method: belongs to the class
        return x * x;                           // cannot use count (no object)
    }

    public static void main(String[] args) {
        System.out.println(Counter.square(5));  // 25: call through the class name
        Counter c = new Counter();
        c.increment();                          // instance method needs an object
        // increment();                         // error: non-static method cannot be
                                                //        referenced from a static context
    }
}

A static method cannot use this or instance fields directly. Use static methods for utilities that need no object state (Math.max, Integer.parseInt). Objects are explained fully in Module 2.

Overloading

Overloading means several methods with the same name but different parameter lists (count, types or order) in the same class. It is resolved at compile time from the declared types of the arguments. Changing only the return type is not overloading: it is a compile error (method already defined). Overloading is different from overriding, which is a runtime concept for subclasses (Module 2).

How Java picks the overload

The compiler tries three phases in order and stops at the first phase that finds a match:

  1. Exact match or widening of primitives and references (no boxing): int → long → float → double, or a subclass to its superclass.
  2. Boxing or unboxing: int ↔ Integer, then widening of the result.
  3. Varargs methods.

Within a phase, the most specific method wins. If none is more specific, the call is ambiguous and does not compile.

public class Overloads {
    static void show(int x)       { System.out.println("int"); }
    static void show(long x)      { System.out.println("long"); }
    static void show(Integer x)   { System.out.println("Integer"); }
    static void show(Object x)    { System.out.println("Object"); }
    static void show(int... x)    { System.out.println("varargs"); }

    static void text(String s)        { System.out.println("String"); }
    static void text(Object o)        { System.out.println("Object"); }
    static void both(String s)        { System.out.println("String"); }
    static void both(StringBuilder s) { System.out.println("StringBuilder"); }

    public static void main(String[] args) {
        show(5);                       // int      exact match
        show(5L);                      // long
        show((short) 5);               // int      short widens to int (closest type)
        show('a');                     // int      char widens to int
        show(Integer.valueOf(5));      // Integer  exact reference match
        show(5.5);                     // Object   double is boxed to Double, then widened
        show("hi");                    // Object
        show(1, 2);                    // varargs
        show();                        // varargs
        text(null);                    // String   most specific of String and Object
        // both(null);                 // error: reference to both is ambiguous
    }
}

Varargs

Varargs (type... name) lets a method accept zero or more arguments. Inside, it is just an array. Rules: it must be the last parameter, and a method has only one.

static int sum(int... nums) {          // nums is an int[]
    int total = 0;
    for (int n : nums) total += n;
    return total;
}

static String label(String prefix, Object... parts) {
    return prefix + ": " + parts.length + " parts";
}

public static void main(String[] args) {
    System.out.println(sum());                 // 0
    System.out.println(sum(4));                // 4
    System.out.println(sum(1, 2, 3));          // 6
    System.out.println(sum(new int[]{5, 5}));  // 10: you may pass an array directly
    System.out.println(label("order"));        // order: 0 parts
}

Varargs allocates an array on each call, so avoid it in hot code. Familiar varargs methods: String.format, List.of, Arrays.asList, printf.

Recursion (intro)

Recursion is a method calling itself. Every recursive method needs a base case (where it stops) and a step that moves toward it. Each call gets its own stack frame; too many frames cause StackOverflowError (Stack and heap).

static long factorial(int n) {
    if (n <= 1) return 1;                 // base case
    return n * factorial(n - 1);          // smaller problem
}

static int sumDigits(int n) {
    return n == 0 ? 0 : n % 10 + sumDigits(n / 10);
}

static long fibSlow(int n) {              // correct, but exponential time
    return n < 2 ? n : fibSlow(n - 1) + fibSlow(n - 2);
}

public static void main(String[] args) {
    System.out.println(factorial(5));     // 120
    System.out.println(sumDigits(4821));  // 15
    System.out.println(fibSlow(10));      // 55
    System.out.println(factorial(21));    // -4249290049419214848 (long overflow)
}

Many recursive solutions can also be written with a loop, which is faster and cannot overflow the stack. Java does not optimise tail calls. Recursion shines for trees, graphs and divide-and-conquer (see DSA · Module 2).

Rules

  • Overloads must differ in the number, types or order of parameters, not just in return type or parameter names.
  • Overload resolution uses the compile-time (declared) types: Object o = "hi"; show(o); picks the Object version.
  • A varargs parameter must be last; at most one per method.
  • A method must return a value on every path if its return type is not void.

Conventions

  • Methods are verbs (calculateFee), booleans start with is/has/can.
  • Keep a method short and focused: one job, ideally under 20–30 lines, three or four parameters at most. If you need more, group them in a record or object.
  • Validate arguments at the start and throw IllegalArgumentException for bad input.
  • Do not overload with confusing, nearly identical signatures like remove(int) and remove(Object) — List.remove has exactly this trap.

Common mistakes

  • Missing base case or a step that never reaches it: StackOverflowError.
  • Ignoring a return value: name.trim(); does nothing useful because strings are immutable.
  • Calling an instance method from static main without creating an object.
  • Expecting a method to change the caller's variable — see the next article.

Interview: "What is method overloading? How does the compiler choose?"

  • Same name, different parameter lists; resolved at compile time (static polymorphism); return type alone is not enough.
  • Order: exact/widening → boxing → varargs; the most specific candidate wins; otherwise ambiguity error.
  • Give the example show(5) with show(long) and show(Integer): long is chosen because widening beats boxing.
  • Overloading vs overriding: compile-time vs runtime, same class vs parent-child.

Pass-by-value: why Java never passes by reference

Java always passes a copy of the argument: for primitives it copies the value, for objects it copies the reference — so a method can change the object the caller sees, but can never re-point the caller's variable.

This is the most misunderstood point in Java, and interviewers ask it constantly. The statement is simple: Java is always pass-by-value. There is no pass-by-reference in the language. What confuses people is that the value being copied for an object variable is a reference.

Primitives: the method gets a copy of the number

static void addTen(int x) {
    x = x + 10;                     // changes only the method's own copy
    System.out.println("inside: " + x);
}

public static void main(String[] args) {
    int amount = 100;
    addTen(amount);
    System.out.println("outside: " + amount);
}
inside: 110
outside: 100

Objects: the method gets a copy of the reference

A variable of an object type holds a reference to an object on the heap, not the object itself. When you call a method, the parameter becomes a second variable holding a copy of that reference. Both variables now point to the same object.

Two things can happen with that copied reference, and they behave differently:

static void mutate(StringBuilder s) {
    s.append(" world");              // follows the reference, changes the SHARED object
}

static void reassign(StringBuilder s) {
    s = new StringBuilder("other");  // changes only the local copy of the reference
}

static void tryChangeString(String s) {
    s = s + "!";                     // strings are immutable: a new object, local only
}

public static void main(String[] args) {
    StringBuilder sb = new StringBuilder("hello");
    mutate(sb);
    System.out.println(sb);          // hello world   (caller sees the change)
    reassign(sb);
    System.out.println(sb);          // hello world   (caller's reference unchanged)

    String name = "Ravi";
    tryChangeString(name);
    System.out.println(name);        // Ravi

    int[] marks = {50, 60};
    changeFirst(marks);
    System.out.println(marks[0]);    // 99: arrays are objects too
}

static void changeFirst(int[] a) { a[0] = 99; }
hello world
hello world
Ravi
99

So: using the copied reference (calling methods, changing fields, array elements) affects the shared object. Reassigning the parameter affects nothing outside. That one fact answers almost every question.

The swap test

If Java had pass-by-reference, a swap method would work. It does not:

static void swap(int a, int b) {
    int temp = a;
    a = b;
    b = temp;                         // swaps the copies only
}

static void swapNames(StringBuilder a, StringBuilder b) {
    StringBuilder temp = a;
    a = b;
    b = temp;                         // swaps the copied references only
}

static void swapInArray(int[] arr, int i, int j) {
    int temp = arr[i];
    arr[i] = arr[j];                  // modifies the shared array: this one works
    arr[j] = temp;
}

public static void main(String[] args) {
    int x = 1, y = 2;
    swap(x, y);
    System.out.println(x + " " + y);              // 1 2

    StringBuilder p = new StringBuilder("P"), q = new StringBuilder("Q");
    swapNames(p, q);
    System.out.println(p + " " + q);              // P Q

    int[] nums = {1, 2};
    swapInArray(nums, 0, 1);
    System.out.println(nums[0] + " " + nums[1]);  // 2 1
}

To swap two variables you do it inline, or you return values (a record or array holding both), or you swap elements inside a shared container as in swapInArray — as Collections.swap(list, i, j) does.

Pass-by-value vs pass-by-reference

QuestionPass-by-value (Java)True pass-by-reference (C++ &)
What does the method receive?A copy of the variable's content (number or reference)An alias of the caller's variable itself
Can the method change the caller's primitive?NoYes
Can the method change the object's fields?Yes, through the copied referenceYes
Can the method make the caller's variable point to a new object?NoYes

Practical consequences

  • A method that receives a List can add to the caller's list. If that is not what you want, copy it first (new ArrayList<>(list) or List.copyOf).
  • To return more than one result, return a record: record MinMax(int min, int max) {}.
  • Marking a parameter final stops the method from reassigning it, but does not stop it from changing the object.
  • The same copying rule applies to assignment: b = a; copies the reference, so a and b share one object (aliasing), unless you make a real copy.

Rule: you can change the object, not the caller's variable

Inside a method, param.something() can change the shared object. param = ... only changes the local copy. Java has no way to modify a caller's local variable from another method.

Edge cases

  • null is passed as a null reference; calling a method on it throws NullPointerException, but assigning a new object to the parameter is still invisible to the caller.
  • Immutable arguments (String, Integer, BigDecimal, records of immutables) cannot be modified through a reference, so they behave "like values" in practice.
  • Arrays are objects: int[] passed to a method can be modified in place; its length cannot change.

Common mistakes

  • Saying "primitives are passed by value, objects by reference". Wrong: both by value; for objects the value is the reference.
  • Writing a void normalize(String s) that "fixes" the string; since String is immutable it must return the new string.
  • Storing a caller's mutable list inside your object without copying, so later changes by the caller silently alter your state.

Interview: "Is Java pass by value or pass by reference?"

  • Always pass by value. For objects the value copied is the reference.
  • Prove it with the swap example: a method cannot swap two caller variables, because only copies are swapped.
  • A method can mutate a passed object (list.add) but reassigning the parameter has no effect on the caller.
  • Follow-up: "What is printed after reassign(sb)?" Use the diagram to answer: the local reference moved; the caller's did not.

Arrays (1D and 2D) and the Arrays class

An array is a fixed-size, zero-indexed block of same-typed elements stored as an object; the java.util.Arrays class provides sort, search, fill, copy, compare and print helpers.

An array stores a fixed number of values of one type in contiguous memory. It is an object (it lives on the heap), its size is fixed when created, and it is indexed from 0 to length - 1. Access by index is O(1).

Declaring and creating

int[] marks = new int[5];                  // five zeros: default values
int[] scores = {90, 85, 70};               // literal, size from the values
int[] more = new int[]{1, 2, 3};           // also valid, needed in some places
String[] names = new String[3];            // [null, null, null]
int legacy[] = new int[2];                 // C-style declaration: legal, avoid it

marks[0] = 50;
System.out.println(marks.length);          // 5   (a field, not a method: no parentheses)
System.out.println(scores[scores.length - 1]);   // 70: the last element
System.out.println(java.util.Arrays.toString(names));
5
70
[null, null, null]
  • Default values: 0 for numbers, false for boolean, '\u0000' for char, null for objects.
  • The size is fixed. To "grow" an array, create a bigger one and copy (Arrays.copyOf), or use ArrayList, which does this for you.
  • Printing an array directly shows a useless identity like [I@1b6d3586. Use Arrays.toString.
  • int[] b = a; does not copy; both variables refer to the same array.

Errors you will meet

int[] a = new int[5];
a[5] = 1;

  java.lang.NegativeArraySizeException: -1

Looping and common operations

int[] a = {4, 9, 2, 7};

int max = a[0], sum = 0;
for (int v : a) {                       // enhanced for: read-only walk
    if (v > max) max = v;
    sum += v;
}
System.out.println("max=" + max + " sum=" + sum + " avg=" + (double) sum / a.length);

// reverse in place with two pointers
for (int i = 0, j = a.length - 1; i < j; i++, j--) {
    int t = a[i]; a[i] = a[j]; a[j] = t;

Two-dimensional and jagged arrays

Java has no true matrix: a 2D array is an array of arrays. Each row is its own array object, so rows can have different lengths (a jagged array).

import java.util.Arrays;

public class Matrix {
    public static void main(String[] args) {
        int[][] grid = new int[2][3];                  // 2 rows, 3 columns, all zeros
        int[][] m = {{1, 2}, {3, 4}, {5, 6}};          // 3 rows, 2 columns
        int[][] jagged = new int[3][];                 // rows not created yet
        for (int i = 0; i < jagged.length; i++) {
            jagged[i] = new int[i + 1];                // lengths 1, 2, 3
            Arrays.fill(jagged[i], i + 1);
        }

        System.out.println(m.length + " rows, " + m[0].length + " columns");
        System.out.println(Arrays.toString(m[1]));     // [3, 4]
        System.out.println(Arrays.deepToString(jagged));

        // matrix multiplication: (2x3) * (3x2) = (2x2)
        int[][] a = {{1, 2, 3}, {4, 5, 6}};
        int[][] b = {{7, 8}, {9, 10}, {11, 12}};
        int[][] c = new int[a.length][b[0].length];
        for (int i = 0; i < a.length; i++) {
            for (int j = 0; j < b[0].length; j++) {
                for (int k = 0; k < b.length; k++) {
                    c[i][j] += a[i][k] * b[k][j];
                }
            }
        }
        System.out.println(Arrays.deepToString(c));
    }
}

Printing a 2D array with Arrays.toString shows the row identities; use deepToString. A loop over int[][] is two nested loops; the outer loop variable is a row (int[]).

import java.util.*;

public class ArraysClass {
    public static void main(String[] args) {
        int[] a = {5, 3, 9, 1, 7};
        int[] copy = Arrays.copyOf(a, 7);               // [5, 3, 9, 1, 7, 0, 0]
        int[] part = Arrays.copyOfRange(a, 1, 4);       // [3, 9, 1]
        int[] same = a.clone();                         // shallow copy, same length

        Arrays.sort(a);
        System.out.println(Arrays.toString(a));         // [1, 3, 5, 7, 9]
        System.out.println(Arrays.binarySearch(a, 7));  // 3
        System.out.println(Arrays.binarySearch(a, 4));  // -3  (insertion point 2)
        System.out.println(Arrays.equals(a, same));     // false: a is sorted now
        System.out.println(a == same);                  // false: different objects
        System.out.println(Arrays.stream(a).sum() + " " + Arrays.stream(a).max().getAsInt());
        System.out.println(Arrays.toString(copy) + " " + Arrays.toString(part));

        int[] zeros = new int[4];
        Arrays.fill(zeros, -1);                         // [-1, -1, -1, -1]

        Integer[] boxed = {3, 1, 2};
        Arrays.sort(boxed, Collections.reverseOrder()); // descending needs objects
        System.out.println(Arrays.toString(boxed));     // [3, 2, 1]

        String[] words = {"pear", "fig", "banana"};
        Arrays.sort(words, Comparator.comparing(String::length));
        System.out.println(Arrays.toString(words));     // [fig, pear, banana]

        List<String> fixed = Arrays.asList("a", "b", "c");
        fixed.set(0, "z");                              // allowed: writes through
        System.out.println(fixed);                      // [z, b, c]
        fixed.add("d");                                 // UnsupportedOperationException
    }
}
  • Arrays.sort on primitives uses a dual-pivot quicksort; on objects it uses a stable merge sort (TimSort). Both are O(n log n); sort an array once and then use binarySearch for O(log n) lookups.
  • binarySearch on an unsorted array gives an undefined result.
  • Arrays.asList(1, 2, 3) returns a List<Integer>, but Arrays.asList(intArray) returns a List<int[]> with a single element — a classic trap. It is fixed-size (add/remove throw UnsupportedOperationException); wrap it with new ArrayList<>(...) to get a growable list, or use List.of.
  • Copies: clone(), copyOf and System.arraycopy(src, srcPos, dest, destPos, length) are shallow — an array of objects copies the references, not the objects. For a 2D array, each row must be copied separately.
  • array.equals(other) is identity comparison (inherited from Object). Use Arrays.equals.

Array covariance and ArrayStoreException

Arrays are covariant: a String[] is also an Object[]. The compiler therefore allows an unsafe store, and the JVM checks the real element type at runtime:

Object[] objects = new String[2];
objects[0] = "ok";
objects[1] = 42;           // compiles, but fails at runtime
java.lang.ArrayStoreException: java.lang.Integer

Generic collections are invariant (List<String> is not a List<Object>), so the same mistake is caught at compile time — one of the reasons to prefer collections to arrays (Module 4).

Rules

  • Array size is fixed at creation and cannot be changed; valid indexes are 0..length-1.
  • length is a field for arrays, length() a method for strings, size() a method for collections.
  • Arrays are objects: passed by value (the reference is copied), compared by identity with ==, and shared on assignment.

Common mistakes

  • for (int i = 0; i <= a.length; i++) — off by one, ArrayIndexOutOfBoundsException.
  • Printing System.out.println(arr) and getting [I@....
  • Thinking int[] copy = original; makes a copy.
  • Creating an array of objects and calling a method on an element before filling it: new Person[3] holds three nulls.
  • Using Arrays.sort(int[], Collections.reverseOrder()) — it does not compile; use Integer[] or sort and reverse.

Interview: array questions

  • "Array vs ArrayList?" — fixed vs resizable, primitives allowed vs objects only, faster and lighter vs more features (Module 4).
  • "Can you change the size of an array?" — no; create a new one and copy.
  • "What does binarySearch return when the key is missing?" — -(insertion point) - 1.
  • Coding warm-ups: reverse an array, find the second largest, rotate by k, remove duplicates from a sorted array, merge two sorted arrays, matrix transpose.
