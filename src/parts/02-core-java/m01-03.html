Strings: immutability, the String pool and common methods

A String is an immutable sequence of characters; literals are shared through the String pool, so compare contents with equals(), never ==, and remember that every "change" creates a new object.

A String is an object (not a primitive) that holds text. You create it with a literal: String city = "Pune";. Strings are used everywhere — names, JSON, SQL, URLs, log lines — so it is worth understanding exactly how they behave.

Immutability

Immutable means the object cannot change after creation. Methods such as toUpperCase(), replace() and trim() do not modify the string; they return a new one.

String name = "ravi";
name.toUpperCase();                 // result thrown away: name is unchanged
System.out.println(name);           // ravi
name = name.toUpperCase();          // now name points to a NEW string "RAVI"
System.out.println(name);           // RAVI

Why Java made String immutable:

  • String pool sharing. Many variables can safely point to one shared "java" object, because nobody can change it. If strings were mutable, changing one would change all.
  • Security. Strings carry file paths, class names, database URLs and user names. If a path could change after a security check passed, the check would be meaningless.
  • Thread safety. Immutable objects can be shared between threads with no locks.
  • Hash code caching. A string's hashCode() is computed once and stored, which makes String an excellent HashMap key. This only works because the content cannot change.
  • Class loading. Class names are strings; they must not change between lookup and load.

The price: many temporary objects when you build text in a loop. That is the job of StringBuilder.

The String pool

The String pool (string constant pool or intern pool) is a special area inside the heap (since Java 7; before that it was in PermGen) where the JVM keeps one copy of each distinct string literal. When you write a literal, the JVM first looks in the pool; if the text already exists it reuses that object, otherwise it adds it.

String a = "java";
String b = "java";
String c = new String("java");      // always creates a new object on the heap
String d = c.intern();              // returns the pooled "java"

System.out.println(a == b);         // true   same pooled object
System.out.println(a == c);         // false  different objects
System.out.println(a.equals(c));    // true   same characters
System.out.println(a == d);         // true   intern() gives the pooled copy

String e = "ja" + "va";             // joined by the compiler: constant expression
System.out.println(a == e);         // true

String part = "ja";
String f = part + "va";             // computed at runtime: new object
System.out.println(a == f);         // false

final String fixed = "ja";
String g = fixed + "va";            // final variable with a constant: compile-time constant
System.out.println(a == g);         // true
System.out.println(a == f.intern());// true
  • new String("java") creates one new heap object, and the literal "java" inside the parentheses is in the pool (created the first time that line is loaded, if not already there). A common interview question: "How many objects does new String("abc") create?" — answer: one on the heap, plus the pooled literal if it did not exist yet (so one or two).
  • The compiler joins constant expressions at compile time, so "ja" + "va" is stored as "java". Concatenation that involves a non-final variable or a method call happens at runtime and creates a new object.
  • intern() returns the pooled instance of equal content. It is rarely needed in application code; do not use it to avoid writing equals.
  • Strings produced at runtime (from Scanner, files, JSON, the network, substring) are not in the pool, which is another reason == fails on real data.

Characters like . | * + ? ( ) [ ] \ $ ^ have special meaning in a regex. Escape them with \\ (a backslash in a Java string literal is written \\) or use Pattern.quote(".").

trim vs strip, isEmpty vs isBlank

  • trim() (old) removes characters up to code point ' ' (space, tab, newline and control characters). It does not remove Unicode spaces such as the non-breaking space.
  • strip() (Java 11) uses Character.isWhitespace and understands Unicode. Prefer it in new code. stripLeading() and stripTrailing() exist too.
  • isEmpty() is true only for length 0. isBlank() is true for length 0 or whitespace only. For form input, isBlank() is usually what you want.

Immutability trap in a loop

String result = "";
for (int i = 0; i < 5; i++) {
    result += i;                // creates a new String each time
}
System.out.println(result);     // 01234

Each pass copies the whole text so far. For five items this is nothing; for 100,000 it is slow and creates a lot of garbage. See the next article.

Rules

  • Compare string contents with equals/equalsIgnoreCase; == compares references.
  • String methods return new strings; assign the result.
  • String indexes start at 0; substring(from, to) includes from and excludes to.
  • switch on a String uses equals and throws NullPointerException for null.

Exceptions and edge cases

  • StringIndexOutOfBoundsException from charAt or substring when an index is negative or too large (the message wording differs between Java versions).
  • NullPointerException on s.length() when s is null. The text "null" appears if you concatenate a null: "x" + null is "xnull".
  • NumberFormatException from Integer.parseInt("12a") or parseInt("").
  • length() counts UTF-16 units, so an emoji can count as 2. For true characters use codePointCount.
  • Case conversion depends on locale for some languages (Turkish dotted i). Use toLowerCase(Locale.ROOT) for identifiers and keys.

Common mistakes

  • if (name == "Ravi") — works in a quick demo because of the pool, then fails with real input.
  • Calling str.toUpperCase() and ignoring the result.
  • Using split(".") or split("|") without escaping.
  • Using new String("text") for no reason; it wastes memory and breaks == expectations.
  • Putting a password in a String: it stays in memory until garbage collected, so Java APIs for passwords use char[], which can be wiped.

Interview: "Why is String immutable? What is the String pool? == vs equals?"

  • Immutable for pool sharing, security, thread safety, cached hash code and class loading.
  • The pool is a region of the heap that stores one copy of each literal; intern() adds or fetches a string from it; new String("a") bypasses it.
  • == compares references, equals compares characters; give the example a == c false, a.equals(c) true.
  • Compile-time constant folding: "ja" + "va" == "java" is true; with a non-final variable it is false.
  • Related: String is final (cannot be subclassed), implements Comparable, CharSequence and Serializable.

StringBuilder, StringBuffer and building text efficiently

Use StringBuilder to build text in a loop because it changes one internal buffer instead of creating a new String each time; StringBuffer is its old synchronized twin.

StringBuilder (Java 5) is a mutable sequence of characters. It keeps an internal array that grows when needed (the default capacity is 16, and it grows automatically), so append is cheap on average.

StringBuilder sb = new StringBuilder();
sb.append("Order #").append(1042).append(" total: ").append(499.5);   // chaining
sb.insert(0, "[NEW] ");
System.out.println(sb);                    // [NEW] Order #1042 total: 499.5
System.out.println(sb.length());           // 31

sb.setLength(0);                           // clear and reuse the builder
sb.append("racecar");
System.out.println(sb.reverse());          // racecar  (reverse changes sb in place)

StringBuilder b2 = new StringBuilder("Hello");
b2.append(' ').append("World");
b2.replace(0, 5, "HELLO");                 // [0, 5) replaced
b2.deleteCharAt(b2.length() - 1);          // remove last char
b2.setCharAt(0, 'J');
System.out.println(b2);                    // JELLO Worl
System.out.println(b2.indexOf("W") + " " + b2.charAt(2));   // 6 L
String finished = b2.toString();           // turn into an immutable String when done

A StringBuilder is normally a local variable used by one thread, so locking in StringBuffer is wasted effort. Sharing one builder between threads is almost always a design smell anyway.

Why + in a loop is slow

// Slow: O(n^2) work. Pass k copies all the k characters built so far.
String s = "";
for (int i = 0; i < 100_000; i++) {
    s += "x";
}

// Fast: O(n). One buffer, appended in place.
StringBuilder sb = new StringBuilder(100_000);   // optional: pre-size the capacity
for (int i = 0; i < 100_000; i++) {
    sb.append("x");
}
String t = sb.toString();

A single expression such as "a" + b + "c" + d is fine: the compiler turns it into one efficient concatenation (since Java 9 through invokedynamic; before it used a hidden StringBuilder). The problem is only repeated concatenation across loop passes, where each pass creates a new intermediate string. For one-off joins prefer String.join, StringJoiner, String.format or stream.collect(Collectors.joining(", ")).

Typical uses

// 1. Palindrome check
static boolean isPalindrome(String s) {
    String clean = s.toLowerCase().replaceAll("[^a-z0-9]", "");
    return clean.contentEquals(new StringBuilder(clean).reverse());
}

// 2. Build a comma-separated list without a trailing comma
static String csv(int[] values) {
    StringBuilder sb = new StringBuilder();
    for (int i = 0; i < values.length; i++) {
        if (i > 0) sb.append(", ");
        sb.append(values[i]);
    }
    return sb.toString();
}

// 3. Count characters, then rebuild
static String compress(String s) {          // "aaabbc" -> "a3b2c1"
    StringBuilder out = new StringBuilder();
    int i = 0;
    while (i < s.length()) {
        char c = s.charAt(i);
        int j = i;
        while (j < s.length() && s.charAt(j) == c) j++;
        out.append(c).append(j - i);
        i = j;
    }
    return out.toString();
}

public static void main(String[] args) {
    System.out.println(isPalindrome("A man, a plan, a canal: Panama"));   // true
    System.out.println(csv(new int[]{3, 5, 8}));                         // 3, 5, 8
    System.out.println(compress("aaabbc"));                              // a3b2c1
}

Rule: StringBuilder does not override equals() or hashCode()

sb1.equals(sb2) compares references, and a builder is a bad HashMap key because its content can change. Compare with sb1.compareTo(sb2) == 0 (Java 11), or convert with toString() first. String.contentEquals(CharSequence) compares a string to a builder.

Common mistakes

  • Passing a char where an int is expected: new StringBuilder('A') sets the capacity to 65, it does not add "A". Use new StringBuilder("A").
  • Appending 'a' + 'b' (which is the int 195) instead of "a" + "b".
  • Calling sb.reverse() and forgetting that it changed sb itself.
  • Concatenating strings in a loop and wondering why a report takes minutes.

How a StringBuilder works inside

A StringBuilder owns one array of characters (a compact byte array since Java 9) and a counter called count. length() is that counter; capacity() is the size of the array. append copies the new characters into the free space. Only when the array is full does the builder allocate a bigger array (about double the old size plus 2) and copy the old content once. Because the size doubles, the copying cost over many appends adds up to O(n) in total, so each append is amortised O(1).

StringBuilder a = new StringBuilder();
System.out.println(a.capacity());            // 16 (the default)
a.append("12345678901234567");               // 17 characters do not fit in 16
System.out.println(a.length() + " " + a.capacity());   // 17 34

StringBuilder b = new StringBuilder("Hello");
System.out.println(b.capacity());            // 21 = 16 + length of the initial text

StringBuilder c = new StringBuilder(1000);   // you choose the capacity
c.ensureCapacity(5000);                      // grow once, up front
c.append("short");
c.trimToSize();                              // give back the unused space
System.out.println(c.length() + " " + c.capacity());   // 5 5

Pre-sizing with new StringBuilder(expectedLength) avoids the repeated growth. It is a small gain; correct use of a builder matters far more than the exact capacity.

StringBuffer: what "synchronized" really gives you

Each StringBuffer method locks the object while it runs, so two threads calling append at the same time never corrupt the buffer. That protects only single calls. A sequence such as "check length(), then append" is still a race, because another thread can run between the two calls. If threads must build one text together, hold your own lock around the whole sequence, or let each thread build its own StringBuilder and merge the results. In new code StringBuffer is almost never the answer.

Exceptions and edge cases

  • StringIndexOutOfBoundsException — charAt, setCharAt, deleteCharAt, insert or substring with an index outside 0..length. Also thrown by delete(start, end) when start is negative or greater than end; an end past the length is silently clamped.
  • NegativeArraySizeException — new StringBuilder(-1).
  • NullPointerException — new StringBuilder((String) null). But append((String) null) does not throw: it appends the four letters null.
  • OutOfMemoryError — the buffer cannot grow beyond about 2 billion characters, and a huge builder can exhaust the heap sooner.
  • reverse() treats a surrogate pair (an emoji or a rare script character) as one unit, so it does not break such characters.

Wrong: a builder defeated by + inside append

StringBuilder sb = new StringBuilder();
for (String name : names) {
    sb.append(name + ", ");        // creates a temporary String every pass
}

Right: append each piece

StringBuilder sb = new StringBuilder();
for (String name : names) {
    sb.append(name).append(", ");
}
// or simply: String.join(", ", names)

Conventions

  • Keep the builder a local variable, build, call toString() once, and return the String. Do not store builders in fields or pass them between threads.
  • Declare the variable as StringBuilder (it has no useful interface); take CharSequence in method parameters that only read text.
  • Do not rewrite a simple a + b + c into a builder; it is no faster and harder to read.
  • For a trailing separator, either test i > 0 before appending (as above) or call setLength(sb.length() - 2) at the end.

In real projects

Builders appear in report and CSV export code, custom toString() methods, log messages built in loops, and code generators. For SQL do not glue user input into a builder: that opens the door to SQL injection. Build the statement text with a builder if you must, but pass the values as ? parameters to a PreparedStatement.

Interview: "String vs StringBuilder vs StringBuffer"

  • String is immutable; StringBuilder is mutable and not thread-safe; StringBuffer is mutable and synchronized.
  • Loop concatenation with + is O(n²) because of repeated copying; builder appends are amortised O(1).
  • Default capacity 16; the buffer grows (roughly doubling) when it is full — pre-size when you know the size.
  • Mention that a single-line + expression is already optimised by the compiler.

Input and output: Scanner, BufferedReader, printf and text blocks

Read console input with Scanner (easy) or BufferedReader (fast), watch the nextInt() + nextLine() pitfall, and format output with printf or String.format.

Output basics

  • System.out.println(x) prints and adds a line break; print(x) does not.
  • System.out.printf(format, args...) formats like C's printf; System.out.format is the same.
  • System.err is the error stream: it can be redirected separately (2>errors.txt). In real applications you use a logger instead (Logging).

Scanner

java.util.Scanner splits input into tokens (separated by whitespace) and converts them for you.

import java.util.Scanner;

public class ScannerDemo {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);
        System.out.print("Enter age: ");
        int age = sc.nextInt();
        System.out.print("Enter price: ");
        double price = sc.nextDouble();
        System.out.print("Enter first word: ");
        String word = sc.next();                 // one token
        sc.nextLine();                           // consume the rest of that line
        System.out.print("Enter full name: ");
        String fullName = sc.nextLine();         // whole line, spaces allowed
        System.out.println(age + " " + price + " " + word + " [" + fullName + "]");
        sc.close();
    }
}

The nextInt() + nextLine() pitfall

If the user types 5 and presses Enter, the input buffer contains 5\n. nextInt() reads 5 and stops, leaving \n. The next nextLine() immediately reads the rest of that line — which is empty — and returns "", so your program seems to skip the question.

Wrong: the name is always empty

int n = sc.nextInt();
String name = sc.nextLine();   // reads the leftover "\n" -> ""

Right: consume the line break first

int n = Integer.parseInt(sc.nextLine().trim());
String name = sc.nextLine();   // reads the real line

Two safe approaches: read everything with nextLine() and parse yourself (shown above), or call an extra sc.nextLine() after nextInt(). Invalid input such as abc for nextInt() throws InputMismatchException and leaves the bad token in the buffer, so loops must call sc.next() to discard it. Reading when nothing is left throws NoSuchElementException.

static int readInt(Scanner sc, String prompt) {
    while (true) {
        System.out.print(prompt);
        if (sc.hasNextInt()) {
            int value = sc.nextInt();
            sc.nextLine();                 // clear the line break
            return value;
        }
        System.out.println("Please enter a whole number.");
        sc.next();                         // discard the bad token
    }
}

A Scanner can also parse a string or file: new Scanner("10 20 30"). Closing a Scanner on System.in closes the standard input for the whole program, so create one Scanner for System.in and close it once, at the end.

BufferedReader — fast input

Scanner is convenient but slow for large input (it uses regular expressions). BufferedReader reads whole lines through a buffer and is the usual choice when input has many lines — competitive programming, big files. It reads text only; you convert it yourself.

import java.io.BufferedReader;
import java.io.IOException;
import java.io.InputStreamReader;
import java.util.StringTokenizer;

public class FastInput {
    public static void main(String[] args) throws IOException {
        try (BufferedReader br = new BufferedReader(new InputStreamReader(System.in))) {
            int n = Integer.parseInt(br.readLine().trim());        // first line: count
            StringTokenizer st = new StringTokenizer(br.readLine()); // second line: numbers
            long sum = 0;
            for (int i = 0; i < n; i++) {
                sum += Long.parseLong(st.nextToken());
            }
            System.out.println("Sum = " + sum);
        }
    }
}

  • readLine() throws the checked IOException: declare throws IOException or catch it.
  • Instead of StringTokenizer you can use line.split(" ") — simpler, slightly slower.

Text blocks (Java 15)

A text block is a multi-line string between triple quotes. It keeps line breaks, needs no \n or escaped quotes, and removes the common indentation. It is ideal for JSON, SQL and HTML. More about it in Module 5.

String sql = """
        SELECT id, name
        FROM customers
        WHERE city = 'Pune'
        ORDER BY name
        """;
System.out.print(sql);
SELECT id, name
FROM customers
WHERE city = 'Pune'
ORDER BY name

Rules

  • The opening """ must be followed by a line break; the closing """ position decides the indentation that is removed.
  • Every printf specifier must match its argument type; the count of arguments must match the count of specifiers.
  • Create one Scanner per input source; do not close System.in early.

Common mistakes

  • The nextInt() / nextLine() skip (above).
  • Using %d for a double or %f for an int.
  • Using \n in printf for a platform-correct newline; use %n.
  • Forgetting to trim() before Integer.parseInt(line): a trailing space causes NumberFormatException.
  • Creating a new Scanner(System.in) in every method: buffered input is lost between scanners.

Interview: "Scanner vs BufferedReader? Why does nextLine() seem to be skipped?"

  • Scanner tokenises and parses (convenient, slower); BufferedReader reads lines (fast, manual parsing, throws IOException).
  • nextInt() leaves the line break in the buffer; the following nextLine() consumes that empty remainder.
  • Fix: read lines and parse, or add one extra nextLine().
  • Mention hasNextInt() for validation and InputMismatchException.

The Math class, Random and ThreadLocalRandom

Math offers static methods for everyday arithmetic (pow, sqrt, floorMod, addExact); use ThreadLocalRandom for quick random numbers and SecureRandom when the value protects something.

To round a price to two decimals with double people write Math.round(x * 100) / 100.0. It is acceptable for display, but use BigDecimal.setScale for real money. Use pow only when you need powers of non-integers or large powers; for squares write x * x, which is faster and exact for integers.

import java.util.Random;
import java.util.concurrent.ThreadLocalRandom;

public class RandomDemo {
    public static void main(String[] args) {
        Random seeded = new Random(42);              // same seed -> same sequence every run
        int fromRandom = seeded.nextInt(100);        // 0..99
        double d = seeded.nextDouble();              // [0.0, 1.0)

        int dice = ThreadLocalRandom.current().nextInt(1, 7);   // 1..6

        System.out.println("dice=" + dice + " otp-length=" + String.valueOf(otp).length());

Common mistakes

  • Math.random() * 10 cast to int gives 0–9, not 1–10: add 1 for 1–10.
  • Creating a new Random() inside a loop — create it once.
  • Using Random for OTPs or session tokens: it is predictable. Use SecureRandom.
  • Assuming Math.round returns an int: it returns long for a double, so int r = Math.round(x); does not compile.

Interview: Random vs ThreadLocalRandom vs SecureRandom

  • Random: seedable, reproducible, shared state; ThreadLocalRandom: one instance per thread, no contention, not seedable; SecureRandom: unpredictable, for security.
  • Math.floorMod vs % with negatives; Math.round(-2.5) is −2.

Interview questions — Basics and syntax

What are the JDK, JRE and JVM? How is Java platform independent?

The JVM runs bytecode. The JRE is the JVM plus the standard libraries. The JDK is the JRE plus development tools such as javac. javac compiles source to platform-neutral bytecode in .class files; each operating system has its own JVM that executes the same bytecode. So the bytecode is portable and the JVM is platform specific. At runtime the class loader loads classes, the verifier checks them, and the interpreter and JIT compiler run them.

Why is main declared public static void?

public so the JVM can call it from outside; static so no object is needed to start the program; void because it returns nothing to the JVM (use System.exit(code) for a status). The parameter String[] args carries the command-line arguments. A different signature compiles but will not be started as the entry point.

Why does Integer a = 127, b = 127; a == b give true, but 128 gives false?

Autoboxing calls Integer.valueOf, which returns cached objects for values from −128 to 127. Inside that range both variables share one object; outside it, two different objects are created, and == compares references. Always use equals() for wrapper objects.

Is Java pass-by-value or pass-by-reference?

Always pass-by-value. For primitives the value is copied. For objects the reference is copied, so the method and the caller share one object: calling list.add(x) in the method changes what the caller sees. But assigning a new object to the parameter only changes the local copy. That is why a swap(a, b) method cannot swap the caller's variables.

Why is String immutable, and what is the String pool?

Immutability allows safe sharing of literals in the pool, protects security-sensitive values like paths and class names, makes strings thread-safe, and lets hashCode() be cached, which is ideal for HashMap keys. The String pool is a heap area that keeps one instance for each distinct literal. new String("a") creates a separate heap object; intern() returns the pooled one.

What does this print? String a = "java"; String b = new String("java"); System.out.println(a == b); System.out.println(a.equals(b));

false then true. a points to the pooled literal and b to a new heap object, so the references differ, but the characters are equal. "ja" + "va" == "java" would be true because the compiler folds constants, while part + "va" == "java" with a non-final variable part is false.

String vs StringBuilder vs StringBuffer?

String is immutable. StringBuilder is mutable and not thread-safe, so it is the fastest for building text. StringBuffer is mutable and synchronized, so it is thread-safe but slower, and rarely needed. Concatenating with + in a loop is O(n²) because every pass copies the text; use a StringBuilder there.

Why can't you use double for money? What do you use instead?

Binary floating point cannot represent most decimal fractions exactly: 0.1 + 0.2 is 0.30000000000000004, and errors accumulate. Use BigDecimal created from Strings (new BigDecimal("0.10")), set the scale and a RoundingMode explicitly, and compare with compareTo. Or keep the amount as a long in paise. In the database use NUMERIC(p, s).

Why does byte b = 10; b += 5; compile but b = b + 5; does not?

b + 5 is promoted to int, and assigning an int to a byte needs a cast. A compound assignment b += 5 is defined as b = (byte)(b + 5), so the compiler adds the cast for you. The same hidden cast silently truncates in int i = 10; i += 3.7; (result 13).

What is the output of int x = 5; x = x++ + ++x;?

12. x++ yields 5 and sets x to 6; ++x sets x to 7 and yields 7; the sum 12 is then assigned to x. Java evaluates operands left to right. Also remember that x = x++; leaves x unchanged.

How does Java choose between overloaded methods?

At compile time, in three phases: first exact match or widening without boxing, then boxing/unboxing, then varargs. The most specific method wins; if none is more specific, the call is ambiguous. So with show(int), show(long) and show(Integer), the call show(5) picks int, and without show(int) it picks long (widening beats boxing). Return type is not part of the signature.

Why does Scanner.nextLine() sometimes return an empty string after nextInt()?

nextInt() reads only the number and leaves the line break in the buffer. The next nextLine() reads the rest of that line, which is empty. Fix it by reading all input with nextLine() and parsing with Integer.parseInt, or by calling one extra nextLine() after nextInt().

What can a switch be used on, and what is a switch expression?

The selector may be byte, short, char, int (and wrappers), String or an enum — not long, double or boolean. In the old colon form, missing break causes fall-through. Since Java 14 the arrow form has no fall-through, and a switch expression produces a value (int days = switch (m) { case "Feb" -> 28; default -> 31; };), must be exhaustive, and uses yield inside a block.

What does Arrays.asList return, and what are its traps?

A fixed-size list backed by the array: set works and writes through to the array, but add and remove throw UnsupportedOperationException. With a primitive array like int[] you get a List<int[]> of size 1. Wrap it in new ArrayList<>(...) for a normal list, or use List.of for an immutable one.

What exceptions can arrays and strings throw at runtime?

ArrayIndexOutOfBoundsException for a bad array index, NegativeArraySizeException for a negative size, ArrayStoreException when storing the wrong type into a covariant array, StringIndexOutOfBoundsException for charAt/substring, NullPointerException for a null array or string, NumberFormatException for bad numeric text, and ArithmeticException: / by zero for integer division by zero.

Cheat sheet — Basics and syntax

  • JDK ⊃ JRE ⊃ JVM JDK has the tools, JRE the libraries, JVM runs bytecode.
  • Run javac A.java then java A; or java A.java (Java 11+); jshell for experiments.
  • main public static void main(String[] args); one public class per file, file name = class name.
  • Primitives byte 8, short 16, int 32, long 64, float 32, double 64, char 16 (unsigned), boolean.
  • Literals 10L, 3.14f, 1_000_000, 0xFF, 0b101; decimals default to double, integers to int.
  • Defaults fields and array elements: 0 / false / null; locals have none.
  • Integer cache −128…127; compare wrappers with equals.
  • Unboxing null throws NullPointerException.
  • var local variables only; needs an initializer; still statically typed.
  • Division int / int drops the fraction; -7 % 3 == -1; use Math.floorMod for wrap-around.
  • Overflow wraps silently; Math.addExact throws; use 1000000L * 1000000 for long maths.
  • 0.1 + 0.2 is 0.30000000000000004; money → BigDecimal("0.10") + setScale + RoundingMode.
  • Promotion byte/short/char arithmetic gives int; b += 1 has a hidden cast, b = b + 1 does not compile.
  • Casting narrowing truncates: (int) 3.99 == 3, (byte) 130 == -126.
  • i++ / ++i old value then add / add then new value.
  • && and || short-circuit; & and | evaluate both sides.
  • switch arrow form has no fall-through; switch expressions return a value and use yield.
  • Loops for, enhanced for, while, do-while; break outer; leaves a labeled loop.
  • Pass-by-value always; object references are copied; reassigning a parameter never changes the caller.
  • Overload order exact/widening → boxing → varargs; most specific wins.
  • Arrays fixed size, length field; Arrays.toString, deepToString, sort, copyOf, fill, equals.
  • Arrays.asList fixed-size view; List.of immutable; new ArrayList<>(…) growable.
  • Strings immutable; literals pooled; equals for content, "x".equals(s) avoids null.
  • split takes a regex: split("\\."), split("\\s+"); trailing empty strings dropped.
  • Builders StringBuilder for loops (not thread-safe), StringBuffer synchronized.
  • Input Scanner for small programs, BufferedReader for speed; beware nextInt() then nextLine().
  • printf %d %s %.2f %n %5d %-10s %05d %,d.
  • Random ThreadLocalRandom.current().nextInt(1, 7) for everyday use; SecureRandom for secrets.

Practice — Basics and syntax

  1. Warm-up: types and operators (easy). In JShell or a single file, predict and then check: 7 / 2, -7 % 3, (byte) 200, 0.1 + 0.2, 'a' + 1, 1 + 2 + "x", Integer.MAX_VALUE + 1. Done when all seven guesses match the output and you can explain each.
  2. Star and number patterns (easy). Print a right triangle, an inverted triangle, a pyramid, a diamond, a hollow square, Floyd's triangle and Pascal's triangle of height n. Done when each prints correctly for n = 1, 5 and 9.
  3. Number programs (easy). Write: even/odd, prime check (up to √n), primes up to N, factorial (iterative and recursive), Fibonacci (first N), GCD and LCM, Armstrong number, perfect number, sum of digits, reverse a number, palindrome number, binary to decimal and back. Done when each handles 0, 1 and a large int without errors.
  4. String programs (easy to medium). Write: reverse a string, palindrome (ignoring case and punctuation), count vowels and consonants, anagram check (sort the chars, then a count array), first non-repeating character, remove duplicates, count words, capitalise each word, run-length compression. Done when each works on empty strings and on strings with spaces.
  5. Array programs (medium). Write: reverse an array, largest and second largest, sum and average, remove duplicates from a sorted array, merge two sorted arrays, rotate by k, linear and binary search, bubble sort, count frequency of each element. Done when you use no library sort for the sorting task and handle length 0 and 1.
  6. Matrix programs (medium). Write: matrix addition, multiplication (use the example in the Arrays article), transpose, row and column sums, diagonal sum, spiral print of a 4×4 matrix. Done when it works for non-square matrices where mathematically valid.
  7. Menu-driven calculator (medium). Use a do-while menu with a switch expression, a Scanner and a method per operation; reject division by zero and non-numeric input without crashing. Done when the program survives entering letters at every prompt.
  8. Pass-by-value lab (medium). Write methods that try to swap two ints, two Strings, two array elements, and mutate or reassign a StringBuilder and an int[]. Predict each result on paper, run it, and write one sentence per case explaining what was copied.
  9. Billing with BigDecimal (medium). Read item names, prices and quantities with BufferedReader, compute a subtotal, 18% GST and a total with BigDecimal, round with HALF_UP to two decimals, and print an aligned receipt with printf. Done when 3 × ₹33.33 plus GST matches a hand calculation to the paisa.
  10. Mini project: word and number statistics (harder). Read a text file given as a command-line argument line by line, then print the 5 most frequent words (use a loop and arrays or a Map if you know it), the longest word, and the average word length. Build the final report with a StringBuilder. Done when it handles an empty file and a missing file with a clear message.
