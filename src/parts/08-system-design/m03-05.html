Design Splitwise (expenses, balances and settling debts)

Record each expense as "who paid, how much, split how among whom" using a SplitStrategy (equal, exact, percentage), keep a pairwise balance sheet, and simplify debts by computing each person's net balance and matching the biggest debtor with the biggest creditor.

Requirements and assumptions

Functional:

  • Users add expenses: one person pays; the amount is split among participants.
  • Split types: equal, exact (each person's amount given), percentage.
  • Show who owes whom: per user, and for the whole group.
  • Settle up: record a payment from one user to another.
  • Simplify debts: the fewest transfers that clear everything.

Assumptions: one currency, amounts in paise as long, one group (extension: many groups), the payer may or may not be in the split, rounding leftovers go to the first participants one paisa at a time so the parts always add up to the total.

Entities

  • Split: a user id and the amount that user owes for one expense.
  • SplitStrategy: interface that turns (total, participants, values) into a list of Splits; implementations for equal, exact and percentage. Strategy pattern.
  • Expense: payer, total, list of splits. Kept for history.
  • BalanceSheet (inside the service here): owes[debtor][creditor] in paise.
  • Transfer: from, to, amount, the output of simplification.

Key design decisions

  • Strategy per split type so a new type (by shares, by item) is a new class. A small EnumMap from SplitType to strategy plays the role of a factory (Module 2).
  • Validate in the strategy: exact amounts must sum to the total; percentages must sum to 100.
  • Net out opposite debts immediately: if B owes A 100 and A now owes B 30, store "B owes A 70". The sheet never has both directions for one pair.
  • Simplify on demand from the sheet, without mutating it. It produces a plan; actually settling is a separate call.
  • Money is long paise. Splitting Rs 10.00 three ways is 334, 333, 333 paise, not 333.33 each.

Core code: split strategies

import java.util.ArrayList;
import java.util.List;

enum SplitType { EQUAL, EXACT, PERCENT }

record Split(String userId, long amountPaise) { }

interface SplitStrategy {
    /** values is null for EQUAL; amounts for EXACT; percentages for PERCENT. */
    List<Split> split(long total, List<String> users, List<Long> values);
}

class EqualSplit implements SplitStrategy {
    public List<Split> split(long total, List<String> users, List<Long> values) {
        int n = users.size();
        long base = total / n, extra = total % n;
        List<Split> out = new ArrayList<>();
        for (int i = 0; i < n; i++) {
            out.add(new Split(users.get(i), base + (i < extra ? 1 : 0)));  // spread leftovers
        }
        return out;
    }
}

class ExactSplit implements SplitStrategy {
    public List<Split> split(long total, List<String> users, List<Long> values) {
        long sum = values.stream().mapToLong(Long::longValue).sum();
        if (sum != total) throw new IllegalArgumentException("Amounts must add up to total");
        List<Split> out = new ArrayList<>();
        for (int i = 0; i < users.size(); i++) out.add(new Split(users.get(i), values.get(i)));
        return out;
    }
}

class PercentSplit implements SplitStrategy {
    public List<Split> split(long total, List<String> users, List<Long> values) {
        long pct = values.stream().mapToLong(Long::longValue).sum();
        if (pct != 100) throw new IllegalArgumentException("Percentages must add up to 100");
        List<Split> out = new ArrayList<>();
        long assigned = 0;
        for (int i = 0; i < users.size(); i++) {
            long amount = total * values.get(i) / 100;
            out.add(new Split(users.get(i), amount));
            assigned += amount;
        }
        long left = total - assigned;                       // rounding leftover
        out.set(0, new Split(out.get(0).userId(), out.get(0).amountPaise() + left));
        return out;
    }
}

Core code: the service and debt simplification

import java.util.ArrayList;
import java.util.EnumMap;
import java.util.HashMap;
import java.util.List;
import java.util.Map;
import java.util.PriorityQueue;

record Transfer(String from, String to, long amountPaise) { }

class SplitwiseService {
    private final Map<SplitType, SplitStrategy> strategies = new EnumMap<>(SplitType.class);
    // owes.get(debtor).get(creditor) = amount in paise
    private final Map<String, Map<String, Long>> owes = new HashMap<>();

    SplitwiseService() {
        strategies.put(SplitType.EQUAL, new EqualSplit());
        strategies.put(SplitType.EXACT, new ExactSplit());
        strategies.put(SplitType.PERCENT, new PercentSplit());
    }

    synchronized void addExpense(String payer, long total, SplitType type,
                                 List<String> users, List<Long> values) {
        if (total <= 0 || users.isEmpty()) throw new IllegalArgumentException("Bad expense");
        for (Split s : strategies.get(type).split(total, users, values)) {
            if (!s.userId().equals(payer) && s.amountPaise() > 0) {
                addDebt(s.userId(), payer, s.amountPaise());
            }
        }
    }

    synchronized void settle(String from, String to, long amount) {
        addDebt(to, from, amount);              // paying reduces what 'from' owes 'to'
    }

    private void addDebt(String debtor, String creditor, long amount) {
        Map<String, Long> reverse = owes.computeIfAbsent(creditor, k -> new HashMap<>());
        long back = reverse.getOrDefault(debtor, 0L);       // does creditor owe debtor?
        if (back >= amount) {
            if (back == amount) reverse.remove(debtor); else reverse.put(debtor, back - amount);
        } else {
            reverse.remove(debtor);
            owes.computeIfAbsent(debtor, k -> new HashMap<>()).merge(creditor, amount - back, Long::sum);
        }
    }

    synchronized long owed(String debtor, String creditor) {
        return owes.getOrDefault(debtor, Map.of()).getOrDefault(creditor, 0L);
    }

    private record Bal(String user, long amount) { }

    /** Greedy min cash flow: biggest debtor pays biggest creditor. */
    synchronized List<Transfer> simplify() {
        Map<String, Long> net = new HashMap<>();            // + means is owed, - means owes
        owes.forEach((d, m) -> m.forEach((c, amt) -> {
            net.merge(d, -amt, Long::sum);
            net.merge(c, amt, Long::sum);
        }));
        PriorityQueue<Bal> creditors = new PriorityQueue<>((a, b) -> Long.compare(b.amount(), a.amount()));
        PriorityQueue<Bal> debtors = new PriorityQueue<>((a, b) -> Long.compare(b.amount(), a.amount()));
        net.forEach((u, v) -> {
            if (v > 0) creditors.add(new Bal(u, v));
            else if (v < 0) debtors.add(new Bal(u, -v));    // store debt as positive
        });
        List<Transfer> plan = new ArrayList<>();
        while (!creditors.isEmpty() && !debtors.isEmpty()) {
            Bal c = creditors.poll(), d = debtors.poll();
            long pay = Math.min(c.amount(), d.amount());
            plan.add(new Transfer(d.user(), c.user(), pay));
            if (c.amount() > pay) creditors.add(new Bal(c.user(), c.amount() - pay));
            if (d.amount() > pay) debtors.add(new Bal(d.user(), d.amount() - pay));
        }
        return plan;
    }
}
import java.util.List;

public class SplitwiseDemo {
    public static void main(String[] args) {
        var sw = new SplitwiseService();
        sw.addExpense("A", 300_000, SplitType.EQUAL, List.of("A", "B", "C"), null);
        sw.addExpense("B", 60_000, SplitType.EQUAL, List.of("B", "C"), null);
        System.out.println("B owes A: " + sw.owed("B", "A"));
        sw.simplify().forEach(t ->
            System.out.println(t.from() + " pays " + t.to() + " " + t.amountPaise()));
    }
}

Why the greedy simplification works

Only each person's net balance matters: what they are owed minus what they owe. Net balances always sum to zero. Repeatedly settling the largest debtor against the largest creditor clears at least one person per transfer, so with N people with non-zero balance you need at most N-1 transfers. Finding the true minimum is NP-hard (it is a subset-sum style problem); the greedy result is the standard interview answer and is optimal in most practical cases. Say that sentence aloud; interviewers like it.

Concurrency

Group members add expenses at the same time. The service methods are synchronized, so each expense (several balance updates) applies atomically and simplify sees a consistent sheet. For many independent groups, keep one service (or lock) per group so groups never block each other. In a database, an expense and its balance changes go in one transaction; balances are derived or updated with UPDATE ... SET amount = amount + ?.

Edge cases

  • Payer not in the split: they paid for others; every split row creates a debt to the payer.
  • Payer is the only participant: no debt created.
  • Exact amounts do not add up, or percentages are not 100: reject before changing anything (validation happens before the loop).
  • Rounding: leftover paise are assigned deterministically, so totals always match.
  • Settling more than owed: here it flips the direction (the other person now owes); a stricter version rejects it.
  • Unknown user ids: validate against a user registry.

Extensions interviewers ask

  • Groups and friends: a Group entity with its own balance sheet.
  • Split by shares or by item: new strategies; no change to the service.
  • Multiple currencies: a Money type and an exchange-rate service.
  • Edit or delete an expense: keep expenses as an event log; reverse the old effect, apply the new one.
  • Notifications: Observer on expense added.
  • Activity feed and history: read from the history list.

Design BookMyShow (seat booking without double booking)

Model movies, shows and per-show seats; let a user hold seats for a few minutes under a per-show lock (all or nothing), pay, then confirm, so two people can never get the same seat and abandoned checkouts free their seats automatically.

Requirements and assumptions

Functional:

  • Cities have theatres; theatres have screens; screens have seats. A show is a movie on a screen at a time.
  • Users browse shows and see seat availability for a show.
  • A user selects seats (up to 6), pays, and receives a booking.
  • Seat prices vary by seat category (for example regular and premium).
  • Unpaid selections expire after 5 minutes.

Non-functional: no seat is ever sold twice, even with thousands of users on one popular show; booking is all-or-nothing for multiple seats.

Assumptions: payment is an external call that may succeed or fail, no cancellations or refunds in the core code, in-memory model first; the database version is discussed afterwards.

Entities

A very common mistake is to put "booked" on the physical Seat. A physical seat exists once; its availability is different for each show. So the booking state lives on ShowSeat, one object per seat per show.

ClassResponsibility
Movie, Theatre, Screen, SeatMostly static data: titles, locations, layout
ShowMovie, screen, start time; owns its ShowSeats and the lock
ShowSeatSeat id, price, status AVAILABLE, HELD or BOOKED, hold owner and expiry
HoldTemporary claim on seats: id, user, seat ids, expiry, total
BookingConfirmed purchase
BookingServiceOrchestrates hold, payment, confirm, release
PaymentGatewayInterface; the external payment service

Key design decisions

  • Per-show lock, not per-seat: a booking touches several seats, and one lock per show makes all-or-nothing trivial and deadlock-free. Different shows never block each other. (The reasoning and alternatives are in Concurrency in LLD.)
  • Hold, pay, confirm: the lock is held for microseconds (to mark seats HELD), never during payment. Payment takes seconds and must not block other users.
  • Lazy expiry: a HELD seat whose time passed counts as available. No timer threads are needed for correctness; a cleaner job only tidies memory.
  • Confirm re-checks the hold owner and the expiry before marking BOOKED.
  • Patterns: a thin Facade (BookingService), a Strategy for seat pricing if rules grow, an Observer to notify users (Module 2).

Core code: seats, holds and the show

import java.time.Duration;
import java.time.Instant;
import java.util.ArrayList;
import java.util.LinkedHashMap;
import java.util.LinkedHashSet;
import java.util.List;
import java.util.Map;
import java.util.UUID;
import java.util.concurrent.locks.ReentrantLock;

enum SeatStatus { AVAILABLE, HELD, BOOKED }

class SeatUnavailableException extends RuntimeException {
    SeatUnavailableException(String seatId) { super("Seat " + seatId + " unavailable"); }
}

record Hold(String id, String userId, List<String> seatIds, Instant expiresAt, long total) { }

record Booking(String id, String userId, String showId, List<String> seatIds, long total) { }

class ShowSeat {
    final String seatId;
    final long price;
    SeatStatus status = SeatStatus.AVAILABLE;
    String heldBy;                          // hold id
    Instant holdUntil;

    ShowSeat(String seatId, long price) {
        this.seatId = seatId;
        this.price = price;
    }

    boolean isAvailable(Instant now) {
        return status == SeatStatus.AVAILABLE
            || (status == SeatStatus.HELD && !now.isBefore(holdUntil));   // expired hold
    }
}

class Show {
    static final int MAX_SEATS = 6;
    private final String id;
    private final Map<String, ShowSeat> seats = new LinkedHashMap<>();
    private final Map<String, Hold> holds = new LinkedHashMap<>();
    private final ReentrantLock lock = new ReentrantLock();

    Show(String id, List<ShowSeat> layout) {
        this.id = id;
        layout.forEach(s -> seats.put(s.seatId, s));
    }

    String id() { return id; }

    Hold hold(String userId, List<String> seatIds, Instant now, Duration ttl) {
        List<String> ids = new ArrayList<>(new LinkedHashSet<>(seatIds));   // drop duplicates
        if (ids.isEmpty() || ids.size() > MAX_SEATS) {
            throw new IllegalArgumentException("Choose 1 to " + MAX_SEATS + " seats");
        }
        lock.lock();
        try {
            long total = 0;
            for (String sid : ids) {                              // check ALL first
                ShowSeat s = seats.get(sid);
                if (s == null) throw new IllegalArgumentException("No seat " + sid);
                if (!s.isAvailable(now)) throw new SeatUnavailableException(sid);
                total += s.price;
            }
            Hold h = new Hold(UUID.randomUUID().toString(), userId, ids, now.plus(ttl), total);
            for (String sid : ids) {                              // then mark ALL
                ShowSeat s = seats.get(sid);
                s.status = SeatStatus.HELD;
                s.heldBy = h.id();
                s.holdUntil = h.expiresAt();
            }
            holds.put(h.id(), h);
            return h;
        } finally {
            lock.unlock();
        }
    }
}

Core code: confirm, release and the service

These two methods belong in the same Show class; they are shown separately to keep the blocks short.

// inside class Show

Booking confirm(String holdId, String userId, Instant now) {
    lock.lock();
    try {
        Hold h = holds.get(holdId);
        if (h == null || !h.userId().equals(userId)) {
            throw new IllegalStateException("No such hold");
        }
        if (!now.isBefore(h.expiresAt())) {
            releaseLocked(h);
            throw new IllegalStateException("Hold expired, please select seats again");
        }
        for (String sid : h.seatIds()) {
            ShowSeat s = seats.get(sid);
            if (!holdId.equals(s.heldBy)) throw new SeatUnavailableException(sid);
        }
        for (String sid : h.seatIds()) seats.get(sid).status = SeatStatus.BOOKED;
        holds.remove(holdId);
        return new Booking(UUID.randomUUID().toString(), userId, id, h.seatIds(), h.total());
    } finally {
        lock.unlock();
    }
}

void release(String holdId) {
    lock.lock();
    try {
        Hold h = holds.get(holdId);
        if (h != null) releaseLocked(h);
    } finally {
        lock.unlock();
    }
}

private void releaseLocked(Hold h) {
    for (String sid : h.seatIds()) {
        ShowSeat s = seats.get(sid);
        if (h.id().equals(s.heldBy) && s.status == SeatStatus.HELD) {   // only our own hold
            s.status = SeatStatus.AVAILABLE;
            s.heldBy = null;
            s.holdUntil = null;
        }
    }
    holds.remove(h.id());
}
import java.time.Clock;
import java.time.Duration;
import java.time.Instant;
import java.util.List;
import java.util.Map;

interface PaymentGateway {
    boolean charge(String userId, long amountPaise);
}

class BookingService {
    private static final Duration HOLD_TTL = Duration.ofMinutes(5);
    private final Map<String, Show> shows;
    private final PaymentGateway payment;
    private final Clock clock;

    BookingService(Map<String, Show> shows, PaymentGateway payment, Clock clock) {
        this.shows = shows;
        this.payment = payment;
        this.clock = clock;
    }

    Booking checkout(String showId, String userId, List<String> seatIds) {
        Show show = shows.get(showId);
        if (show == null) throw new IllegalArgumentException("No show " + showId);

        Hold hold = show.hold(userId, seatIds, Instant.now(clock), HOLD_TTL);  // fast, locked
        try {
            if (!payment.charge(userId, hold.total())) {                       // slow, unlocked
                throw new IllegalStateException("Payment failed");
            }
            return show.confirm(hold.id(), userId, Instant.now(clock));
        } catch (RuntimeException e) {
            show.release(hold.id());                                           // free the seats
            throw e;
        }
    }
}

import java.time.Duration;
import java.time.Instant;
import java.util.List;
import java.util.Map;

public class BookMyShowDemo {
    public static void main(String[] args) {
        Show show = new Show("S1", List.of(new ShowSeat("A1", 25_000), new ShowSeat("A2", 25_000)));
        Instant now = Instant.now();

        Hold h = show.hold("u1", List.of("A1", "A2"), now, Duration.ofMinutes(5));
        try {
            show.hold("u2", List.of("A2"), now, Duration.ofMinutes(5));
        } catch (SeatUnavailableException e) {
            System.out.println("u2: " + e.getMessage());
        }
        Booking b = show.confirm(h.id(), "u1", now.plusSeconds(60));
        System.out.println("Booked " + b.seatIds() + " total " + b.total());

        var service = new BookingService(Map.of("S1", show), (u, amt) -> true, Clock.systemUTC());
        try {
            service.checkout("S1", "u3", List.of("A1"));
        } catch (SeatUnavailableException e) {
            System.out.println("u3: " + e.getMessage());
        }
    }
}

Concurrency: from this code to production

The in-memory ReentrantLock works for one JVM. With several app servers, move the truth into the database (see Concurrency in LLD and SQL · Module 5):

-- hold N seats atomically: succeeds only if ALL rows were updated
UPDATE show_seat
   SET status = 'HELD', held_by = :holdId, hold_expires_at = now() + interval '5 minutes'
 WHERE show_id = :show AND seat_id IN (:seats)
   AND (status = 'AVAILABLE' OR (status = 'HELD' AND hold_expires_at < now()));
-- if rows updated <> number of seats: ROLLBACK (someone else got one)

-- final guard on the bookings table
ALTER TABLE booking_seat ADD CONSTRAINT uq_show_seat UNIQUE (show_id, seat_id);

Keep that transaction to the one statement above. Never keep it open while the user pays.

Edge cases

  • Payment succeeds but the hold expired meanwhile: confirm fails; you must refund. Use a longer hold than the payment timeout, and make the refund path explicit.
  • Payment fails or the user closes the tab: release (explicit, or lazily by expiry).
  • Same user clicks twice: duplicate seat ids are removed; the second hold on the same seats fails unless you allow re-hold by the same user.
  • Two users want overlapping seat sets: one wins entirely, the other gets none (no partial holds).
  • Show already started or cancelled: check startTime in hold.
  • Idempotent payment callbacks: confirm by hold id so a repeated callback does not create two bookings (the hold is removed on first confirm).

Extensions interviewers ask

  • Cancellation and refund: a CANCELLED booking state; seats go back to AVAILABLE; refund through the gateway.
  • Dynamic pricing: a PricingStrategy deciding each ShowSeat price by demand or time.
  • Seat recommendations ("seats together"): scan a row for a contiguous free block.
  • Search shows by city and movie: indexes by city and movie id.
  • Waiting list: Observer: notify when a held seat is released.
  • Coupons and offers: decorator over the price (Module 2).
