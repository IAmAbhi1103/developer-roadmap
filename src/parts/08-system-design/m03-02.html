Design a parking lot

Model vehicles, spots, floors, tickets and a pricing Strategy; park a vehicle by finding a free spot of the right type, and make the spot claim atomic so two cars never get the same spot.

Requirements and assumptions

Functional:

  • A lot has several floors; each floor has spots of types BIKE, CAR and TRUCK.
  • On entry the system finds a free spot for the vehicle type and issues a ticket.
  • On exit the system computes the fee from the parking duration and frees the spot.
  • The lot reports free spots per type.

Non-functional: thread-safe (several gates run at once), easy to add new pricing rules and vehicle types.

Assumptions: one lot, in-memory, a vehicle uses exactly one spot of its own type, fee is hourly and any started hour is charged, payment is out of scope, one entry gate chooses the spot (no reservation in advance).

Entities

ClassResponsibility
VehicleType (enum)BIKE, CAR, TRUCK; also the spot size class
VehiclePlate number and type
ParkingSpotOne spot: id, type, and whether it is taken
ParkingFloorOwns spots; finds and claims a free one
TicketVehicle, spot, entry time
PricingStrategyInterface: duration and type to fee
ParkingLotFacade: park and unpark; tracks active tickets

Key design decisions

  • Strategy for pricing (Module 2): hourly today, flat-rate or weekend-rate tomorrow. ParkingLot never changes (open/closed principle, Module 1).
  • Enum for types instead of a Vehicle subclass per type: the types differ only by data (the rate and the spot size), not behaviour. Subclasses would be inheritance for its own sake.
  • The spot owns its own occupancy and uses an atomic compare-and-set, so claiming a spot is one indivisible step.
  • Inject a Clock so tests can move time instead of sleeping.
  • A spot-allocation strategy (nearest to entrance, lowest floor first) can be a second Strategy if asked; here floors are scanned in order.

Core code: model

import java.time.Instant;
import java.util.concurrent.atomic.AtomicReference;

enum VehicleType { BIKE, CAR, TRUCK }

record Vehicle(String plate, VehicleType type) { }

class ParkingSpot {
    private final String id;
    private final VehicleType type;
    private final AtomicReference<Vehicle> parked = new AtomicReference<>();

    ParkingSpot(String id, VehicleType type) {
        this.id = id;
        this.type = type;
    }

    String id() { return id; }
    VehicleType type() { return type; }
    boolean isFree() { return parked.get() == null; }

    /** Atomic: only one thread can move the spot from empty to occupied. */
    boolean tryPark(Vehicle v) {
        return v.type() == type && parked.compareAndSet(null, v);
    }

    void free() { parked.set(null); }
}

record Ticket(String id, Vehicle vehicle, ParkingSpot spot, Instant entry) { }

Core code: pricing and floor

import java.time.Duration;
import java.util.EnumMap;
import java.util.List;
import java.util.Map;
import java.util.Optional;

interface PricingStrategy {
    long fee(VehicleType type, Duration parkedFor);   // result in paise
}

class HourlyPricing implements PricingStrategy {
    private final Map<VehicleType, Long> ratePerHour = new EnumMap<>(VehicleType.class);

    HourlyPricing() {
        ratePerHour.put(VehicleType.BIKE, 1_000L);
        ratePerHour.put(VehicleType.CAR, 3_000L);
        ratePerHour.put(VehicleType.TRUCK, 6_000L);
    }

    public long fee(VehicleType type, Duration parkedFor) {
        long minutes = Math.max(1, parkedFor.toMinutes());
        long hours = (minutes + 59) / 60;               // any started hour counts
        return hours * ratePerHour.get(type);
    }
}

class ParkingFloor {
    private final List<ParkingSpot> spots;

    ParkingFloor(List<ParkingSpot> spots) { this.spots = List.copyOf(spots); }

    Optional<ParkingSpot> claimSpot(Vehicle v) {
        for (ParkingSpot s : spots) {
            if (s.isFree() && s.tryPark(v)) return Optional.of(s);  // CAS decides the winner
        }
        return Optional.empty();
    }

    long freeCount(VehicleType t) {
        return spots.stream().filter(s -> s.type() == t && s.isFree()).count();
    }
}

Core code: the lot (facade)

import java.time.Clock;
import java.time.Duration;
import java.time.Instant;
import java.util.List;
import java.util.Map;
import java.util.Set;
import java.util.UUID;
import java.util.concurrent.ConcurrentHashMap;

class ParkingLot {
    private final List<ParkingFloor> floors;
    private final PricingStrategy pricing;
    private final Clock clock;
    private final Map<String, Ticket> active = new ConcurrentHashMap<>();
    private final Set<String> platesInside = ConcurrentHashMap.newKeySet();

    ParkingLot(List<ParkingFloor> floors, PricingStrategy pricing, Clock clock) {
        this.floors = List.copyOf(floors);
        this.pricing = pricing;
        this.clock = clock;
    }

    Ticket park(Vehicle v) {
        if (!platesInside.add(v.plate())) {                  // atomic duplicate check
            throw new IllegalStateException("Vehicle already inside: " + v.plate());
        }
        for (ParkingFloor f : floors) {
            var spot = f.claimSpot(v);
            if (spot.isPresent()) {
                Ticket t = new Ticket(UUID.randomUUID().toString(), v,
                                      spot.get(), Instant.now(clock));
                active.put(t.id(), t);
                return t;
            }
        }
        platesInside.remove(v.plate());                      // undo on failure
        throw new IllegalStateException("Lot full for " + v.type());
    }

    long unpark(String ticketId) {
        Ticket t = active.remove(ticketId);                  // atomic: one exit per ticket
        if (t == null) throw new IllegalArgumentException("Unknown ticket " + ticketId);
        Duration d = Duration.between(t.entry(), Instant.now(clock));
        long fee = pricing.fee(t.vehicle().type(), d);
        t.spot().free();
        platesInside.remove(t.vehicle().plate());
        return fee;
    }
}
import java.time.Clock;
import java.util.List;

public class ParkingDemo {
    public static void main(String[] args) {
        var floor = new ParkingFloor(List.of(
                new ParkingSpot("F0-1", VehicleType.CAR),
                new ParkingSpot("F0-2", VehicleType.BIKE)));
        var lot = new ParkingLot(List.of(floor), new HourlyPricing(), Clock.systemUTC());

        Ticket t = lot.park(new Vehicle("KA01AB1234", VehicleType.CAR));
        System.out.println("Spot: " + t.spot().id());
        System.out.println("Fee: " + lot.unpark(t.id()));
        System.out.println("Free cars: " + floor.freeCount(VehicleType.CAR));
    }
}

Concurrency

  • Two gates can reach the same free spot. compareAndSet(null, v) lets only one succeed; the loser moves to the next spot.
  • active.remove(ticketId) is atomic, so a ticket cannot be used for two exits (no double refund or double free).
  • platesInside.add returns false for a duplicate, an atomic "is this car already in?" check.

Use atomics for one flag, locks for several fields

An AtomicReference is perfect when one value changes. If a spot also tracked "reserved until" and "owner", you would use a lock or an immutable state object swapped with CAS.

Edge cases

  • Lot full for one type but free for another: message names the type.
  • Lost or unknown ticket: IllegalArgumentException; a real system has a lost-ticket fee and manual lookup.
  • Same ticket scanned twice at exit: the second call finds nothing and fails cleanly.
  • Parked less than a minute: charged one hour (minimum rule is a pricing concern, so it is in the strategy).
  • Day boundary and long stays: use Duration, not clock hours.

Extensions interviewers ask

  • EV charging spots: add EV_CAR to the enum or a SpotFeature set on ParkingSpot; add a charging fee in a decorator over PricingStrategy.
  • Bigger vehicle in a bigger spot: replace the type equality in tryPark with a canFit method and try the smallest fitting spot first.
  • Spot allocation policy: a SpotAllocationStrategy interface (nearest to the lift, fill floor by floor).
  • Display board: an Observer on spot changes (Module 2).
  • Multiple entry and exit gates: already safe because state lives in the lot, not in gates.
  • Persistence: a TicketRepository interface; the DB gets a unique constraint on active (spot) so two tickets cannot share a spot.

How to present this in 45 minutes

  1. 5 min: ask about types, floors, pricing, concurrency; state assumptions.
  2. 8 min: draw the diagram; say "pricing is a Strategy, spots own their occupancy".
  3. 20 min: code ParkingSpot, PricingStrategy, ParkingLot.park/unpark.
  4. 7 min: explain the CAS claim, edge cases, then the EV extension.

Design tic-tac-toe (and how Snake and Ladder differs)

Keep game state (board, players, current turn, status) in one Game class, validate every move, and detect a win in O(1) with row, column and diagonal counters instead of scanning the board.

Requirements and assumptions

  • Two players, X and O, alternate turns on an N×N board (default 3×3); X starts.
  • A move is rejected if it is out of range, on an occupied cell, by the wrong player, or after the game ended.
  • The game ends when a player fills a whole row, column or diagonal (win), or the board is full (draw).
  • Assumptions: console or API driven, no AI opponent, no undo for now, single-threaded game (one game object per match, moves arrive one at a time).

Entities

  • Mark (enum X, O) and GameStatus (enum IN_PROGRESS, WON, DRAW).
  • Player (name, mark).
  • Board: the grid and the win detection. It knows nothing about players' names or turns.
  • Game: owns the board and players, enforces turn order, exposes makeMove.

Key design decisions

  • Separate Board from Game (single responsibility, Module 1): the board validates geometry; the game validates turn order. Either can change alone.
  • O(1) win check. Give X the value +1 and O the value −1. Keep a running sum per row, per column and for both diagonals. After a move only the sums touched by that cell change; if any reaches N or −N, that player wins. Scanning the board is O(N) per move, which is also fine in an interview, but counters impress.
  • Return the status from makeMove, so the caller prints or reacts; the game has no console code inside (keeps it testable and reusable in a REST controller).
  • Patterns: none are needed, and saying so is a good sign. If asked for different board sizes or win rules, a WinRule Strategy fits; for undo, the Command pattern (Module 2).

Core code

enum Mark { X, O }

enum GameStatus { IN_PROGRESS, WON, DRAW }

record Player(String name, Mark mark) { }

class Board {
    private final int n;
    private final Mark[][] cells;
    private final int[] rowSum, colSum;
    private int diagSum, antiSum, filled;

    Board(int n) {
        this.n = n;
        this.cells = new Mark[n][n];
        this.rowSum = new int[n];
        this.colSum = new int[n];
    }

    /** Places a mark and returns true if this move completes a line. */
    boolean place(int r, int c, Mark m) {
        if (r < 0 || r >= n || c < 0 || c >= n) {
            throw new IllegalArgumentException("Cell out of range: " + r + "," + c);
        }
        if (cells[r][c] != null) {
            throw new IllegalStateException("Cell already taken: " + r + "," + c);
        }
        cells[r][c] = m;
        filled++;
        int v = (m == Mark.X) ? 1 : -1;
        rowSum[r] += v;
        colSum[c] += v;
        if (r == c) diagSum += v;
        if (r + c == n - 1) antiSum += v;
        return Math.abs(rowSum[r]) == n || Math.abs(colSum[c]) == n
            || Math.abs(diagSum) == n || Math.abs(antiSum) == n;
    }

    boolean isFull() { return filled == n * n; }
}
import java.util.List;

class Game {
    private final Board board;
    private final List<Player> players;
    private int turn = 0;
    private GameStatus status = GameStatus.IN_PROGRESS;
    private Player winner;

    Game(int size, Player first, Player second) {
        this.board = new Board(size);
        this.players = List.of(first, second);
    }

    GameStatus makeMove(Player p, int row, int col) {
        if (status != GameStatus.IN_PROGRESS) {
            throw new IllegalStateException("Game is over");
        }
        if (!players.get(turn).equals(p)) {
            throw new IllegalStateException("Not " + p.name() + "'s turn");
        }
        boolean won = board.place(row, col, p.mark());   // may throw; turn does not change
        if (won) {
            status = GameStatus.WON;
            winner = p;
        } else if (board.isFull()) {
            status = GameStatus.DRAW;
        } else {
            turn = 1 - turn;                              // switch only after a valid move
        }
        return status;
    }

    Player winner() { return winner; }
}

public class TicTacToeDemo {
    public static void main(String[] args) {
        Player a = new Player("Asha", Mark.X), b = new Player("Ravi", Mark.O);
        Game g = new Game(3, a, b);
        g.makeMove(a, 0, 0); g.makeMove(b, 1, 0);
        g.makeMove(a, 0, 1); g.makeMove(b, 1, 1);
        System.out.println(g.makeMove(a, 0, 2));
        System.out.println(g.winner().name());
    }
}

Edge cases

  • Invalid move (taken cell, out of range): exception thrown before the turn switches, so the same player retries.
  • Move after the game ended: rejected.
  • The winning move that also fills the board: win is checked first, so it is a win, not a draw.
  • Both diagonals on odd boards share the centre cell; the counters handle that naturally.

Concurrency

One game is a turn-based conversation, so moves are naturally serial. If two clients can call makeMove on the same game (a web service), make the method synchronized; the turn check then rejects the stale caller. Games are independent, so different games never contend.

Snake and Ladder: what changes

The same split works: Board (size, snakes and ladders as a Map<Integer, Integer> from start cell to end cell), Dice, Player (name, position) and Game (turn queue, status). A turn is: roll the dice, compute pos + roll; if it exceeds the last cell the player stays; otherwise follow a snake or ladder if one starts there. The first to land exactly on the last cell wins.

import java.util.HashMap;
import java.util.Map;
import java.util.Random;

class SnakeBoard {
    private final int last;
    private final Map<Integer, Integer> jumps = new HashMap<>();  // snakes and ladders

    SnakeBoard(int last) { this.last = last; }

    void addJump(int from, int to) {
        if (from == to || from < 1 || to < 1 || from >= last) {
            throw new IllegalArgumentException("Bad jump " + from + "->" + to);
        }
        jumps.put(from, to);
    }

    int move(int position, int roll) {
        int next = position + roll;
        if (next > last) return position;              // needs an exact roll
        return jumps.getOrDefault(next, next);          // follow snake or ladder once
    }
}

class Dice {
    private final Random random = new Random();
    int roll() { return random.nextInt(6) + 1; }
}

Make Dice an interface if you want deterministic tests (inject a fixed sequence). Validate that jumps do not form a loop (a ladder ending on a snake head that leads back to the ladder start).

Extensions interviewers ask

  • N players or bigger boards: the players list and the board size are already parameters. For N×N with a win length K < N (Gomoku style), counters no longer work; scan around the last move in four directions.
  • Undo: keep a stack of Move commands; undo reverses counters (subtract the same value) and steps the turn back.
  • Computer player: a MoveStrategy interface (random, minimax).
  • Replay and history: store moves in a list; replay is a fold over the list.

How to present this in 45 minutes

  1. 5 min: board size, players, win rule, undo yes or no.
  2. 5 min: draw Game, Board, Player, enums; say why Board and Game are separate.
  3. 20 min: code Board.place with the counters, then Game.makeMove.
  4. 10 min: show a run, discuss invalid moves, then undo with Command and the AI Strategy.
