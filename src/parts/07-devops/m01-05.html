Interview questions — Linux and the command line

Why do most servers run Linux, and what is the difference between the kernel and a distribution?

Linux is free, stable, light on resources, scriptable and remote-friendly, and the cloud tools (Docker, Kubernetes, Nginx, the JVM) were built for it. The kernel manages hardware, processes, memory and files. A distribution such as Ubuntu or Amazon Linux packages the kernel with a package manager, tools and defaults.

What does chmod 755 mean, and why is chmod 777 a bad idea?

Each digit adds r=4, w=2, x=1. So 755 is rwxr-xr-x: the owner can read, write and run; group and others can read and run. 777 gives every user and every compromised process write access, which is a security hole and usually hides a wrong owner. Fix the owner with chown or give the minimum bits instead.

Why must an SSH private key have permission 600?

The private key is equivalent to a password. If other users could read it, they could log in as you. The SSH client therefore refuses keys with open permissions and prints "UNPROTECTED PRIVATE KEY FILE". Use chmod 600 key.pem; also keep ~/.ssh at 700.

What is the difference between kill -15 and kill -9?

kill -15 sends SIGTERM: the process may catch it and shut down cleanly (a Spring Boot app runs its shutdown hooks and closes pools). kill -9 sends SIGKILL: the kernel removes the process at once and the app cannot clean up. Always try 15 first. A JVM stopped by SIGTERM exits with code 143, which is why a systemd unit adds SuccessExitStatus=143.

Your Spring Boot app fails with "Port 8080 was already in use". What do you do?

Find the process: sudo lsof -i :8080 or sudo ss -tulpn | grep :8080. Decide whether it is an old copy of your app. Stop it with kill PID (or systemctl stop if it is a service), then start again. If both must run, give the new one another port with --server.port=8081.

What does 2>&1 mean? What is the difference between > and >>?

File descriptor 2 is stderr and 1 is stdout. 2>&1 sends stderr to wherever stdout currently goes, so cmd > out.log 2>&1 puts both in one file (order matters). A single > replaces the file; >> appends to it.

How do you find the top 5 most frequent IP addresses in an access log? 
awk '{print $1}' access.log | sort | uniq -c | sort -rn | head -5

Extract the first field, sort so equal IPs are adjacent, count each group with uniq -c, sort by the count (numeric, reverse) and keep five. The same idiom works for URLs, status codes or exception names.

How do you keep a Spring Boot JAR running after you log out of SSH?

Create a systemd service: a unit file in /etc/systemd/system/ with User=, WorkingDirectory=, EnvironmentFile=, ExecStart=/usr/bin/java -jar ... and Restart=on-failure, then daemon-reload and enable --now. It starts at boot, restarts on crash and logs to the journal (journalctl -u name -f). nohup or & survive logout but not a crash or reboot.

What is the difference between apt update and apt upgrade?

apt update downloads the latest package lists from the repositories; it installs nothing. apt upgrade installs newer versions of the packages you already have. Run update before install, or you may get "Unable to locate package" or an old version.

How does SSH key-based authentication work?

You generate a key pair. The public key goes into the server's ~/.ssh/authorized_keys; the private key stays on your machine. At login the server sends a challenge, your client signs it with the private key, and the server verifies the signature with the public key. The private key is never transmitted. Harden the server with PasswordAuthentication no and PermitRootLogin no.

You get "Permission denied (publickey)" when connecting to EC2. What do you check?

The user name (ubuntu for Ubuntu, ec2-user for Amazon Linux), that you pass the right key with -i, that the key file has permission 600, and that the instance was launched with that key pair. A timeout (not "permission denied") points to the security group, network ACL or a wrong IP instead.

What does set -euo pipefail do in a bash script?

-e exits when a command fails; -u treats unset variables as errors; pipefail makes a pipeline fail if any stage fails. The script stops at the first problem instead of carrying on with a broken state, for example running rm -rf "$DIR/"* with an empty DIR.

What do the five fields in a crontab line mean? Write a job that runs a backup at 2 a.m. daily.

Minute, hour, day of month, month, day of week. A daily 02:00 backup:

0 2 * * * /opt/scripts/backup-db.sh >> /var/log/backup.log 2>&1

Use absolute paths, because cron runs with a minimal PATH, and redirect output so errors are not lost.

The disk shows 100% full and the app is failing. How do you find what is using the space?

Confirm with df -h. Then drill down: sudo du -sh /var/* | sort -h, go into the biggest folder and repeat. Logs are the usual cause: truncate or rotate them, delete old archives with find -mtime +N -delete. If df stays full after deleting, a running process still holds the deleted file; restart it.

Your app listens on 127.0.0.1:8080 but others cannot reach it. Why?

127.0.0.1 is the loopback address: only programs on the same machine can connect. To accept outside connections the app must listen on 0.0.0.0 (all interfaces), and the firewall or security group must allow the port. In a typical setup the app stays on localhost and Nginx on port 80/443 forwards to it. See Module 2.

Cheat sheet — Linux and the command line

  • pwd / ls -la / cd - where am I, list with details and hidden files, go back
  • mkdir -p, cp -r, mv, rm -r create nested folders, copy tree, move or rename, delete tree
  • rm -rf no recycle bin; list with ls first; quote and check variables
  • less / tail -f / tail -F scroll a file, follow a log, follow through log rotation
  • find . -name "*.log" -mtime -1 search by name, type, age or size
  • man cmd / cmd --help / which cmd read the manual, quick help, which binary runs
  • rwx = 4+2+1 755 programs, 644 files, 600 private keys and secrets, 700 private folders
  • chmod +x / chown user:group make a script runnable; change owner (needs sudo)
  • usermod -aG group user add to a group; always include -a
  • sudo one command as root; do not build projects with sudo
  • ps aux | grep x / pgrep -f x find a process and its PID
  • kill PID / kill -9 PID polite stop (SIGTERM, exit 143) / forced stop (SIGKILL, exit 137)
  • ss -tulpn / lsof -i :8080 who listens on which address and port
  • systemctl start|stop|restart|status|enable --now control a service; daemon-reload after unit edits
  • journalctl -u name -f / -n 100 / --since read and follow service logs
  • > >> 2> 2>&1 | overwrite, append, stderr, both streams, pipe
  • grep -inr -E -v -A/-B/-C search text: case, line numbers, recursive, regex, invert, context
  • sort | uniq -c | sort -rn | head count and rank any value
  • awk '{print $1}' / sed 's/a/b/g' pick columns / substitute text; sed -i.bak edits in place
  • apt update; apt install -y pkg refresh the list, then install; upgrade updates installed packages
  • export VAR=x; source ~/.bashrc set for children; reload shell config; services need EnvironmentFile
  • ssh-keygen -t ed25519; ssh-copy-id; ssh -i key.pem user@host create, install, use keys
  • scp file host:path / rsync -avz src/ host:dst/ copy files; rsync sends only changes
  • vim: i, Esc, :wq, :q!, /text, dd, u insert, normal mode, save+quit, quit without saving, search, delete line, undo
  • #!/usr/bin/env bash; set -euo pipefail shebang and fail-fast for every script
  • df -h / du -sh * / free -h / uptime disk, folder sizes, memory (read available), load
  • tar -czf out.tgz dir / tar -xzf out.tgz -C dest create and extract a gzip archive
  • curl -i / -v / -X POST -H -d test APIs; -f fails on HTTP errors; -s -o /dev/null -w "%{http_code}"
  • crontab -e minute hour day month weekday command; use absolute paths and redirect output

Practice — Linux and the command line

  1. Set up a Linux shell. Install WSL2 with wsl --install (or use an Ubuntu VM). Run cat /etc/os-release and uname -r, create ~/projects/linux-lab with mkdir -p, and open it from Windows Explorer. Done when you can show the distro, the kernel and your Windows files under /mnt/c.
  2. Files and globs. In linux-lab create logs/ with app-1.log ... app-5.log using brace expansion. Copy them to archive/, rename one, delete another, and list only app-[1-3].log. Done when each command output matches what you predicted before running it.
  3. Permissions drill. Create deploy.sh, confirm that ./deploy.sh gives "Permission denied", fix it with chmod, then set secrets.env to 600 and a folder to 750. Create a second user with sudo adduser and prove that user cannot read secrets.env. Done when you can explain each digit.
  4. Processes and ports. Start python3 -m http.server 8000 (or any app), find it with ps aux | grep, ss -tulpn and lsof -i :8000. Start a second copy to see "address already in use", then stop the first with kill and confirm port 8000 is free. Done when you never needed kill -9.
  5. Log analysis. Copy the eight-line access log from Log analysis into a file. Write one-line pipelines for: counts per status, requests per IP, the three slowest requests, the average time, and only the 5xx lines. Then add 20 more lines with a loop and re-run. Done when your answers match a manual count.
  6. Run a JAR as a service. Build any Spring Boot app (mvn package), install OpenJDK, create the billing style user, /opt folder, env file and unit file from the systemd article. Start it, curl its health endpoint, kill the process with kill -9 and watch systemd restart it, and read the journal. Done when the app survives a reboot (sudo reboot) and a logout.
  7. SSH to a server. Create an ed25519 key, launch a free-tier-eligible Ubuntu EC2 instance (or any small VPS), connect with the .pem key, add a ~/.ssh/config alias, copy a file with scp, then disable password login and root login and verify with a second terminal. Done when ssh myserver works and password login is refused.
  8. Write and schedule a script. Write backup.sh with set -euo pipefail, an argument check, tar -czf with a dated name and deletion of backups older than 7 days. Schedule it in cron every five minutes while testing, check the log, then change it to daily. Done when the log file shows successful runs.
  9. Break it, then fix it. On your test server fill a folder with a big file until df -h shows high use, then find it with du. Next stop the database and read your app's log to find the connection error. Finally make the app listen only on 127.0.0.1 and diagnose it with ss. Done when you can state the cause of each problem from the commands alone: "you can SSH into a server and find why your app crashed from its logs".
  10. OverTheWire Bandit, levels 0 to 14. Play the Bandit wargame at overthewire.org (connect with ssh bandit0@bandit.labs.overthewire.org -p 2220; the site gives the first password and the goal of each level). Clear the first 15 levels (Level 0 up to the login for Level 14 and the password for Level 15). Keep a text file of the commands you used. The levels train ls, cat, find, grep, sort | uniq, base64, tar, ssh -i and permissions. Done when you finish without spoilers, and use the terminal daily afterwards.
