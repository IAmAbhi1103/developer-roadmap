Almost every Java application you write will end up running on a Linux server: an AWS EC2 machine, a Docker container, a Kubernetes pod, or a build agent in CI. Your laptop may run Windows, but production does not. This module teaches you the Linux command line well enough to log in to a server, find your app, read its logs, fix a crash, deploy a new JAR and keep it running after you log out.

Everything later on this page builds on it. Docker (Module 3) is Linux underneath. GitHub Actions (Module 4) runs your steps in Linux shells. Cloud deployment (Module 5) starts with an SSH login. The networking ideas in Module 2 use the same tools you meet here (ss, curl). Operating-system theory (processes, files, memory) is explained in CS Fundamentals · Module 1; here we stay practical.

Plan for daily practice: open a Linux terminal every day, even for a ten-minute task. Typing the commands is the only way they stick.

After this module you will be able to:

  • Set up Ubuntu (or WSL2 on Windows) and move around the filesystem confidently.
  • Read and change file permissions, and explain why an SSH key must be 600.
  • List processes and ports, stop a stuck program, and fix "address already in use".
  • Run a Spring Boot JAR as a systemd service and read its logs with journalctl.
  • Search and summarise logs with grep, awk, sort and uniq.
  • Install software with apt, set environment variables, and log in with SSH keys.
  • Write a safe bash script, schedule it with cron, and test an API with curl.

Why servers run Linux: kernel, distributions, shells and WSL2

Linux is a free operating-system kernel that powers most servers and containers; you use it through a shell (usually bash) inside a terminal, and on Windows 11 you get a real Ubuntu with wsl --install.

Why servers run Linux

When you rent a virtual machine from AWS, Azure or Google Cloud, the default choice is Linux. The reasons are practical, not fashion:

  • Cost. Linux is free. Windows Server needs a licence, which is added to your cloud bill.
  • Light and stable. A Linux server runs happily with 1 GB of RAM and stays up for months without a reboot.
  • Everything is text. Configuration is in plain files, and every task can be scripted. That is what makes automation (CI/CD, Docker, Terraform) possible.
  • Remote by default. You manage a server over SSH with no graphical desktop. A server has no screen, so there is nothing to click.
  • The ecosystem. Docker, Kubernetes, Nginx, PostgreSQL, Kafka and the JVM were built and tested on Linux first.

Kernel versus distribution

The kernel is the core of the operating system. It talks to the hardware, schedules processes, manages memory and files. "Linux" strictly means this kernel. A distribution (distro) packages the kernel with a package manager, system tools, default settings and a release schedule. Two distros run the same kernel family but differ in how you install software.

DistributionFamilyPackage toolWhere you meet it

These notes use Ubuntu. An LTS (long-term support) release gets security updates for years, so it is the safe choice for servers. The ideas (files, permissions, processes, SSH) are the same on every distro; only the install command changes.

Terminal, shell and bash

Terminal
The window where you type. It only shows text and sends your keystrokes.
Shell
The program inside the terminal that reads your command, runs it and prints the result. Common shells are bash (default on Ubuntu and most servers), zsh (default on macOS) and sh (minimal; used by many scripts and Alpine).
Prompt
The text before your cursor, for example ubuntu@web-1:~$ = user ubuntu on host web-1, in the home folder ~. $ means a normal user; # means root.

Learn bash. Scripts, CI pipelines and Dockerfiles are all written for it.

Installing WSL2 on Windows 11

WSL2 (Windows Subsystem for Linux) runs a real Linux kernel in a lightweight virtual machine inside Windows. You get Ubuntu in a terminal, with no dual-boot. Open PowerShell as Administrator:

PS> wsl --install
PS> wsl --list --online
PS> wsl --install -d Ubuntu
PS> wsl -l -v
  NAME      STATE           VERSION
* Ubuntu    Running         2

wsl --install turns on the needed Windows features and installs Ubuntu by default; restart when asked. On first launch Ubuntu asks you to create a Linux username and password. That password is for sudo inside WSL, separate from your Windows password. Check that the VERSION column says 2.

Tip: keep your projects inside the Linux filesystem

Work in ~/projects, not in /mnt/c/.... Reading thousands of small files (a Maven build, node_modules) through /mnt/c is much slower, and file permissions behave oddly there. Access the files from Windows through the \\wsl$ path when you need to.

Mistake: copying Windows line endings into scripts

A script saved in Notepad with CRLF line endings fails on Linux with bad interpreter: /bin/bash^M or $'\r': command not found. Save shell scripts with LF endings (VS Code shows CRLF/LF in the status bar), or convert with dos2unix script.sh after sudo apt install dos2unix.

Edge cases

  • If wsl --install only prints help text, WSL is already present; use wsl --install -d Ubuntu to add a distro.
  • WSL needs virtualisation enabled in BIOS/UEFI. The error mentions "virtualization" when it is off.
  • Linux is case-sensitive: App.java and app.java are different files. This is the classic "works on my Windows laptop, fails on the server" bug.

Interview: "Why do most production servers run Linux?"

  • Free, stable, light, scriptable, remote-first; the tools of the cloud era were built on it.
  • Know the difference: the kernel is the core; a distribution adds packages and defaults.
  • Mention that you practise on Ubuntu or WSL2 and can work without a GUI.

The filesystem: hierarchy, paths and ls -la

Linux has one tree starting at /; know where config (/etc), logs (/var/log) and your files (/home) live, and read ls -la column by column.

One tree, no drive letters

Windows has C: and D:. Linux has a single tree that starts at the root directory, written /. Other disks are mounted into the tree at some folder. Every file on the machine has a place below /.

DirectoryWhat lives thereExample
/homeOne folder per user/home/ubuntu/projects
/etcSystem-wide configuration (text files)/etc/nginx/nginx.conf
/var/logLogs from the system and services/var/log/syslog, /var/log/nginx/
/optSelf-contained third-party apps/opt/billing/billing.jar
/usr/binCommands installed by packages/usr/bin/java (often a link)
/tmpScratch space for anyoneUpload staging, temporary dumps
/dev/nullA special file that discards everything written to itcmd > /dev/null

Absolute and relative paths

An absolute path starts with / and means the same thing from anywhere: /etc/nginx/nginx.conf. A relative path does not start with / and is read from your current directory. Three shortcuts help:

  • ~ is your home directory (/home/ubuntu). ~/logs is always the same place.
  • . is the current directory. ./run.sh runs the script in this folder.
  • .. is the parent directory. cd .. goes up one level.
$ pwd
/home/ubuntu
$ cd /var/log
$ pwd
/var/log
$ cd ../lib
$ pwd
/var/lib
$ cd ~
$ pwd
/home/ubuntu
$ cd -
/var/lib

cd - jumps back to the previous directory. cd alone goes home.

Hidden files

A file whose name starts with a dot is hidden: .bashrc, .ssh, .gitignore. Plain ls skips them; ls -a shows them. Configuration for your user lives in such "dotfiles".

Reading ls -la column by column

$ ls -la
total 24
drwxr-xr-x  4 ubuntu ubuntu 4096 Nov 11 10:02 .
drwxr-x--- 12 ubuntu ubuntu 4096 Nov 11 09:58 ..
-rw-------  1 ubuntu ubuntu  412 Nov 10 18:30 .bash_history
-rwxr-xr-x  1 ubuntu ubuntu  120 Nov 11 10:02 deploy.sh
drwxr-xr-x  2 ubuntu ubuntu 4096 Nov 11 10:00 logs
-rw-r--r--  1 ubuntu ubuntu   42 Nov 11 10:01 notes.txt

Take the line -rwxr-xr-x 1 ubuntu ubuntu 120 Nov 11 10:02 deploy.sh:

  1. Type and permissions (-rwxr-xr-x). The first character is the type: - regular file, d directory, l symbolic link. The next nine characters are three groups of rwx for owner, group and others (see Permissions).
  2. Link count (1). Number of hard links. For a directory it is roughly 2 plus the number of sub-directories. You rarely need it.
  3. Owner (ubuntu). The user who owns the file.
  4. Group (ubuntu). The group that owns the file.
  5. Size (120) in bytes. Add -h (ls -lah) for 4.0K, 2.1M.
  6. Modified time (Nov 11 10:02). For files older than about six months it shows the year instead of the time.
  7. Name (deploy.sh). A link shows name -> target.

The first two lines, . and .., are the directory itself and its parent. total 24 is the disk blocks used by the listed files, not a file count.

Globbing: wildcards the shell expands

Before a command runs, the shell expands patterns called globs into file names. The command never sees the star; it sees the list.

PatternMatchesExample
*Any characters (including none)ls *.log
?Exactly one characterls app-?.log → app-1.log
[abc], [0-9]One character from the set or rangels app-[1-3].log
{a,b}Brace expansion (not a glob, but handy)mkdir -p logs/{2025,2026}
 
$ ls
app-1.log  app-2.log  app-10.log  notes.txt
$ ls app-?.log
app-1.log  app-2.log
$ ls app-*.log
app-10.log  app-1.log  app-2.log
$ echo *.txt
notes.txt

The star does not match hidden files, and it does not cross /.

Rule: quote names that contain spaces

The shell splits on spaces. cd My Projects passes two arguments. Write cd "My Projects", or better, never use spaces in file names on servers — use my-projects or my_projects.

Edge cases

  • If no file matches a glob, bash passes the pattern as plain text: ls *.xyz prints ls: cannot access '*.xyz': No such file or directory.
  • /home/ubuntu is not /home/ubuntu/ to a human, but to the system both are the same directory. A trailing slash matters only for a few tools such as rsync.
  • Symbolic links: /usr/bin/java is usually a link to a JDK folder. ls -l shows -> and the target.

Interview: "Where would you look for logs and config on a Linux server?"

  • Logs in /var/log (and journalctl for systemd services); config in /etc; apps you install by hand in /opt.
  • Explain absolute versus relative paths and the meaning of ~, ., ...

mkdir -p creates all missing parent folders and does not complain if the folder exists. cp -r (recursive) is required for folders. mv is both "move" and "rename": moving to the same folder with a new name is a rename.

The danger of rm -rf

rm deletes immediately and permanently. There is no trash. -r means recursive (go into directories); -f means force (no questions, ignore missing files). Together, rm -rf will wipe a whole tree without asking. Real incidents come from an empty variable: rm -rf "$APP_DIR"/* becomes rm -rf /* when APP_DIR is unset.

Rule: look before you delete

  • Run ls with the same pattern first, then edit the command into rm.
  • Use rm -ri (interactive) when unsure; it asks for each file.
  • Never run rm -rf with a variable you have not checked. In scripts use set -u (see Bash scripting).
  • Never type sudo rm -rf / or rm -rf /*. Ever.

Tip: speed up the terminal

  • Tab completes file and command names; press it twice to list options.
  • ↑ recalls earlier commands; Ctrl+R searches your history.
  • Ctrl+C stops a running command; Ctrl+L clears the screen; Ctrl+A / Ctrl+E jump to the start / end of the line.
  • !! repeats the last command: sudo !! retries it as root.

Mistake: cp and mv silently overwrite

cp a.txt b.txt replaces b.txt without a warning. Use cp -i or mv -i to be asked first, and cp -n to never overwrite. Also remember: mv file dir moves into the folder if dir exists, but renames file to dir if it does not.

Errors you will see

  • No such file or directory — a wrong path, a typo, or a case difference.
  • Permission denied — you lack the right on the file or folder (next article).
  • cp: -r not specified; omitting directory 'x' — add -r.
  • rm: cannot remove 'x': Is a directory — add -r (or use rmdir for an empty folder).
  • Argument list too long — a glob expanded to too many files; use find ... -delete or xargs.

Interview: "How do you find large files or recent changes on a server?"

  • find / -type f -size +500M 2>/dev/null for big files; du -sh * to see which folder is big; find -mtime -1 for what changed today.
  • Mention that 2>/dev/null hides "permission denied" noise.

Users, groups, permissions, chmod, chown and sudo

Every file has an owner, a group and three permission sets (read, write, execute for user, group, others); chmod changes the bits, chown changes the owner, and sudo runs one command as root.

Why permissions exist

Linux is multi-user. Your web server, your database and you should not be able to read each other's secrets or delete each other's files. Every file therefore records who owns it and who may do what. If a compromised app runs as a low-privilege user, the attacker cannot touch the rest of the system. This is the base of server security.

Reading rwx

From the ls -l output: -rwxr-xr-- has a type character and three groups of three.

BitOn a fileOn a directory
r read (4)View the contentsList the names inside (ls)
w write (2)Change the contentsCreate, rename and delete files inside
x execute (1)Run it as a program or scriptEnter it (cd) and access files by name

The system checks in order: if you are the owner, the owner bits apply; else if you are in the group, the group bits apply; else the "others" bits apply. Root ignores these checks.

Octal notation

Add the values r=4, w=2, x=1 for each group. rwx = 7, r-x = 5, rw- = 6, r-- = 4, --- = 0. Three digits give owner, group, others.

OctalSymbolicTypical use
755rwxr-xr-xPrograms, scripts, directories everyone may enter
644rw-r--r--Normal files, config others may read
600rw-------Private files: SSH private keys, .env secrets
700rwx------Private directories, e.g. ~/.ssh
777rwxrwxrwxEveryone can do everything. Almost never correct

chmod: change the mode

Two styles. Octal sets all nine bits at once. Symbolic changes some bits: who (u user/owner, g group, o others, a all), an operator (+, -, =), and the bits.

$ ls -l deploy.sh
-rw-r--r-- 1 ubuntu ubuntu 120 Nov 11 10:02 deploy.sh
$ ./deploy.sh
bash: ./deploy.sh: Permission denied
$ chmod +x deploy.sh
$ ls -l deploy.sh
-rwxr-xr-x 1 ubuntu ubuntu 120 Nov 11 10:02 deploy.sh
$ chmod 600 secrets.env
$ chmod u+x,g-w,o-rwx deploy.sh
$ chmod -R 755 public/
$ ls -l secrets.env deploy.sh
-rw------- 1 ubuntu ubuntu  64 Nov 11 10:03 secrets.env
-rwxr-x--- 1 ubuntu ubuntu 120 Nov 11 10:02 deploy.sh

-R applies the change to a whole tree. Be careful: giving 755 recursively to a tree also makes every data file executable. Use find -type d -exec chmod 755 and find -type f -exec chmod 644 to treat folders and files separately.

chown: change the owner

$ sudo chown billing:billing /opt/billing/billing.jar
$ sudo chown -R billing:billing /opt/billing
$ sudo chown ubuntu app.log
$ ls -l /opt/billing/billing.jar
-rw-r--r-- 1 billing billing 58123456 Nov 11 10:10 /opt/billing/billing.jar

The format is user:group. Only root can give a file to another user, so you need sudo. Common reason: you copied a JAR as ubuntu but the service runs as billing and cannot write its own log folder.

Users, groups and sudo

$ whoami
ubuntu
$ id
uid=1000(ubuntu) gid=1000(ubuntu) groups=1000(ubuntu),27(sudo),999(docker)
$ sudo adduser deploy
$ sudo usermod -aG sudo deploy
$ sudo usermod -aG docker deploy
$ groups deploy
deploy : deploy sudo docker
  • root is the all-powerful user (UID 0). It can read, change and delete anything. You should almost never log in as root.
  • sudo ("superuser do") runs one command as root after asking for your own password (on EC2 Ubuntu the default user has passwordless sudo). Members of the sudo group on Ubuntu may use it. sudo -i opens a root shell; avoid leaving it open.
  • adduser creates a user with a home folder (the friendly Debian/Ubuntu command). usermod -aG GROUP USER adds the user to a group. Always include -a: without it, you replace all the user's groups.
  • Adding a user to docker lets them run Docker without sudo, but it is effectively root-level power. The user must log out and in for new groups to apply.
  • Service accounts: create a system user with no login for each app, for example sudo adduser --system --group billing (checked on Ubuntu/Debian).

Why SSH keys must be 600

An SSH private key is a password in a file. If other users could read it, they could log in as you. So the SSH client refuses to use a key that is readable by others:

$ ssh -i mykey.pem ubuntu@203.0.113.10
@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@
@         WARNING: UNPROTECTED PRIVATE KEY FILE!          @
@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@
Permissions 0644 for 'mykey.pem' are too open.
$ chmod 600 mykey.pem
$ ssh -i mykey.pem ubuntu@203.0.113.10

On the server, ~/.ssh should be 700 and authorized_keys 600, or the SSH server may ignore it.

Mistake: fixing "Permission denied" with chmod 777

chmod 777 makes every user and every compromised process able to modify the file. It hides the real problem (wrong owner, or missing x). Find out who needs access, then use chown or the minimum bits, such as chmod 750.

Mistake: sudo for everything

sudo mvn package or sudo npm install creates root-owned files in your project, and later builds fail with permission errors. Run builds as yourself. Use sudo only for things that really need root: apt, systemctl, editing /etc.

Edge cases

  • To delete a file you need w on the directory, not on the file.
  • A directory without x cannot be entered even if you can read its name.
  • A shell script needs x to run as ./script.sh, but bash script.sh needs only r.
  • sudo echo "x" > /etc/file fails: the redirection is done by your shell, not by sudo. Use echo "x" | sudo tee /etc/file (add -a to append).
  • Special bits (setuid, sticky bit on /tmp) exist; you can ignore them for now.
  • On WSL, files under /mnt/c may show 777-like permissions regardless of chmod.

Interview: "What does chmod 755 mean? Why is chmod 777 bad?"

  • 7 = rwx for the owner; 5 = r-x for group and others. Owner full control, others read and run.
  • 777 lets any user or process change or replace the file — a security hole and usually a sign of a wrong owner.
  • Add: SSH private keys need 600; use least privilege, run services as a non-root user.
