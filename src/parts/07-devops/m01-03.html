Log analysis with awk, sed, sort, uniq and xargs

Combine grep, awk, sort and uniq -c to count errors, rank URLs and find the slowest requests in seconds; use sed for quick edits and xargs to run a command per line.

When production misbehaves, nobody opens a 500 MB log in an editor. You ask questions with a pipeline: how many errors? which URL fails most? which client is noisy? how slow is the slowest request? This article shows the patterns on two realistic logs.

awk in five minutes

awk reads text line by line, splits each line into fields (by whitespace, by default) and runs your code. $1 is the first field, $NF the last, $0 the whole line, NR the line number. The shape is awk 'CONDITION { ACTION }' file; BEGIN and END blocks run before the first and after the last line.

$ echo "alice 30 mumbai" | awk '{print $1, $3}'
alice mumbai
$ echo "a,b,c" | awk -F, '{print $2}'
b
$ awk 'NR <= 2' names.txt
$ awk '$2 > 100 {print $1}' data.txt
$ awk '{s += $2} END {print s}' data.txt

-F, sets the field separator. Conditions such as $7 ~ /^5/ use a regular expression match; ==, >, && work as in Java.

Example 1: an Nginx access log with request time

Suppose you added a log format that ends with the request time in seconds ($request_time), so each line looks like this:

203.0.113.7 [11/Nov/2026:10:15:30 +0530] "GET /api/orders HTTP/1.1" 200 512 0.043
203.0.113.7 [11/Nov/2026:10:15:31 +0530] "GET /api/orders/42 HTTP/1.1" 200 230 0.021
198.51.100.4 [11/Nov/2026:10:15:33 +0530] "POST /api/orders HTTP/1.1" 201 180 0.350
198.51.100.4 [11/Nov/2026:10:15:40 +0530] "GET /api/orders HTTP/1.1" 500 95 1.920
192.0.2.9 [11/Nov/2026:10:15:42 +0530] "GET /api/products HTTP/1.1" 200 2048 0.087
203.0.113.7 [11/Nov/2026:10:15:50 +0530] "GET /api/orders HTTP/1.1" 200 512 0.040
192.0.2.9 [11/Nov/2026:10:15:51 +0530] "GET /api/orders/99 HTTP/1.1" 404 60 0.012
198.51.100.4 [11/Nov/2026:10:15:58 +0530] "POST /api/orders HTTP/1.1" 500 95 2.410

Splitting on whitespace gives: $1 client IP, $2 $3 the time, $4 the method (with a leading quote), $5 the path, $6 the protocol, $7 the status, $8 bytes, $9 request time.

$ wc -l access.log
8 access.log
$ awk '{print $7}' access.log | sort | uniq -c | sort -rn
      4 200
      2 500
      1 404
      1 201
$ awk '$7 ~ /^5/ {print $1}' access.log | sort | uniq -c
      2 198.51.100.4
$ awk '{print $9, $5}' access.log | sort -rn | head -3
2.410 /api/orders
1.920 /api/orders
0.350 /api/orders
$ awk '{s += $9; n++} END {printf "average %.3f s over %d requests\n", s/n, n}' access.log
average 0.610 s over 8 requests
$ awk '{print $5}' access.log | sort | uniq -c | sort -rn | head -3
      4 /api/orders
      1 /api/products
      1 /api/orders/99

The first line of the status count is the pattern to memorise: ... | sort | uniq -c | sort -rn = "count each distinct value, biggest first". It works for IPs, URLs, status codes, user ids, exception names. The 500s all come from one client IP on /api/orders and are also the slowest requests: a good lead.

Example 2: a Spring Boot application log

Default Spring Boot log lines have the shape TIMESTAMP LEVEL PID --- [thread] logger : message. Questions you ask the app log:

$ grep -c " ERROR " app.log
18
$ grep " ERROR " app.log | awk '{print $1}' | cut -c1-16 | sort | uniq -c
      2 2026-11-11T09:5
     14 2026-11-11T10:0
      2 2026-11-11T10:1
$ grep -E "Exception|Error" app.log | sed -E 's/.*(java\.[a-zA-Z.]+Exception).*/\1/' \
    | sort | uniq -c | sort -rn | head -3
     11 java.net.SocketTimeoutException
      4 java.sql.SQLTransientConnectionException
      1 java.lang.NullPointerException
$ grep -A 15 "OrderService : Order 991 failed" app.log | head -20

The second command cuts the timestamp to ten-minute buckets (first 16 characters) to see when errors spike. The third pulls the exception class name out of each line and ranks them. The numbers shown are sample output. A trailing backslash continues the command on the next line.

sed: edit streams

sed is a stream editor. Its most common use is substitution: s/old/new/ (first match per line) and s/old/new/g (all matches).

$ echo "port=8080" | sed 's/8080/9090/'
port=9090
$ sed -n '100,120p' app.log
$ sed '/^#/d' application.properties
$ sed -i.bak 's/localhost/db.internal/' application.properties
$ sed -n '/10:09:4/,/10:09:5/p' app.log
  • sed -n '100,120p' prints only lines 100-120 (a quick way to view a part of a big file).
  • sed '/^#/d' deletes comment lines.
  • sed -i edits the file in place; -i.bak keeps a backup copy first. Test without -i before you change a file.
  • The last example prints a time window between two patterns.

xargs: turn lines into arguments

Some commands take arguments, not stdin. xargs reads lines from a pipe and puts them on the command line.

$ find . -name "*.tmp" | xargs rm
$ find . -name "*.log" -print0 | xargs -0 grep -l "OutOfMemory"
$ grep -rl "TODO" src/ | xargs wc -l
$ echo "a b c" | xargs -n 1 echo item
item a
item b
item c

If file names can contain spaces, use -print0 with xargs -0 (null separators). find ... -exec cmd {} + does a similar job without xargs.

Putting it together: a 30-second triage

  1. Is it up? systemctl status billing and ss -tulpn | grep 8080.
  2. When did it fail? journalctl -u billing --since "1 hour ago" | grep -n ERROR | head.
  3. What is the top error? The sed + uniq -c pipeline above.
  4. Context: grep -B 3 -A 15 "first error text" app.log.
  5. Who and what is affected? Group the access log by IP, URL and status.

Tip: build pipelines one stage at a time

Run the first command alone, check the output, add | next, check again. When a pipeline gives a strange answer, you can see exactly which stage broke it. Save the good ones as shell aliases or small scripts.

Mistake: wrong column numbers

Log formats put spaces inside quotes ("GET /api HTTP/1.1") or in the date, so $7 in one log is $9 in another. Print the fields first with head -1 access.log | awk '{for (i=1; i<=NF; i++) print i, $i}' and use what you see.

Edge cases

  • Sorting numbers needs sort -n; plain sort is alphabetical, so 10 comes before 9.
  • A locale can change sort order; use LC_ALL=C sort for strict byte order and a faster sort on huge files.
  • sed -i differs on macOS (needs -i ''). On Linux and WSL the examples here work as written.
  • Multi-line stack traces break "one line = one event" analysis. Count only the first line of each event (the one with a timestamp), or use grep -A for context.

Interview: "How would you find the top 5 IPs hitting your server?"

  • awk '{print $1}' access.log | sort | uniq -c | sort -rn | head -5
  • Explain each stage: extract the field, group equal values, count, order, limit.
  • Similar for slow requests: sort on the time column with sort -k9 -nr.

Installing software with apt, Java setup and environment variables

apt update refreshes the package list, apt install installs from it; environment variables such as JAVA_HOME and PATH configure programs and are set in ~/.bashrc, systemd env files or .env files.

Package managers

On Ubuntu you do not download installers from websites. A package manager installs signed software from trusted repositories, resolves dependencies, and updates everything with one command. On Ubuntu and Debian it is apt.

CommandWhat it does
sudo apt updateDownload the latest list of available packages and versions. Installs nothing.
sudo apt upgradeInstall newer versions of packages you already have.
sudo apt install nginxInstall a package and its dependencies.
sudo apt remove nginxRemove the program, keep its config files.
sudo apt purge nginxRemove the program and its config.
sudo apt autoremoveRemove dependencies nobody needs now.
apt search keywordSearch package names and descriptions.
apt show nginxDetails of a package; apt list --installed lists what you have.

The classic mistake: apt update and apt upgrade are different. update only refreshes the catalogue; upgrade changes software. Run update before install on a fresh machine, or you may get Unable to locate package or an old version.

$ sudo apt update
Hit:1 http://archive.ubuntu.com/ubuntu noble InRelease
Reading package lists... Done
$ sudo apt install -y nginx htop curl unzip
$ nginx -v
nginx version: nginx/1.24.0 (Ubuntu)
$ apt search openjdk-21 | head -3

-y answers "yes" automatically; use it in scripts. Red Hat family systems use dnf install/yum install instead; Alpine uses apk add.

Installing Java

$ sudo apt update
$ apt search openjdk | grep -E "^openjdk-[0-9]+-jdk/"
$ sudo apt install -y openjdk-21-jdk
$ java -version
openjdk version "21.0.5" 2024-10-15
OpenJDK Runtime Environment (build 21.0.5+11-Ubuntu-1ubuntu1)
OpenJDK 64-Bit Server VM (build 21.0.5+11-Ubuntu-1ubuntu1, mixed mode, sharing)
$ javac -version
javac 21.0.5
$ readlink -f $(which java)
/usr/lib/jvm/java-21-openjdk-amd64/bin/java

Package names include the Java version (openjdk-17-jdk, openjdk-21-jdk); use apt search to see what your Ubuntu release offers. The version numbers above are sample output. On a server that only runs an app, a JRE (-jre-headless) is enough; on a build machine you need the JDK. Temurin (Eclipse Adoptium) is another common distribution; it provides its own apt repository (see adoptium.net for the current instructions). If several Java versions are installed, choose the default with sudo update-alternatives --config java.

Environment variables

An environment variable is a named value that every program started from a shell inherits. Apps read them for configuration: database URLs, passwords, profiles, ports. This is how the "twelve-factor" approach keeps config out of code. Spring Boot maps them automatically: the variable SPRING_DATASOURCE_URL sets spring.datasource.url, and SERVER_PORT sets server.port.

$ NAME=asha
$ echo $NAME
asha
$ bash -c 'echo "child sees: $NAME"'
child sees:
$ export NAME=asha
$ bash -c 'echo "child sees: $NAME"'
child sees: asha
$ printenv HOME
/home/ubuntu
$ env | grep JAVA
JAVA_HOME=/usr/lib/jvm/java-21-openjdk-amd64
$ unset NAME
$ SPRING_PROFILES_ACTIVE=prod java -jar app.jar

A plain assignment (NAME=asha) is local to the current shell. export marks it for child processes, such as java. A variable placed before a command (VAR=x cmd) lives only for that command.

PATH and JAVA_HOME

PATH is a colon-separated list of directories. When you type java, the shell searches them in order for an executable with that name. JAVA_HOME is a convention: it points to the JDK folder, and tools such as Maven and Gradle read it.

# append these lines to ~/.bashrc
export JAVA_HOME=/usr/lib/jvm/java-21-openjdk-amd64
export PATH="$JAVA_HOME/bin:$PATH"
export PATH="$HOME/bin:$PATH"
$ source ~/.bashrc
$ echo $JAVA_HOME
/usr/lib/jvm/java-21-openjdk-amd64
$ echo $PATH
/usr/lib/jvm/java-21-openjdk-amd64/bin:/home/ubuntu/bin:/usr/local/sbin:/usr/local/bin:...

Put your folder first (NEW:$PATH) to override a system program; put it last to keep the system one as the default. Never write PATH="..." without including the old $PATH, or you will lose ls, cd and everything else.

.bashrc, .profile and .env files

FileRead whenUse for
~/.bashrcEach new interactive bash terminalAliases, prompt, PATH, JAVA_HOME for interactive use
~/.profileLogin shells (SSH login, console)Variables for your login session; Ubuntu's default .profile also loads .bashrc
/etc/environmentSystem-wide, at loginSimple KEY=value lines for all users
EnvironmentFile= in a unitWhen a service startsVariables for a systemd service (not read from .bashrc!)

A .env file is a plain text file of KEY=value lines, common in projects and Docker. To load it into your shell, source it with auto-export on:

$ cat .env
DB_HOST=localhost
DB_PASSWORD=s3cret
$ set -a
$ source .env
$ set +a
$ echo $DB_HOST
localhost

set -a exports every variable defined while it is on. Treat .env as a secret: chmod 600 .env and add it to .gitignore.

Mistake: expecting a systemd service to see your .bashrc

A service starts without your shell, so JAVA_HOME from .bashrc is not set. Give it variables with Environment= or EnvironmentFile= (systemd article) and use full paths. Same for cron jobs, which run with a tiny PATH.

Mistake: spaces around = and unquoted values

NAME = asha fails (NAME: command not found). Write NAME=asha. Quote values with spaces: GREETING="hello world".

Rule: no secrets in code, Git, or command lines

Passwords passed as command arguments show up in ps aux and shell history. Put them in a file with 600 or 640 permissions, or in a secret manager (Module 5).

Edge cases

  • E: Could not get lock /var/lib/dpkg/lock-frontend — another apt process is running (often automatic updates on a fresh EC2). Wait a minute and retry; do not delete the lock file.
  • E: Unable to locate package x — run apt update, check the spelling and the Ubuntu release.
  • The repository version of a tool can be old. For the latest versions, use the vendor's own repository or a container image, and check the vendor documentation.
  • Environment changes in .bashrc need a new terminal or source ~/.bashrc.

Interview: "What is the difference between apt update and apt upgrade?"

  • update refreshes the package index; upgrade installs newer versions of installed packages.
  • Environment variables: how you pass config to a Spring Boot app, what export does, and why a service does not read .bashrc.

SSH: keys, config, EC2, scp, rsync and hardening

SSH gives you an encrypted shell on a remote machine; use a key pair instead of a password, save hosts in ~/.ssh/config, copy files with scp or rsync, and turn off password and root login on servers.

What SSH is

SSH (Secure Shell) lets you run commands on a remote machine as if you sat in front of it, over an encrypted connection, on TCP port 22. It also carries file copies (scp, rsync) and port forwards. Every Linux server you manage — EC2, a VPS, a Raspberry Pi — is reached this way.

$ ssh ubuntu@203.0.113.10
The authenticity of host '203.0.113.10 (203.0.113.10)' can't be established.
ED25519 key fingerprint is SHA256:abc...xyz.
Are you sure you want to continue connecting (yes/no/[fingerprint])? yes
Warning: Permanently added '203.0.113.10' (ED25519) to the list of known hosts.
ubuntu@203.0.113.10's password:
$ ssh -p 2222 ubuntu@server.example.com
$ ssh ubuntu@203.0.113.10 "uptime"
 10:40:01 up 3 days,  2:11,  1 user,  load average: 0.05, 0.03, 0.01
$ exit

The first connection asks you to trust the server's host key; the client saves it in ~/.ssh/known_hosts and warns loudly if it ever changes (which can mean a rebuilt server or a man-in-the-middle attack). Adding a command after the host runs it and returns.

How key-based authentication works

Passwords can be guessed by bots; a key cannot. You make a key pair: a private key that never leaves your machine, and a public key you copy to the server's ~/.ssh/authorized_keys.

The server only checks the signature with the public key. Even a stolen public key is useless without the private one. Protect the private key (chmod 600), and consider a passphrase that encrypts it on disk.

Create and install a key

$ ssh-keygen -t ed25519 -C "asha@laptop"
Generating public/private ed25519 key pair.
Enter file in which to save the key (/home/asha/.ssh/id_ed25519):
Enter passphrase (empty for no passphrase):
Your identification has been saved in /home/asha/.ssh/id_ed25519
Your public key has been saved in /home/asha/.ssh/id_ed25519.pub
$ ls ~/.ssh
id_ed25519  id_ed25519.pub  known_hosts
$ ssh-copy-id ubuntu@203.0.113.10
$ ssh ubuntu@203.0.113.10
Welcome to Ubuntu 24.04 LTS

ed25519 is the modern, short and fast key type; id_ed25519 is private, .pub is public (safe to share, for example in GitHub settings). ssh-copy-id appends your public key to the server's authorized_keys using your password once.

Connect to AWS EC2 with a .pem key

When you launch an EC2 instance, AWS lets you create a key pair and downloads the private key as a .pem file (you can download it only once). AWS puts the public half on the instance for the default user. The default user depends on the image: ubuntu for Ubuntu, ec2-user for Amazon Linux.

  1. Move the file somewhere safe: mv ~/Downloads/billing-key.pem ~/.ssh/
  2. Restrict it: chmod 600 ~/.ssh/billing-key.pem
  3. Find the instance's public IP or DNS name in the EC2 console.
  4. Make sure the security group allows inbound TCP 22 from your IP (Firewalls).
  5. Connect: ssh -i ~/.ssh/billing-key.pem ubuntu@203.0.113.10
$ ssh -i ~/.ssh/billing-key.pem ubuntu@ec2-203-0-113-10.ap-south-1.compute.amazonaws.com
ubuntu@ip-172-31-5-20:~$ hostname
ip-172-31-5-20
ubuntu@ip-172-31-5-20:~$ sudo apt update

Errors and meanings: Permission denied (publickey) = wrong user name or wrong key; Connection timed out = the security group, firewall or IP is wrong (the packets never arrive); Connection refused = the machine answered but nothing listens on that port.

~/.ssh/config: host aliases

Host billing
    HostName 203.0.113.10
    User ubuntu
    IdentityFile ~/.ssh/billing-key.pem
    Port 22

Host *
    ServerAliveInterval 60
$ ssh billing
$ scp app.jar billing:/tmp/
$ ssh billing "systemctl is-active billing"
active

The alias works for ssh, scp, rsync and Git over SSH. ServerAliveInterval sends a keep-alive so idle sessions are not dropped. Keep the file at 600.

Copying files: scp and rsync

$ scp target/billing-1.0.1.jar billing:/tmp/
billing-1.0.1.jar            100%   56MB   9.1MB/s   00:06
$ scp -i ~/.ssh/billing-key.pem notes.txt ubuntu@203.0.113.10:/home/ubuntu/
$ scp billing:/var/log/nginx/access.log .
$ scp -r config/ billing:/tmp/config
$ scp -P 2222 file.txt user@host:/tmp/

The form is scp SOURCE DESTINATION; a remote path is host:path. Note: scp uses uppercase -P for the port, ssh uses lowercase -p. rsync is better for repeated copies, because it sends only what changed:

$ rsync -avz --progress dist/ billing:/var/www/app/
$ rsync -avz --delete dist/ billing:/var/www/app/
$ rsync -avzn dist/ billing:/var/www/app/
$ rsync -avz -e "ssh -i ~/.ssh/billing-key.pem" ./backup/ ubuntu@203.0.113.10:/backup/

-a archive (keeps permissions and times), -v verbose, -z compress, --delete removes files on the target that no longer exist in the source, -n is a dry run (shows what would happen). A trailing slash on the source matters: dist/ copies the contents, dist copies the folder itself.

Port forwarding (brief)

An SSH tunnel forwards a local port to a port on the server, through the encrypted connection. It lets you reach a database that listens only on 127.0.0.1 of the server, without opening it to the internet.

$ ssh -L 5433:localhost:5432 billing
$ psql -h localhost -p 5433 -U billing billing

While the SSH session is open, localhost:5433 on your laptop connects to PostgreSQL on the server. Add -N to open the tunnel without a shell.

Hardening basics

Any server with a public IP is probed by bots within minutes. After you can log in with a key, tighten /etc/ssh/sshd_config:

PasswordAuthentication no
PermitRootLogin no
PubkeyAuthentication yes
$ sudo sshd -t
$ sudo systemctl reload ssh

On Ubuntu the service is called ssh; on Red Hat style systems it is sshd. Keep your current session open and test a second login in a new terminal before closing the first one, so a typo cannot lock you out. Also: allow port 22 only from your IP in the firewall; keep the system updated; use fail2ban if you want automatic blocking; never share a private key between people (add each person's public key instead).

Mistake: committing or sharing a private key

A .pem or id_ed25519 in Git, a chat or an email means anyone can log in. If it happens, remove the public key from authorized_keys / replace the EC2 key pair and create a new one. Only the .pub file is safe to share.

Edge cases

  • WARNING: REMOTE HOST IDENTIFICATION HAS CHANGED! — the server's host key differs from known_hosts. If you rebuilt the server, remove the old line with ssh-keygen -R 203.0.113.10. If you did not, stop and investigate.
  • A stopped and restarted EC2 instance usually gets a new public IP unless you attach an Elastic IP; update your config.
  • On WSL, a key stored under /mnt/c keeps wide permissions and SSH refuses it. Copy it into ~/.ssh in the Linux filesystem and run chmod 600.
  • Windows 10/11 also ships an OpenSSH client in PowerShell, with the same commands.

Interview: "How does SSH key authentication work, and how do you secure SSH?"

  • Public key on the server, private key on the client; the client proves it holds the private key by signing a challenge; the key itself is never sent.
  • Hardening: keys only, no root login, restrict port 22 to known IPs, updates, optionally fail2ban and a non-default setup behind a bastion host.
  • Say that private keys must be 600 and never committed.
