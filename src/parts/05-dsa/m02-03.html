Linked lists: nodes, dummy node, reversal

A linked list is a chain of nodes where each node stores a value and a reference to the next node; you cannot jump to index i, so every problem is about moving and rewiring pointers carefully.

An array keeps its elements side by side in memory, so a[i] is instant. A linked list keeps each element in its own small object called a node. The node holds the value and a reference (pointer) to the next node. The first node is the head. The last node points to null. You reach the 5th element only by starting at the head and following four next links, so access is O(n). In return, if you already hold a reference to a node, inserting or deleting after it is O(1) and nothing shifts. Interviews love linked lists because the code is short but one wrong pointer assignment breaks everything.

public class ListNode {
    int val;
    ListNode next;
    ListNode(int val) { this.val = val; }
    ListNode(int val, ListNode next) { this.val = val; this.next = next; }
}

Recognise it and use the standard moves

The problem gives you a ListNode head and asks you to reverse, merge, delete, reorder or detect something in O(1) extra space. Learn these moves; almost every problem is a mix of them.

// Traverse
for (ListNode cur = head; cur != null; cur = cur.next) {
    // use cur.val
}

// Insert node n after node p (order matters!)
n.next = p.next;     // 1. n takes over p's old successor
p.next = n;          // 2. p points to n

// Delete the node after p
p.next = p.next.next;

Rule: rewire in the right order, and save next before you cut it

Each assignment destroys one old link. If you write p.next = n first in the insert above, you lose the rest of the list. Before changing cur.next, store the old value in a local variable such as nxt.

The dummy node trick

When the head itself may be deleted or replaced, your code needs a special case ("if head is the target..."). A dummy node (also called a sentinel) removes that case. Create a fake node whose next is the real head, work with it, and return dummy.next. Now every real node, including the old head, has a previous node.

// Remove Linked List Elements (LeetCode 203): delete every node with value val
public ListNode removeElements(ListNode head, int val) {
    ListNode dummy = new ListNode(0, head);
    ListNode prev = dummy;
    while (prev.next != null) {
        if (prev.next.val == val) prev.next = prev.next.next;   // skip it
        else prev = prev.next;                                  // move on
    }
    return dummy.next;
}

Note that prev does not move after a deletion, because the new prev.next has not been checked yet. Complexity: O(n) time, O(1) space.

Reverse a linked list (iterative)

Reverse Linked List (LeetCode 206) is the most important list operation; Merge, Palindrome, Reorder and k-group all use it. Walk once and flip each link to point backwards. You need three references: prev (the already reversed part), cur (the node being flipped) and the saved nxt.

public ListNode reverseList(ListNode head) {
    ListNode prev = null, cur = head;
    while (cur != null) {
        ListNode nxt = cur.next;   // 1. save the rest
        cur.next = prev;           // 2. flip the link
        prev = cur;                // 3. grow the reversed part
        cur = nxt;                 // 4. move on
    }
    return prev;                   // prev is the new head
}

Complexity: O(n) time, O(1) space.

Reverse a linked list (recursive)

Trust the recursion: assume reverseList(head.next) already reversed everything after the head. Then head.next is now the tail of that reversed part. Make that tail point back to head, and cut head loose.

public ListNode reverseList(ListNode head) {
    if (head == null || head.next == null) return head;   // base case
    ListNode newHead = reverseList(head.next);            // reverse the rest
    head.next.next = head;     // the old next node now points back to head
    head.next = null;          // head becomes the tail
    return newHead;
}

Complexity: O(n) time but O(n) space for the recursion stack. For a list of 100,000 nodes this can throw StackOverflowError, so prefer the iterative version unless asked.

Reverse a part: Reverse Linked List II (LeetCode 92)

Reverse only the nodes from position left to right (1-based). Use a dummy, walk to the node before position left, then repeatedly take the node after the segment's first node and move it to the front of the segment.

public ListNode reverseBetween(ListNode head, int left, int right) {
    ListNode dummy = new ListNode(0, head);
    ListNode before = dummy;
    for (int i = 1; i < left; i++) before = before.next;
    ListNode first = before.next;            // stays in place, ends as the tail
    for (int i = 0; i < right - left; i++) {
        ListNode move = first.next;          // node to move to the front
        first.next = move.next;
        move.next = before.next;
        before.next = move;
    }
    return dummy.next;
}

For 1→2→3→4→5, left=2, right=4, the result is 1→4→3→2→5. Complexity: O(n) time, O(1) space.

Merge Two Sorted Lists (LeetCode 21)

Like the merge step of merge sort (see Module 1): keep a tail of the answer, attach the smaller head each time, then attach whatever remains. A dummy node avoids the "which is the first node" special case.

public ListNode mergeTwoLists(ListNode a, ListNode b) {
    ListNode dummy = new ListNode(0), tail = dummy;
    while (a != null && b != null) {
        if (a.val <= b.val) { tail.next = a; a = a.next; }
        else                { tail.next = b; b = b.next; }
        tail = tail.next;
    }
    tail.next = (a != null) ? a : b;     // attach the leftover list in one step
    return dummy.next;
}

Complexity: O(m + n) time, O(1) space (the nodes are reused, not copied). Using <= keeps the merge stable.

Common mistakes with list pointers

  • Dereferencing null: cur.next.next when cur.next may be null. Check the loop condition first, for example while (cur != null && cur.next != null).
  • Creating a cycle by forgetting head.next = null after reversing or splitting.
  • Losing the head: returning head after the head changed. Return dummy.next or prev.
  • Comparing nodes with .val when you meant identity (== on the node), or the other way round.

Doubly linked lists and the LRU cache idea

In a doubly linked list each node also has a prev reference, so you can delete a node in O(1) when you hold the node itself, without finding its predecessor. Java's LinkedList is doubly linked. The famous use is the LRU cache (LeetCode 146): a HashMap from key to node gives O(1) lookup, and a doubly linked list keeps nodes ordered by recent use. On every get or put you unlink the node and move it to the front; when the cache is full you drop the node at the back. Both operations are O(1). Dummy head and tail nodes remove all null checks. The system design side is in System Design · Module 3.

Interview angle

Expect "reverse a linked list" iteratively and recursively, with the space cost of each. Draw the three pointers before coding. Mention the dummy node when the head can change. Interviewers watch for null checks and for saving next before overwriting it.

Linked lists: fast and slow pointers and classic problems

Two pointers moving at different speeds find the middle, detect and locate cycles, and split a list, all in O(n) time and O(1) space; combine them with reversal and merge for palindrome, reorder and add-two-numbers problems.

The fast and slow pointer technique (the tortoise and hare, or Floyd's algorithm) moves slow one node per step and fast two nodes per step. It is the same two-pointer idea from Two pointers, but on a structure where you cannot index. Use it when the problem mentions the middle, a cycle, "k-th from the end" or splitting in halves.

Middle of the linked list (LeetCode 876)

When fast reaches the end, slow has covered half the distance, so it is in the middle.

public ListNode middleNode(ListNode head) {
    ListNode slow = head, fast = head;
    while (fast != null && fast.next != null) {
        slow = slow.next;
        fast = fast.next.next;
    }
    return slow;   // for an even count, this is the SECOND middle
}

For 1→2→3→4→5 it returns 3; for 1→2→3→4 it returns 3 (the second middle). If you need the first middle (to split an even list evenly), loop with fast.next != null && fast.next.next != null instead. Complexity: O(n) time, O(1) space.

Cycle detection: Linked List Cycle (LeetCode 141)

If the list has a cycle, the fast pointer eventually laps the slow one inside the loop and they meet. If there is no cycle, fast reaches null. Each step the gap between them grows by one, so inside a cycle of length L they must meet within L steps once both are in it.

public boolean hasCycle(ListNode head) {
    ListNode slow = head, fast = head;
    while (fast != null && fast.next != null) {
        slow = slow.next;
        fast = fast.next.next;
        if (slow == fast) return true;    // compare references, not values
    }
    return false;
}

A HashSet of visited nodes also works, but costs O(n) space. Floyd's version is O(1) space.

Finding where the cycle starts: Linked List Cycle II (LeetCode 142)

After slow and fast meet, put one pointer back at the head and move both one step at a time. They meet again exactly at the cycle's entry.

public ListNode detectCycle(ListNode head) {
    ListNode slow = head, fast = head;
    while (fast != null && fast.next != null) {
        slow = slow.next;
        fast = fast.next.next;
        if (slow == fast) {
            ListNode p = head;
            while (p != slow) { p = p.next; slow = slow.next; }
            return p;                 // the entry node
        }
    }
    return null;                      // no cycle
}

Why it works. Let a be the distance from the head to the cycle entry, b the distance from the entry to the meeting point, and c the rest of the cycle, so the cycle length is b + c. When they meet, slow walked a + b. Fast walked twice that, 2(a + b), and also a + b plus some whole laps, k(b + c). So a + b = k(b + c), which gives a = (k - 1)(b + c) + c. Walking a steps from the meeting point goes c steps to the entry plus whole laps, so it lands on the entry, exactly when a pointer from the head also arrives. Complexity: O(n) time, O(1) space.

Remove Nth Node From End of List (LeetCode 19)

Make fast go n steps ahead, then move both until fast hits the last node. The gap of n keeps slow just before the node to delete. A dummy node handles deleting the head.

public ListNode removeNthFromEnd(ListNode head, int n) {
    ListNode dummy = new ListNode(0, head);
    ListNode slow = dummy, fast = dummy;
    for (int i = 0; i < n; i++) fast = fast.next;   // gap of n
    while (fast.next != null) {
        slow = slow.next;
        fast = fast.next;
    }
    slow.next = slow.next.next;          // slow is the node BEFORE the target
    return dummy.next;
}

Complexity: O(n) time, one pass, O(1) space.

Palindrome Linked List (LeetCode 234)

Find the middle, reverse the second half, compare both halves, and (politely) restore the list if the caller needs it.

public boolean isPalindrome(ListNode head) {
    ListNode slow = head, fast = head;
    while (fast != null && fast.next != null) {
        slow = slow.next;
        fast = fast.next.next;
    }
    ListNode second = reverse(slow);          // reverse from the middle
    for (ListNode a = head, b = second; b != null; a = a.next, b = b.next) {
        if (a.val != b.val) return false;
    }
    return true;
}

private ListNode reverse(ListNode head) {
    ListNode prev = null;
    while (head != null) {
        ListNode nxt = head.next;
        head.next = prev;
        prev = head;
        head = nxt;
    }
    return prev;
}

For an odd length the middle node stays in the second half; the comparison stops when the second half ends, so it is skipped naturally. Complexity: O(n) time, O(1) space.

Intersection of Two Linked Lists (LeetCode 160)

Two lists may merge into a shared tail. Walk pointer a along list A then list B, and pointer b along list B then list A. Both walk lenA + lenB steps in total, so they line up and meet at the intersection (or both become null together if there is none).

public ListNode getIntersectionNode(ListNode headA, ListNode headB) {
    ListNode a = headA, b = headB;
    while (a != b) {
        a = (a == null) ? headB : a.next;
        b = (b == null) ? headA : b.next;
    }
    return a;
}

Complexity: O(m + n) time, O(1) space.

Add Two Numbers (LeetCode 2)

Digits are stored in reverse order (least significant first), so you add from the head with a carry, exactly like school addition. A dummy node builds the result.

public ListNode addTwoNumbers(ListNode l1, ListNode l2) {
    ListNode dummy = new ListNode(0), tail = dummy;
    int carry = 0;
    while (l1 != null || l2 != null || carry != 0) {
        int sum = carry;
        if (l1 != null) { sum += l1.val; l1 = l1.next; }
        if (l2 != null) { sum += l2.val; l2 = l2.next; }
        tail.next = new ListNode(sum % 10);
        tail = tail.next;
        carry = sum / 10;
    }
    return dummy.next;
}

Do not forget the final carry (carry != 0 in the loop condition): 5 + 5 gives 0→1. Complexity: O(max(m, n)) time and space for the output.

Reorder List (LeetCode 143)

Turn L0→L1→…→Ln into L0→Ln→L1→Ln-1→…. Three moves you already know: find the middle, reverse the second half, then interleave the two halves.

public void reorderList(ListNode head) {
    if (head == null || head.next == null) return;
    ListNode slow = head, fast = head;
    while (fast.next != null && fast.next.next != null) {   // first middle
        slow = slow.next;
        fast = fast.next.next;
    }
    ListNode second = reverse(slow.next);      // reverse() from the palindrome code
    slow.next = null;                          // cut the list in two
    ListNode first = head;
    while (second != null) {
        ListNode n1 = first.next, n2 = second.next;
        first.next = second;
        second.next = n1;
        first = n1;
        second = n2;
    }
}

For 1→2→3→4→5 the result is 1→5→2→4→3. Complexity: O(n) time, O(1) space.

Brief: harder list problems

  • Reverse Nodes in k-Group (LeetCode 25). Count k nodes; if k are available, reverse exactly that segment (the iterative reverse with a counter), connect it to the previous group's tail, and repeat. If fewer than k remain, leave them as they are. O(n) time, O(1) space.
  • Copy List with Random Pointer (LeetCode 138). Pass 1: create a copy of each node and store old → copy in a HashMap. Pass 2: set copy.next = map.get(old.next) and copy.random = map.get(old.random). O(n) time and space. An O(1)-space version weaves copies between the originals, but the map version is what most interviews accept.
  • Sort List (LeetCode 148). Merge sort on a list: split at the middle (fast/slow), sort both halves, merge. O(n log n) time.

How to think about a list problem

  1. Can the head change? Add a dummy node.
  2. Need the middle, the end or a gap? Use fast/slow or a gap of n.
  3. Need to read it backwards? Reverse a half in place instead of using an array.
  4. Draw 3 to 5 nodes, move the pointers by hand, and check the empty, one-node and two-node cases.

Stacks: ArrayDeque, parentheses, min stack, RPN

A stack is last-in, first-out; use it when the most recent unfinished thing must be handled first, such as matching brackets, undo, nested expressions and "go back to the previous" logic.

A stack allows work at one end only: push adds on top, pop removes from the top, peek reads the top. The last item pushed is the first popped (LIFO: last in, first out). Think of a pile of plates, the browser Back button, or the call stack of your program. All three operations are O(1).

Use ArrayDeque, not Stack

Java has a legacy class java.util.Stack that extends Vector, so every method is synchronized and slow, and it exposes index methods that break the stack idea. The Java documentation itself recommends Deque for stack use.

Deque<Integer> stack = new ArrayDeque<>();
stack.push(10);              // addFirst: top of the stack is the front
stack.push(20);
int top = stack.peek();      // 20, null if empty
int x = stack.pop();         // 20, throws NoSuchElementException if empty
boolean empty = stack.isEmpty();
int size = stack.size();

Common mistake: pop or peek on an empty stack

pop() on an empty ArrayDeque throws NoSuchElementException, and peek() returns null, which then throws NullPointerException when auto-unboxed to int. Always check isEmpty() first. Also remember that ArrayDeque rejects null elements.

Valid Parentheses (LeetCode 20)

Given a string of ()[]{}, decide whether every bracket closes in the right order. Push each opening bracket. For a closing bracket, the top of the stack must be its matching opener.

public boolean isValid(String s) {
    Deque<Character> stack = new ArrayDeque<>();
    for (char c : s.toCharArray()) {
        if (c == '(') stack.push(')');           // push the EXPECTED closer
        else if (c == '[') stack.push(']');
        else if (c == '{') stack.push('}');
        else if (stack.isEmpty() || stack.pop() != c) return false;
    }
    return stack.isEmpty();                      // nothing left unclosed
}

Dry run on "([)]": push ), push ]; the next char is ) but the popped value is ], so return false. Pushing the expected closer saves a lookup map. Complexity: O(n) time, O(n) space.

Min Stack (LeetCode 155)

Design a stack that also returns its minimum in O(1). Store, with each element, the minimum of the stack at the moment it was pushed.

class MinStack {
    private final Deque<int[]> stack = new ArrayDeque<>();   // {value, minSoFar}

    public void push(int val) {
        int min = stack.isEmpty() ? val : Math.min(val, stack.peek()[1]);
        stack.push(new int[] {val, min});
    }
    public void pop()    { stack.pop(); }
    public int top()     { return stack.peek()[0]; }
    public int getMin()  { return stack.peek()[1]; }
}

Every operation is O(1); space is O(n). Because the minimum is stored per element, popping automatically restores the previous minimum.

Evaluate Reverse Polish Notation (LeetCode 150)

In reverse Polish notation (postfix) the operator comes after its operands: ["2","1","+","3","*"] means (2 + 1) × 3 = 9. Push numbers; on an operator, pop two, apply, push the result.

public int evalRPN(String[] tokens) {
    Deque<Integer> stack = new ArrayDeque<>();
    for (String t : tokens) {
        switch (t) {
            case "+" -> stack.push(stack.pop() + stack.pop());
            case "*" -> stack.push(stack.pop() * stack.pop());
            case "-" -> { int b = stack.pop(), a = stack.pop(); stack.push(a - b); }
            case "/" -> { int b = stack.pop(), a = stack.pop(); stack.push(a / b); }
            default  -> stack.push(Integer.parseInt(t));
        }
    }
    return stack.pop();
}

Edge case: operand order for - and /

The first pop is the right operand. For ["4","2","-"] you must compute 4 − 2, so pop b first and then a, and push a - b. Java integer division truncates toward zero, which is what this problem expects. Complexity: O(n) time and space.

Brief: Decode String (LeetCode 394)

For "3[a2[c]]" the answer is "accaccacc". Use two stacks (or one of pairs): one for repeat counts, one for the string built so far. On [ push the current count and string and start fresh. On ] pop, repeat the current string count times, and append it to the popped string. O(output length) time.

Brief: Basic Calculator ideas

For expressions with + - ( ), keep a running result and a sign. On ( push both and reset; on ) pop and combine. This is the same "save the outer state, restore on close" idea as Decode String.

Recognise a stack problem

  • Matching or nesting (brackets, tags, nested structures).
  • "Undo" or "go back to the last unfinished item".
  • Expression evaluation, simplification of paths (Simplify Path, LeetCode 71: push directory names, pop on ..).
  • Replacing recursion with an explicit stack (used again in tree traversals).
  • "Next greater" style questions: see the monotonic stack.

Interview angle

Valid Parentheses is a warm-up; state the three failure cases (wrong type, closer with empty stack, leftover openers). Be ready to say why you chose ArrayDeque over Stack, and to explain how Min Stack keeps O(1) time. A follow-up is the O(1) extra-space variant that stores only the difference from the minimum; the pair approach above is acceptable.

Monotonic stack: next greater element and histograms

A monotonic stack keeps its elements sorted (always increasing or always decreasing) by popping anything that breaks the order, so each element is pushed and popped once and "next greater/smaller" questions run in O(n).

Take the question: for every day, how many days until a warmer one? The brute force scans forward from each day, which is O(n²). Notice that while you are looking for a warmer day, a day that is already colder than a newer day can never be the answer for anything that comes later. The monotonic stack exploits this. It holds the indexes of elements still "waiting for an answer". When a new element arrives that answers the waiting ones, you pop them and settle their answers. Each index is pushed once and popped once, so the total is O(n), even with a while loop inside the for loop (the same amortized argument as the sliding window).

The template: next greater element

For each index i, find the next index j > i with a[j] > a[i]. Keep a stack of indexes whose values are in decreasing order from bottom to top. A new element larger than the top answers the top.

// result[i] = value of the next greater element to the right, or -1
public int[] nextGreater(int[] a) {
    int n = a.length;
    int[] result = new int[n];
    Arrays.fill(result, -1);
    Deque<Integer> stack = new ArrayDeque<>();       // indexes, values decreasing
    for (int i = 0; i < n; i++) {
        while (!stack.isEmpty() && a[stack.peek()] < a[i]) {
            result[stack.pop()] = a[i];                // a[i] is the answer for them
        }
        stack.push(i);
    }
    return result;                                     // leftovers keep -1
}

Choose the pop condition from the question. For "next greater" pop while the top is < the new value. For "next smaller" pop while the top is > the new value. To handle "greater or equal", change < to <=. For "previous greater/smaller", read the stack top before pushing i: the top is the answer for i.

Rule: store indexes, not values

Indexes let you compute distances (i - top) and still recover the value with a[top]. Store values only when you never need the position.

Daily Temperatures (LeetCode 739)

The answer for day j is the distance to the next warmer day, so it is the template with i - j as the stored result.

public int[] dailyTemperatures(int[] t) {
    int[] days = new int[t.length];                 // 0 means "no warmer day"
    Deque<Integer> stack = new ArrayDeque<>();
    for (int i = 0; i < t.length; i++) {
        while (!stack.isEmpty() && t[stack.peek()] < t[i]) {
            int j = stack.pop();
            days[j] = i - j;
        }
        stack.push(i);
    }
    return days;
}

Input [73,74,75,71,69,72,76,73] gives [1,1,4,2,1,1,0,0]. Complexity: O(n) time, O(n) space.

Next Greater Element II (LeetCode 503): circular array

The array is circular, so walk it twice (i from 0 to 2n - 1, use i % n) and push only during the first pass.

public int[] nextGreaterElements(int[] nums) {
    int n = nums.length;
    int[] res = new int[n];
    Arrays.fill(res, -1);
    Deque<Integer> stack = new ArrayDeque<>();
    for (int i = 0; i < 2 * n; i++) {
        int v = nums[i % n];
        while (!stack.isEmpty() && nums[stack.peek()] < v) res[stack.pop()] = v;
        if (i < n) stack.push(i);
    }
    return res;
}

Complexity: O(n) time, O(n) space.

Online Stock Spanner (LeetCode 901)

The span of today's price is the number of consecutive days up to today with price less than or equal to today's. That is "previous greater element": distance back to the nearest strictly greater price. Keep a stack of pairs {price, span} and merge popped spans.

class StockSpanner {
    private final Deque<int[]> stack = new ArrayDeque<>();   // {price, span}

    public int next(int price) {
        int span = 1;
        while (!stack.isEmpty() && stack.peek()[0] <= price) {
            span += stack.pop()[1];          // absorb the span of smaller prices
        }
        stack.push(new int[] {price, span});
        return span;
    }
}

Prices 100, 80, 60, 70, 60, 75, 85 give spans 1, 1, 1, 2, 1, 4, 6. Complexity: amortized O(1) per call.

Largest Rectangle in Histogram (LeetCode 84)

Bars have width 1 and given heights. Find the largest rectangle. For each bar, the best rectangle that uses its full height extends left and right until a shorter bar. So for each bar you need the previous smaller and the next smaller index. One pass with an increasing stack finds both: when a bar pops, its next smaller is the current index and its previous smaller is the new top.

public int largestRectangleArea(int[] heights) {
    int n = heights.length, best = 0;
    Deque<Integer> stack = new ArrayDeque<>();       // indexes, heights increasing
    for (int i = 0; i <= n; i++) {
        int h = (i == n) ? 0 : heights[i];            // height 0 flushes the stack
        while (!stack.isEmpty() && heights[stack.peek()] >= h) {
            int height = heights[stack.pop()];
            int left = stack.isEmpty() ? -1 : stack.peek();   // previous smaller
            best = Math.max(best, height * (i - left - 1));
        }
        stack.push(i);
    }
    return best;
}

Dry run on [2,1,5,6,2,3]: stack holds 1, 5, 6 (as indexes 1, 2, 3). At i=4 (height 2): pop 6 → width 4-2-1 = 1, area 6; pop 5 → width 4-1-1 = 2, area 10; the top is now height 1 (smaller than 2), stop. The best is 10. Complexity: O(n) time, O(n) space. Related: Maximal Rectangle (LeetCode 85) runs this once per row of a binary matrix, treating each row as a histogram.

Brief: Remove K Digits (LeetCode 402)

To make the number smallest, remove a digit whenever it is bigger than the digit after it. Push digits on an increasing stack; while the new digit is smaller than the top and removals remain, pop. After the loop, if removals remain, drop digits from the end; finally strip leading zeros and return "0" if empty. O(n).

Brief: Trapping Rain Water with a stack

Besides the two-pointer version, a decreasing stack works: when a bar higher than the top arrives, the popped bar is a valley; its water is bounded by the new top (left wall) and the current bar (right wall), with width i - top - 1 and height min(wallL, wallR) - valley.

Edge cases with equal values

Decide what equality means before you code. "Next greater" needs a strictly larger value, so equal values stay on the stack (pop on <). In Stock Span, equal prices count in the span, so pop on <=. In the histogram, popping on >= is safe because a bar of equal height will compute the same wider rectangle later.

Interview angle

You rarely get a hint that it is a monotonic stack. The clue is "for each element, find the nearest element to the left or right that is bigger or smaller". Say the invariant out loud ("the stack is decreasing; a bigger element pops smaller ones"), then justify O(n): each index is pushed once and popped at most once. The histogram problem is the standard hard test.
