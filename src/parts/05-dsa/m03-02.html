Combinations (choose k of n)

A combination is a group of k items where order does not matter; use the loop-from-start template, record when the path has k elements, and prune the loop so it stops when too few numbers are left to finish the group.

A combination is a selection in which order does not matter: [1, 2] and [2, 1] are the same combination. The number of ways to choose k items from n is written C(n, k) = n! / (k! · (n − k)!). For n = 4 and k = 2 that is 6. This is the same template as subsets — a number is only followed by numbers to its right, which fixes the order — with two changes: you record an answer only when the path has exactly k elements, and you stop going deeper once it does.

Problem — Combinations (LeetCode 77)

Given n and k, return all combinations of k numbers chosen from 1..n.

import java.util.ArrayList;
import java.util.List;

public class Combinations {
    public static List<List<Integer>> combine(int n, int k) {
        List<List<Integer>> result = new ArrayList<>();
        backtrack(n, k, 1, new ArrayList<>(), result);
        return result;
    }

    private static void backtrack(int n, int k, int start, List<Integer> path,
                                  List<List<Integer>> result) {
        if (path.size() == k) {                    // complete group: record a copy
            result.add(new ArrayList<>(path));
            return;
        }
        int need = k - path.size();                // how many more numbers we must add
        // feasibility pruning: after picking i there must be (need - 1) numbers to its right
        for (int i = start; i <= n - need + 1; i++) {
            path.add(i);                           // choose
            backtrack(n, k, i + 1, path, result);  // explore: only larger numbers
            path.remove(path.size() - 1);          // un-choose
        }
    }

    public static void main(String[] args) {
        System.out.println(combine(4, 2));
    }
}
[[1, 2], [1, 3], [1, 4], [2, 3], [2, 4], [3, 4]]

The pruning, step by step

Suppose n = 4, k = 3 and the path is empty. You need 3 numbers, so the first number can be at most n − need + 1 = 4 − 3 + 1 = 2. Starting with 3 would leave only [3, 4] — too short, a dead end. Without the bound, the loop still runs to n, enters useless calls and returns empty-handed. The bound does not change the output; it removes only branches that cannot succeed. For large n with small k the saving is big: C(n, k) answers are produced, but the useless calls would otherwise add a factor on top.

Dry run for n = 4, k = 2:

  1. Root: path [], need = 2, the loop runs i = 1 to 3 (not 4).
  2. i = 1: path [1], need = 1, loop i = 2 to 4 → records [1,2], [1,3], [1,4].
  3. i = 2: path [2], loop i = 3 to 4 → records [2,3], [2,4].
  4. i = 3: path [3], loop i = 4 to 4 → records [3,4]. The root never tries 4.

Complexity: O(k · C(n, k)) time — C(n, k) answers, each copied in O(k) — and O(k) extra space. The pruned tree has no dead leaves, so the internal nodes add only a small factor.

Include / exclude version

The binary-choice view also works: for each number decide "in" or "out", and stop early when the group is full or when the remaining numbers cannot fill it.

static void dfs(int i, int n, int k, List<Integer> path, List<List<Integer>> res) {
    if (path.size() == k) { res.add(new ArrayList<>(path)); return; }
    if (i > n || n - i + 1 < k - path.size()) return;  // not enough numbers left
    path.add(i);
    dfs(i + 1, n, k, path, res);                       // take i
    path.remove(path.size() - 1);
    dfs(i + 1, n, k, path, res);                       // skip i
}

Variation — Combination Sum III

"Find all combinations of k numbers from 1..9 that add up to n, each number used at most once." It is the same code with a remaining argument: record when path.size() == k && remaining == 0 and prune when remaining < 0 or path.size() == k. Because the candidates are 1..9, the tree is tiny.

Mistake: starting the next level at start + 1 or at 1

Wrong: restarts at 1 — this is permutations, not combinations

    backtrack(n, k, 1, path, result);     // [1,2] and [2,1] both appear
    path.remove(path.size() - 1);
}

Right: the next level starts after the chosen number

    path.add(i);
    backtrack(n, k, i + 1, path, result); // i + 1, not start + 1
    path.remove(path.size() - 1);
}

Edge cases

  • k = n → exactly one combination, all numbers. k = 1 → n single-element combinations.
  • k = 0 → one combination, the empty list (the base case fires immediately). LeetCode guarantees k ≥ 1, so you rarely need it.
  • k > n → no combination; the pruned loop never runs and the result is empty.

Interview angle

The question is easy to state, so the interviewer watches the details: do you copy the path, do you start the next level at i + 1, and do you know the pruning bound n − need + 1? Say the answer count C(n, k) out loud and tie the complexity to it. A common follow-up is "do it without recursion" — an iterative version keeps an array of k indices and increments it like an odometer, but recursion is the answer interviewers expect.

Combination Sum I and II

Sort the candidates, keep a remaining target, recurse until it reaches zero and break the loop when a candidate is larger than what remains; allow reuse by recursing with i, forbid it by recursing with i + 1 and skipping equal neighbours.

"Find every combination of numbers that adds up to a target" is the most asked backtracking question after subsets and permutations. It combines three ideas you already know: the start index (so order does not matter), bound pruning on sorted input, and the duplicate skip. The only real difference between the two versions is whether a number may be used again.

Problem 1 — Combination Sum (LeetCode 39)

Given distinct positive integers candidates and a target, return all unique combinations that add up to the target. The same number may be chosen any number of times. For [2, 3, 6, 7] and target 7 the answer is [2,2,3] and [7].

Idea. The state is the path and the remaining amount. At each step choose a candidate at position i or later (never earlier, so [2,3] and [3,2] are not both produced). Recurse with the same i because the number can be reused. Stop with success when remaining == 0. Because the candidates are sorted, once one is bigger than remaining all later ones are too, so break.

import java.util.ArrayList;
import java.util.Arrays;
import java.util.List;

public class CombinationSum {
    public static List<List<Integer>> combinationSum(int[] candidates, int target) {
        int[] a = candidates.clone();
        Arrays.sort(a);                              // enables the break below
        List<List<Integer>> result = new ArrayList<>();
        backtrack(a, target, 0, new ArrayList<>(), result);
        return result;
    }

    private static void backtrack(int[] a, int remaining, int start,
                                  List<Integer> path, List<List<Integer>> result) {
        if (remaining == 0) {                        // exact sum reached
            result.add(new ArrayList<>(path));
            return;
        }
        for (int i = start; i < a.length; i++) {
            if (a[i] > remaining) break;             // sorted: all later ones are too big
            path.add(a[i]);
            backtrack(a, remaining - a[i], i, path, result);  // i, not i + 1: reuse allowed
            path.remove(path.size() - 1);
        }
    }

    public static void main(String[] args) {
        System.out.println(combinationSum(new int[]{2, 3, 6, 7}, 7));
    }
}
[[2, 2, 3], [7]]

Dry run for [2, 3, 6, 7], target 7:

Complexity. The tree depth is at most target / min(candidates) (all smallest numbers), and each node has up to N children, so the time is bounded by about O(NT/m) where N is the number of candidates, T the target and m the smallest candidate. That is a loose upper bound; pruning makes real runs much smaller. Extra space: O(T / m) for the recursion and path. The problem guarantees small input and a bounded number of answers.

Exception: zero or negative candidates

The problem says candidates are positive. With a 0 in the array, remaining never shrinks while the same index is reused, so the recursion never ends and throws StackOverflowError. With negatives, the break rule is wrong as well. Always check the constraints before choosing the break-based pruning.

Problem 2 — Combination Sum II (LeetCode 40)

Now the candidates may contain duplicates and each element can be used at most once. For [10, 1, 2, 7, 6, 1, 5] and target 8, the answer has four combinations: [1,1,6], [1,2,5], [1,7], [2,6]. Note that [1,7] must appear once even though there are two 1s.

Idea. Sort. Recurse with i + 1 (one use per position). To avoid duplicate combinations, at one level try each distinct value only once — the same i > start skip rule as in Subsets II.

import java.util.ArrayList;
import java.util.Arrays;
import java.util.List;

public class CombinationSum2 {
    public static List<List<Integer>> combinationSum2(int[] candidates, int target) {
        int[] a = candidates.clone();
        Arrays.sort(a);                              // equal values side by side
        List<List<Integer>> result = new ArrayList<>();
        backtrack(a, target, 0, new ArrayList<>(), result);
        return result;
    }

    private static void backtrack(int[] a, int remaining, int start,
                                  List<Integer> path, List<List<Integer>> result) {
        if (remaining == 0) {
            result.add(new ArrayList<>(path));
            return;
        }
        for (int i = start; i < a.length; i++) {
            if (a[i] > remaining) break;                    // bound pruning
            if (i > start && a[i] == a[i - 1]) continue;   // same value, same level: skip
            path.add(a[i]);
            backtrack(a, remaining - a[i], i + 1, path, result); // i + 1: use each once
            path.remove(path.size() - 1);
        }
    }

    public static void main(String[] args) {
        System.out.println(combinationSum2(new int[]{10, 1, 2, 7, 6, 1, 5}, 8));
    }
}
[[1, 1, 6], [1, 2, 5], [1, 7], [2, 6]]

Dry run on the sorted array [1, 1, 2, 5, 6, 7, 10]:

  • Root picks the first 1 (remaining 7). The next level may pick the second 1 (i == start, so the skip does not fire) → [1,1], remaining 6 → finally picks 6 → [1,1,6].
  • Still under the first 1, the next level skips the second 1 (i > start and equal to its neighbour) and finds [1,2,5] and [1,7].
  • Back at the root, i = 1 is the second 1: i > start and equal to a[0] → skipped. Its subtree would only repeat what the first 1 already produced.
  • The root then picks 2 → [2,6]. Candidates 7 and 10 give nothing more (7 → remaining 1, no fit; 10 > 8 breaks).

Complexity: O(2n) nodes in the worst case (each element in or out) times O(n) to copy, plus O(n log n) to sort. Extra space O(n).

Which skip rule, and which recursion index?

Make a quick two-question decision for any "combination" problem:

  1. Can an element be reused? Yes → recurse with i. No → recurse with i + 1.
  2. Can the input contain equal values? Yes → sort and add if (i > start && a[i] == a[i - 1]) continue;. No → no skip.

If the input has duplicates and reuse is allowed, deduplicate the array first (for example with stream().distinct() or a manual pass over the sorted array) and use the Combination Sum I code.

Mistake: using a Set to remove duplicate combinations

For Combination Sum II you can "fix" the duplicates by putting every sorted combination into a HashSet. It passes small tests and then times out, because the tree is still full of duplicate subtrees. The sort + i > start skip removes those subtrees before they are explored.

Mistake: break versus continue in the pruning line

On sorted input break is right for the bound check — every later candidate is at least as large. Writing continue is still correct but wastes time scanning the rest of the loop. On unsorted input, break is wrong because a later candidate may be small enough. The bound check and the sort belong together.

Tip: count instead of listing

If the problem asks only for the number of ways to reach a target with reusable coins (Coin Change II style), do not list combinations. The state (remaining amount, index) repeats a lot, so it is a dynamic programming problem with O(T · N) time.

Interview angle

Typical flow: solve Combination Sum I, then the interviewer adds duplicates and "each number once". The strong answer says exactly what changed: the recursion index goes from i to i + 1 and the skip line appears. Explain the bound pruning, state the complexity as a tree bound, and note that the sort costs O(n log n). Mention that zero or negative values would break both the termination and the pruning.

Letter combinations, parentheses and palindrome partitions

Three string-building problems with the same loop: choose a character (or a cut), recurse, un-choose with a StringBuilder or list; the rules — a digit's letters, "close never exceeds open", "the piece must be a palindrome" — decide which choices are allowed.

These three problems are small, common in interviews, and show how the template changes when the state is a string. The choices are not numbers from an array but characters, brackets or cut positions. When you build a string, use a StringBuilder and undo with deleteCharAt(sb.length() - 1) or setLength; appending to an immutable String would also work but creates a new object at every step.

Problem 1 — Letter Combinations of a Phone Number (LeetCode 17)

Each digit 2–9 on an old phone keypad maps to letters (2 → abc, 3 → def, … 9 → wxyz). Given a digit string, return all letter strings it could spell. Here the tree has one level per digit, and the branching factor is the number of letters of that digit (3 or 4).

import java.util.ArrayList;
import java.util.List;

public class LetterCombinations {
    private static final String[] LETTERS =
        {"", "", "abc", "def", "ghi", "jkl", "mno", "pqrs", "tuv", "wxyz"};

    public static List<String> letterCombinations(String digits) {
        List<String> result = new ArrayList<>();
        if (digits.isEmpty()) return result;            // empty input → no combinations
        dfs(digits, 0, new StringBuilder(), result);
        return result;
    }

    private static void dfs(String digits, int pos, StringBuilder sb, List<String> result) {
        if (pos == digits.length()) {                   // one letter chosen per digit
            result.add(sb.toString());
            return;
        }
        String options = LETTERS[digits.charAt(pos) - '0'];
        for (char ch : options.toCharArray()) {
            sb.append(ch);                              // choose
            dfs(digits, pos + 1, sb, result);           // explore the next digit
            sb.deleteCharAt(sb.length() - 1);           // un-choose
        }
    }

    public static void main(String[] args) {
        System.out.println(letterCombinations("23"));
    }
}
[ad, ae, af, bd, be, bf, cd, ce, cf]

Complexity: at most 4n answers (digits 7 and 9 have four letters), each of length n → O(n · 4n) time; O(n) extra space. The edge case matters: for "" return an empty list, not a list with one empty string — LeetCode expects [].

Problem 2 — Generate Parentheses (LeetCode 22)

Given n pairs, generate all strings of well-formed (balanced) parentheses. For n = 3 there are five.

Idea. A string is well-formed if, while reading left to right, the number of closing brackets never exceeds the number of opening ones, and the totals are equal at the end. So track open and close counts and allow only two moves: add ( if open < n; add ) if close < open. Invalid strings are never built — that is pruning at its best, and the tree has no dead leaves.

import java.util.ArrayList;
import java.util.List;

public class GenerateParentheses {
    public static List<String> generateParenthesis(int n) {
        List<String> result = new ArrayList<>();
        dfs(n, 0, 0, new StringBuilder(), result);
        return result;
    }

    private static void dfs(int n, int open, int close, StringBuilder sb,
                            List<String> result) {
        if (sb.length() == 2 * n) {                 // n pairs placed
            result.add(sb.toString());
            return;
        }
        if (open < n) {                             // can still open a bracket
            sb.append('(');
            dfs(n, open + 1, close, sb, result);
            sb.deleteCharAt(sb.length() - 1);
        }
        if (close < open) {                         // a closing bracket needs an open partner
            sb.append(')');
            dfs(n, open, close + 1, sb, result);
            sb.deleteCharAt(sb.length() - 1);
        }
    }

    public static void main(String[] args) {
        System.out.println(generateParenthesis(3));
    }
}
[((())), (()()), (())(), ()(()), ()()()]

Complexity: the number of answers is the n-th Catalan number, C(2n, n) / (n + 1) — 1, 2, 5, 14, 42 for n = 1…5. It grows like 4n / (n · √n). Time is O(n) per answer times the Catalan count, which is about O(4n / √n); space O(n).

Problem 3 — Palindrome Partitioning (LeetCode 131)

Split a string into pieces so that every piece is a palindrome; return all such splits. For "aab": [a, a, b] and [aa, b].

Idea. The state is the position start where the next piece begins. The choice is the piece's end position. Try every end from start onward; if s[start..end] is a palindrome, add it and recurse from end + 1. When start == s.length(), the whole string has been cut into palindromes — record. A non-palindrome piece is never extended: that is the pruning.

import java.util.ArrayList;
import java.util.List;

public class PalindromePartitioning {
    public static List<List<String>> partition(String s) {
        List<List<String>> result = new ArrayList<>();
        backtrack(s, 0, new ArrayList<>(), result);
        return result;
    }

    private static void backtrack(String s, int start, List<String> path,
                                  List<List<String>> result) {
        if (start == s.length()) {                      // cut the whole string
            result.add(new ArrayList<>(path));
            return;
        }
        for (int end = start; end < s.length(); end++) {
            if (!isPalindrome(s, start, end)) continue; // prune: bad piece
            path.add(s.substring(start, end + 1));      // choose the piece
            backtrack(s, end + 1, path, result);        // explore the rest
            path.remove(path.size() - 1);               // un-choose
        }
    }

    private static boolean isPalindrome(String s, int lo, int hi) {
        while (lo < hi) {
            if (s.charAt(lo++) != s.charAt(hi--)) return false;
        }
        return true;
    }

    public static void main(String[] args) {
        System.out.println(partition("aab"));
    }
}
[[a, a, b], [aa, b]]

Dry run for "aab": at start 0, end = 0 gives "a" (palindrome) → recurse at 1; there "a" → recurse at 2; there "b" → start reaches 3 → record [a, a, b]. Back at start 1, end = 2 gives "ab" → not a palindrome, skip. Back at start 0, end = 1 gives "aa" → recurse at 2 → "b" → record [aa, b]. end = 2 gives "aab" → not a palindrome.

Complexity: in the worst case (a string of one repeated letter, where every cut is a palindrome) there are 2n − 1 partitions, each costing O(n) to copy and check, so O(n · 2n) time. The palindrome test inside the loop costs O(n) per call; precomputing a boolean table isPal[i][j] with dynamic programming makes each test O(1) — worth mentioning in an interview. Extra space O(n).

Mistake: sharing a String path without undoing

If you pass path + ch as a new String to the next call there is nothing to undo, which is fine. But if you use one StringBuilder and forget deleteCharAt, the second branch starts with the first branch's leftovers. Pick one style per solution and stick to it.

Mistake: adding ")" without checking close < open

If the rule is "close < n" instead of "close < open", strings like ())(() are generated — equal counts at the end, but invalid in the middle. The invariant is about every prefix, not only the final totals.

Tip: the answer count is a free sanity check

For parentheses the counts 1, 2, 5, 14 tell you at once whether your pruning is right. For letter combinations multiply the letter counts of the digits. Print result.size() on a small input before submitting.

Interview angle

For Generate Parentheses the key sentence is "I only add a closing bracket when there is an unmatched opening one, so I never build an invalid string and never need to validate". For Palindrome Partitioning, say "the choice at each step is where to cut" and offer the DP palindrome table as an optimisation. For Letter Combinations, point out that the recursion depth equals the number of digits, so the stack is never a problem.

N-Queens and Sudoku

Place queens one row at a time and, for each column, check three boolean arrays — used columns, used "row − col" diagonals and used "row + col" anti-diagonals — in O(1); a branch with no safe column is abandoned immediately, which turns n^n guesses into a few thousand for n = 8.

A queen attacks along its row, its column and both diagonals. The N-Queens puzzle asks for every way to put n queens on an n × n board so that none attacks another. It is the classic constraint-satisfaction example: the constraints are strong, so pruning decides everything.

Key observation: one queen per row

Two queens in the same row attack each other, so every row has exactly one queen. That lets you choose by row: at row r decide which column gets the queen. The state is just an array queenCol[r]. You never need to check the row. For the other lines you need an O(1) test:

  • Column c: one boolean per column.
  • Diagonal (top-left to bottom-right): all cells on it share the same row − col. The value ranges from −(n−1) to n−1, so use the index row − col + n − 1 (range 0 to 2n−2).
  • Anti-diagonal (top-right to bottom-left): all cells share the same row + col (range 0 to 2n−2).

Problem — N-Queens (LeetCode 51)

Return all distinct solutions; each solution is a list of n strings where 'Q' is a queen and '.' is empty. For n = 4 there are two solutions.

import java.util.ArrayList;
import java.util.Arrays;
import java.util.List;

public class NQueens {
    public static List<List<String>> solveNQueens(int n) {
        List<List<String>> result = new ArrayList<>();
        place(0, n, new int[n], new boolean[n],
              new boolean[2 * n - 1], new boolean[2 * n - 1], result);
        return result;
    }

    private static void place(int row, int n, int[] queenCol, boolean[] cols,
                              boolean[] diag, boolean[] anti, List<List<String>> result) {
        if (row == n) {                                  // all rows have a queen
            result.add(draw(queenCol, n));
            return;
        }
        for (int c = 0; c < n; c++) {
            int d = row - c + n - 1;                     // diagonal index
            int a = row + c;                             // anti-diagonal index
            if (cols[c] || diag[d] || anti[a]) continue; // prune: attacked square
            cols[c] = diag[d] = anti[a] = true;          // choose
            queenCol[row] = c;
            place(row + 1, n, queenCol, cols, diag, anti, result);  // explore next row
            cols[c] = diag[d] = anti[a] = false;         // un-choose (queenCol is overwritten)
        }
    }

    private static List<String> draw(int[] queenCol, int n) {
        List<String> board = new ArrayList<>();
        for (int r = 0; r < n; r++) {
            char[] line = new char[n];
            Arrays.fill(line, '.');
            line[queenCol[r]] = 'Q';
            board.add(new String(line));
        }
        return board;
    }

    public static void main(String[] args) {
        for (List<String> board : solveNQueens(4)) {
            board.forEach(System.out::println);
            System.out.println();
        }
    }
}

Complexity. There are at most n! placements to try (n columns for row 0, fewer for each later row, since columns are used up); with diagonal pruning far fewer. Time O(n!) as an upper bound, extra space O(n) for the three arrays, queenCol and the stack (plus the output). The number of solutions: n = 1 → 1, 4 → 2, 5 → 10, 6 → 4, 7 → 40, 8 → 92, 9 → 352.

Variation — counting solutions (N-Queens II, LeetCode 52)

When only the count is needed, drop queenCol and draw and return the count instead of building boards:

static int count(int row, int n, boolean[] cols, boolean[] diag, boolean[] anti) {
    if (row == n) return 1;
    int total = 0;
    for (int c = 0; c < n; c++) {
        int d = row - c + n - 1, a = row + c;
        if (cols[c] || diag[d] || anti[a]) continue;
        cols[c] = diag[d] = anti[a] = true;
        total += count(row + 1, n, cols, diag, anti);
        cols[c] = diag[d] = anti[a] = false;
    }
    return total;
}

Speed-up used in competitions: keep the three sets as integer bitmasks and find free columns with ~(cols | diag | anti) & fullMask; the lowest free bit is free & -free. It is the same algorithm, only faster. Mention it; do not start with it.

Sudoku Solver (LeetCode 37) — briefly

Sudoku is the same idea on a 9 × 9 board. The constraints are: each row, each column and each 3 × 3 box contains the digits 1–9 once. The choice is the digit for the next empty cell; keep three tables of used digits (row, column, box) so the validity check is O(1), and return boolean because one solution is enough — the first success must stop the whole search.

public class SudokuSolver {
    private final boolean[][] rowUsed = new boolean[9][10];
    private final boolean[][] colUsed = new boolean[9][10];
    private final boolean[][] boxUsed = new boolean[9][10];
    private final char[][] board;

    public SudokuSolver(char[][] board) {
        this.board = board;
        for (int r = 0; r < 9; r++) {
            for (int c = 0; c < 9; c++) {
                if (board[r][c] != '.') mark(r, c, board[r][c] - '0', true);
            }
        }
    }

    private void mark(int r, int c, int d, boolean value) {
        rowUsed[r][d] = colUsed[c][d] = boxUsed[(r / 3) * 3 + c / 3][d] = value;
    }

    public boolean solve() { return solve(0); }

    private boolean solve(int pos) {
        if (pos == 81) return true;                      // every cell is filled
        int r = pos / 9, c = pos % 9;
        if (board[r][c] != '.') return solve(pos + 1);   // given cell: move on
        for (int d = 1; d <= 9; d++) {
            if (rowUsed[r][d] || colUsed[c][d] || boxUsed[(r / 3) * 3 + c / 3][d]) continue;
            board[r][c] = (char) ('0' + d);              // choose
            mark(r, c, d, true);
            if (solve(pos + 1)) return true;             // explore; stop at first success
            mark(r, c, d, false);                        // un-choose
            board[r][c] = '.';
        }
        return false;                                    // no digit fits: backtrack
    }
}

The worst case is 9(empty cells), but the constraints prune so strongly that real puzzles solve in milliseconds. A well-known speed-up is to fill the cell with the fewest legal digits first; it is not needed for interviews.

Mistake: forgetting the offset in the diagonal index

row − col is negative for cells above the main diagonal. Using it directly as an array index throws ArrayIndexOutOfBoundsException. Add n − 1 to shift the range to 0..2n−2, and size the arrays 2 * n − 1.

Mistake: checking attacks by scanning the board

A beginner version loops over earlier rows to see whether any queen shares a column or diagonal: O(n) per check, so O(n) extra work at every node. The three boolean arrays make it O(1). If the interviewer asks "can you make the check faster?", this is the answer.

Edge cases

  • n = 1 → one solution ["Q"]. n = 2 and n = 3 → no solution (empty list).
  • Mirror images and rotations count as different solutions in LeetCode 51/52 — you do not deduplicate them. (For n = 4 the two solutions are mirror images.)

Interview angle

Say the three key points in order: one queen per row, O(1) conflict check with column and the two diagonal formulas, and un-choose after each recursive call. Give the complexity as O(n!) upper bound and say that pruning makes it much smaller in practice. A good follow-up answer: "to count only, return a number; to find one solution only, return a boolean and stop at the first success."

Word Search: backtracking on a grid

Start a depth-first search from every cell, match the word one letter at a time in four directions, mark the current cell as visited before going deeper and restore it afterwards, and stop at the first full match.

In Word Search (LeetCode 79) you get an m × n board of letters and a word. The word exists if you can spell it by moving to adjacent cells (up, down, left, right), using each cell at most once in one path. Unlike the earlier problems, the state is a position on the board and the "visited" information must be undone, so this is backtracking on a graph (see grids as graphs — there, visited cells stay marked because you only ask "reachable?" once; here the mark is removed because different paths may share cells).

Idea

  1. For every cell, try to start the word there: dfs(r, c, 0).
  2. dfs(r, c, idx) asks: "can the suffix word[idx..] be spelled starting at cell (r, c)?"
  3. Fail at once if the cell is outside the board or its letter is not word[idx].
  4. If idx is the last letter and it matches, succeed.
  5. Otherwise mark the cell visited, try the four neighbours with idx + 1, then restore the cell.

To mark a cell without a separate boolean[][], overwrite it with a character that cannot appear in the word, such as '#'. The letter is saved in a local variable and put back after the four calls. This saves memory and is the usual interview style (state clearly that you modify the board temporarily).

public class WordSearch {
    private static final int[][] DIRS = {{1, 0}, {-1, 0}, {0, 1}, {0, -1}};

    public static boolean exist(char[][] board, String word) {
        for (int r = 0; r < board.length; r++) {
            for (int c = 0; c < board[0].length; c++) {
                if (dfs(board, word, r, c, 0)) return true;   // any start cell may work
            }
        }
        return false;
    }

    private static boolean dfs(char[][] board, String word, int r, int c, int idx) {
        if (r < 0 || c < 0 || r >= board.length || c >= board[0].length) return false;
        if (board[r][c] != word.charAt(idx)) return false;    // also rejects '#' (visited)
        if (idx == word.length() - 1) return true;            // matched the last letter

        char saved = board[r][c];
        board[r][c] = '#';                                    // choose: mark visited
        for (int[] d : DIRS) {
            if (dfs(board, word, r + d[0], c + d[1], idx + 1)) {
                board[r][c] = saved;                          // restore before returning
                return true;
            }
        }
        board[r][c] = saved;                                  // un-choose
        return false;
    }

    public static void main(String[] args) {
        char[][] board = {
            {'A', 'B', 'C', 'E'},
            {'S', 'F', 'C', 'S'},
            {'A', 'D', 'E', 'E'}
        };
        System.out.println(exist(board, "ABCCED"));   // true
        System.out.println(exist(board, "SEE"));      // true
        System.out.println(exist(board, "ABCB"));     // false: would reuse the B
    }
}

Dry run for "ABCCED": start at (0,0) A → (0,1) B → (0,2) C → down to (1,2) C → down to (2,2) E → left to (2,1) D, which is the last letter → true. Going right from (0,2) to E would fail on the second C, so that branch returns false and the search tries the next direction.

Complexity

From each of the m · n start cells, the first step has 4 directions and every later step at most 3 (you cannot go back to the cell you just came from, since it is marked). The path is at most L = word.length() long. Time: O(m · n · 3L) in the worst case. Space: O(L) for the recursion stack; the board itself is reused. In practice the first-letter check kills most start cells, and mismatches cut branches early.

Optimisations worth naming

  • Letter-frequency check: if the board does not contain enough copies of some letter in the word, return false before searching.
  • Search from the rarer end: if the last letter is rarer on the board than the first, reverse the word. Fewer start cells means less search.
  • Many words at once (Word Search II): searching each word separately repeats work. Put the words in a trie and run one DFS that follows the trie; tries are in the second half of this module.

Mistake: forgetting to restore the cell

Wrong: the board stays damaged

board[r][c] = '#';
boolean found = dfs(board, word, r + 1, c, idx + 1)
             || dfs(board, word, r - 1, c, idx + 1);
return found;   // cell is still '#': later start cells fail

Right: restore on every exit path

board[r][c] = '#';
boolean found = dfs(board, word, r + 1, c, idx + 1)
             || dfs(board, word, r - 1, c, idx + 1);
board[r][c] = saved;   // restore, then return
return found;

Mistake: checking the base case before the bounds

If you write if (idx == word.length()) return true; as the first line, you must handle idx == length before calling word.charAt(idx), or you get StringIndexOutOfBoundsException. The version above avoids the issue by testing "last letter matched" after the character comparison. Either style is fine — pick one and trace it on a one-letter word.

Edge cases

  • A one-letter word: succeeds at the first matching cell; the loop over directions never runs.
  • A word longer than m · n can never fit — return false early.
  • If the word contained '#' as a real letter, the marker would collide with it. LeetCode uses letters only; with other alphabets use a separate boolean[][] visited.
  • Modifying the input board is not safe if other threads read it. In production code use a visited array.

Interview angle

The interviewer is checking three things: the bounds checks, the mark/restore pair and the complexity. Say "3L, not 4L, because one neighbour is already visited". Explain why visited is restored (a different start or branch may use the same cell) and how this differs from Number of Islands, where cells stay marked forever. Offer the trie solution for Word Search II as the natural extension.

Tip: backtracking complexity at a glance

Always count three things: how many nodes the tree has (bd for branching factor b and depth d), how much work each node does (copying an answer is O(n)), and whether pruning changes the bound (it usually lowers real running time, not the worst-case formula). If the formula is at most about 107 for the given limits, the solution will pass.
