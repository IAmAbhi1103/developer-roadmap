Choosing the right pattern: signals, constraints and a study plan

Most medium problems are built on about ten patterns; the input type, the size limits and the question words usually tell you which one to use before you write any code.

A pattern is a reusable plan for a family of problems. "Longest substring without repeating characters" and "smallest subarray with sum at least K" look different, but both are solved by the same sliding-window loop. Interviewers rarely ask a problem you have seen word for word. They ask one that uses a pattern you should know. So your real goal in this module is not to memorise 100 solutions. It is to learn 10 patterns so well that you can spot them in a new problem.

Let the size limits pick the complexity

Every problem states constraints — limits such as 1 ≤ n ≤ 10^5. They are a strong hint. As a rough rule, an online judge runs about 107–108 simple operations per second. So with n = 105, an O(n²) solution does about 1010 operations and will time out, while O(n log n) does about 1.7 million and passes easily.

The routine for every problem

  1. Restate the problem in one line and write down the size limits.
  2. Work two or three small examples by hand, including one edge case: empty input, one element, all values equal, negative numbers.
  3. Say the brute force and its complexity. It is your fallback, and in an interview it is your starting point.
  4. Find the repeated work in the brute force. Match the signals above to a pattern that removes it.
  5. Write the pattern's template first, then fill in the problem-specific parts.
  6. Dry run your code on one example, tracking every variable on paper.
  7. State the time and space complexity. Then log the problem — pattern, key trick, your mistake — using the log format from Module 1.

Interview angle: think aloud in this order

Interviewers grade the process, not only the final code. A strong answer sounds like: "Brute force is O(n²) because it checks every pair. The array is sorted, so I can use two pointers — moving the left pointer only makes the sum bigger — which gives O(n) time and O(1) space. Edge cases: empty array, no valid pair." Clarify the input first (sorted? duplicates? negative numbers? can I change the input?), then state the brute force, then the pattern and why it is correct.

Two pointers: the three shapes and their templates

Keep two indices into the data and move them by a fixed rule, so that each step throws away candidates you no longer need — pair problems drop from O(n²) to O(n).

The brute force for any "find a pair" problem checks every pair (i, j). That is n(n−1)/2 pairs, so O(n²). For n = 105 that is about 5 × 109 checks — far too slow. The two-pointer technique keeps two indices and, at each step, moves one of them in one direction only. A pointer never moves back, so together they make at most about n moves. The whole scan is O(n).

Why it is correct: the elimination argument

Take a sorted array and a target sum. Put l at the smallest value and r at the largest.

  • If a[l] + a[r] < target: a[r] is the biggest value still in play, so a[l] plus any other remaining value is even smaller. a[l] cannot be part of any answer. Drop it: l++.
  • If a[l] + a[r] > target: a[l] is the smallest value still in play, so a[r] plus anything is even bigger. Drop it: r--.

Each move removes one element that provably cannot be in the answer. This gives you an invariant — a statement that stays true on every loop iteration: "if a valid pair exists, it lies inside [l, r]." Every two-pointer solution has an invariant like this. If you can say it, you can defend your solution in an interview.

Shape 1 — opposite ends (converging pointers)

One pointer starts at the left end, the other at the right end, and they move towards each other until they meet. Use it for pair sums in a sorted array, palindromes, reversing in place, "container with most water" and trapping rain water.

int l = 0, r = a.length - 1;
while (l < r) {                  // l < r: two different elements
    // look at a[l] and a[r]
    if (/* answer found */) {
        // record it, or return it
    } else if (/* need a bigger value */) {
        l++;
    } else {
        r--;
    }
}

Shape 2 — same direction (read and write pointers)

Both pointers move left to right. The read pointer (also called fast) visits every element. The write pointer (also called slow) marks the next free slot for an element you decide to keep. Everything before write is the finished answer. Use it to remove elements, remove duplicates, move zeros or compact an array in place with O(1) extra space.

int write = 0;                        // a[0..write-1] is the answer so far
for (int read = 0; read < a.length; read++) {
    if (/* keep a[read]? */) {
        a[write++] = a[read];
    }
}
return write;                         // the new logical length

The same-direction idea with two speeds — one pointer moving one step, the other moving two — is the fast and slow pointer technique for linked lists. It gets its own article: Fast and slow pointers.

Shape 3 — two sequences

One pointer walks each input. At every step you compare the two current elements and advance one (or both) pointers. Use it to merge two sorted arrays, intersect two sorted arrays, or check whether one string is a subsequence of another.

// Merge two sorted arrays into one sorted array: O(n + m) time
public int[] mergeSorted(int[] a, int[] b) {
    int[] out = new int[a.length + b.length];
    int i = 0, j = 0, k = 0;
    while (i < a.length && j < b.length) {
        if (a[i] <= b[j]) {        // <= keeps equal elements from a first (stable)
            out[k++] = a[i++];
        } else {
            out[k++] = b[j++];
        }
    }
    while (i < a.length) out[k++] = a[i++];   // copy what is left
    while (j < b.length) out[k++] = b[j++];
    return out;
}
// Is Subsequence (LeetCode 392): is s a subsequence of t?
public boolean isSubsequence(String s, String t) {
    int i = 0;                                       // next char of s to match
    for (int j = 0; j < t.length() && i < s.length(); j++) {
        if (s.charAt(i) == t.charAt(j)) {
            i++;
        }
    }
    return i == s.length();
}

isSubsequence("ace", "abcde") returns true; isSubsequence("aec", "abcde") returns false. Both run in O(|t|) time and O(1) space.

How to think

  1. Is the input sorted, or can you sort it without losing what the question needs? Sorting destroys original indices.
  2. Decide what each pointer means, and write the invariant in one sentence, for example "everything before write is final".
  3. Decide which pointer moves in each case, and why the element you skip can never be part of an answer.
  4. Pick the loop condition: l < r when you need two different elements, l <= r when a single middle element still needs processing (as in Sort Colors).
  5. Dry run on a tiny input with duplicates, then on an empty array.

Rule: opposite-ends pair search needs sorted input

The elimination argument only holds when moving l right can only increase the value and moving r left can only decrease it. On unsorted data the same loop silently misses answers. Sort first, or use a HashMap.

Edge cases: empty input, duplicates and overflow

  • Empty array: r = a.length - 1 = -1, so l < r is false at once and the loop never runs. Make sure your return value is still correct.
  • Duplicates: decide whether the answer wants unique values (3Sum) or every pair; skip equal neighbours when it wants unique values.
  • Overflow: a[l] + a[r] overflows int when values are near ±231. Java does not throw — the sum silently wraps to a negative number. Use long sum = (long) a[l] + a[r]; when the constraints allow values up to 109.

Mistake: using l <= r in a pair search

With <=, the pointers can meet on one index and use the same element twice. For a = [1, 5, 8] and target 10 the wrong loop reaches l = r = 1 and reports 5 + 5.

Wrong: may pair an element with itself

while (l <= r) {
    int sum = a[l] + a[r];
    if (sum == target) return new int[] {l, r};
    if (sum < target) l++; else r--;
}

Right: two different indices

while (l < r) {
    int sum = a[l] + a[r];
    if (sum == target) return new int[] {l, r};
    if (sum < target) l++; else r--;
}

Tip: write the invariant as a comment

Before the loop, write one line such as // nums[0..write-1] holds the unique values. It keeps your updates consistent, and reading it aloud is a ready-made explanation for the interviewer.

Interview angle

Typical follow-ups: "Can you do it in O(1) extra space?", "Why is it safe to move the smaller side?", "What if the array is not sorted?" A strong answer names the shape, states the invariant, explains in one sentence why each skipped element cannot be in the answer, and gives the complexity. If the array is unsorted, compare "sort + two pointers, O(n log n), indices lost" with "HashMap, O(n) time, O(n) space".

Two pointers: classic problems step by step

Seven problems cover almost every two-pointer variation: pair sum, palindrome, container, 3Sum with de-duplication, in-place removal, trapping rain water and the three-way partition.

1. Two Sum II — Input Array Is Sorted (LeetCode 167)

The array is sorted in non-decreasing order. Return the 1-based indices of the two numbers that add up to target. Exactly one answer exists, you may not use the same element twice, and you must use O(1) extra space. This is the opposite-ends template almost unchanged.

public int[] twoSum(int[] numbers, int target) {
    int l = 0, r = numbers.length - 1;
    while (l < r) {
        int sum = numbers[l] + numbers[r];
        if (sum == target) {
            return new int[] {l + 1, r + 1};   // the problem wants 1-based indices
        } else if (sum < target) {
            l++;                               // need a bigger sum
        } else {
            r--;                               // need a smaller sum
        }
    }
    return new int[] {-1, -1};                 // not reached: an answer is guaranteed
}

Dry run with numbers = [2, 7, 11, 15], target = 9:

022 + 11 = 1313 > 9, so r--

Complexity: O(n) time, O(1) space.

2. Valid Palindrome (LeetCode 125)

A phrase is a palindrome if, after keeping only letters and digits and ignoring case, it reads the same both ways. "A man, a plan, a canal: Panama" is a palindrome; "race a car" is not. Instead of building a cleaned copy (O(n) extra space), skip the unwanted characters with the pointers.

public boolean isPalindrome(String s) {
    int l = 0, r = s.length() - 1;
    while (l < r) {
        char a = s.charAt(l), b = s.charAt(r);
        if (!Character.isLetterOrDigit(a)) { l++; continue; }   // skip spaces, commas
        if (!Character.isLetterOrDigit(b)) { r--; continue; }
        if (Character.toLowerCase(a) != Character.toLowerCase(b)) {
            return false;
        }
        l++;
        r--;
    }
    return true;
}

Complexity: O(n) time, O(1) space. A common follow-up is Valid Palindrome II (LeetCode 680): you may delete at most one character. At the first mismatch, check whether either s[l+1..r] or s[l..r-1] is a palindrome — still O(n).

3. Container With Most Water (LeetCode 11)

Each height[i] is a vertical line. Pick two lines that, with the x-axis, hold the most water. The water between lines l and r is min(height[l], height[r]) × (r − l). Start with the widest container. Then always move the shorter line inward. Why is that safe? Any container that keeps the shorter line and moves the other one inward is narrower, and its height is still capped by the shorter line. It can never beat the current area. So the shorter line is finished and can be dropped.

public int maxArea(int[] height) {
    int l = 0, r = height.length - 1, best = 0;
    while (l < r) {
        int area = Math.min(height[l], height[r]) * (r - l);
        best = Math.max(best, area);
        if (height[l] < height[r]) {
            l++;            // the shorter line cannot do better with any other partner
        } else {
            r--;
        }
    }
    return best;
}

For [1, 8, 6, 2, 5, 4, 8, 3, 7] the answer is 49 (lines at index 1 and 8: min(8, 7) × 7). Complexity: O(n) time, O(1) space.

4. 3Sum (LeetCode 15) — with de-duplication

Return all unique triplets that sum to 0. Sort the array, fix the first element nums[i], and run Two Sum II on the part to its right with target -nums[i]. The hard part is avoiding duplicate triplets without a HashSet:

  • Skip an i whose value equals the previous i's value — it would produce the same triplets again.
  • After recording a triplet, move l and r past all copies of the values just used.
public List<List<Integer>> threeSum(int[] nums) {
    Arrays.sort(nums);
    List<List<Integer>> result = new ArrayList<>();
    int n = nums.length;
    for (int i = 0; i < n - 2; i++) {
        if (nums[i] > 0) break;                          // smallest is positive: no zero sum
        if (i > 0 && nums[i] == nums[i - 1]) continue;   // same first value as before
        int l = i + 1, r = n - 1;
        while (l < r) {
            int sum = nums[i] + nums[l] + nums[r];
            if (sum == 0) {
                result.add(List.of(nums[i], nums[l], nums[r]));
                l++;
                r--;
                while (l < r && nums[l] == nums[l - 1]) l++;   // skip same second value
                while (l < r && nums[r] == nums[r + 1]) r--;   // skip same third value
            } else if (sum < 0) {
                l++;
            } else {
                r--;
            }
        }
    }
    return result;
}

Dry run with nums = [-1, 0, 1, 2, -1, -4]. After sorting: [-4, -1, -1, 0, 1, 2].

  • i = 0 (−4): needs 4 from [-1, -1, 0, 1, 2]. The largest pair is 1 + 2 = 3, so l walks right and nothing is found.
  • i = 1 (−1): l = 2 (−1), r = 5 (2): sum 0 → record [-1, -1, 2]. Move to l = 3 (0), r = 4 (1): sum 0 → record [-1, 0, 1]. Pointers cross.
  • i = 2 (−1): same value as nums[1] → skipped. Without this line you would record [-1, 0, 1] a second time.
  • i = 3 (0): 0 + 1 + 2 = 3 > 0, nothing found.
[[-1, -1, 2], [-1, 0, 1]]

Complexity: O(n²) time — the sort's O(n log n) is smaller. Extra space is O(1) apart from the output and the sort's own stack (O(log n) for sorting a primitive array). The same skeleton solves 3Sum Closest (16) and, with one more outer loop, 4Sum (18) in O(n³). In 4Sum the values go up to 109, so add them in a long.

Mistake: skipping duplicates by looking forward

Comparing nums[i] with nums[i + 1] skips the first copy of a value. Then the second copy can no longer be used as nums[l], and you lose triplets such as [-1, -1, 2].

Wrong: loses [-1, -1, 2]

if (i + 1 < n && nums[i] == nums[i + 1]) continue;

Right: use the first copy, skip later ones

if (i > 0 && nums[i] == nums[i - 1]) continue;

Putting triplets in a HashSet<List<Integer>> also removes duplicates, but it costs extra memory and hashing, and interviewers usually ask you to remove it.

5. Remove Duplicates from Sorted Array (LeetCode 26) — read/write

Remove duplicates in place so each value appears once; return the new length k. Only the first k slots matter. Because the array is sorted, a value is new exactly when it differs from the last value you kept.

public int removeDuplicates(int[] nums) {
    if (nums.length == 0) return 0;
    int write = 1;                          // nums[0..write-1] holds the unique values
    for (int read = 1; read < nums.length; read++) {
        if (nums[read] != nums[write - 1]) {
            nums[write++] = nums[read];
        }
    }
    return write;
}

// Remove Duplicates from Sorted Array II (LeetCode 80): keep at most two copies
public int removeDuplicatesAtMostTwo(int[] nums) {
    int write = 0;
    for (int x : nums) {
        if (write < 2 || x != nums[write - 2]) {   // change 2 to k for "at most k"
            nums[write++] = x;
        }
    }
    return write;
}

[0, 0, 1, 1, 1, 2, 2, 3, 3, 4] gives k = 5 with [0, 1, 2, 3, 4] in front. [1, 1, 1, 2, 2, 3] with "at most two" gives k = 5 with [1, 1, 2, 2, 3]. Writing never overtakes reading (write ≤ read), so you never overwrite a value you still need. Complexity: O(n) time, O(1) space.

Move Zeroes (LeetCode 283) is the same shape. Swap instead of copying, so the zeros end up at the back and the non-zero values keep their order:

public void moveZeroes(int[] nums) {
    int write = 0;
    for (int read = 0; read < nums.length; read++) {
        if (nums[read] != 0) {
            int tmp = nums[write];
            nums[write] = nums[read];
            nums[read] = tmp;
            write++;
        }
    }
}

[0, 1, 0, 3, 12] becomes [1, 3, 12, 0, 0].

6. Trapping Rain Water (LeetCode 42) — the two-pointer version

Bars of width 1 have heights height[i]. How much rain is trapped? Water above bar i is min(maxLeft, maxRight) − height[i], where maxLeft and maxRight are the tallest bars on each side, including i. The simple solution precomputes both maxima in two arrays (O(n) space). The two-pointer version needs O(1) space. Keep running maxima from both ends and always process the side with the lower bar. If height[l] < height[r], a bar taller than height[l] exists on the right, so the left side is the limit. The water at l is exactly leftMax − height[l], even though you have not seen the whole right side yet.

public int trap(int[] height) {
    int l = 0, r = height.length - 1;
    int leftMax = 0, rightMax = 0, water = 0;
    while (l < r) {
        if (height[l] < height[r]) {
            leftMax = Math.max(leftMax, height[l]);
            water += leftMax - height[l];      // the right side has a taller bar
            l++;
        } else {
            rightMax = Math.max(rightMax, height[r]);
            water += rightMax - height[r];     // the left side has a bar at least as tall
            r--;
        }
    }
    return water;
}

Complexity: O(n) time, O(1) space. The same problem can be solved with a monotonic stack that fills water layer by layer — see Monotonic stack.

7. Sort Colors (LeetCode 75) — the Dutch national flag

Sort an array of 0s, 1s and 2s in place in one pass. Counting the values and rewriting the array works in two passes. The one-pass answer uses three pointers and the invariant written in the comment. It is the same three-way partition that makes quicksort fast when many keys repeat (see sorting in Module 1).

public void sortColors(int[] nums) {
    int low = 0, mid = 0, high = nums.length - 1;
    // [0..low-1] = 0s, [low..mid-1] = 1s, [mid..high] = unknown, [high+1..] = 2s
    while (mid <= high) {                 // <= : nums[high] itself is still unknown
        if (nums[mid] == 0) {
            swap(nums, low++, mid++);
        } else if (nums[mid] == 1) {
            mid++;
        } else {
            swap(nums, mid, high--);      // do NOT move mid: the new nums[mid] is unchecked
        }
    }
}

private void swap(int[] a, int i, int j) {
    int t = a[i];
    a[i] = a[j];
    a[j] = t;
}

[2, 0, 2, 1, 1, 0] becomes [0, 0, 1, 1, 2, 2]. Complexity: O(n) time, O(1) space.

Edge cases to test every time

  • Arrays of length 0, 1 and 2 — the loops must not read outside the array.
  • All values equal: 3Sum on [0, 0, 0, 0] must return exactly one triplet, [[0, 0, 0]].
  • Sort Colors when the swapped-in value from high is a 0 — this is why mid must not move after that swap.
  • Trapping Rain Water with strictly increasing or decreasing heights traps 0.

Mistake: moving the taller line in Container With Most Water

Moving the taller line can never help: the width shrinks and the height stays capped by the shorter line. If heights are equal, moving either one is fine — any better container must drop both of them anyway.
