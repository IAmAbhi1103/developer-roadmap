Longest increasing subsequence: O(n²) DP and O(n log n)

LIS asks for the longest strictly increasing subsequence; the DP "best sequence ending at i" costs O(n²), and keeping a sorted "tails" array with binary search brings it down to O(n log n).

A subsequence keeps the original order but may skip elements (it is not the same as a subarray, which must be contiguous). For [10, 9, 2, 5, 3, 7, 101, 18] the LIS length is 4, for example 2, 3, 7, 18. LIS (LeetCode "Longest Increasing Subsequence") is one of the most asked DP problems because it has two good solutions, and interviewers like to ask for the second after you give the first.

Method 1: dp[i] = LIS that ends at index i

The trick is the state. "Best LIS in the first i elements" is not enough, because to extend it you must know its last value. So fix the last element: dp[i] = length of the longest increasing subsequence that ends exactly at nums[i].

  • State: dp[i], ending at index i.
  • Transition: look at every earlier j < i with nums[j] < nums[i]; you can append nums[i] to the best sequence ending at j. So dp[i] = 1 + max(dp[j]) over those j.
  • Base case: every dp[i] starts at 1 (the element alone).
  • Answer: the maximum over all dp[i], not dp[n-1], because the best sequence may end anywhere.
public int lengthOfLIS(int[] nums) {
    int n = nums.length;
    int[] dp = new int[n];
    java.util.Arrays.fill(dp, 1);              // each element alone is a sequence of 1
    int best = 1;
    for (int i = 1; i < n; i++) {
        for (int j = 0; j < i; j++) {
            if (nums[j] < nums[i]) {           // strictly increasing
                dp[i] = Math.max(dp[i], dp[j] + 1);
            }
        }
        best = Math.max(best, dp[i]);
    }
    return best;                               // empty input is not allowed by the problem
}

Dry run on [10, 9, 2, 5, 3, 7]: dp = [1, 1, 1, 2, 2, 3]. For 7 (index 5) the smaller earlier values are 2, 5 and 3 with dp 1, 2, 2, so dp[5] = 3. Complexity: O(n²) time, O(n) space. Fine for n up to about 2,500; too slow for n = 105.

Method 2: tails array and binary search

Keep an array tails where tails[k] is the smallest possible last value of an increasing subsequence of length k+1. The array is always sorted, which is why binary search works. For each number x:

  1. Find the first position pos in tails with tails[pos] >= x (a lower bound).
  2. If no such position exists, x is bigger than every tail: append it, the LIS grows by one.
  3. Otherwise overwrite tails[pos] = x. A smaller tail for the same length is strictly better for future extensions.
public int lengthOfLIS(int[] nums) {
    int[] tails = new int[nums.length];
    int size = 0;                              // tails[0..size-1] is in use and sorted
    for (int x : nums) {
        int lo = 0, hi = size;                 // lower bound: first index with tails[idx] >= x
        while (lo < hi) {
            int mid = lo + (hi - lo) / 2;
            if (tails[mid] < x) lo = mid + 1;
            else hi = mid;
        }
        tails[lo] = x;
        if (lo == size) size++;                // x extended the longest sequence
    }
    return size;
}

Complexity: O(n log n) time (one binary search per element), O(n) space.

The tails array is not a valid subsequence

After the run above tails = [2, 3, 7, 18] happens to be real, but in general it is a mix of different candidate sequences (for example [2, 3] was built after 5 was replaced). Only its length is guaranteed correct. To print the actual LIS, store for each element its parent index and the index sitting in each tails slot, then walk back from the last slot; or use the O(n²) DP with a parent[] array.

Strict vs non-strict

For a strictly increasing sequence use lower bound (first tails[idx] >= x), so equal values replace instead of append. For a non-decreasing sequence use upper bound (first tails[idx] > x). Using the wrong one is the classic bug: [2, 2, 2] must give 1 for strict LIS.

Where LIS hides

  • Russian Doll Envelopes: sort by width ascending, and for equal widths by height descending, then run LIS on heights. The descending tie-break stops two envelopes of equal width from chaining.
  • Number of LIS (count of optimal sequences): keep a second array count[i] in the O(n²) DP.
  • Largest divisible subset and longest chain of pairs: sort, then the same "best chain ending at i" DP.
  • Minimum deletions to make an array sorted = n - LIS.

Maximum Product Subarray (brief)

A neighbour of Kadane's algorithm, but a negative number flips the biggest into the smallest. So track both the maximum and the minimum product ending at the current index.

public int maxProduct(int[] nums) {
    int curMax = nums[0], curMin = nums[0], best = nums[0];
    for (int i = 1; i < nums.length; i++) {
        int x = nums[i];
        int a = curMax * x, b = curMin * x;    // a negative x swaps the roles
        curMax = Math.max(x, Math.max(a, b));  // restart at x, or extend
        curMin = Math.min(x, Math.min(a, b));
        best = Math.max(best, curMax);
    }
    return best;                               // O(n) time, O(1) space
}

Dry run on [2, 3, -2, 4]: (max, min) goes (2,2), (6,3), (-2,-12), (4,-48); best is 6.

Interview angle

Give the O(n²) DP first and say why the state is "ending at i". When asked to improve, describe the tails array: "the smallest tail for each length, kept sorted, so I binary search". Mention strict vs non-strict and that tails is not the sequence itself.

Grid DP: unique paths, min path sum, triangle, maximal square

In grid DP the state is a cell (row, col), and each cell is computed from the cells above and to the left, so a double loop in reading order fills the table in O(rows × cols).

When a robot moves only right and down, the way to reach a cell depends only on the cell above and the cell to the left. That is optimal substructure in its cleanest form. The state is dp[r][c]; the iteration order is row by row, left to right, so that both neighbours are ready; and because each row reads only the previous row, you can usually shrink the table to one row.

The grid template

int[][] dp = new int[m][n];
dp[0][0] = /* start value */ 0;
// first row and first column have only one source each: fill them first
for (int c = 1; c < n; c++) dp[0][c] = /* from dp[0][c-1] */ 0;
for (int r = 1; r < m; r++) dp[r][0] = /* from dp[r-1][0] */ 0;
for (int r = 1; r < m; r++) {
    for (int c = 1; c < n; c++) {
        dp[r][c] = /* combine(dp[r-1][c], dp[r][c-1]) */ 0;
    }
}
return dp[m - 1][n - 1];

Unique Paths (LeetCode 62)

A robot starts at the top-left of an m × n grid and moves only right or down. How many paths reach the bottom-right? State: dp[r][c] = number of paths to that cell. Transition: dp[r][c] = dp[r-1][c] + dp[r][c-1]. Base: the whole first row and first column are 1 (only one way: straight).

public int uniquePaths(int m, int n) {
    int[] row = new int[n];                    // one row is enough
    java.util.Arrays.fill(row, 1);             // first row: 1 way to each cell
    for (int r = 1; r < m; r++) {
        for (int c = 1; c < n; c++) {
            row[c] += row[c - 1];              // row[c] (above) + row[c-1] (left)
        }
    }
    return row[n - 1];
}

For a 3 × 3 grid the rows become [1,1,1], [1,2,3], [1,3,6], so the answer is 6. Complexity: O(m·n) time, O(n) space. A maths shortcut is C(m+n-2, m-1), but it overflows easily; the DP is safer.

Unique Paths II: with obstacles (LeetCode 63)

Same problem, but cells marked 1 are blocked. An obstacle cell has zero paths. The first row and column are no longer all 1: once a blocked cell appears, everything after it in that row (or column) is unreachable.

public int uniquePathsWithObstacles(int[][] g) {
    int m = g.length, n = g[0].length;
    int[] row = new int[n];
    row[0] = g[0][0] == 1 ? 0 : 1;             // start blocked means 0 paths
    for (int r = 0; r < m; r++) {
        for (int c = 0; c < n; c++) {
            if (g[r][c] == 1) {
                row[c] = 0;                    // blocked: no way to be here
            } else if (c > 0) {
                row[c] += row[c - 1];          // above (old row[c]) + left
            }
        }
    }
    return row[n - 1];
}

The code handles row 0 naturally: row[c] starts at 0 for c > 0 and receives the left value. Complexity: O(m·n) time, O(n) space.

Minimum Path Sum (LeetCode 64)

Each cell has a cost; find the cheapest right/down path. Transition: dp[r][c] = grid[r][c] + min(dp[r-1][c], dp[r][c-1]). In the first row and column only one neighbour exists.

public int minPathSum(int[][] grid) {
    int m = grid.length, n = grid[0].length;
    int[] dp = new int[n];
    for (int r = 0; r < m; r++) {
        for (int c = 0; c < n; c++) {
            if (r == 0 && c == 0) dp[c] = grid[0][0];
            else if (r == 0) dp[c] = dp[c - 1] + grid[r][c];       // only from the left
            else if (c == 0) dp[c] = dp[c] + grid[r][c];           // only from above
            else dp[c] = Math.min(dp[c], dp[c - 1]) + grid[r][c];
        }
    }
    return dp[n - 1];
}

For [[1,3,1],[1,5,1],[4,2,1]] the answer is 7 (1→3→1→1→1). Complexity: O(m·n) time, O(n) space. If you must not change the input, the 1D array is the clean choice; if you may, reusing grid as the table gives O(1) extra space.

Triangle (LeetCode 120)

Find the minimum path from the top of a triangle to the bottom, moving to an adjacent number on the row below (index j or j+1). Going bottom-up is neat: start with the last row as the base and fold upward, so the answer ends in dp[0] and you need no edge checks.

public int minimumTotal(java.util.List<java.util.List<Integer>> triangle) {
    int n = triangle.size();
    int[] dp = new int[n];
    for (int j = 0; j < n; j++) dp[j] = triangle.get(n - 1).get(j);   // last row
    for (int i = n - 2; i >= 0; i--) {
        for (int j = 0; j <= i; j++) {
            dp[j] = triangle.get(i).get(j) + Math.min(dp[j], dp[j + 1]);
        }
    }
    return dp[0];                              // O(n^2) time, O(n) space
}

Maximal Square (LeetCode 221)

Given a 0/1 matrix, find the area of the largest square of 1s. State: dp[r][c] = side length of the largest square whose bottom-right corner is (r, c). If the cell is 0, it is 0. Otherwise the square is limited by the weakest of its three neighbours: dp[r][c] = 1 + min(up, left, up-left).

public int maximalSquare(char[][] matrix) {
    int m = matrix.length, n = matrix[0].length;
    int[][] dp = new int[m + 1][n + 1];        // extra row and column of zeros: no edge checks
    int side = 0;
    for (int r = 1; r <= m; r++) {
        for (int c = 1; c <= n; c++) {
            if (matrix[r - 1][c - 1] == '1') {
                dp[r][c] = 1 + Math.min(dp[r - 1][c],
                                Math.min(dp[r][c - 1], dp[r - 1][c - 1]));
                side = Math.max(side, dp[r][c]);
            }
        }
    }
    return side * side;                        // area, O(m*n) time and space
}

Why the min of three? A square of side k at the corner needs squares of side k-1 above, to the left and diagonally. Any smaller neighbour is the bottleneck.

Dungeon Game (brief)

A knight moves right/down from top-left to bottom-right; cells add or subtract health; health must stay at least 1. Going forward fails because "best so far" is not enough: you need to know the minimum health required. So run the DP backwards: need[r][c] = minimum health needed when entering the cell. need[r][c] = max(1, min(need[r+1][c], need[r][c+1]) - dungeon[r][c]), with the princess cell using max(1, 1 - dungeon). Lesson: when a forward state is not enough, define it backwards.

Common grid DP mistakes

  • Forgetting to initialise the first row and column (or the padding row) so index -1 is read.
  • Mixing up m (rows) and n (columns) when allocating new int[m][n].
  • In the 1D version, updating in the wrong direction; for right/down grids a left-to-right sweep is correct.

0/1 knapsack: 2D table, then 1D with reverse iteration

0/1 knapsack picks each item at most once to maximise value within a weight limit; the 2D table is dp[i][w], and the 1D version works only if the capacity loop runs from high to low.

You have n items, each with a weight and a value, and a bag that holds weight W. Each item is taken 0 or 1 times (that is the "0/1"). Maximise the total value. Greedy by value-per-weight fails here (it works only for the fractional version). Brute force tries 2n subsets. The DP solves it in O(n·W) — a pseudo-polynomial time, because it depends on the number W, not on its bit length.

The 2D table

  • State: dp[i][w] = best value using only the first i items with capacity w.
  • Transition: for item i either skip it, dp[i-1][w], or take it (if wt[i-1] <= w), dp[i-1][w - wt[i-1]] + val[i-1]. Take the max.
  • Base cases: row 0 (no items) and column 0 (no capacity) are all 0.
  • Order: row by row; each row reads only the previous row.
  • Answer: dp[n][W].
public static int knapsack(int[] wt, int[] val, int W) {
    int n = wt.length;
    int[][] dp = new int[n + 1][W + 1];        // zeros are the base cases
    for (int i = 1; i <= n; i++) {
        for (int w = 0; w <= W; w++) {
            dp[i][w] = dp[i - 1][w];                           // skip item i-1
            if (wt[i - 1] <= w) {
                dp[i][w] = Math.max(dp[i][w],
                        dp[i - 1][w - wt[i - 1]] + val[i - 1]); // take it
            }
        }
    }
    return dp[n][W];
}

Example: weights [1, 3, 4, 5], values [1, 4, 5, 7], W = 7. The best is items of weight 3 and 4 for value 9. Complexity: O(n·W) time and space.

The 1D version and why you iterate backwards

Row i uses only row i-1, so one array can hold "the previous row" and be updated in place. The catch: dp[w] must use the old dp[w - wt] (from row i-1). If you loop w upward, dp[w - wt] has already been updated for item i, so the same item can be counted again and again — you have turned the problem into the unbounded knapsack by accident. Looping w from W down to wt guarantees that smaller indexes are still untouched when you read them.

public static int knapsack1D(int[] wt, int[] val, int W) {
    int[] dp = new int[W + 1];                 // dp[w] = best value with capacity w
    for (int i = 0; i < wt.length; i++) {
        for (int w = W; w >= wt[i]; w--) {     // REVERSE: each item used at most once
            dp[w] = Math.max(dp[w], dp[w - wt[i]] + val[i]);
        }
    }
    return dp[W];                              // O(n*W) time, O(W) space
}

Wrong: forward loop reuses the item

for (int w = wt[i]; w <= W; w++) {
    dp[w] = Math.max(dp[w], dp[w - wt[i]] + val[i]);
}
// weights [3], values [4], W = 9 gives 12 (three copies)

Right: backward loop uses it once

for (int w = W; w >= wt[i]; w--) {
    dp[w] = Math.max(dp[w], dp[w - wt[i]] + val[i]);
}
// same input gives 4 (one copy)

Which items were chosen?

The 1D array loses the history. To recover the chosen items, keep the 2D table and walk back from dp[n][W]: if dp[i][w] != dp[i-1][w], item i-1 was taken, so record it and set w -= wt[i-1]; then move to i-1.

int w = W;
java.util.List<Integer> chosen = new java.util.ArrayList<>();
for (int i = n; i >= 1; i--) {
    if (dp[i][w] != dp[i - 1][w]) {            // value changed, so item i-1 was taken
        chosen.add(i - 1);
        w -= wt[i - 1];
    }
}

Recognising a 0/1 knapsack in disguise

Look for "choose a subset, each element at most once, with a limit or a target": subset sum, partition, target sum, last stone weight II, ones and zeroes (a 2D capacity). The next article turns these into small variations of the same loop. The unbounded sibling is in Unbounded knapsack and rod cutting.

Pseudo-polynomial time

O(n·W) looks polynomial, but with W = 109 the table cannot be built. Knapsack is NP-hard in general; the DP only helps when W is small. If the constraints give W up to 109 but values are small, swap the roles: let the DP index be total value and store the minimum weight.

Why greedy fails and why the DP is correct

A greedy idea is to sort by value per weight and take items until the bag is full. On the example above the ratios are 1, 1.33, 1.25 and 1.4, so greedy takes the weight-5 item (value 7) first, then only the weight-1 item fits in the remaining 2 units: total 8. The true best is 9 (weights 3 and 4). Greedy fails because items are indivisible: a good-looking item can waste space that two other items would use better. The DP never commits early; for every capacity it keeps the best answer over both choices for the current item.

Correctness follows from the "take or skip" split. Any best selection for the first i items either does not contain item i (then it is a best selection for the first i-1 items at the same capacity) or contains it (then the rest is a best selection for the first i-1 items at capacity w - wt). Those two cases cover every possibility, and the table stores the best of each.

The same recurrence top-down

In an interview you can start from the recursion and then convert it. The state is (index of the item, remaining capacity). The memo table has n × W cells, which is why the time is O(n·W).

static int solve(int i, int w, int[] wt, int[] val, int[][] memo) {
    if (i == wt.length || w == 0) return 0;           // no items or no room left
    if (memo[i][w] != -1) return memo[i][w];
    int best = solve(i + 1, w, wt, val, memo);        // skip item i
    if (wt[i] <= w) {                                 // take item i if it fits
        best = Math.max(best, val[i] + solve(i + 1, w - wt[i], wt, val, memo));
    }
    return memo[i][w] = best;
}
// call: fill every row of memo with -1, then solve(0, W, wt, val, memo)

Recursion depth is n, so for n in the thousands prefer the iterative table. Without the memo the same code is O(2n).

At most W versus exactly W

The code above fills the bag up to W: all cells start at 0, so unused space is allowed. Some problems demand that the weight equals the target exactly (subset sum with value, "can you fill the bag exactly"). Then initialise dp[0] = 0 and every other cell to negative infinity (a large negative number, or a separate boolean array), so that unreachable capacities are never extended. The recurrence does not change; only the starting values do.

When W is huge but n is small

If W is around 109 and n is at most about 40, the table is impossible, but 2n is also too big. A meet in the middle approach splits the items into two halves, lists all subset (weight, value) pairs of each half (220 each), sorts one list, and combines with binary search. It runs in about O(2n/2 · n). It is rarely required, but it shows you know where the DP stops working.

Edge cases

  • An item heavier than W: the inner loop w >= wt[i] never runs, so the item is skipped. No exception, no special case.
  • W = 0 or no items: the answer is 0 from the initial array.
  • Weight 0 with positive value: the reverse loop adds that value exactly once (it reads the old dp[w]), which is correct for 0/1. In an unbounded problem such an item would give an infinite answer.
  • Negative weight or value: the recurrence assumes non-negative numbers. A negative weight makes w - wt[i] exceed W and read outside the array.
  • Large values: total value can exceed int; use long when values are large.

Mistake: a 1D array with a forward loop

Wrong: forward loop reuses the item

for (int w = wt[i]; w <= W; w++)
    dp[w] = Math.max(dp[w], dp[w - wt[i]] + val[i]);   // 1D array, forward

Right: read the previous row (2D) or go backward (1D)

dp2[i][w] = Math.max(dp2[i - 1][w], dp2[i - 1][w - wt[i - 1]] + val[i - 1]);
// or, with one array: for (int w = W; w >= wt[i]; w--) ...

Interview angle

Two questions are common: "optimise the space" (answer: 1D array, reverse loop) and "why reverse?" (answer: forward lets the same item be used twice because dp[w - wt] already includes it).

Subset sum, partition, target sum and counting subsets

These four problems are the 0/1 knapsack with a boolean or count in place of a value: iterate items, loop the sum downwards, and either OR, or add, the "without this item" answer.

Once you can write the 1D 0/1 loop, the next problems are mostly a change of what dp[s] stores. The structure never changes: for each item, for s from target down to item.

Subset sum (can we reach exactly T?)

State: dp[s] = true if some subset of the items seen so far sums to s. Base: dp[0] = true (the empty subset). Transition: dp[s] |= dp[s - x].

public static boolean subsetSum(int[] nums, int target) {
    boolean[] dp = new boolean[target + 1];
    dp[0] = true;                              // the empty subset makes 0
    for (int x : nums) {
        for (int s = target; s >= x; s--) {    // reverse: use each number once
            dp[s] = dp[s] || dp[s - x];
        }
    }
    return dp[target];                         // O(n * target) time, O(target) space
}

Partition Equal Subset Sum (LeetCode 416)

Can the array be split into two subsets with equal sums? Let total be the sum. If it is odd, the answer is no. Otherwise ask for a subset summing to total / 2; the rest then also sums to total / 2.

public boolean canPartition(int[] nums) {
    int total = 0;
    for (int x : nums) total += x;
    if (total % 2 != 0) return false;          // odd sums cannot split evenly
    int target = total / 2;
    boolean[] dp = new boolean[target + 1];
    dp[0] = true;
    for (int x : nums) {
        for (int s = target; s >= x; s--) dp[s] |= dp[s - x];
        if (dp[target]) return true;           // early exit
    }
    return dp[target];
}

For [1, 5, 11, 5], total 22, target 11: 11 alone works, so true. Complexity: O(n · total/2) time, O(total/2) space. A bitset (java.util.BitSet or a long shift trick) is a faster constant but not needed in interviews.

Count of subsets with a given sum

Now count rather than decide. State: dp[s] = number of subsets giving sum s. Base: dp[0] = 1. Transition: dp[s] += dp[s - x] (the subsets without x are already in dp[s]; those with x come from dp[s - x]). Reverse loop again.

public static int countSubsets(int[] nums, int target) {
    int[] dp = new int[target + 1];
    dp[0] = 1;                                 // one way to make 0: take nothing
    for (int x : nums) {
        for (int s = target; s >= x; s--) {
            dp[s] += dp[s - x];
        }
    }
    return dp[target];                         // use long if the count can be huge
}

Zeros change the count

If nums may contain 0, then a zero can be in or out of any subset, so the answer doubles per zero. The loop above handles it correctly only when x = 0 is allowed to run: the inner loop s >= 0 then does dp[s] += dp[s] in reverse order, which doubles every entry — correct. Always test with a zero in the input.

Target Sum (LeetCode 494)

Put a + or - before every number; how many ways reach target? Let P be the sum of numbers with + and N the sum with -. Then P - N = target and P + N = total, so P = (total + target) / 2. The problem becomes "count subsets with sum P". Guard the impossible cases: total + target odd, or |target| > total.

public int findTargetSumWays(int[] nums, int target) {
    int total = 0;
    for (int x : nums) total += x;
    if (Math.abs(target) > total || (total + target) % 2 != 0) return 0;
    int p = (total + target) / 2;              // the sum of the numbers that get '+'
    int[] dp = new int[p + 1];
    dp[0] = 1;
    for (int x : nums) {
        for (int s = p; s >= x; s--) dp[s] += dp[s - x];
    }
    return dp[p];                              // O(n * p) time, O(p) space
}

For [1,1,1,1,1] with target 3: total 5, P = 4; subsets of four 1s: C(5,4) = 5. Answer 5.

Last Stone Weight II (idea)

Smashing stones is the same as splitting them into two groups and minimising the difference of the sums. Find the largest subset sum s <= total/2 that is reachable; the answer is total - 2 * s. It is subset sum with a "closest to half" read at the end.

Mistakes to avoid

  • Looping s upward: numbers get reused (this becomes combination counting with unlimited copies).
  • Forgetting the odd-total check in partition, or the sign/parity check in target sum.
  • Negative array values in subset sum: the array index would be negative. These problems assume non-negative numbers.

Dry runs: what the array holds

Decide (partition). For [1, 5, 11, 5] the target is 11. Think of dp as the set of reachable sums. It starts as {0}. Item 1 adds 1: {0, 1}. Item 5 adds 5 to each existing sum: {0, 1, 5, 6}. Item 11 adds 11: {0, 1, 5, 6, 11, ...}, and 11 is the target, so the answer is true. The reverse loop is what prevents "5 + 5 + 1" from being built out of one 5: while processing the first 5 the loop reads only sums that existed before it.

Minimum subset sum difference and Last Stone Weight II

Split the array into two groups so that the difference of their sums is as small as possible. If one group has sum s, the other has total - s, and the difference is total - 2s. To make this small, make s as close to total/2 from below as possible. So run subset sum up to total/2 and take the largest reachable s.

public static int minDifference(int[] nums) {
    int total = 0;
    for (int x : nums) total += x;
    int half = total / 2;
    boolean[] dp = new boolean[half + 1];
    dp[0] = true;
    for (int x : nums) {
        for (int s = half; s >= x; s--) dp[s] |= dp[s - x];
    }
    for (int s = half; s >= 0; s--) {          // largest reachable sum not above half
        if (dp[s]) return total - 2 * s;
    }
    return total;                              // not reached: dp[0] is always true
}
// [2, 7, 4, 1, 8, 1]: total 23, half 11, s = 11 (2+7+1+1) -> 23 - 22 = 1

Last Stone Weight II is this exact code: smashing stones equals choosing signs, which equals splitting into two groups.

Which subset? Reconstruction

A 1D boolean array cannot tell you which numbers were used. Keep the 2D table reach[i][s] = "can the first i numbers make sum s", then walk back from reach[n][target]: if reach[i-1][s] is true, item i-1 was not needed; otherwise it was used, so record it and subtract its value from s. The cost is O(n · target) memory, so do it only when the question asks for the set itself.

Edge cases

  • Target 0: always true (the empty subset), and the count includes that empty subset. With zeros in the array the count of subsets for target 0 is 2 raised to the number of zeros.
  • Target larger than the total: the answer is false or 0. Check this first; otherwise you allocate a huge array for nothing.
  • Target Sum with target negative: the sign split is symmetric, so use Math.abs(target). The code above already rejects |target| > total and a wrong parity.
  • Counts overflow: a count of subsets can reach 2n. If the problem does not promise it fits in int, use long or a modulo such as 109 + 7.
  • Negative numbers: not supported by these loops; you would need an offset or a map from sum to count.

Mistake: using a forward loop for counting

Wrong: each number can be used many times

for (int x : nums)
    for (int s = x; s <= target; s++) dp[s] += dp[s - x];
// [1,2,3], target 3 gives 3 (adds 1+1+1), not 2

Right: backward loop, each number once

for (int x : nums)
    for (int s = target; s >= x; s--) dp[s] += dp[s - x];
// [1,2,3], target 3 gives 2

Interview angle

Partition Equal Subset Sum is the usual first question. A strong answer says four things: the odd-total shortcut, the reduction to "subset with sum total/2", the 1D boolean array with a reverse loop, and the time O(n · total/2). Then expect two follow-ups: "count the ways" (change OR to plus and the base to 1) and "what if the numbers are large?" (the DP is pseudo-polynomial; with a big sum you need another idea, such as meet in the middle for small n). For Target Sum, show the algebra: P − N = target and P + N = total, so P = (total + target) / 2.

Unbounded knapsack, rod cutting, and the knapsack variants table

In unbounded knapsack each item can be used any number of times, so the capacity loop runs forward (low to high); rod cutting and coin change are the same recurrence.

"Unbounded" means unlimited copies of every item. The recurrence is dp[w] = max(dp[w], dp[w - wt] + val) — identical to 0/1 — but you want the item to be reusable, so dp[w - wt] should already include the current item. That is exactly what a forward loop gives. The whole difference between the two knapsacks is the loop direction.

Unbounded knapsack

public static int unbounded(int[] wt, int[] val, int W) {
    int[] dp = new int[W + 1];                 // dp[w] = best value with capacity w
    for (int i = 0; i < wt.length; i++) {
        for (int w = wt[i]; w <= W; w++) {     // FORWARD: item i may be reused
            dp[w] = Math.max(dp[w], dp[w - wt[i]] + val[i]);
        }
    }
    return dp[W];                              // O(n*W) time, O(W) space
}

With weights [2, 3], values [3, 5], W = 7: two items of weight 2 and one of weight 3 give 3 + 3 + 5 = 11; three items of weight 2 give only 9. The best is 11.

Rod cutting

A rod of length n can be cut into integer pieces; price[k] is the price of a piece of length k+1. Maximise the total price. Each piece length is an "item" with weight = length and value = price, unlimited copies, and the rod length is the capacity — an unbounded knapsack where you must fill the capacity exactly (it always can, using pieces of length 1).

public static int rodCutting(int[] price, int n) {
    int[] dp = new int[n + 1];                 // dp[len] = best revenue for a rod of length len
    for (int len = 1; len <= n; len++) {
        for (int cut = 1; cut <= len && cut <= price.length; cut++) {
            dp[len] = Math.max(dp[len], price[cut - 1] + dp[len - cut]);
        }
    }
    return dp[n];                              // O(n^2) time, O(n) space
}

For prices [1, 5, 8, 9, 10, 17, 17, 20] and n = 8 the answer is 22 (cut into 2 and 6: 5 + 17).

Coin change as unbounded knapsack

Coin change is the same shape: coins are items of unlimited supply. For the minimum number of coins, dp[w] = min(dp[w], dp[w - c] + 1) with dp[0] = 0 and "infinity" elsewhere. For the number of ways, dp[w] += dp[w - c] with the coin loop on the outside — that outer-coin order counts combinations, not permutations, as shown in that article.

Ones and Zeroes (2D capacity, brief)

Choose the largest subset of binary strings using at most m zeros and n ones. Each string is an item with two weights. Use dp[z][o] and loop both downwards for each string: it is 0/1 knapsack with a two-dimensional bag.

One question decides the loop direction

Ask: "may the same item be used again for this capacity?" If yes, go forward (low to high) so the updated cell is visible. If no, go backward (high to low) so only the old cells are visible.

Loop order: when it matters

For maximum or minimum answers, the order of the two loops does not change the result: both "items outside, capacity inside" and "capacity outside, items inside" explore all multisets. It matters when you count:

  • Items outside, capacity inside: each combination is counted once, in the order of the items. This is Coin Change II (combinations).
  • Capacity outside, items inside: the same coins in a different order count again, so you get permutations. This is Combination Sum IV.

For rod cutting above we used capacity outside and cuts inside; it is fine because we only take a maximum.

Another problem: Perfect Squares

The fewest perfect squares that sum to n. The "items" are 1, 4, 9, 16, ... with unlimited copies, the "capacity" is n, and each item has cost 1. That is unbounded knapsack with a minimum. For n = 12 the answer is 3 (4 + 4 + 4).

public int numSquares(int n) {
    int[] dp = new int[n + 1];                 // dp[i] = fewest squares summing to i
    java.util.Arrays.fill(dp, n + 1);          // n + 1 acts as infinity (1+1+...+1 needs only i)
    dp[0] = 0;
    for (int i = 1; i <= n; i++) {
        for (int j = 1; j * j <= i; j++) {
            dp[i] = Math.min(dp[i], dp[i - j * j] + 1);
        }
    }
    return dp[n];                              // O(n * sqrt(n)) time, O(n) space
}

Ones and Zeroes in code (2D capacity)

Each binary string costs some zeros and some ones, and each string can be used once, so both capacity loops run downwards.

public int findMaxForm(String[] strs, int m, int n) {
    int[][] dp = new int[m + 1][n + 1];        // dp[z][o] = most strings using at most z zeros, o ones
    for (String s : strs) {
        int zeros = 0, ones = 0;
        for (char c : s.toCharArray()) {
            if (c == '0') zeros++; else ones++;
        }
        for (int z = m; z >= zeros; z--) {
            for (int o = n; o >= ones; o--) {
                dp[z][o] = Math.max(dp[z][o], dp[z - zeros][o - ones] + 1);
            }
        }
    }
    return dp[m][n];                           // O(len * m * n) time, O(m * n) space
}

Bounded knapsack: each item has a limit

Between 0/1 (one copy) and unbounded (infinite copies) is the bounded version: item i has cnt[i] copies. The simplest method is to treat every copy as a separate 0/1 item, which costs O(W · total copies). A faster method splits cnt into pieces of size 1, 2, 4, ... plus a remainder, and treats each piece as one 0/1 item of weight and value multiplied by the piece size. Any number of copies from 0 to cnt can be formed from these pieces.

for (int i = 0; i < wt.length; i++) {
    int left = cnt[i];
    for (int k = 1; left > 0; k <<= 1) {
        int take = Math.min(k, left);
        left -= take;
        int w = take * wt[i], v = take * val[i];       // a bundle of 'take' copies
        for (int c = W; c >= w; c--) {                 // 0/1 loop: backward
            dp[c] = Math.max(dp[c], dp[c - w] + v);
        }
    }
}

Edge cases

  • Weight 0 and positive value: the forward loop would grow forever in theory (an unlimited gain). Problems rule this out; check the constraints.
  • No exact fit: in "fill exactly W" versions (coin change) use a large sentinel and test it at the end; return −1 if W cannot be made.
  • Rod longer than the price list: in rod cutting, cap the cut length by price.length (the loop above does) or price[cut - 1] throws ArrayIndexOutOfBoundsException.
  • Overflow with sentinel: Integer.MAX_VALUE + 1 becomes negative. Use a smaller sentinel such as W + 1 or guard the addition.

Interview angle

A favourite follow-up is "what changes between 0/1 and unbounded?" Answer in one line: the direction of the inner loop. Be ready to prove it with a one-item example (weight 3, value 4, W = 9).
