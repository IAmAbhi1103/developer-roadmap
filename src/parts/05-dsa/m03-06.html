Union-Find (Disjoint Set Union)

Union-find keeps a collection of disjoint groups and answers "are these two in the same group?" and "merge their groups" in nearly O(1) amortized time, using a parent array with path compression and union by size.

Suppose people join friend groups one friendship at a time, and after each friendship you must answer "are Asha and Ravi in the same group?" or "how many groups are there now?". A DFS after every update would cost O(V + E) each time. The union-find structure (also called disjoint set union, DSU) handles a stream of merges and queries in almost constant time per operation. It is the natural tool for dynamic connectivity, Kruskal's algorithm, cycle detection in undirected graphs and grouping problems.

How it works

Every group is a tree stored in a parent[] array. Each element points to a parent; the root points to itself and acts as the group's representative. Two elements are in the same group exactly when they have the same root.

  • find(x) — follow parents up to the root.
  • union(a, b) — find both roots; if they differ, hang one root under the other.

Used naively, the trees can become long chains and find costs O(n). Two small optimisations fix that:

Path compression
While walking up in find, make the visited nodes point closer to (or directly at) the root. The next find on any of them is short. The code below uses path halving: each node on the way is re-pointed to its grandparent, a one-line iterative form of compression.
Union by size (or rank)
When merging, hang the smaller tree under the larger one. Trees then stay shallow: the height is at most log n.

With both, the amortized cost per operation is O(α(n)), where α is the inverse Ackermann function. It grows so slowly that α(n) is at most 4 for any n you can store; treat it as "nearly constant". With only one of the two optimisations the cost is O(log n) amortized.

Java template

public class UnionFind {
    private final int[] parent;
    private final int[] size;        // size of the tree whose root is i (valid only for roots)
    private int components;          // number of groups

    public UnionFind(int n) {
        parent = new int[n];
        size = new int[n];
        components = n;
        for (int i = 0; i < n; i++) {
            parent[i] = i;           // everyone is their own root
            size[i] = 1;
        }
    }

    public int find(int x) {
        while (parent[x] != x) {
            parent[x] = parent[parent[x]];   // path halving: skip to the grandparent
            x = parent[x];
        }
        return x;
    }

    // returns true if a merge happened, false if a and b were already in the same group
    public boolean union(int a, int b) {
        int ra = find(a), rb = find(b);
        if (ra == rb) return false;
        if (size[ra] < size[rb]) { int t = ra; ra = rb; rb = t; }   // ra is the larger root
        parent[rb] = ra;                     // hang the smaller tree under the larger
        size[ra] += size[rb];
        components--;
        return true;
    }

    public boolean connected(int a, int b) { return find(a) == find(b); }

    public int components() { return components; }
    public int sizeOf(int x) { return size[find(x)]; }
}

The boolean result of union is the key trick: false means "this edge joins two vertices that were already connected", that is, the edge closes a cycle. The recursive form of find is if (parent[x] != x) parent[x] = find(parent[x]); return parent[x];; it is shorter but recurses as deep as the tree, so the iterative form is safer.

Problem 1 — Number of Provinces (LeetCode 547)

Same problem as in the traversal article, solved with union-find: union every pair of directly connected cities, then return the component count.

public class ProvincesUnionFind {
    public static int findCircleNum(int[][] isConnected) {
        int n = isConnected.length;
        UnionFind uf = new UnionFind(n);
        for (int i = 0; i < n; i++) {
            for (int j = i + 1; j < n; j++) {          // upper triangle is enough (symmetric)
                if (isConnected[i][j] == 1) uf.union(i, j);
            }
        }
        return uf.components();
    }

    public static void main(String[] args) {
        System.out.println(findCircleNum(new int[][]{{1, 1, 0}, {1, 1, 0}, {0, 0, 1}}));  // 2
    }
}

Complexity: O(n² · α(n)) because the input is an n × n matrix. With an edge list of E pairs it is O((n + E) · α(n)).

Problem 2 — Redundant Connection (LeetCode 684)

A tree with n nodes (labelled 1..n) had one extra edge added, so it now has exactly one cycle. Return the edge that can be removed to make it a tree again; if several work, return the one that appears last in the input.

Idea. Add the edges in order. The first edge whose endpoints are already connected is the one that closes the cycle — and since we process in input order, it is the last of the cycle's edges to appear.

public class RedundantConnection {
    public static int[] findRedundantConnection(int[][] edges) {
        UnionFind uf = new UnionFind(edges.length + 1);    // labels are 1..n, so size n + 1
        for (int[] e : edges) {
            if (!uf.union(e[0], e[1])) return e;           // already connected: this closes a cycle
        }
        return new int[0];                                 // not reached for valid input
    }

    public static void main(String[] args) {
        int[][] edges = {{1, 2}, {1, 3}, {2, 3}};
        System.out.println(java.util.Arrays.toString(findRedundantConnection(edges)));  // [2, 3]
    }
}

Complexity: O(n · α(n)) time, O(n) space. A DFS-based solution would cost O(n²).

Problem 3 — Accounts Merge (LeetCode 721), briefly

Each account is a name followed by email addresses. Two accounts belong to the same person if they share an email. Merge them and return, for each person, the name and the sorted list of all their emails.

Idea. The accounts are the elements. Walk through all emails and remember which account first used each email in a map. When an email appears again, union the two accounts. At the end, group emails by the root of their account, sort each group and put the name in front.

import java.util.ArrayList;
import java.util.HashMap;
import java.util.List;
import java.util.Map;
import java.util.TreeSet;

public class AccountsMerge {
    public static List<List<String>> accountsMerge(List<List<String>> accounts) {
        int n = accounts.size();
        UnionFind uf = new UnionFind(n);
        Map<String, Integer> owner = new HashMap<>();          // email → first account index
        for (int i = 0; i < n; i++) {
            List<String> acc = accounts.get(i);
            for (int j = 1; j < acc.size(); j++) {              // index 0 is the name
                Integer prev = owner.putIfAbsent(acc.get(j), i);
                if (prev != null) uf.union(prev, i);            // shared email → same person
            }
        }
        Map<Integer, TreeSet<String>> groups = new HashMap<>();   // TreeSet keeps emails sorted
        for (Map.Entry<String, Integer> e : owner.entrySet()) {
            groups.computeIfAbsent(uf.find(e.getValue()), k -> new TreeSet<>()).add(e.getKey());
        }
        List<List<String>> result = new ArrayList<>();
        for (Map.Entry<Integer, TreeSet<String>> g : groups.entrySet()) {
            List<String> row = new ArrayList<>();
            row.add(accounts.get(g.getKey()).get(0));            // the person's name
            row.addAll(g.getValue());
            result.add(row);
        }
        return result;
    }
}

Complexity: with N total emails and longest email length L: O(N · α · L) for the unions and map work plus O(N log N · L) for sorting. Space O(N · L).

Other uses

  • Kruskal's minimum spanning tree — next article.
  • Number of Islands II (cells become land one at a time) — union with land neighbours, report the component count after each step; far better than recomputing with DFS.
  • Graph Valid Tree: n − 1 edges and no union returns false (or exactly one component).
  • Satisfiability of Equality Equations, Most Stones Removed, Smallest String With Swaps: group by connectivity, then answer per group.

Rule: always compare roots, never raw parents

Two elements are in the same group when find(a) == find(b). Comparing parent[a] == parent[b] is wrong because the parent array is not fully flattened: elements of one group can have different parents.

Mistake: union without finding roots

Wrong: links the elements, not their roots

void union(int a, int b) {
    parent[a] = b;          // a's old group is split off from a's old root
}

Right: link the roots

void union(int a, int b) {
    int ra = find(a), rb = find(b);
    if (ra != rb) parent[ra] = rb;
}

Limits and edge cases

  • No delete / split. Union-find only merges. If groups can also split, process the operations in reverse (turn deletions into merges) or use another structure.
  • Labels from 1..n need an array of size n + 1; labels that are strings or large numbers need a map from label to index first.
  • Directed connectivity (strongly connected components) is not union-find's job; it ignores direction.
  • sizeOf must go through find — size[x] is valid only at a root.

Interview angle

Describe the data structure in one sentence ("a forest in an array; the root is the group's name"), name both optimisations and the resulting O(α(n)) amortized time, and mention union returning a boolean for cycle detection. Compare with DFS: DFS is better for a single static query; union-find is better when edges arrive over time and you query connectivity repeatedly.

Minimum spanning tree: Kruskal and Prim

A minimum spanning tree connects all vertices of a weighted undirected graph with V − 1 edges of the smallest possible total weight; Kruskal sorts the edges and adds each one that does not close a cycle (checked with union-find), while Prim grows one tree from a start vertex using a min-heap.

A spanning tree of a connected undirected graph is a subset of its edges that connects all V vertices without any cycle; it always has exactly V − 1 edges. Among all spanning trees, the one with the smallest total weight is the minimum spanning tree (MST). Think of laying cable to connect all offices of a company: you want everyone connected, no wasted loops, and the lowest total cost. MSTs also appear in network design, clustering, and approximations for hard problems.

Do not confuse MST with shortest paths. A shortest-path tree minimises the distance from one source to each vertex; an MST minimises the total weight of the connecting edges and has no source.

Why greedy works: the cut property

Split the vertices into two non-empty sets in any way (a cut). The cheapest edge crossing the cut belongs to some MST. (If it did not, adding it to an MST would create a cycle that crosses the cut at least once more; removing that other crossing edge, which is not cheaper, gives a spanning tree that is no worse.) Both algorithms below keep picking such a "safe" cheapest edge, so they are exchange-argument greedy algorithms. If all edge weights are distinct, the MST is unique.

Kruskal's algorithm: sort edges, skip cycles

  1. Sort all edges by weight, smallest first.
  2. For each edge (u, v, w): if u and v are in different components (union returns true), take the edge and add w to the total.
  3. Stop when V − 1 edges are taken. If fewer, the graph is disconnected and has no spanning tree (only a spanning forest).
import java.util.Arrays;

public class Kruskal {
    // edges[i] = {u, v, w}; returns the MST weight, or -1 if the graph is disconnected
    public static int mstWeight(int n, int[][] edges) {
        int[][] sorted = edges.clone();
        Arrays.sort(sorted, (a, b) -> Integer.compare(a[2], b[2]));   // cheapest first
        UnionFind uf = new UnionFind(n);
        int total = 0, taken = 0;
        for (int[] e : sorted) {
            if (uf.union(e[0], e[1])) {            // different components: safe to connect
                total += e[2];
                if (++taken == n - 1) break;       // a spanning tree has n - 1 edges
            }                                      // else: would close a cycle, skip
        }
        return taken == n - 1 ? total : -1;
    }

    public static void main(String[] args) {
        int[][] edges = {{0, 1, 10}, {0, 2, 6}, {0, 3, 5}, {1, 3, 15}, {2, 3, 4}};
        System.out.println(mstWeight(4, edges));   // 19
    }
}

Dry run on the example: sorted weights are 4 (2-3), 5 (0-3), 6 (0-2), 10 (0-1), 15 (1-3). Take 2-3 (total 4). Take 0-3 (total 9). Edge 0-2: 0 and 2 are already connected through 3 → skip. Take 0-1 (total 19) — three edges, done. The MST is {2-3, 0-3, 0-1} with weight 19.

Complexity: O(E log E) for the sort (equal to O(E log V), since E ≤ V²) plus O(E · α(V)) for the unions, so O(E log E) overall; O(V) extra space for union-find. Kruskal is the simplest MST code to write in an interview because it needs only an edge list and the DSU class you already have.

Prim's algorithm: grow one tree

Start from any vertex. Keep a min-heap of edges leaving the current tree. Repeatedly pop the cheapest edge; if its far end is already in the tree, skip it (stale), otherwise add that vertex and push its edges. It resembles Dijkstra, with one difference: the heap key is the weight of the single connecting edge, not the total distance from the source.

import java.util.List;
import java.util.PriorityQueue;

public class Prim {
    // g.get(u) holds {neighbour, weight}; undirected graph (each edge stored both ways)
    public static int mstWeight(List<List<int[]>> g) {
        int n = g.size();
        boolean[] inTree = new boolean[n];
        PriorityQueue<int[]> pq = new PriorityQueue<>((a, b) -> Integer.compare(a[0], b[0]));
        pq.add(new int[]{0, 0});                     // {edge weight, vertex}: enter at vertex 0
        int total = 0, taken = 0;
        while (!pq.isEmpty() && taken < n) {
            int[] cur = pq.poll();
            int w = cur[0], u = cur[1];
            if (inTree[u]) continue;                 // far end already connected: skip
            inTree[u] = true;
            total += w;
            taken++;
            for (int[] e : g.get(u)) {
                if (!inTree[e[0]]) pq.add(new int[]{e[1], e[0]});   // edge to a new vertex
            }
        }
        return taken == n ? total : -1;              // -1: graph is disconnected
    }

    public static void main(String[] args) {
        int[][] edges = {{0, 1, 10}, {0, 2, 6}, {0, 3, 5}, {1, 3, 15}, {2, 3, 4}};
        System.out.println(mstWeight(GraphBuilder.buildWeighted(4, edges, false)));   // 19
    }
}

Complexity: O(E log V) time with a binary heap, O(V + E) space. For a dense graph (E near V²) the array version, which scans for the minimum instead of using a heap, runs in O(V²) and is faster; see the next problem.

Problem — Min Cost to Connect All Points (LeetCode 1584)

Points on a plane; the cost between two points is their Manhattan distance |x1 − x2| + |y1 − y2|. Find the minimum cost to connect all points. Every pair is connected, so the graph is complete: E = V(V − 1) / 2. Building and sorting all edges (Kruskal) costs O(V² log V); the heapless Prim below is O(V²) and uses only O(V) memory.

import java.util.Arrays;

public class MinCostConnectPoints {
    public static int minCostConnectPoints(int[][] p) {
        int n = p.length;
        int[] minDist = new int[n];            // cheapest known edge from the tree to vertex i
        boolean[] used = new boolean[n];
        Arrays.fill(minDist, Integer.MAX_VALUE);
        minDist[0] = 0;
        int total = 0;
        for (int step = 0; step < n; step++) {
            int u = -1;
            for (int i = 0; i < n; i++) {                     // pick the closest outside vertex
                if (!used[i] && (u == -1 || minDist[i] < minDist[u])) u = i;
            }
            used[u] = true;
            total += minDist[u];
            for (int v = 0; v < n; v++) {                     // update distances to the tree
                if (!used[v]) {
                    int d = Math.abs(p[u][0] - p[v][0]) + Math.abs(p[u][1] - p[v][1]);
                    if (d < minDist[v]) minDist[v] = d;
                }
            }
        }
        return total;
    }

    public static void main(String[] args) {
        int[][] points = {{0, 0}, {2, 2}, {3, 10}, {5, 2}, {7, 0}};
        System.out.println(minCostConnectPoints(points));   // 20
    }
}

Complexity: O(n²) time, O(n) space.

Problems that are MST in disguise

  • Connecting Cities With Minimum Cost and Min Cost to Connect All Points — direct MST.
  • Optimize Water Distribution in a Village — add a virtual vertex 0 joined to each house with the well-building cost, then MST.
  • Critical and Pseudo-Critical Edges in the MST — compute the MST weight with and without each edge (advanced).
  • Maximum spanning tree — sort descending.
  • Clustering into k groups — run Kruskal and stop when k components remain.

Mistake: using an MST when the question asks for shortest paths

The MST path between two vertices is not necessarily the shortest path between them. In a triangle with edge weights 1, 1 and 1.5, the MST skips the 1.5 edge, so the route between its two endpoints inside the MST costs 2, while the real shortest path is the direct edge with cost 1.5. Read whether the problem wants total cost of connecting everything (MST) or distance between specific vertices (shortest path).

Mistake: forgetting to check connectivity

If the graph is disconnected there are fewer than V − 1 usable edges. Return −1 (or whatever the problem says) when taken != n − 1 instead of returning a partial total.

Edge cases

  • A single vertex → MST weight 0.
  • Equal weights → several different MSTs exist, but all have the same total weight; if the problem asks for the tree itself, any valid one is accepted unless stated otherwise.
  • Negative weights are fine for both algorithms (unlike Dijkstra).
  • Directed graphs: the problem is different (minimum arborescence, Edmonds' algorithm) and not asked in interviews.

Interview angle

Know the definition (V − 1 edges, minimum total weight, no cycles), the cut-property reason that greedy works, and both algorithms with complexities. Say "I will use Kruskal since the edges are given as a list; union-find tells me whether an edge closes a cycle." If asked for dense graphs, mention array-based Prim in O(V²).

Which graph algorithm should I use?

Pick the shortest-path algorithm from three facts — are edges weighted, can they be negative, is the graph a DAG — and pick the structure algorithm from the question: groups (DFS or union-find), order (topological sort), cheapest connection (MST).

In an interview the hardest step is often choosing the algorithm, not writing it. The tables below summarise the choices in this module. Use them as a checklist when you read a graph problem: first model the graph (what are the vertices, what are the edges, are they directed, weighted?), then match the question.

A worked decision

Problem: "A delivery app has n junctions and roads with travel times in minutes. Find the fastest time from the restaurant to every customer." Vertices are junctions, edges are roads, weighted with positive times, one source → single-source shortest path with non-negative weights → Dijkstra. If a road also had a "toll refund" of −2 minutes, Dijkstra could be wrong → Bellman-Ford. If the app asked "which pair of junctions is farthest apart" on 300 junctions, → Floyd-Warshall.

Mistake: BFS on a weighted graph

BFS minimises the number of edges, not the total weight. On weighted graphs it can return a path with fewer roads but a longer distance. If someone says "shortest path", always ask what is being measured.

Tip: questions to ask the interviewer

  • Directed or undirected? Weighted? Can weights be zero or negative?
  • Can the graph have cycles, self-loops or parallel edges? Is it connected?
  • How large are V and E? (This decides between O(V²), O(V³) and heap-based solutions.)

Interview angle

Interviewers often ask the table itself: "when would you use BFS, Dijkstra, Bellman-Ford?" Answer with the three conditions (weighted? negative? edge limit?) and the complexities. Naming a trade-off — for example "Dijkstra is faster, but only valid without negative edges" — is worth more than reciting code.
