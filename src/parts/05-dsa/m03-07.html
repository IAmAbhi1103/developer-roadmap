Interview questions — Backtracking, greedy and graphs

What is backtracking, and how is it different from plain recursion and from DFS?

Recursion is the tool, DFS is a traversal order, and backtracking is a search strategy built on both. It builds a solution step by step in one shared state: choose an option, recurse, then undo the option before trying the next one. It prunes any branch that already breaks a rule. Plain DFS on a graph keeps visited vertices marked; backtracking un-marks them, because a different path may legitimately reuse them.

Write the backtracking template and name the three things that go wrong most often.

Skeleton: if the state is complete, record a copy and return; for each valid choice, apply it, recurse, undo it.

void backtrack(List<Integer> path, int start) {
    result.add(new ArrayList<>(path));          // record a COPY
    for (int i = start; i < nums.length; i++) {
        path.add(nums[i]);                      // choose
        backtrack(path, i + 1);                 // explore
        path.remove(path.size() - 1);           // un-choose
    }
}

Common bugs: storing the live path instead of a copy, forgetting to undo one of several changes (for example used[i]), and calling path.remove(nums[i]), which removes by index for an int argument.

How do you avoid duplicate results in Subsets II, Combination Sum II and Permutations II?

Sort the input so equal values are neighbours, then skip a value that equals its left neighbour at the same level. For subsets and combinations the rule is if (i > start && a[i] == a[i - 1]) continue;. For permutations it is if (i > 0 && a[i] == a[i - 1] && !used[i - 1]) continue;, which forces equal values to be used left to right. Using i > 0 in the first rule is wrong, because it also blocks legal picks such as the second 2 in [2, 2]. A Set of results works but wastes time generating duplicates.

What is the time complexity of generating all subsets, all permutations and N-Queens?

Subsets: O(n · 2n) — 2n subsets, O(n) to copy each. Permutations: O(n · n!). Combinations of k from n: O(k · C(n, k)). N-Queens: O(n!) as an upper bound on placements tried, much less with pruning. In every case the extra space is O(n) for the path and recursion, not counting the output. The input limits give it away: n ≤ 20 hints at 2n, n ≤ 10 at n!.

How does N-Queens check conflicts in O(1)?

Place one queen per row, so rows never conflict. Keep three boolean arrays: columns, diagonals indexed by row − col + n − 1 and anti-diagonals indexed by row + col. All cells on one diagonal share row − col; all cells on one anti-diagonal share row + col. A square is safe if all three entries are false. Set them to true when you place a queen and back to false when you undo it. Checking earlier rows by scanning would cost O(n) per square.

When is a greedy algorithm correct? Give a proof idea and a counter-example.

It needs the greedy-choice property (some optimal solution contains the greedy choice) and optimal substructure. You usually prove it with an exchange argument: take any optimal solution, swap one of its choices for the greedy choice, and show it does not get worse. Activity selection by earliest end time works because the earliest-ending meeting leaves the most room. Counter-example: coin change with coins {1, 3, 4} and amount 6 — greedy gives 4 + 1 + 1 (3 coins) while the best is 3 + 3 (2 coins), so you need dynamic programming.

Non-overlapping Intervals and Minimum Arrows to Burst Balloons: what is the same and what is different?

Both sort by end time and sweep once, keeping the end of the last chosen interval. Non-overlapping Intervals keeps an interval when start >= lastEnd (touching intervals do not overlap) and the answer is n minus the number kept. Arrows starts a new arrow when start > arrowX (balloons touching at one point are burst by one arrow). The only real difference is >= versus >. Both are O(n log n) because of the sort.

Explain the O(n) solutions to Jump Game, Jump Game II and Gas Station.

Jump Game: keep farthest, the largest reachable index; if the current index exceeds it, return false. Jump Game II is BFS without a queue: curEnd is the edge of the current level, farthest the edge of the next; when you reach curEnd, count a jump and move it. Gas Station: if total gas is less than total cost there is no answer; otherwise scan with a running tank, and whenever it goes negative at station i, no start up to i works, so restart at i + 1. All three use O(n) time and O(1) space.

Adjacency matrix, adjacency list or edge list — which do you choose and why?

Adjacency list is the default: O(V + E) space and O(degree) to scan neighbours, which suits BFS, DFS and Dijkstra on sparse graphs. An adjacency matrix takes O(V²) space but gives O(1) edge lookup, so it fits dense graphs, small V and Floyd-Warshall. An edge list (O(E)) is what Kruskal's algorithm, Bellman-Ford and union-find consume. In Java: List<List<Integer>> for unweighted and List<List<int[]>> with {to, weight} for weighted graphs.

Why does BFS find the shortest path in an unweighted graph, and when should you mark a vertex visited?

BFS processes all vertices at distance d before any at distance d + 1, so the first time it reaches a vertex is along a path with the fewest edges. Mark a vertex visited when you add it to the queue, not when you remove it; otherwise the same vertex can enter the queue many times and the queue can grow to O(E). Complexity is O(V + E) time and O(V) space. On weighted graphs BFS minimises the edge count, not the weight, so you need Dijkstra.

How do you detect a cycle in an undirected graph versus a directed graph?

Undirected: run DFS passing the parent; reaching a visited vertex that is not the parent means a cycle. Union-find works too — if an edge's endpoints already have the same root, the edge closes a cycle. Directed: a visited vertex is not enough (a diamond has two paths to one vertex but no cycle), so use three states — unvisited, on the current path, finished — and report a cycle when you reach a vertex that is on the current path. Alternatively run Kahn's algorithm and check whether all vertices were processed. All are O(V + E).

Explain topological sort with Kahn's algorithm. How does it detect a cycle?

A topological order lists vertices so that every edge u → v has u before v; it exists only for a DAG. Compute in-degrees, put all vertices with in-degree 0 in a queue, then repeatedly remove one, append it to the order and decrease the in-degree of its out-neighbours, enqueueing those that reach 0. If the order has fewer than V vertices, the remaining vertices lie on or behind a cycle, so no valid order exists. That is exactly how Course Schedule I (can finish?) and II (give an order) are solved, in O(V + E).

How does Dijkstra work, why does it need non-negative weights, and what is its complexity?

Keep a tentative distance for every vertex. Repeatedly take the unfinished vertex with the smallest distance from a min-heap of {dist, vertex}, treat that distance as final and relax its outgoing edges. The distance is final because any other route has to pass through a vertex that is at least as far away and then add a non-negative weight. A negative edge can later shorten a route that Dijkstra has already finalised. With a binary heap and lazy deletion (skip stale entries) it runs in O((V + E) log V).

When would you use Bellman-Ford or Floyd-Warshall instead of Dijkstra?

Bellman-Ford handles negative edge weights: relax every edge V − 1 times (O(V · E)); one more pass that still improves a distance proves a reachable negative cycle. It also solves "at most k edges" problems such as Cheapest Flights Within K Stops by running k + 1 rounds on a copy of the distance array. Floyd-Warshall computes all-pairs shortest paths with three nested loops, k outermost, in O(V³) time and O(V²) space — fine for a few hundred vertices. If every edge weighs 0 or 1, 0-1 BFS with a deque does it in O(V + E).

What is union-find and why is it almost O(1) per operation?

It stores disjoint groups as trees in a parent[] array; the root is the group's representative. find follows parents to the root and union links two roots. Path compression flattens the tree during find, and union by size attaches the smaller tree under the larger, so trees stay shallow. Together they give O(α(n)) amortized time per operation, where α is the inverse Ackermann function, below 5 for any practical n. union returning false means "already connected", which is the cycle test used in Redundant Connection and Kruskal.

Compare Kruskal and Prim for a minimum spanning tree.

Both build a tree of V − 1 edges with the smallest total weight and rely on the cut property: the cheapest edge across any cut is in some MST. Kruskal sorts all edges and adds each edge that joins two different components (checked with union-find): O(E log E), natural when the input is an edge list and for sparse graphs. Prim grows one tree from a start vertex using a min-heap of edges leaving the tree: O(E log V), or O(V²) with an array, which is better for dense graphs. If the graph is disconnected, neither produces a spanning tree.

Cheat sheet — Backtracking, greedy and graphs

  • Backtracking template choose → explore → un-choose; record a copy of the path at the goal
  • Order matters? no → loop from start and recurse with i + 1; yes → loop from 0 with used[]
  • Reuse allowed? recurse with i (Combination Sum I); once only → i + 1
  • Skip duplicates sort; subsets/combinations: i > start && a[i] == a[i-1]; permutations: i > 0 && a[i] == a[i-1] && !used[i-1]
  • Backtracking cost subsets O(n · 2n), permutations O(n · n!), combinations O(k · C(n, k)), word search O(m · n · 3L)
  • Pruning constraint check before recursing; break on sorted input when a value exceeds the remainder; stop when too few items are left
  • N-Queens one queen per row; column, row − col + n − 1 and row + col boolean arrays
  • Word search mark the cell (e.g. '#'), try 4 directions, restore the cell on every exit
  • Greedy needs the greedy-choice property and optimal substructure; prove it with an exchange argument
  • Greedy fails coin change {1, 3, 4} for 6 (greedy 3 coins, best 2); 0/1 knapsack; negative-edge shortest paths
  • Intervals sort by end for max non-overlapping and min arrows; >= to keep, > for a new arrow
  • Jump Game track farthest; Jump Game II uses curEnd and farthest like BFS levels
  • Gas Station total gas ≥ total cost, and reset the start to i + 1 when the tank goes negative
  • Graph storage adjacency list O(V + E) by default; matrix O(V²) for dense; edge list for Kruskal and Bellman-Ford
  • BFS queue, mark visited on enqueue, shortest path in unweighted graphs, O(V + E); level loop uses queue.size()
  • DFS recursion or ArrayDeque stack; watch StackOverflowError on deep graphs
  • Grids direction array {{1,0},{-1,0},{0,1},{0,-1}}, bounds check, mark visited; multi-source BFS starts with all sources in the queue
  • Cycle, undirected DFS with parent, or union-find where union returns false
  • Cycle, directed three colours (white, grey, black) or Kahn's count < V
  • Bipartite two-colour with BFS; fails on an odd cycle; start from every uncoloured vertex
  • Topological sort Kahn: in-degree 0 queue; DFS: reverse post-order; both O(V + E)
  • Dijkstra min-heap of {dist, node}, skip stale entries, non-negative weights, O((V + E) log V)
  • Bellman-Ford relax all edges V − 1 times, one more pass detects a negative cycle, O(V · E)
  • Floyd-Warshall k outermost, d[i][j] = min(d[i][j], d[i][k] + d[k][j]), O(V³); safe INF (not MAX_VALUE)
  • 0-1 BFS deque: weight 0 to the front, weight 1 to the back, O(V + E)
  • Union-find parent array + path compression + union by size, ≈ O(α(n)); Number of Provinces, Redundant Connection, Accounts Merge
  • MST V − 1 edges; Kruskal = sort + union-find, O(E log E); Prim = heap, O(E log V), O(V²) when dense

Practice — Backtracking, greedy and graphs

  1. Backtracking warm-up (easy). Solve Subsets, Permutations and Combinations without looking at the notes. Print the answer for [1, 2, 3] and check the counts 8, 6 and C(n, k). Done when each output matches and you can say why you copy the path.
  2. Duplicates (medium). Solve Subsets II, Permutations II and Combination Sum II. Test with [1, 2, 2], [1, 1, 2] and [10, 1, 2, 7, 6, 1, 5] with target 8. Done when there are no duplicate results and you can explain i > start versus i > 0.
  3. String and board backtracking (medium). Solve Letter Combinations of a Phone Number, Generate Parentheses, Palindrome Partitioning, Word Search and N-Queens (print all 2 boards for n = 4 and count 92 solutions for n = 8). Done when each runs in under a second on its largest input.
  4. Backtracking month (target: 25 problems in month 7, together with greedy). Add Combination Sum I and III, Sudoku Solver and Word Search II after you have read the tries article. For each, write the state-space tree size and compare it with the input limit.
  5. Greedy core (medium). Solve Assign Cookies, Non-overlapping Intervals, Minimum Number of Arrows to Burst Balloons, Partition Labels, Jump Game I and II, Gas Station and Candy. For each, write the greedy rule and a two-sentence exchange argument in a comment. Done when you can break a wrong rule (sort by start, sort by length) with a small counter-example.
  6. Greedy versus DP (medium). Run the coin-change program with coins {1, 3, 4} and amount 6 using both the greedy loop and the DP table; then find your own counter-example for greedy 0/1 knapsack. Done when you can state in one sentence why fractional knapsack is greedy and 0/1 knapsack is not.
  7. Graph traversals (easy to medium). Build a graph from an edge list and implement BFS distances, recursive and iterative DFS, and connected components. Then solve Number of Islands, Flood Fill, Max Area of Island, Rotting Oranges and Number of Provinces. Done when the island count and the 4-minute Rotting Oranges example match.
  8. Cycles, colouring and states (medium). Solve Is Graph Bipartite, Clone Graph, Word Ladder, Course Schedule I and II (once with Kahn, once with DFS) and detect cycles in both directed and undirected graphs. Done when you can state which technique each cycle test needs and why.
  9. Weighted graphs and the month 8 target (hard). Solve Network Delay Time, Path With Minimum Effort, Cheapest Flights Within K Stops, Number of Provinces and Redundant Connection with union-find, and Min Cost to Connect All Points with both Kruskal and Prim. Together with exercise 7 and 8 this makes the 30 graph problems planned for month 8. Done when you can choose the algorithm from the which-algorithm table before coding.
  10. Timed contest (hard). Enter two online contests or take a four-problem mock set under time pressure. Aim to solve 2 of the 4 problems by the end of month 8 and write down, for each unsolved problem, which pattern from this part would have solved it.
