Binary trees: LCA, views, construction and serialization

Lowest common ancestor is a bottom-up recursion that returns a node when it finds a target; side views use level-order BFS; top and bottom views add a horizontal-distance map; construction and serialization rebuild a tree from preorder data.

These problems use the ideas from traversals and tree recursion. Each one is a small change to BFS or DFS.

Lowest Common Ancestor of a Binary Tree (LeetCode 236)

The lowest common ancestor (LCA) of nodes p and q is the deepest node that has both as descendants (a node counts as its own descendant). Think of two employees and the nearest manager above both.

Contract: lca(node, p, q) returns p or q if it finds one of them in this subtree, the LCA if it finds both, otherwise null. If both the left and right calls return non-null, the current node is where the two paths meet, so it is the LCA. If only one side returns non-null, pass that up.

public TreeNode lowestCommonAncestor(TreeNode root, TreeNode p, TreeNode q) {
    if (root == null || root == p || root == q) return root;   // found one, or fell off
    TreeNode left = lowestCommonAncestor(root.left, p, q);
    TreeNode right = lowestCommonAncestor(root.right, p, q);
    if (left != null && right != null) return root;           // p and q are on both sides
    return left != null ? left : right;                        // both on one side
}

Dry run on the tree 3 / (5, 1) with p = 5, q = 1: the left call returns 5 at once, the right call returns 1 at once, both are non-null, so the answer is 3. If p = 5 and q is inside 5's subtree, the left call returns 5 (it stops at 5 without searching deeper) and the right call returns null, so the answer is 5, which is correct. Complexity: O(n) time, O(h) space. This code assumes both nodes exist in the tree.

Views of a binary tree

Right side view (LeetCode 199): the nodes you see standing on the right of the tree. That is the last node of every level. Use the level-order template and keep the node at index size - 1. For the left view, keep the first node (i == 0).

public List<Integer> rightSideView(TreeNode root) {
    List<Integer> view = new ArrayList<>();
    if (root == null) return view;
    Queue<TreeNode> q = new ArrayDeque<>();
    q.offer(root);
    while (!q.isEmpty()) {
        int size = q.size();
        for (int i = 0; i < size; i++) {
            TreeNode node = q.poll();
            if (i == size - 1) view.add(node.val);     // last in the level
            if (node.left != null)  q.offer(node.left);
            if (node.right != null) q.offer(node.right);
        }
    }
    return view;
}

A DFS version visits the right child first and records a value the first time it reaches a new depth: if (depth == view.size()) view.add(node.val). Complexity: O(n) time, O(w) space for BFS.

Top view and bottom view with horizontal distance

Draw vertical lines through the tree. Give the root horizontal distance (HD) 0, a left child HD − 1 and a right child HD + 1. Nodes with the same HD sit on the same vertical line. The top view shows the first node you meet on each line going downward (use BFS so higher nodes come first, and store a value only if the HD is new). The bottom view shows the last node on each line (BFS, overwrite the value every time). A TreeMap keeps columns sorted from left to right.

public List<Integer> topView(TreeNode root) {
    TreeMap<Integer, Integer> firstAtHd = new TreeMap<>();   // hd -> value
    if (root == null) return new ArrayList<>();
    Queue<TreeNode> nodes = new ArrayDeque<>();
    Queue<Integer> hds = new ArrayDeque<>();
    nodes.offer(root);  hds.offer(0);
    while (!nodes.isEmpty()) {
        TreeNode node = nodes.poll();
        int hd = hds.poll();
        firstAtHd.putIfAbsent(hd, node.val);       // top view: keep the first
        // bottom view: use firstAtHd.put(hd, node.val) to keep the last
        if (node.left != null)  { nodes.offer(node.left);  hds.offer(hd - 1); }
        if (node.right != null) { nodes.offer(node.right); hds.offer(hd + 1); }
    }
    return new ArrayList<>(firstAtHd.values());       // ordered left to right
}

Do not use DFS for the top view: a deeper node could be seen before a shallower node of the same column. Complexity: O(n log n) time because of the TreeMap (O(n + c) if you track min/max HD and use an array or HashMap), O(n) space. Vertical Order Traversal (LeetCode 987) is the same idea keeping every node per column, sorted by row and then value.

Construct Binary Tree from Preorder and Inorder (LeetCode 105)

Preorder starts with the root. Find that root in the inorder array: everything to its left is the left subtree, everything to its right is the right subtree. The size of the left part tells you how many preorder elements belong to the left subtree. Recurse. A HashMap from value to inorder index replaces the linear search (values are unique).

private int preIdx = 0;
private Map<Integer, Integer> inIndex = new HashMap<>();

public TreeNode buildTree(int[] preorder, int[] inorder) {
    for (int i = 0; i < inorder.length; i++) inIndex.put(inorder[i], i);
    return build(preorder, 0, inorder.length - 1);
}

private TreeNode build(int[] preorder, int lo, int hi) {   // range in inorder
    if (lo > hi) return null;
    TreeNode root = new TreeNode(preorder[preIdx++]);      // next preorder = root
    int mid = inIndex.get(root.val);
    root.left = build(preorder, lo, mid - 1);              // left FIRST (preorder)
    root.right = build(preorder, mid + 1, hi);
    return root;
}

With preorder = [3,9,20,15,7] and inorder = [9,3,15,20,7]: root 3, inorder index 1, so 9 is the left subtree and [15,20,7] the right one. Complexity: O(n) time and space. You cannot rebuild a tree from preorder and postorder alone in general, and preorder alone is not enough either; but preorder with null markers is (next section).

Serialize and Deserialize Binary Tree (LeetCode 297)

Turn a tree into a string and back. Preorder with an explicit marker for null children is unambiguous, because the markers show where each subtree ends.

public class Codec {
    public String serialize(TreeNode root) {
        StringBuilder sb = new StringBuilder();
        write(root, sb);
        return sb.toString();                     // e.g. "1,2,#,#,3,#,#,"
    }
    private void write(TreeNode node, StringBuilder sb) {
        if (node == null) { sb.append("#,"); return; }
        sb.append(node.val).append(',');
        write(node.left, sb);
        write(node.right, sb);
    }

    public TreeNode deserialize(String data) {
        Deque<String> tokens = new ArrayDeque<>(Arrays.asList(data.split(",")));
        return read(tokens);
    }
    private TreeNode read(Deque<String> tokens) {
        String t = tokens.poll();
        if (t.equals("#")) return null;
        TreeNode node = new TreeNode(Integer.parseInt(t));
        node.left = read(tokens);
        node.right = read(tokens);
        return node;
    }
}

Complexity: O(n) time and space. A level-order version using a queue gives the format LeetCode shows in its examples.

Brief: Lowest Common Ancestor shortcuts and Subtree of Another Tree

  • If every node has a parent pointer, the LCA is the intersection of two lists (see Intersection of Two Linked Lists in the linked list article).
  • Subtree of Another Tree (LeetCode 572): for each node of the big tree call isSameTree against the small tree. O(m·n) simple version.
  • Count Good Nodes, Sum Root to Leaf Numbers: top-down recursion passing the max-so-far or the number built so far.

Edge cases

  • LCA when one node is an ancestor of the other: the ancestor itself is the answer (the code above handles it).
  • LCA when a target is not in the tree: this simple code returns the other node wrongly; count matches explicitly if the problem says nodes may be missing.
  • Deserializing negative numbers or multi-digit values: that is why the format uses a separator like a comma.
  • Views of a skewed tree: the view has one node per level, so the view length is n.

Interview angle

LCA is asked at nearly every company. Explain the contract in one sentence, then the "both sides non-null means this is the LCA" rule. Be ready with the BST version (next article) that is O(h) with no recursion on both sides. For views, say why BFS (not DFS) is natural for top view and what the horizontal distance map stores.

Binary search trees: search, insert, delete, validate

A BST keeps every left descendant smaller and every right descendant larger than a node, so search, insert and delete follow one path in O(h), and an inorder walk yields sorted values.

A binary search tree (BST) is a binary tree with one rule at every node: all values in the left subtree are smaller, all values in the right subtree are larger (we assume no duplicates unless a problem says otherwise). This is binary search turned into a data structure (see binary search in Module 1): at each node you discard one half of what remains.

If the tree is balanced, its height is about log₂ n, so search, insert and delete are O(log n). If you insert already sorted data into a plain BST, it degenerates into a linked list of height n and everything becomes O(n). Self-balancing trees (AVL, red-black) fix this; Java's TreeMap and TreeSet are red-black trees (see below).

Search and insert

// Search in a BST (LeetCode 700)
public TreeNode searchBST(TreeNode root, int val) {
    while (root != null && root.val != val) {
        root = (val < root.val) ? root.left : root.right;
    }
    return root;                                     // null if absent
}

// Insert into a BST (LeetCode 701)
public TreeNode insertIntoBST(TreeNode root, int val) {
    if (root == null) return new TreeNode(val);      // found the empty slot
    if (val < root.val) root.left = insertIntoBST(root.left, val);
    else                root.right = insertIntoBST(root.right, val);
    return root;
}

The recursive insert re-assigns root.left or root.right on the way back, which is harmless for unchanged children and attaches the new leaf at the bottom. Complexity: O(h) time; O(1) space for the loop, O(h) for the recursion.

Delete a node (LeetCode 450): three cases

First find the node. Then:

  1. Leaf: return null to the parent.
  2. One child: return that child, which takes the node's place.
  3. Two children: replace the node's value with its inorder successor (the smallest value in the right subtree, found by going right once and then left as far as possible), then delete that successor from the right subtree. The inorder predecessor (largest in the left subtree) works equally well.
public TreeNode deleteNode(TreeNode root, int key) {
    if (root == null) return null;
    if (key < root.val)      root.left = deleteNode(root.left, key);
    else if (key > root.val) root.right = deleteNode(root.right, key);
    else {
        if (root.left == null)  return root.right;     // leaf or only right child
        if (root.right == null) return root.left;      // only left child
        TreeNode succ = root.right;                    // two children
        while (succ.left != null) succ = succ.left;    // smallest in right subtree
        root.val = succ.val;                           // copy its value up
        root.right = deleteNode(root.right, succ.val); // remove the successor
    }
    return root;
}

Deleting 3 from the tree above: it has two children; the successor is 4 (right child 6, then left to 4). Copy 4 into the node, then delete the old 4 (a leaf). Complexity: O(h) time and space.

Validate Binary Search Tree (LeetCode 98)

The tempting solution checks only node.left.val < node.val < node.right.val. That is wrong, because the rule applies to the whole subtree, not just the direct children.

The correct approach passes an allowed range down. Each node must lie strictly between lo and hi. Going left tightens hi to the node's value; going right raises lo.

public boolean isValidBST(TreeNode root) {
    return valid(root, null, null);
}

private boolean valid(TreeNode node, Integer lo, Integer hi) {
    if (node == null) return true;
    if (lo != null && node.val <= lo) return false;
    if (hi != null && node.val >= hi) return false;
    return valid(node.left, lo, node.val) && valid(node.right, node.val, hi);
}

Common mistake: bounds with Integer.MIN_VALUE

If you start with long lo = Integer.MIN_VALUE as the bound, a tree containing the value Integer.MIN_VALUE is wrongly rejected. Use Integer objects with null for "no bound" as above, or use Long.MIN_VALUE and Long.MAX_VALUE.

The alternative: an inorder traversal of a valid BST is strictly increasing, so keep the previously visited value and check that each value is greater than it. Both ways are O(n) time and O(h) space.

Kth Smallest Element in a BST (LeetCode 230)

Inorder visits values in sorted order, so the k-th node visited is the answer. Use the iterative inorder from traversals and stop early.

public int kthSmallest(TreeNode root, int k) {
    Deque<TreeNode> stack = new ArrayDeque<>();
    TreeNode cur = root;
    while (cur != null || !stack.isEmpty()) {
        while (cur != null) { stack.push(cur); cur = cur.left; }
        cur = stack.pop();
        if (--k == 0) return cur.val;       // the k-th smallest
        cur = cur.right;
    }
    throw new IllegalArgumentException("k is larger than the tree size");
}

Complexity: O(h + k) time, O(h) space. If the tree is modified often and k-th queries are frequent, store the subtree size in each node to get O(h) per query (a follow-up asked in interviews).

LCA in a BST (LeetCode 235)

The BST order lets you decide the direction without exploring both sides. If both targets are smaller than the current node, go left; if both are larger, go right; otherwise the current node is where they split, so it is the LCA.

public TreeNode lowestCommonAncestor(TreeNode root, TreeNode p, TreeNode q) {
    while (root != null) {
        if (p.val < root.val && q.val < root.val)      root = root.left;
        else if (p.val > root.val && q.val > root.val) root = root.right;
        else return root;                                    // split point
    }
    return null;
}

Complexity: O(h) time, O(1) space.

Floor and ceiling

The floor of x is the largest value ≤ x in the tree; the ceiling is the smallest value ≥ x. Walk down as in search; whenever a node qualifies, remember it and keep going to find a better one.

// floor: largest value <= x, or null if none
public Integer floor(TreeNode root, int x) {
    Integer best = null;
    while (root != null) {
        if (root.val == x) return x;
        if (root.val < x) { best = root.val; root = root.right; }  // candidate, go bigger
        else               root = root.left;
    }
    return best;
}
// ceiling: mirror image -> if (root.val > x) { best = root.val; root = root.left; }

Complexity: O(h).

Convert Sorted Array to Binary Search Tree (LeetCode 108)

Choose the middle element as the root so both halves have nearly equal size, then recurse on each half. The result is height-balanced.

public TreeNode sortedArrayToBST(int[] nums) {
    return build(nums, 0, nums.length - 1);
}

private TreeNode build(int[] nums, int lo, int hi) {
    if (lo > hi) return null;
    int mid = lo + (hi - lo) / 2;
    TreeNode node = new TreeNode(nums[mid]);
    node.left = build(nums, lo, mid - 1);
    node.right = build(nums, mid + 1, hi);
    return node;
}

Complexity: O(n) time, O(log n) recursion depth.

Brief: BST Iterator (LeetCode 173)

Implement next() and hasNext() over inorder. Keep a stack holding the left spine. next() pops a node, then pushes the left spine of its right child. Each node is pushed and popped once, so next() is amortized O(1) and space is O(h). It is the iterative inorder loop frozen between steps.

TreeMap and TreeSet: balanced BSTs in Java

In real projects you do not write BST code; you use TreeMap or TreeSet, which are red-black trees (self-balancing BSTs), so all operations are O(log n) guaranteed and keys stay sorted.

Use a TreeMap when you need sorted keys or nearest-value lookups (for example "the closest earlier booking time"). Use a HashMap when you only need exact lookups at O(1) average. TreeSet has the same methods: floor, ceiling, lower, higher, first, last. See Core Java · Module 4 for the collections view.

Rule: TreeMap keys need an ordering

Keys must be Comparable or you must pass a Comparator. Two keys that compare as equal are treated as the same key, even if equals() says they differ. A null key throws NullPointerException with natural ordering.

Interview angle

The classic trap is the wrong "check only children" validation; draw the counter-example above. Know the three delete cases and say "inorder successor". Mention that a plain BST can degrade to O(n) and that TreeMap is the balanced answer. "Kth smallest" = inorder; "closest value" = walk down while tracking the best.
