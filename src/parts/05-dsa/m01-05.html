Strings: the Java API, StringBuilder and palindromes

A Java String is an immutable sequence of chars, so every "change" creates a new string; build results with StringBuilder or a char[], and check palindromes with two pointers moving inward.

Mistake: building a string with += in a loop

Strings are immutable. s += c allocates a new string and copies all of s each time, so n appends cost 1 + 2 + … + n = O(n²). For n = 105 this is a time-limit failure. Use StringBuilder (O(n) total).

public class Building {
    public static void main(String[] args) {
        StringBuilder sb = new StringBuilder();
        for (char c = 'a'; c <= 'e'; c++) sb.append(c).append(',');
        sb.setLength(sb.length() - 1);               // drop the trailing comma
        System.out.println(sb);
        sb.reverse();                                 // in place; returns the same object
        System.out.println(sb);

        char[] chars = "hello".toCharArray();         // mutable copy
        chars[0] = 'j';
        System.out.println(new String(chars) + " " + String.valueOf(chars, 1, 3));

        String a = "abc", b = new String("abc");
        System.out.println((a == b) + " " + a.equals(b));
    }
}

Palindromes with two pointers

A palindrome reads the same both ways. Put one pointer at each end and move inward while characters match. O(n) time, O(1) space.

public class Palindromes {
    static boolean isPalindrome(String s) {
        int i = 0, j = s.length() - 1;
        while (i < j) {
            if (s.charAt(i++) != s.charAt(j--)) return false;
        }
        return true;
    }

    // Valid Palindrome (125): ignore non-alphanumerics and case
    static boolean isPalindromeClean(String s) {
        int i = 0, j = s.length() - 1;
        while (i < j) {
            while (i < j && !Character.isLetterOrDigit(s.charAt(i))) i++;
            while (i < j && !Character.isLetterOrDigit(s.charAt(j))) j--;
            if (Character.toLowerCase(s.charAt(i)) != Character.toLowerCase(s.charAt(j)))
                return false;
            i++; j--;
        }
        return true;
    }

    // Valid Palindrome II (680): may delete at most one character
    static boolean validPalindromeII(String s) {
        int i = 0, j = s.length() - 1;
        while (i < j) {
            if (s.charAt(i) != s.charAt(j)) {
                return isRange(s, i + 1, j) || isRange(s, i, j - 1);
            }
            i++; j--;
        }
        return true;
    }

    static boolean isRange(String s, int i, int j) {
        while (i < j) if (s.charAt(i++) != s.charAt(j--)) return false;
        return true;
    }

    // Longest Palindromic Substring (5): expand around each centre, O(n^2)
    static String longestPalindrome(String s) {
        int start = 0, end = 0;
        for (int c = 0; c < s.length(); c++) {
            int len = Math.max(expand(s, c, c), expand(s, c, c + 1));   // odd, even
            if (len > end - start) {
                start = c - (len - 1) / 2;
                end = c + len / 2;
            }
        }
        return s.substring(start, end + 1);
    }

    static int expand(String s, int l, int r) {
        while (l >= 0 && r < s.length() && s.charAt(l) == s.charAt(r)) { l--; r++; }
        return r - l - 1;                                    // length of the palindrome
    }

    public static void main(String[] args) {
        System.out.println(isPalindromeClean("A man, a plan, a canal: Panama"));
        System.out.println(validPalindromeII("abca") + " " + longestPalindrome("babad"));
    }
}

Longest palindromic substring: O(n²) time, O(1) space (2n − 1 centres, each expands up to n). Manacher's algorithm makes it O(n) but is rarely expected.

Edge cases for strings

Empty string, single character, all identical characters, case differences, spaces and punctuation, and — if the statement allows — Unicode. charAt with a bad index throws StringIndexOutOfBoundsException. null input: ask whether it can occur.

Interview angle

"Why are Java strings immutable?" Safety (hash keys, class loading, security), caching of hash codes, string pool sharing, thread safety — see Core Java · Module 1. For DSA, the practical answer is: so every modification costs O(n), and you reach for StringBuilder or char[].

Strings: anagrams, frequency counting and classic problems

Most string problems reduce to counting characters in an int[26] or HashMap, comparing sorted forms, or walking the string with one or two indices.

Frequency counting

Two strings are anagrams when they use the same characters the same number of times, in any order ("listen", "silent"). There are two standard checks:

  • Sort both and compare: O(n log n) time.
  • Count characters with an int[26]: add for one string, subtract for the other; all zeros means anagram. O(n) time, O(1) space (26 is a constant).
import java.util.*;

public class Anagrams {
    // Valid Anagram (242)
    static boolean isAnagram(String s, String t) {
        if (s.length() != t.length()) return false;
        int[] count = new int[26];
        for (int i = 0; i < s.length(); i++) {
            count[s.charAt(i) - 'a']++;
            count[t.charAt(i) - 'a']--;
        }
        for (int c : count) if (c != 0) return false;
        return true;
    }

    // Group Anagrams (49): key = the 26 counts, O(n * k) for n words of length k
    static List<List<String>> groupAnagrams(String[] words) {
        Map<String, List<String>> groups = new HashMap<>();
        for (String w : words) {
            int[] count = new int[26];
            for (char c : w.toCharArray()) count[c - 'a']++;
            String key = Arrays.toString(count);          // e.g. "[1, 0, 0, ..., 1]"
            groups.computeIfAbsent(key, k -> new ArrayList<>()).add(w);
        }
        return new ArrayList<>(groups.values());
    }

    public static void main(String[] args) {
        System.out.println(isAnagram("listen", "silent") + " " + isAnagram("rat", "car"));
        String[] words = {"eat", "tea", "tan", "ate", "nat", "bat"};
        System.out.println(groupAnagrams(words).size());
    }
}

For Group Anagrams, the key can also be the sorted word (new String(sortedChars)) — O(n × k log k), simpler to write. Pick the sorted key in a hurry; use the count key when asked to optimise.

Edge case: the alphabet

int[26] is correct only for lowercase English letters. If the problem allows uppercase, digits or Unicode, use int[128]/int[256] or a HashMap<Character, Integer> — otherwise you get ArrayIndexOutOfBoundsException.

First Unique Character in a String (387)

Count all characters in one pass; scan again to find the first with count 1. Two passes, O(n) time, O(1) space.

public class FirstUnique {
    static int firstUniqChar(String s) {
        int[] count = new int[26];
        for (char c : s.toCharArray()) count[c - 'a']++;
        for (int i = 0; i < s.length(); i++) {
            if (count[s.charAt(i) - 'a'] == 1) return i;
        }
        return -1;
    }

    public static void main(String[] args) {
        System.out.println(firstUniqChar("leetcode") + " " + firstUniqChar("aabb"));
    }
}

Longest Common Prefix (14)

Take the first word as the candidate prefix and shorten it until every other word starts with it. O(total characters), O(1) extra space.

public class CommonPrefix {
    static String longestCommonPrefix(String[] strs) {
        if (strs.length == 0) return "";
        String prefix = strs[0];
        for (int i = 1; i < strs.length; i++) {
            while (!strs[i].startsWith(prefix)) {
                prefix = prefix.substring(0, prefix.length() - 1);
                if (prefix.isEmpty()) return "";
            }
        }
        return prefix;
    }

    public static void main(String[] args) {
        System.out.println(longestCommonPrefix(new String[]{"flower", "flow", "flight"}));
    }
}
fl

Dry run: prefix "flower" → "flow" matches "flow" → vs "flight": "flow", "flo", "fl" — now matches. Answer "fl".

Reverse Words in a String (151)

Split on whitespace (ignoring extra spaces), reverse the word order, join with one space.

import java.util.*;

public class ReverseWords {
    static String reverseWords(String s) {
        String[] parts = s.trim().split("\\s+");        // one or more whitespace chars
        StringBuilder sb = new StringBuilder();
        for (int i = parts.length - 1; i >= 0; i--) {
            sb.append(parts[i]);
            if (i > 0) sb.append(' ');
        }
        return sb.toString();
    }

    public static void main(String[] args) {
        System.out.println("[" + reverseWords("  the sky   is blue ") + "]");
    }
}
[blue is sky the]

O(n) time and space. To do it in O(1) extra space on a char[]: reverse the whole array, then reverse each word — the same reversal trick as array rotation.

String Compression (443) and run-length encoding

Replace runs like "aaabb" by "a3b2" (a count of 1 is omitted in LeetCode's version). Walk with a read pointer that finds each run, and write the character and the digits of the count.

public class Compress {
    // in place on a char array; returns the new length (LeetCode 443 style)
    static int compress(char[] chars) {
        int write = 0, read = 0;
        while (read < chars.length) {
            char c = chars[read];
            int start = read;
            while (read < chars.length && chars[read] == c) read++;
            chars[write++] = c;
            int run = read - start;
            if (run > 1) {
                for (char d : String.valueOf(run).toCharArray()) chars[write++] = d;
            }
        }
        return write;
    }

    public static void main(String[] args) {
        char[] c = "aabbbccccccccccccc".toCharArray();
        int n = compress(c);
        System.out.println(new String(c, 0, n));
    }
}
a2b3c13

O(n) time, O(1) space. The count 13 takes two characters — that is why you convert the number to a string rather than writing one digit.

Tip: how to think about string problems

  1. Is order important (palindrome, subsequence) or only counts (anagram, frequency)? Counts → array or map.
  2. Do I need to look both ways → two pointers; do I need a window → sliding window.
  3. Am I modifying a lot → char[] or StringBuilder, not String.
  4. State the alphabet size out loud: it decides between int[26] and a map.

The count-array idea is the most reusable tool in string problems: one pass fills it, and the "state" of a window or a prefix is just 26 numbers that you can compare with Arrays.equals.

Find All Anagrams in a String (a fixed window of counts)

Given a text s and a pattern p, return every start index where a substring of s is an anagram of p. Every such substring has length p.length(), so slide a window of that size: add the new character on the right, remove the old one on the left, and compare the two count arrays. This is the fixed-size window from sliding window, applied to counts.

import java.util.*;

public class FindAnagrams {
    static List<Integer> findAnagrams(String s, String p) {
        List<Integer> res = new ArrayList<>();
        int m = p.length();
        if (s.length() < m) return res;
        int[] need = new int[26], win = new int[26];
        for (char c : p.toCharArray()) need[c - 'a']++;
        for (int i = 0; i < s.length(); i++) {
            win[s.charAt(i) - 'a']++;                      // character enters on the right
            if (i >= m) win[s.charAt(i - m) - 'a']--;      // character leaves on the left
            if (Arrays.equals(need, win)) res.add(i - m + 1);
        }
        return res;                                        // O(26 * n) time, O(1) space
    }

    public static void main(String[] args) {
        System.out.println(findAnagrams("cbaebabacd", "abc"));
    }
}
[0, 6]

Dry run: at i = 2 the window is "cba", whose counts equal those of "abc", so index 0 is added. Windows "bae", "aeb", "eba", "bab" and "aba" fail. At i = 8 the window is s[6..8] = "bac", which matches, so index 6 is added. The last window "acd" fails.

Ransom Note and Roman to Integer

Ransom Note (383): can the note be built from the letters of a magazine, using each letter once? Count the magazine, then subtract for each note letter; a count that goes below zero means failure. It is the anagram check with "at least" instead of "exactly". O(n + m) time, O(1) space.

Roman to Integer (13): read left to right. A symbol smaller than the one after it is subtracted (as in IV or CM); otherwise it is added.

static int romanToInt(String s) {
    Map<Character, Integer> v = Map.of('I', 1, 'V', 5, 'X', 10, 'L', 50,
                                       'C', 100, 'D', 500, 'M', 1000);
    int total = 0;
    for (int i = 0; i < s.length(); i++) {
        int cur = v.get(s.charAt(i));
        if (i + 1 < s.length() && cur < v.get(s.charAt(i + 1))) total -= cur;
        else total += cur;
    }
    return total;                              // O(n) time, O(1) space
}
// "MCMXCIV": 1000 - 100 + 1000 - 10 + 100 - 1 + 5 = 1994

How to think: a checklist

  1. Name the alphabet and the length limit before you pick a structure. Lowercase letters and n up to 105 point to counts and O(n).
  2. Decide what matters: counts only (anagram, ransom note), order (palindrome, subsequence), or contiguous pieces (substring, window).
  3. Use one pass plus a state whenever you can: a count array, a pair of pointers, or a stack.
  4. Build results with StringBuilder or a char[], never by += in a loop.
  5. Test the edges before you submit: empty string, one character, all equal characters, leading and trailing spaces.

Edge cases and the exceptions behind them

  • Empty or null input: s.length() on null throws NullPointerException. LeetCode rarely sends null, but real code must check.
  • Leading spaces and split(" "): " a b".split(" ") gives empty strings in the array. Use trim() and split("\\s+").
  • Case: "Listen" and "Silent" are not anagrams if case matters. Read the statement; call toLowerCase() only if it says to ignore case.
  • Unicode: charAt returns a 16-bit unit, so characters outside the basic plane (many emoji) are two units. For such text, iterate over code points with s.codePoints().
  • Different lengths: return false at once in Valid Anagram. It saves work and avoids reading past the shorter string.

Mistake: comparing strings with == and re-sorting inside a loop

Wrong: == compares references

String key = new String(sortedChars);
if (key == previousKey) {                 // may be false for equal text
    group.add(word);
}

Right: equals compares text

String key = new String(sortedChars);
if (key.equals(previousKey)) {
    group.add(word);
}

With a HashMap you do not compare keys yourself; the map calls hashCode and equals for you. A related slip is using the int[] itself as a map key: arrays use identity hashCode, so two equal arrays are different keys. Convert to a String (as above) or a List first.

Interview angle

Valid Anagram is a warm-up; the follow-up "what if the strings contain Unicode?" expects a HashMap. Group Anagrams expects you to explain the key choice and its cost. For compress/reverse-words, they check that you handle empty input, multiple spaces and runs of 10 or more.

Hashing: how it works, frequency maps and the two-sum idea

A hash table trades O(n) extra space for O(1) average lookups, which turns many O(n²) "find a matching pair" searches into one O(n) pass; the model example is Two Sum.

How hashing works (just enough for DSA)

A HashMap turns a key into an integer with hashCode(), reduces it to a bucket index, and stores the entry there. Lookup computes the same index and compares keys with equals(). With a good hash function and a table that resizes (load factor 0.75), buckets stay tiny, so get, put and containsKey are O(1) on average. The full internals are in Core Java · Module 4.

Worst case: if many keys land in one bucket (collisions), operations slow down. Since Java 8 a bucket with many entries becomes a balanced tree, so the worst case is about O(log n) for comparable keys, but treat "O(1) average" as the honest statement. Two practical consequences:

  • Keys must be immutable or at least not changed after insertion; and objects used as keys need equals and hashCode overridden together. int[] as a key compares by reference — convert to a List<Integer>, a String, or encode as a long.
  • Iteration order of HashMap/HashSet is unspecified. Use LinkedHashMap or TreeMap if the order matters.

Rule: choose the structure by the question you ask

"Have I seen x?" → HashSet. "How many times have I seen x?" / "Where did I see x?" → HashMap. "Is x in a small fixed alphabet or range 0..n?" → plain array (faster, no hashing). "Give me keys in sorted order / nearest key" → TreeMap.

Template 1: frequency map

import java.util.*;

public class FrequencyMap {
    static Map<Integer, Integer> frequency(int[] a) {
        Map<Integer, Integer> freq = new HashMap<>();
        for (int x : a) freq.merge(x, 1, Integer::sum);
        return freq;
    }

    public static void main(String[] args) {
        Map<Integer, Integer> f = frequency(new int[]{3, 1, 3, 2, 3, 1});
        System.out.println(f);                       // {1=2, 2=1, 3=3}
        int mostFrequent = Collections.max(f.entrySet(), Map.Entry.comparingByValue()).getKey();
        System.out.println(mostFrequent);
    }
}

Template 2: the two-sum idea

Two Sum (1): return the indices of two numbers adding to target. Brute force tries all pairs: O(n²). The key observation: for each x you want target - x. Store every number you have already passed in a map from value → index. At each element, look up its complement before inserting itself.

import java.util.*;

public class TwoSum {
    static int[] twoSum(int[] nums, int target) {
        Map<Integer, Integer> seen = new HashMap<>();      // value -> index
        for (int i = 0; i < nums.length; i++) {
            Integer j = seen.get(target - nums[i]);
            if (j != null) return new int[]{j, i};
            seen.put(nums[i], i);                           // insert AFTER checking
        }
        return new int[]{-1, -1};
    }

    public static void main(String[] args) {
        System.out.println(Arrays.toString(twoSum(new int[]{3, 2, 4}, 6)));
        System.out.println(Arrays.toString(twoSum(new int[]{3, 3}, 6)));
    }
}
[1, 2]
[0, 1]

Time O(n), space O(n). Checking before inserting stops an element from pairing with itself (for [3, 2, 4] and target 6, the first 3 must not match itself) while still handling duplicates like [3, 3]. Compare with the sorted two-pointer approach (O(n log n) time, O(1) space, but indices are lost unless you sort pairs):

ApproachTimeSpaceNeeds
Brute force pairsO(n²)O(1)Nothing
Hash map one passO(n)O(n)Hashable values
Sort + two pointersO(n log n)O(1) or O(n)Values, not indices (or sorted input — Two Sum II)

Mistake: using the same element twice

If you insert nums[i] into the map first and then look up the complement, target 6 with [3, 2, 4] returns [0, 0]. Look up first, insert second.

Recognising hashing problems

  • "Find a pair/triple with a property" — the complement idea.
  • "Duplicates", "first repeated", "distinct count" — a set.
  • "Count occurrences", "most frequent", "group by something" — a map keyed by the something.
  • "Subarray with sum K" — prefix sums stored in a map (next article).
  • The brute force has an inner loop that searches for something — replace the search with a lookup.

Interview angle

"Time complexity of HashMap get?" O(1) average; worst case O(log n) in Java 8+ with treeified buckets (O(n) in older versions or with non-comparable keys). Then say what you pay: O(n) extra memory and the boxing of int into Integer. Mention the two-pointer alternative on a sorted array to show you see the trade-off.

Hashing problems: duplicates, subarray sum K, longest consecutive, intersection

The classics all follow the pattern "store what you have seen, then ask the map": a set for duplicates, a prefix-sum map for subarray sums, and a set plus run starts for consecutive sequences.

Contains Duplicate (217) and variants

import java.util.*;

public class Duplicates {
    static boolean containsDuplicate(int[] a) {
        Set<Integer> seen = new HashSet<>();
        for (int x : a) {
            if (!seen.add(x)) return true;          // add returns false if already present
        }
        return false;
    }

    // Contains Duplicate II (219): equal values at most k indices apart
    static boolean containsNearbyDuplicate(int[] a, int k) {
        Map<Integer, Integer> last = new HashMap<>();   // value -> last index
        for (int i = 0; i < a.length; i++) {
            Integer j = last.get(a[i]);
            if (j != null && i - j <= k) return true;
            last.put(a[i], i);
        }
        return false;
    }

    public static void main(String[] args) {
        System.out.println(containsDuplicate(new int[]{1, 2, 3, 1}) + " "
            + containsNearbyDuplicate(new int[]{1, 0, 1, 1}, 1));
    }
}
true true

O(n) time and space. Alternatives: sort and compare neighbours (O(n log n), O(1) extra), which is the right answer when memory is restricted.

Subarray Sum Equals K (560): prefix sum + map

Count contiguous subarrays whose sum is exactly k (values may be negative, so a sliding window fails). Let prefix[i] be the sum of the first i elements. A subarray (j, i] sums to k when prefix[i] - prefix[j] = k, that is prefix[j] = prefix[i] - k. So while scanning, count how many earlier prefixes equal current - k. Seed the map with {0: 1} for the empty prefix, which handles subarrays starting at index 0.

import java.util.*;

public class SubarraySumK {
    static int subarraySum(int[] nums, int k) {
        Map<Integer, Integer> countOfPrefix = new HashMap<>();
        countOfPrefix.put(0, 1);                       // empty prefix
        int prefix = 0, answer = 0;
        for (int x : nums) {
            prefix += x;
            answer += countOfPrefix.getOrDefault(prefix - k, 0);
            countOfPrefix.merge(prefix, 1, Integer::sum);
        }
        return answer;
    }

    public static void main(String[] args) {
        System.out.println(subarraySum(new int[]{1, 1, 1}, 2));
        System.out.println(subarraySum(new int[]{1, 2, 3, -3, 3}, 3));
    }
}

Time O(n), space O(n). Use long for the prefix if sums can exceed the int range.

The same trick solves Continuous Subarray Sum (store prefix % k with first index), Subarray Sums Divisible by K (count equal remainders; normalise negatives with ((p % k) + k) % k), and Contiguous Array (turn 0 into −1 and find the longest subarray with sum 0).

Longest Consecutive Sequence (128)

Find the length of the longest run of consecutive integers (like 4, 5, 6, 7) in an unsorted array, in O(n). Sorting gives O(n log n). The O(n) idea: put all numbers in a set; only start counting from a number that has no predecessor (x - 1 not in the set). Then walk up with x + 1, x + 2… Each number is visited once as part of a run, so the total work is O(n).

import java.util.*;

public class LongestConsecutive {
    static int longestConsecutive(int[] nums) {
        Set<Integer> set = new HashSet<>();
        for (int x : nums) set.add(x);
        int best = 0;
        for (int x : set) {
            if (set.contains(x - 1)) continue;         // not the start of a run
            int len = 1;
            while (set.contains(x + len)) len++;
            best = Math.max(best, len);
        }
        return best;
    }

    public static void main(String[] args) {
        System.out.println(longestConsecutive(new int[]{100, 4, 200, 1, 3, 2}));
    }
}
4

Without the "is it a start?" check the same code is O(n²) (e.g. re-walking from every element of a long run). That one continue line is the whole trick.

Intersection of Two Arrays (349, 350)

Unique intersection: put one array in a set, scan the other, collect matches (remove from the set to avoid duplicates). With multiplicities (350): count the first array in a map, then decrement while scanning the second.

import java.util.*;

public class Intersection {
    static int[] intersectUnique(int[] a, int[] b) {
        Set<Integer> set = new HashSet<>();
        for (int x : a) set.add(x);
        List<Integer> out = new ArrayList<>();
        for (int y : b) if (set.remove(y)) out.add(y);   // remove returns true if present
        return out.stream().mapToInt(Integer::intValue).toArray();
    }

    static int[] intersectWithCounts(int[] a, int[] b) {
        Map<Integer, Integer> cnt = new HashMap<>();
        for (int x : a) cnt.merge(x, 1, Integer::sum);
        List<Integer> out = new ArrayList<>();
        for (int y : b) {
            int c = cnt.getOrDefault(y, 0);
            if (c > 0) { out.add(y); cnt.put(y, c - 1); }
        }
        return out.stream().mapToInt(Integer::intValue).toArray();
    }

    public static void main(String[] args) {
        int[] a = {1, 2, 2, 1}, b = {2, 2};
        System.out.println(Arrays.toString(intersectUnique(a, b)) + " "
            + Arrays.toString(intersectWithCounts(a, b)));
    }
}

Edge cases and pitfalls

Empty array; all elements equal; negative numbers (sliding window is invalid, prefix-sum map is fine); integer overflow in prefix sums; Integer equality — compare boxed values with equals or unbox, since == on two Integer objects above 127 compares references; and never modify a map while iterating over it (ConcurrentModificationException).

Tip: how to think

  1. Write the brute force. Find the inner loop that is a search.
  2. Ask "what exactly am I searching for?" — a complement, a previous prefix, a neighbour value.
  3. Decide what the key and the value of the map are, and write them in a comment.
  4. Decide the order: look up first, then insert (or the reverse); seed the map with the base case ({0: 1}).
