Arrays: prefix sums and the difference array

A prefix-sum array lets you answer any "sum of a range" question in O(1) after one O(n) pass; its mirror image, the difference array, applies many "add x to a range" updates in O(1) each.

Arrays first: what to know

An array is a block of memory with elements of one type; a[i] is O(1) because the address is start + i × element size. The length is fixed (a.length, a field, not a method). Weaknesses: inserting or deleting in the middle is O(n), and searching an unsorted array is O(n). Most array problems are solved by one pass with a smart bit of state, two pointers, or precomputation like prefix sums. Default values: 0 for numbers, false for booleans, null for objects. Index errors throw ArrayIndexOutOfBoundsException.

Recognise array problems by: "subarray" (contiguous), "in place", "O(1) extra space", "sorted array", "range", "sum of elements between i and j".

Prefix sums

Define prefix[i] as the sum of the first i elements: prefix[0] = 0, prefix[i] = prefix[i-1] + a[i-1]. Then the sum of a[l..r] (inclusive) is prefix[r+1] - prefix[l]. The extra leading 0 removes the special case for l = 0.

public class PrefixSum {
    private final long[] prefix;

    PrefixSum(int[] a) {                          // build: O(n) time, O(n) space
        prefix = new long[a.length + 1];
        for (int i = 0; i < a.length; i++) prefix[i + 1] = prefix[i] + a[i];
    }

    long sum(int l, int r) {                      // query: O(1)
        return prefix[r + 1] - prefix[l];
    }

    // Find Pivot Index: index where left sum equals right sum, else -1
    static int pivotIndex(int[] a) {
        long total = 0;
        for (int x : a) total += x;
        long left = 0;
        for (int i = 0; i < a.length; i++) {
            if (left == total - left - a[i]) return i;
            left += a[i];
        }
        return -1;
    }

    public static void main(String[] args) {
        PrefixSum ps = new PrefixSum(new int[]{3, 1, 4, 1, 5});
        System.out.println(ps.sum(1, 3) + " " + ps.sum(0, 4));
        System.out.println(pivotIndex(new int[]{1, 7, 3, 6, 5, 6}));
    }
}

3

Without prefix sums, q range queries on n elements cost O(n × q); with them, O(n + q). Use long for the prefix when values or lengths are large. Dry run, pivot index for [1,7,3,6,5,6], total 28: at i = 3 the left sum is 1+7+3 = 11 and the right sum is 28 − 11 − 6 = 11, so the answer is 3.

2D prefix sums (brief)

For a matrix, let P[i][j] be the sum of the rectangle from (0,0) to (i−1,j−1). Build with P[i][j] = M[i-1][j-1] + P[i-1][j] + P[i][j-1] - P[i-1][j-1]. The sum of the rectangle rows r1..r2, columns c1..c2 is P[r2+1][c2+1] - P[r1][c2+1] - P[r2+1][c1] + P[r1][c1] — add back the corner you subtracted twice. Build O(rows × cols), query O(1). This is LeetCode "Range Sum Query 2D - Immutable".

The difference array

The reverse problem: you have many updates "add v to every element in a[l..r]" and only need the final array. Doing each update in a loop is O(n) per update. Instead, keep diff where diff[l] += v and diff[r+1] -= v; at the end a single prefix-sum pass over diff gives the final array.

import java.util.*;

public class DifferenceArray {
    // updates[k] = {l, r, v}: add v to a[l..r]. Result length n, all zeros initially.
    static int[] applyUpdates(int n, int[][] updates) {
        int[] diff = new int[n + 1];                 // one extra slot for r + 1
        for (int[] u : updates) {
            diff[u[0]] += u[2];
            diff[u[1] + 1] -= u[2];
        }
        int[] result = new int[n];
        int running = 0;
        for (int i = 0; i < n; i++) {
            running += diff[i];
            result[i] = running;
        }
        return result;
    }

    public static void main(String[] args) {
        int[][] updates = {{1, 3, 2}, {2, 4, 3}, {0, 2, -2}};
        System.out.println(Arrays.toString(applyUpdates(5, updates)));
    }
}
[-2, 0, 3, 5, 3]

Time O(n + u) for u updates, space O(n). The same idea solves "Range Addition", "Corporate Flight Bookings" (seats booked per flight over ranges), "Car Pooling" (passengers on a road) and meeting-room occupancy counting.

Tip: spotting the pattern

Many reads of range sums → prefix sums. Many writes to ranges, one read at the end → difference array. Both interleaved → a Fenwick tree or segment tree (Module 3).

Mistake: off-by-one between a and prefix

The prefix array is one longer than a. If you forget the leading zero you get a bug at l = 0. Write the formula on paper once: sum(l, r) = prefix[r+1] - prefix[l].

Why it works

A prefix sum is precomputation: you pay O(n) once to store a running total, so every later range question becomes one subtraction. The sum of a[l..r] is "everything up to r" minus "everything before l"; the shared part cancels. The difference array is the exact reverse. Instead of storing totals, it stores changes: diff[i] is how much the value at i differs from the value at i−1. A range update touches only two changes (where the range starts and where it stops), and one prefix-sum pass turns the changes back into values. So the two techniques are inverses of each other: a prefix sum turns an array into running totals, and the difference array is what you get by undoing that.

Another problem: Car Pooling

Each trip is {passengers, from, to}: passengers get in at from and get out at to. Can the car, with a given capacity, finish all trips? A difference array over the road positions gives the number of people in the car at each position: add at from, subtract at to (they leave there, so they do not count at to).

static boolean carPooling(int[][] trips, int capacity) {
    int last = 0;
    for (int[] t : trips) last = Math.max(last, t[2]);
    int[] diff = new int[last + 1];
    for (int[] t : trips) {
        diff[t[1]] += t[0];                    // people get in
        diff[t[2]] -= t[0];                    // people get out
    }
    int inCar = 0;
    for (int d : diff) {
        inCar += d;
        if (inCar > capacity) return false;
    }
    return true;                               // O(n + last) time, O(last) space
}

Corporate Flight Bookings has the same shape; the only care is that its flight numbers start at 1, so shift by one when you index. In both problems the clue is a stream of "this much, from here to there" updates and a question asked only after all of them.

Edge cases and overflow

  • Empty array: the prefix array has one element (0), and no valid query exists. Check the length before reading a[0].
  • Overflow: 105 values of 105 each add up to 1010, which does not fit in int. Store the prefix in a long[]. Silent overflow gives a wrong answer, not an exception.
  • Negative values: prefix sums still work. If all values are non-negative, the prefix array is non-decreasing, so you can also binary search on it (for example "smallest subarray with sum at least K").
  • Range touching the end: an update with r = n - 1 writes diff[n]. Without the extra slot you get ArrayIndexOutOfBoundsException.

Mistake: applying every range update with a loop

Wrong: O(n) per update

for (int[] u : updates)
    for (int i = u[0]; i <= u[1]; i++) a[i] += u[2];   // O(n * u)

Right: O(1) per update

for (int[] u : updates) {
    diff[u[0]] += u[2];
    diff[u[1] + 1] -= u[2];
}                                                     // then one pass

Interview angle

"Answer 105 range-sum queries on an array of 105 numbers." State the naive O(n × q) = 1010 is too slow, then give O(n + q). Follow-up: the array changes between queries → mention Fenwick tree. Prefix sums are also the heart of "subarray sum equals K" (see the hashing article).

Arrays: Kadane's algorithm and the stock problem

Kadane's algorithm finds the maximum-sum contiguous subarray in one pass by asking at every index: is it better to extend the previous subarray or start fresh here?

The problem

Given an array of integers (positive and negative), find the contiguous subarray with the largest sum — Maximum Subarray (LeetCode 53). Brute force checks all O(n²) subarrays (O(n²) with running sums, O(n³) if you re-add). Kadane does it in O(n) time and O(1) space.

Why it works

Let best_ending_here be the largest sum of a subarray that ends exactly at index i. A subarray ending at i is either just a[i], or a subarray ending at i−1 extended by a[i]. So:

endingHere = max(a[i], endingHere + a[i]). The answer is the maximum endingHere over all i.

Intuition: if the sum so far is negative, it can only hurt the next element, so drop it and restart. This is a tiny piece of dynamic programming (Module 3) with the state compressed to a single variable.

import java.util.*;

public class Kadane {
    static int maxSubarray(int[] a) {
        int endingHere = a[0], best = a[0];          // start with a[0], NOT 0
        for (int i = 1; i < a.length; i++) {
            endingHere = Math.max(a[i], endingHere + a[i]);
            best = Math.max(best, endingHere);
        }
        return best;
    }

    // Also return the subarray's start and end indices
    static int[] maxSubarrayRange(int[] a) {
        int endingHere = a[0], best = a[0];
        int start = 0, bestStart = 0, bestEnd = 0;
        for (int i = 1; i < a.length; i++) {
            if (a[i] > endingHere + a[i]) {          // restart at i
                endingHere = a[i];
                start = i;
            } else {
                endingHere += a[i];
            }
            if (endingHere > best) {
                best = endingHere;
                bestStart = start;
                bestEnd = i;
            }
        }
        return new int[]{best, bestStart, bestEnd};
    }

    public static void main(String[] args) {
        int[] a = {-2, 1, -3, 4, -1, 2, 1, -5, 4};
        System.out.println(maxSubarray(a));
        System.out.println(Arrays.toString(maxSubarrayRange(a)));
        System.out.println(maxSubarray(new int[]{-3, -1, -2}));
    }
}

Mistake: initialising with 0 breaks the all-negative case

If you start best = 0, then for [-3, -1, -2] you return 0 — an empty subarray, which the problem does not allow. Start from a[0] (or Integer.MIN_VALUE, with care). The correct answer is −1, the largest single element.

Related classic problems

Best Time to Buy and Sell Stock (121)
One transaction, buy before sell. Track the minimum price seen so far; at each day the best profit is price - minSoFar. It is Kadane in disguise (max subarray of the day-to-day differences). O(n), O(1).
Best Time to Buy and Sell Stock II (122)
Unlimited transactions: add every positive day-to-day rise. O(n).
Maximum Product Subarray (152)
A negative can turn the smallest product into the largest, so track both the max and min product ending here.
Maximum Sum Circular Subarray (918)
Answer = max(normal Kadane, total − minimum subarray); if every element is negative, return the normal answer.
public class Stocks {
    static int maxProfit(int[] prices) {            // one buy, one sell
        int minPrice = Integer.MAX_VALUE, best = 0;
        for (int p : prices) {
            minPrice = Math.min(minPrice, p);
            best = Math.max(best, p - minPrice);
        }
        return best;
    }

    static int maxProfitUnlimited(int[] prices) {   // as many transactions as you like
        int profit = 0;
        for (int i = 1; i < prices.length; i++) {
            if (prices[i] > prices[i - 1]) profit += prices[i] - prices[i - 1];
        }
        return profit;
    }

    static int maxProduct(int[] a) {                // Maximum Product Subarray
        int max = a[0], min = a[0], best = a[0];
        for (int i = 1; i < a.length; i++) {
            if (a[i] < 0) { int t = max; max = min; min = t; }   // negative flips order
            max = Math.max(a[i], max * a[i]);
            min = Math.min(a[i], min * a[i]);
            best = Math.max(best, max);
        }
        return best;
    }

    public static void main(String[] args) {
        System.out.println(maxProfit(new int[]{7, 1, 5, 3, 6, 4}) + " "
            + maxProfitUnlimited(new int[]{7, 1, 5, 3, 6, 4}) + " "
            + maxProduct(new int[]{2, 3, -2, 4}));
    }
}
5 7 6

All three run in O(n) time and O(1) space. For prices [7,1,5,3,6,4]: min price 1, best sale at 6 gives 5; for unlimited, (5−1) + (6−3) = 7.

How to recognise the pattern

Look for "largest (or smallest) sum or product of a contiguous part" and a hint that the answer depends only on the best run ending at the previous index. The state is tiny: one number, "the best value of a run that ends here". Whenever a problem lets you build the answer at i from the answer at i−1 plus a[i], you can compress a DP table to one or two variables. That is exactly what Kadane does.

A second view: prefix sums

Using the prefix sums from the previous article, the sum of a[j..i] is prefix[i+1] - prefix[j]. For a fixed end i you want the smallest earlier prefix. So the answer is the maximum over i of (current prefix − the minimum prefix seen so far). It is the same algorithm in other words, and it is the same trick as the stock problem: "sell price minus the lowest buy price so far". That is why the stock problem is Kadane in disguise.

static int maxSubarrayViaPrefix(int[] a) {
    long prefix = 0, minPrefix = 0;            // minPrefix starts with the empty prefix
    long best = Long.MIN_VALUE;
    for (int x : a) {
        prefix += x;
        best = Math.max(best, prefix - minPrefix);
        minPrefix = Math.min(minPrefix, prefix);   // update AFTER using it: subarray not empty
    }
    return (int) best;
}

Maximum Sum Circular Subarray in code

In a circular array the best subarray is either a normal one, or it wraps around the end. A wrapping subarray equals the total minus a normal subarray in the middle that is as small as possible. So run Kadane twice (once for the maximum, once for the minimum) in the same loop.

static int maxSubarraySumCircular(int[] a) {
    int total = 0, curMax = 0, curMin = 0, best = a[0], worst = a[0];
    for (int x : a) {
        curMax = Math.max(x, curMax + x);
        best = Math.max(best, curMax);
        curMin = Math.min(x, curMin + x);
        worst = Math.min(worst, curMin);
        total += x;
    }
    if (best < 0) return best;                  // all negative: wrapping would mean "empty"
    return Math.max(best, total - worst);
}
// [5, -3, 5]: best = 7, total = 7, worst = -3 -> max(7, 10) = 10 (the two 5s wrap)

When every element is negative, total - worst would be 0, an empty subarray, which is not allowed; that is why the early return exists.

Edge cases

  • Single element: the loop from index 1 does not run and a[0] is returned, which is correct.
  • All negative: the answer is the largest (least negative) element, never 0.
  • Prices only falling: the stock profit is 0 (do not trade), not negative. That is why best starts at 0 there, but not in Maximum Subarray.
  • Overflow: for very long arrays of large numbers use long. Product problems overflow quickly; LeetCode promises the answer fits in 32 bits.

Divide and conquer also works

You can split the array in half and combine (best in the left, best in the right, best crossing the middle) in O(n log n). Interviewers sometimes ask for it as a follow-up. Kadane is simpler and faster, so mention the idea but code Kadane.

Interview angle

Start with brute force O(n²), then explain Kadane with the "extend or restart" sentence. Be ready for: "return the subarray itself", "what if all numbers are negative", "what if the array is circular". Mention it is DP with O(1) space. A weak answer says "reset to zero when the sum goes negative" without handling the all-negative case.

Arrays: rotation, two pointers and in-place tricks

Many array problems ask for O(1) extra space; the tools are reversal, the read/write two-pointer technique, the three-pointer Dutch flag partition and Boyer–Moore voting.

The read/write pointer pattern

To filter an array in place, keep a read pointer that scans every element and a write pointer marking where the next kept element goes. Everything before write is the finished answer. This single idea solves move zeroes, remove element and remove duplicates.

import java.util.*;

public class ReadWrite {
    // Move Zeroes (283): keep order of non-zeros, push zeros to the end
    static void moveZeroes(int[] a) {
        int write = 0;
        for (int read = 0; read < a.length; read++) {
            if (a[read] != 0) a[write++] = a[read];
        }
        while (write < a.length) a[write++] = 0;
    }

    // Remove Duplicates from Sorted Array (26): return new length
    static int removeDuplicates(int[] a) {
        if (a.length == 0) return 0;
        int write = 1;
        for (int read = 1; read < a.length; read++) {
            if (a[read] != a[write - 1]) a[write++] = a[read];
        }
        return write;
    }

    // Remove Element (27): remove all occurrences of val
    static int removeElement(int[] a, int val) {
        int write = 0;
        for (int x : a) if (x != val) a[write++] = x;
        return write;
    }

    public static void main(String[] args) {
        int[] z = {0, 1, 0, 3, 12};
        moveZeroes(z);
        int[] d = {0, 0, 1, 1, 1, 2, 2, 3};
        int len = removeDuplicates(d);
        System.out.println(Arrays.toString(z) + " " + len + " "
            + Arrays.toString(Arrays.copyOf(d, len)));
    }
}
[1, 3, 12, 0, 0] 4 [0, 1, 2, 3]

All are O(n) time, O(1) space. Dry run, Remove Duplicates on [0,0,1,1,1,2]: write = 1; read 1 (0 equals a[0]) skip; read 2 (1 differs from a[0] = 0) → a[1] = 1, write 2; reads 3 and 4 (1 equals a[1]) skip; read 5 (2 differs) → a[2] = 2, write 3. Length 3: [0,1,2].

Rotation by reversal

Rotate Array (189): move each element k places to the right (cyclically). Making a copy is O(n) space. The in-place trick uses three reversals:

import java.util.*;

public class Rotate {
    static void rotateRight(int[] a, int k) {
        int n = a.length;
        k %= n;                                   // k can exceed n; n = 0 would divide by 0
        reverse(a, 0, n - 1);
        reverse(a, 0, k - 1);
        reverse(a, k, n - 1);
    }

    static void reverse(int[] a, int i, int j) {
        while (i < j) {
            int t = a[i]; a[i] = a[j]; a[j] = t;
            i++; j--;
        }
    }

    public static void main(String[] args) {
        int[] a = {1, 2, 3, 4, 5, 6, 7};
        rotateRight(a, 10);                        // 10 % 7 = 3
        System.out.println(Arrays.toString(a));
    }
}
[5, 6, 7, 1, 2, 3, 4]

O(n) time, O(1) space. Rotating left by k is the same as rotating right by n − k. Guard against an empty array before k %= n.

Dutch national flag (Sort Colors)

Sort Colors (75): the array has only 0, 1 and 2; sort it in one pass without a counting sort. Keep three zones: [0, low) are 0s, [low, mid) are 1s, (high, n-1] are 2s, and [mid, high] is unexplored.

import java.util.*;

public class SortColors {
    static void sortColors(int[] a) {
        int low = 0, mid = 0, high = a.length - 1;
        while (mid <= high) {
            if (a[mid] == 0) {
                swap(a, low++, mid++);              // 0 goes left; the swapped-in value is a 1
            } else if (a[mid] == 1) {
                mid++;
            } else {
                swap(a, mid, high--);               // 2 goes right; do NOT advance mid
            }
        }
    }

    static void swap(int[] a, int i, int j) { int t = a[i]; a[i] = a[j]; a[j] = t; }

    public static void main(String[] args) {
        int[] a = {2, 0, 2, 1, 1, 0};
        sortColors(a);
        System.out.println(Arrays.toString(a));
    }
}
[0, 0, 1, 1, 2, 2]

O(n) time, one pass, O(1) space. After swapping with high you do not know what arrived at mid, so you must look at it again. The same three-way partition is used in quicksort with many duplicates.

Majority element: Boyer–Moore voting

Majority Element (169): find the value that appears more than n/2 times (it is guaranteed to exist). Keep a candidate and a counter: equal element → counter++, different element → counter--, counter 0 → take a new candidate. Each non-majority element cancels one majority element, and the majority is more than half, so it survives.

public class Majority {
    static int majorityElement(int[] a) {
        int candidate = 0, count = 0;
        for (int x : a) {
            if (count == 0) candidate = x;
            count += (x == candidate) ? 1 : -1;
        }
        return candidate;        // correct only if a majority is guaranteed
    }

    public static void main(String[] args) {
        System.out.println(majorityElement(new int[]{2, 2, 1, 1, 1, 2, 2}));
    }
}
2

O(n) time, O(1) space (the HashMap version is O(n) space; sorting and taking the middle element is O(n log n)). If a majority is not guaranteed, make a second pass to verify the count.

Merge Sorted Array (88)

Merge nums2 into nums1, which has room at the end. Merging from the front would overwrite values, so fill from the back with three pointers.

import java.util.*;

public class MergeSorted {
    static void merge(int[] nums1, int m, int[] nums2, int n) {
        int i = m - 1, j = n - 1, k = m + n - 1;
        while (j >= 0) {                           // leftover nums1 is already in place
            if (i >= 0 && nums1[i] > nums2[j]) nums1[k--] = nums1[i--];
            else nums1[k--] = nums2[j--];
        }
    }

    public static void main(String[] args) {
        int[] a = {1, 2, 3, 0, 0, 0};
        merge(a, 3, new int[]{2, 5, 6}, 3);
        System.out.println(Arrays.toString(a));
    }
}
[1, 2, 2, 3, 5, 6]

Rule: when in-place work overwrites data you still need, change the direction

Merging from the back, and rotating by reversals, both exist because going forward would destroy values. Ask "what do I overwrite, and do I still need it?" before writing the loop.

How to recognise an in-place problem

The words are "in place", "O(1) extra space", "do not allocate another array", or "modify the input array". A quick way to choose a technique is to ask what the final array looks like:

Remove Duplicates II: allow each value twice

The read/write idea extends by changing what you compare. To keep at most two copies of each value in a sorted array, a new element is kept unless it equals the element two places behind the write pointer. That element is the last one you are allowed to keep twice.

static int removeDuplicatesII(int[] a) {
    int write = 0;
    for (int x : a) {
        if (write < 2 || x != a[write - 2]) a[write++] = x;
    }
    return write;                              // O(n) time, O(1) space
}

Dry run on [1,1,1,2,2,3]: the first two 1s are kept; the third 1 equals a[0] so it is skipped; 2 differs from a[0] = 1 and is kept (write is now 3); the next 2 differs from a[1] = 1 and is kept (write 4); 3 differs from a[2] = 2 and is kept. The array starts with [1,1,2,2,3] and the return value is 5. Replace 2 by k to allow k copies.

Squares of a sorted array: two pointers from both ends

The input is sorted and may have negatives. Squares make the biggest values appear at either end, never in the middle. So compare the absolute values at the two ends, place the larger square at the back of the result, and move that pointer inward.

static int[] sortedSquares(int[] a) {
    int n = a.length;
    int[] res = new int[n];
    int l = 0, r = n - 1;
    for (int k = n - 1; k >= 0; k--) {         // fill the result from the largest
        if (Math.abs(a[l]) > Math.abs(a[r])) {
            res[k] = a[l] * a[l];
            l++;
        } else {
            res[k] = a[r] * a[r];
            r--;
        }
    }
    return res;                                // O(n) time, O(n) for the output
}

For [-4,-1,0,3,10] the steps place 100, 16, 9, 1, 0 from the back, giving [0,1,9,16,100]. Sorting the squares would be O(n log n); the two-pointer idea uses the sorted order that is already there. The same two-ends idea is the heart of two pointers in Module 2.

Why Boyer–Moore voting works, with a trace

Pair every element that differs from the candidate with a candidate copy and cancel the pair. A true majority appears more than n/2 times, so even if every other element cancels one copy of it, at least one copy is left. The counter never says what the majority is for sure; it only guarantees that the survivor is the only possible one. Trace on [2,2,1,1,1,2,2]:

x2211122
candidate2222112
count after1210101

The final candidate is 2, which is correct. The same idea extends to elements appearing more than n/3 times (Majority Element II): keep two candidates and two counters, because at most two values can exceed n/3.

Edge cases

  • Empty array: k %= n throws ArithmeticException ("/ by zero") when n = 0. Return early for a.length < 2.
  • Negative k: in Java -1 % 7 is -1, not 6. Normalise with k = ((k % n) + n) % n if k can be negative.
  • k = 0 or a multiple of n: after the modulo k is 0 and reverse(a, 0, -1) does nothing, because the loop guard i < j is false. It works, but check it by hand.
  • All zeros or no zeros in Move Zeroes; all equal values in Remove Duplicates (result length 1).
  • No guaranteed majority: verify the candidate with a second pass.

Mistake: using a second array for an "in place" problem

Wrong: extra array breaks the O(1) space rule

int[] tmp = new int[a.length];            // O(n) extra space
int w = 0;
for (int x : a) if (x != 0) tmp[w++] = x;
System.arraycopy(tmp, 0, a, 0, a.length);

Right: read and write inside the same array

int w = 0;
for (int r = 0; r < a.length; r++)
    if (a[r] != 0) a[w++] = a[r];
while (w < a.length) a[w++] = 0;          // O(1) extra space

Interview angle

Interviewers often say "do it in O(1) extra space". Name the technique: read/write pointers, reversal, three-way partition, voting. Explain the invariant (what is true about the prefix at each step) — that is what shows you understand rather than memorised.

Arrays: product except self, next permutation, leaders, missing numbers

These five classics all use a pass from each side, a swap-and-reverse, or the array's own indices as a marker — each is a short idea once you have seen it.

Product of Array Except Self (238)

For each index, the product of all other elements — without division and in O(n). The answer at i is (product of everything left of i) × (product of everything right of i). Build the left products in the result array in one pass, then multiply the right products in a second pass using one variable.

import java.util.*;

public class ProductExceptSelf {
    static int[] productExceptSelf(int[] a) {
        int n = a.length;
        int[] res = new int[n];
        res[0] = 1;
        for (int i = 1; i < n; i++) res[i] = res[i - 1] * a[i - 1];   // left products
        int right = 1;
        for (int i = n - 1; i >= 0; i--) {
            res[i] *= right;                                           // times right products
            right *= a[i];
        }
        return res;
    }

    public static void main(String[] args) {
        System.out.println(Arrays.toString(productExceptSelf(new int[]{1, 2, 3, 4})));
    }
}
[24, 12, 8, 6]

Dry run: after pass 1 res = [1, 1, 2, 6] (left products). Pass 2 from the right with right = 1: i = 3 → 6 × 1 = 6, right = 4; i = 2 → 2 × 4 = 8, right = 12; i = 1 → 1 × 12 = 12, right = 24; i = 0 → 1 × 24 = 24. Time O(n), extra space O(1) beyond the output. Why no division? Zeros make division impossible.

Next Permutation (31)

Rearrange the numbers into the next larger permutation in dictionary order (or the smallest if none exists), in place. Example: 1 2 3 → 1 3 2; 3 2 1 → 1 2 3; 1 5 8 4 7 6 5 3 1 → 1 5 8 5 1 3 4 6 7.

  1. From the right, find the first index i where a[i] < a[i+1] (the "pivot"). The suffix after i is in decreasing order — already the largest arrangement of those numbers.
  2. If no such i exists, the array is the last permutation: reverse it all and stop.
  3. From the right, find the first j with a[j] > a[i] (the smallest bigger number in the suffix). Swap a[i] and a[j].
  4. Reverse the suffix after i, to make it the smallest (increasing) arrangement.
import java.util.*;

public class NextPermutation {
    static void nextPermutation(int[] a) {
        int i = a.length - 2;
        while (i >= 0 && a[i] >= a[i + 1]) i--;       // find the pivot
        if (i >= 0) {
            int j = a.length - 1;
            while (a[j] <= a[i]) j--;                  // smallest bigger value from the right
            swap(a, i, j);
        }
        reverse(a, i + 1, a.length - 1);               // i = -1 reverses the whole array
    }

    static void swap(int[] a, int i, int j) { int t = a[i]; a[i] = a[j]; a[j] = t; }

    static void reverse(int[] a, int l, int r) {
        while (l < r) swap(a, l++, r--);
    }

    public static void main(String[] args) {
        int[] a = {1, 5, 8, 4, 7, 6, 5, 3, 1};
        nextPermutation(a);
        System.out.println(Arrays.toString(a));
    }
}
[1, 5, 8, 5, 1, 3, 4, 6, 7]

O(n) time, O(1) space. Pivot is 4 (index 3); swap with 5 → 1 5 8 5 7 6 4 3 1; reverse the suffix 7 6 4 3 1 → 1 3 4 6 7. Note: the pivot loop uses >=, so duplicate values are handled correctly.

Leaders in an Array

A leader is an element greater than (or equal to, depending on the statement) everything to its right. Scan from the right, keeping the maximum so far; an element beating it is a leader. The last element is always a leader. O(n) time.

import java.util.*;

public class Leaders {
    static List<Integer> leaders(int[] a) {
        List<Integer> result = new ArrayList<>();
        int max = Integer.MIN_VALUE;
        for (int i = a.length - 1; i >= 0; i--) {
            if (a[i] > max) {
                result.add(a[i]);
                max = a[i];
            }
        }
        Collections.reverse(result);                // restore left-to-right order
        return result;
    }

    public static void main(String[] args) {
        System.out.println(leaders(new int[]{16, 17, 4, 3, 5, 2}));
    }
}
[17, 5, 2]

Missing and repeating numbers: use the array as its own map

When the array holds numbers from 1 to n, the values themselves are valid indices. Three tools, from simplest to leanest:

  • Sum formula: the missing number in 0..n is n(n+1)/2 - sum(a) (Missing Number, 268). Use long if n is large. XOR does the same without overflow (see the bit manipulation article).
  • Index marking: for each value v, negate a[|v|-1]. A value whose slot is already negative is a duplicate; a slot still positive at the end means its index+1 is missing.
  • Cycle sort / swap into place: put each v at index v−1.
import java.util.*;

public class MissingRepeating {
    // Find All Numbers Disappeared in an Array (448); values are in 1..n
    static List<Integer> disappeared(int[] a) {
        for (int i = 0; i < a.length; i++) {
            int idx = Math.abs(a[i]) - 1;
            if (a[idx] > 0) a[idx] = -a[idx];          // mark value idx+1 as seen
        }
        List<Integer> missing = new ArrayList<>();
        for (int i = 0; i < a.length; i++) if (a[i] > 0) missing.add(i + 1);
        return missing;
    }

    // Find the Duplicate Number (287) when the array may be modified: marking
    static int findDuplicate(int[] a) {
        for (int x : a) {
            int idx = Math.abs(x) - 1;
            if (a[idx] < 0) return Math.abs(x);        // slot already marked
            a[idx] = -a[idx];
        }
        return -1;
    }

    // Missing Number (268): values are 0..n with one missing
    static int missingNumber(int[] a) {
        long n = a.length;
        long expected = n * (n + 1) / 2, actual = 0;
        for (int x : a) actual += x;
        return (int) (expected - actual);
    }

    public static void main(String[] args) {
        System.out.println(disappeared(new int[]{4, 3, 2, 7, 8, 2, 3, 1}));
        System.out.println(findDuplicate(new int[]{1, 3, 4, 2, 2}));
        System.out.println(missingNumber(new int[]{3, 0, 1}));
    }
}
[5, 6]

All are O(n) time and O(1) extra space. The marking trick modifies the input; if that is forbidden, use a boolean[] (O(n) space) or, for Find the Duplicate Number with a read-only array, Floyd's cycle detection (Module 2, linked lists).

Edge case: duplicates and negatives break the tricks

The index-marking idea needs every value to be a valid index (1..n). If values can be 0, negative or larger than n, first check the constraints, or use a hash set. Always ask: "can the array be modified?"

Tip: how to think about array problems

  1. Write 2–3 small examples and solve by hand; notice what you do with your eyes.
  2. Ask what must be known at position i: something from the left, from the right, or both? (Two passes or prefix/suffix arrays.)
  3. Ask if sorting or a hash set removes the difficulty (and what it costs).
  4. Try to cut space: can the output array or the input itself hold the state?
  5. Test: length 1, all equal, already sorted, reverse sorted, negatives, zeros.

Interview angle

For "product except self" interviewers want the left/right pass idea and the reason division fails (zeros). For "next permutation" they want the four steps spoken in order and the reason the suffix is reversed rather than sorted: it is already in decreasing order, so reversing it sorts it in O(n).
