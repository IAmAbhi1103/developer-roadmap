Interview questions — Core patterns

How do you decide between two pointers and a sliding window?

Both use two indexes that only move forward. Use sliding window when the answer is a contiguous subarray or substring and you maintain a summary (sum, counts) of what is between the indexes. Use two pointers when you compare the elements at the two indexes themselves: pairs in a sorted array, palindromes, in-place read/write. See Two pointers and Sliding window.

Why is the sliding window O(n) even though it has a while loop inside a for loop?

The left pointer only moves forward and never passes the right pointer, so across the whole run it moves at most n times. Each element is added once and removed at most once. The total work is O(n), not O(n²). This is amortized analysis. The same argument proves the monotonic stack and monotonic deque are O(n).

Why does a sum-based sliding window fail with negative numbers? What do you use instead?

The window logic needs monotonicity: adding an element must not decrease the sum, and removing one must not increase it. With negatives that breaks, so "shrink while the sum is too large/valid" can stop too early and miss answers. Use prefix sums with a HashMap: the subarray sum ending at i equals k if an earlier prefix equals prefix - k. This works for any signs (Subarray Sum Equals K).

How do you find the start of a cycle in a linked list, and why does it work?

Run slow (1 step) and fast (2 steps) until they meet. Then reset one pointer to the head and move both one step at a time; they meet at the cycle entry. Let a be the distance from head to entry and c the distance from the meeting point onward to the entry. At the meeting, slow walked a + b and fast walked twice as much, which gives a = (k − 1)(cycle length) + c. So walking a steps from the meeting point lands exactly on the entry. O(n) time, O(1) space.

Reverse a linked list iteratively. What are the three pointers?

Keep prev (head of the reversed part, starts null), cur (the node being flipped) and nxt (the saved cur.next). Loop: save nxt = cur.next, set cur.next = prev, move prev = cur, move cur = nxt. Return prev. It is O(n) time and O(1) space. The recursive version is O(n) stack space and can overflow on long lists.

What is a dummy node and when do you use it?

A fake node placed before the real head so that dummy.next is the head. You use it whenever the head can be deleted, replaced or inserted before, such as Remove Nth From End, Merge Two Lists or Remove Elements. It removes the special case for the head, and you return dummy.next.

Why prefer ArrayDeque over Stack and LinkedList in Java?

Stack extends Vector: synchronized (slow), and it exposes index-based methods that break stack semantics. LinkedList allocates a node per element and is slower and heavier. ArrayDeque is a resizable circular array: fast, compact, and it works as stack, queue and deque. Its drawbacks: no null elements and not thread-safe. Remember pop() throws NoSuchElementException on empty, while peek() and poll() return null.

Explain the monotonic stack and give its complexity.

A stack whose values stay in one order (for example decreasing). When a new element breaks the order, pop elements until the order is restored; the popped elements have just found their "next greater" element. Each index is pushed once and popped at most once, so the whole scan is O(n). Use it for next greater/smaller, Daily Temperatures, Stock Span and Largest Rectangle in Histogram. Store indexes so you can compute distances.

How do you compute the maximum of every window of size k in O(n)?

Use a monotonic deque of indexes with decreasing values. For each new element pop from the back all smaller or equal values, push the new index, pop the front if it left the window (front <= i - k), and read the front as the maximum. Each index enters and leaves once, so O(n) time and O(k) space. A max-heap with lazy deletion also works in O(n log n).

What is the difference between height and depth of a tree node, and what is a balanced tree?

Depth is the number of edges from the root to the node; height is the number of edges on the longest path down to a leaf. A tree is height-balanced when, at every node, the left and right subtree heights differ by at most 1, which keeps the height at O(log n). A skewed tree has height n, and recursion on it uses O(n) stack.

Write an iterative inorder traversal and explain how it works. 
Deque<TreeNode> stack = new ArrayDeque<>();
TreeNode cur = root;
while (cur != null || !stack.isEmpty()) {
    while (cur != null) { stack.push(cur); cur = cur.left; }
    cur = stack.pop();
    visit(cur);
    cur = cur.right;
}

Push the whole left spine, pop the leftmost node, visit it, then repeat for its right subtree. The stack holds the ancestors still waiting. O(n) time, O(h) space.

How do you find the diameter of a binary tree in O(n)?

Write a height function that also updates a global answer. At each node the longest path bending there is leftHeight + rightHeight; record the maximum. Return 1 + max(left, right) to the parent, because a path going up can use only one child. Calling a separate height function at every node would be O(n²) in a skewed tree.

How does the recursive LCA algorithm work?

The function returns the node itself if it equals p or q, or null at a null node. Otherwise it recurses into both children. If both results are non-null, p and q are on different sides, so the current node is the LCA. If only one is non-null, return it up. In a BST you do not need both sides: go left if both values are smaller, right if both are larger, else the current node is the LCA. O(n) for a general tree, O(h) for a BST.

Why is "check left.val < node.val < right.val" not enough to validate a BST?

The BST rule covers the entire subtree, not just the children. A node deep in the right subtree can be smaller than the root even if it is correctly placed relative to its own parent. Pass down a (lo, hi) range: going left sets hi to the node's value, going right sets lo to it. Or check that an inorder traversal is strictly increasing. Use Integer bounds or long to avoid problems with Integer.MIN_VALUE.

Find the K largest elements: why a min-heap, and how does it compare with sorting and quickselect?

Keep a min-heap of size k. Its top is the smallest of the k largest, i.e. the next one to evict when a bigger value arrives. Time O(n log k), memory O(k), and it works on streams. Sorting is O(n log n). Quickselect is O(n) on average but O(n²) in the worst case and needs all the data in memory. If values are bounded or counts are involved, bucket sort gives O(n).

How do you find the minimum number of meeting rooms?

Sort meetings by start. Keep a min-heap of end times of occupied rooms. For each meeting, if the earliest end time is at or before its start, reuse that room (poll). Push the meeting's end. The heap size at the end is the answer. Alternatively sort the starts and ends separately and sweep with two pointers. Both are O(n log n).

Cheat sheet — Core patterns

  • Two pointers (opposite ends) sorted input or palindrome: move the pointer that can improve the answer; O(n).
  • Read/write pointers in-place filtering or de-duplication: read scans, write marks the kept prefix.
  • Fixed window add right, check size k, record, remove left. O(n).
  • Variable window expand right; shrink left while invalid (longest) or while valid (shortest, record before shrinking).
  • Window needs non-negative numbers for sums; otherwise use prefix sums plus a HashMap.
  • Exactly K = atMost(K) − atMost(K − 1).
  • Linked list use a dummy node when the head can change; save next before rewiring.
  • Reverse list prev, cur, nxt; iterative is O(1) space, recursive is O(n).
  • Fast/slow middle, cycle detection; reset one pointer to head to find the cycle entry; gap of n for the n-th from the end.
  • Stack in Java Deque<T> s = new ArrayDeque<>() with push, pop, peek. Never Stack.
  • Valid parentheses push the expected closer; the stack must be empty at the end.
  • Monotonic stack store indexes; pop while the top breaks the order; each index pushed and popped once; O(n).
  • Queue/Deque offer/poll/peek; offerFirst/offerLast/pollFirst/pollLast. Use ArrayDeque.
  • BFS by levels size = q.size() at the start of each round of the while loop.
  • Sliding window max deque of decreasing values; pop back while smaller; pop front when out of range.
  • Tree traversals preorder N-L-R, inorder L-N-R (sorted for a BST), postorder L-R-N; recursion uses O(h) stack.
  • Tree recursion define what each call returns; base case null; for bent paths return one side, update a global with both.
  • Height/diameter/balanced one pass, bottom-up; -1 sentinel for unbalanced.
  • LCA both sides non-null means the current node; BST version walks one path in O(h).
  • Views side views by BFS level; top/bottom view with horizontal distance and a TreeMap.
  • BST left smaller, right larger; delete with 0, 1 or 2 children (use the inorder successor); validate with (lo, hi) bounds.
  • Heap array parent (i - 1) / 2, children 2i + 1, 2i + 2; offer/poll O(log n), peek O(1), heapify O(n).
  • PriorityQueue min-heap by default; Comparator.reverseOrder() for max; use Integer.compare, not subtraction.
  • Top K K largest = min-heap of size k; K smallest = max-heap of size k; O(n log k).
  • Median of a stream max-heap for the lower half, min-heap for the upper half; keep sizes within 1.
  • Intervals sort by start to merge; sort by end to keep the most; heap of end times or sweep line for rooms.
  • Matrix dirs array and bounds checks; rotate = transpose + reverse rows; staircase from the top-right in a sorted-rows-and-columns grid.

Practice — Core patterns

Roadmap target for this module: about 100 problems over months 4 to 6. Start the weekly LeetCode contest in month 4 (one contest per week; solving even the first two problems under time pressure is a good habit). For each problem: say the pattern out loud before coding, write the solution without notes, state time and space, and test an empty and a one-element input.

  1. Month 4: two pointers, sliding window, linked lists (35 problems). Do about 12 two-pointer problems (Two Sum II, 3Sum, Container With Most Water, Remove Duplicates from Sorted Array, Valid Palindrome, Trapping Rain Water, Sort Colors), about 12 sliding-window problems (Maximum Average Subarray, Longest Substring Without Repeating Characters, Minimum Window Substring, Longest Repeating Character Replacement, Permutation in String, Fruit Into Baskets) and about 11 linked-list problems. Done when you can write the fixed and variable window templates from memory and explain why they are O(n).
  2. Linked list set. Implement from scratch, without looking: Reverse Linked List (both ways), Merge Two Sorted Lists, Linked List Cycle and Cycle II, Middle of the Linked List, Remove Nth Node From End, Palindrome Linked List, Add Two Numbers, Reorder List. Done when each runs correctly on empty, one-node and two-node inputs.
  3. Month 5: stacks, queues, intervals, matrix (30 problems). Stacks and monotonic stack: Valid Parentheses, Min Stack, Evaluate Reverse Polish Notation, Daily Temperatures, Next Greater Element II, Largest Rectangle in Histogram, Decode String. Queues: Implement Queue using Stacks, Sliding Window Maximum, a BFS on a small grid. Done when you can state the stack invariant of each problem in one sentence.
  4. Intervals and matrix set. Merge Intervals, Insert Interval, Non-overlapping Intervals, Meeting Rooms I and II (heap and sweep line), Spiral Matrix, Rotate Image, Set Matrix Zeroes, Search a 2D Matrix I and II, Flood Fill. Done when Rotate Image and Set Matrix Zeroes are in place with O(1) extra space.
  5. Month 6: binary trees, BSTs, heaps (35 problems). Trees: all three traversals recursively and iteratively, Maximum Depth, Diameter, Balanced Binary Tree, Same/Symmetric/Invert Tree, Path Sum I and II, Binary Tree Maximum Path Sum, Lowest Common Ancestor, Right Side View, Zigzag Level Order, Construct from Preorder and Inorder, Serialize and Deserialize. Done when you can solve a new tree problem by first writing the contract "what does this call return?".
  6. BST set. Validate BST (with bounds), Kth Smallest Element, Insert and Delete in a BST, LCA of a BST, Convert Sorted Array to BST, BST Iterator. Then use a TreeMap for one problem (for example My Calendar I). Done when you can explain the three delete cases and why checking only the children is wrong.
  7. Heap set. Kth Largest Element in an Array, Top K Frequent Elements (heap and bucket versions), K Closest Points to Origin, Merge K Sorted Lists, Find Median from Data Stream, Task Scheduler. Done when you can implement a min-heap with sift up and sift down on paper.
  8. Build the toolkit. Write your own MinHeap class, an LRU cache with a doubly linked list and a HashMap, and a circular queue. Done when all three pass tests you write yourself, including the full and empty cases.
  9. Weekly contest review. After each contest, re-solve the problems you missed within 48 hours and write down the pattern name and the trick you missed. Done when you keep a one-line-per-problem log of at least 8 contests.
  10. Mock interview. Pick one problem from each pattern group at random, solve it in 30 minutes on paper or a plain editor, and explain the complexity aloud. Next steps: graphs, recursion, dynamic programming and greedy in Module 3. Done when you finish three problems in a row within the time limit.
