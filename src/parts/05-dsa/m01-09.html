Interview questions — DSA foundations

What is the time complexity of ArrayList.add, ArrayList.contains, HashMap.get and PriorityQueue.poll?

ArrayList.add(x) at the end is O(1) amortized (an occasional resize costs O(n)); add(0, x) is O(n). contains is O(n), a linear scan. HashMap.get is O(1) on average; the worst case is O(log n) in Java 8+ when long buckets turn into trees. PriorityQueue.poll is O(log n) and peek is O(1). Knowing these decides whether a loop with a lookup inside is O(n) or O(n²).

How do you find the maximum subarray sum in O(n)? What if all numbers are negative?

Kadane's algorithm: at each index, endingHere = max(a[i], endingHere + a[i]), and keep the maximum of endingHere seen. It means "extend the previous subarray or start fresh here". Initialise both variables with a[0], not 0, so an all-negative array correctly returns its largest single element (for example −1 for [-3,-1,-2]). Time O(n), space O(1).

Solve Two Sum in O(n). Why do you look up the complement before inserting?

Keep a map from value to index. For each x, check whether target - x is already in the map; if so return both indices, otherwise store x. Looking up first prevents an element from pairing with itself (target 6 with a single 3), while two equal values like [3, 3] still work, because the first 3 is already stored when the second arrives. Time O(n), space O(n). If the array is sorted and you only need values, two pointers give O(1) space.

How do you count subarrays with sum K when the array has negative numbers?

Sliding window fails because adding an element no longer always increases the sum. Use prefix sums and a map: a subarray ending at i has sum K when an earlier prefix equals prefix[i] - K. Keep a map from prefix value to how many times it occurred, seeded with {0: 1} for the empty prefix, and add map.get(prefix - K) to the answer at each step. O(n) time and space; use long if sums can be large.

Merge sort vs quick sort: compare time, space, stability and when you would use each.

Merge sort is O(n log n) always, stable, but needs O(n) extra space on arrays. Quick sort is O(n log n) on average and O(n²) in the worst case (bad pivots, for example a sorted array with a first-element pivot), in place with O(log n) stack, and not stable. A random or median-of-three pivot makes the worst case very unlikely. Use merge sort when stability or guaranteed time matters, and for linked lists and external sorting; use quick sort for in-memory primitive arrays, where it is usually faster because of cache-friendly scans.

What sorting algorithms does Java use, and why is Arrays.sort(int[]) different from Arrays.sort(Integer[])?

Arrays.sort(int[]) uses a dual-pivot quicksort: fast and in place, and stability is meaningless for primitives because equal ints are indistinguishable. Arrays.sort(Object[]), Collections.sort and List.sort use TimSort, a stable merge/insertion hybrid that exploits existing sorted runs. Objects need stability, so that sorting by one key after another works.

Why write mid = lo + (hi - lo) / 2 in binary search?

(lo + hi) / 2 can overflow when both indices are large (above 230), producing a negative mid and an exception or infinite loop. lo + (hi - lo) / 2 never exceeds hi, so it cannot overflow. This bug existed in widely used library code for years. (lo + hi) >>> 1 is also safe.

How do you find the first and last occurrence of a value in a sorted array?

Use two boundary searches with the "first true" template. lowerBound(x) is the first index with a[i] >= x; upperBound(x) is the first index with a[i] > x. The first occurrence is lowerBound (check that it is in range and a[first] == x), the last is upperBound - 1, and the count is upperBound - lowerBound. Each is O(log n). A linear scan after an exact-match search can degrade to O(n) with many duplicates.

How does binary search work on a rotated sorted array?

At each step one half around mid is fully sorted. If a[lo] <= a[mid] the left half is sorted: if the target lies in [a[lo], a[mid]) go left, else go right. Otherwise the right half is sorted, and you check (a[mid], a[hi]] the same way. That discards half the array each time: O(log n). With duplicates, a[lo] == a[mid] == a[hi] can hide the sorted half, so you shrink by one and the worst case becomes O(n).

What is "binary search on the answer"? Give an example.

When you can test a candidate answer with a monotonic yes/no check, binary search the answer range rather than an array. In Koko Eating Bananas, if speed k finishes in H hours then any bigger speed does too, so search speeds from 1 to the largest pile with the check sum(ceil(pile / k)) <= H and keep the smallest feasible one. Time O(n log max). The same pattern solves Ship Packages, Split Array Largest Sum and Aggressive Cows ("minimise the maximum", "maximise the minimum").

Why is naive recursive Fibonacci O(2^n), and how do you fix it?

Each call makes two calls, on n−1 and n−2, so the recursion tree has an exponential number of nodes (about 1.618n, bounded by 2n) and the same subproblems such as fib(3) are recomputed many times. Memoization (store each result in an array or map) makes every fib(k) computed once: O(n) time, O(n) space. A loop with two variables gives O(n) time and O(1) space. This is the entry point to dynamic programming.

Does Java optimise tail recursion? What happens with very deep recursion?

No. The JVM does not perform tail-call optimisation, so a tail-recursive method still adds one stack frame per call. Recursion that goes tens of thousands of frames deep throws StackOverflowError with the default thread stack size. Fix it by converting to a loop, using your own ArrayDeque as an explicit stack, or running in a thread with a bigger stack in competitive settings.

Write code to generate all subsets of an array. What is its complexity?

For each index decide "pick" or "skip": add nums[i] to the path, recurse on i + 1, remove it (backtrack), recurse again; at i == n add a copy of the path to the result. There are 2n subsets and each copy costs O(n), so time is O(n × 2n); recursion depth is n. For duplicates, sort first and skip a value equal to the previous one at the same level. A bitmask loop over 0..2^n - 1 gives the same result without recursion.

How do you check whether a number is a power of two, and count its set bits?

n > 0 && (n & (n - 1)) == 0. Subtracting 1 flips the lowest set bit and all bits below it, so AND-ing with n clears the lowest set bit; a power of two has only that one bit, leaving 0. To count set bits repeat n &= n - 1 until n is 0 and count the iterations (Brian Kernighan, O(number of set bits)); in practice call Integer.bitCount(n).

Find the one number that appears once when all others appear twice, in O(n) time and O(1) space.

XOR all elements. Since a ^ a = 0, a ^ 0 = a and XOR is commutative and associative, the pairs cancel and the single value remains. A HashSet works in O(n) space; sorting works in O(n log n). The same idea finds a missing number: XOR every index and every value together with n.

Cheat sheet — DSA foundations

  • Constraints to complexity n ≤ 10 → n!; ≤ 20 → 2n; ≤ 500 → n³; ≤ 5,000 → n²; ≤ 105–106 → n log n or n; ≤ 108 → n; larger → log n.
  • Method read, constraints, examples by hand, brute force, find the pattern, code, test edge cases.
  • Costs ArrayList get O(1), contains O(n); HashMap/HashSet O(1) average; ArrayDeque ends O(1); PriorityQueue offer/poll O(log n), peek O(1); String concat and substring O(length).
  • Overflow int max ≈ 2.1 × 109; cast before multiplying (long) a * b; Math.addExact throws; Math.abs(Integer.MIN_VALUE) stays negative.
  • Characters c - 'a' → index 0..25; int[26] for lowercase letters; int[128] for ASCII.
  • Sorting API Arrays.sort(int[]) dual-pivot quicksort; objects use stable TimSort; descending needs Integer[] or reverse; compare with Integer.compare, never subtraction.
  • Primes test to √n in O(√n); sieve O(n log log n), inner loop from p × p; factorise by trial division to √n.
  • GCD / mod gcd(a, b) = gcd(b, a % b); lcm = a / gcd * b; ((x % m) + m) % m for negatives; use long for a * b % m; fast power O(log n).
  • Prefix sums sum(l..r) = prefix[r+1] - prefix[l]; difference array for many range updates.
  • Kadane endingHere = max(a[i], endingHere + a[i]); start from a[0].
  • In place read/write pointers; reverse-all/reverse-parts for rotation; low/mid/high for Dutch flag; Boyer–Moore voting for majority.
  • Strings immutable; use StringBuilder to build; two pointers for palindromes; counting array for anagrams.
  • Hashing complement lookup (Two Sum); set for duplicates; prefix-sum map seeded with {0:1}; start a run only if x - 1 is absent.
  • Sort facts insertion O(n) best/stable; merge O(n log n)/stable/O(n) space; quick O(n log n) average, O(n²) worst, not stable; counting O(n + k).
  • Binary search exact match: lo <= hi, mid ± 1; boundary: lo < hi, hi = mid; midpoint lo + (hi - lo) / 2.
  • Search on the answer monotonic yes/no check + range; "minimise the max / maximise the min"; round mid up for last-true.
  • Recursion base case, smaller step, leap of faith; time = number of calls, space = depth; Java has no tail-call optimisation.
  • Backtracking choose, explore, un-choose; add a copy of the path; subsets 2n, permutations n!.
  • Bits x & 1 odd; x & (x-1) clears the lowest set bit; x & -x isolates it; XOR cancels pairs; 1L << i for large i.
  • Edge cases empty input, one element, all equal, sorted, reversed, negatives, zeros, maximum values.

Practice — DSA foundations

Foundations take about three months at 1–2 hours a day, roughly 90 problems. Quality beats quantity: solve each problem on paper first, state the complexity before you code, and write it in Java without an IDE hint where you can.

  1. Warm-up (week 1) — complexity and the Java toolkit. For each of your last 10 solutions, write the time and space complexity in a comment and justify it. Then, without looking, write: counting with getOrDefault, a min-heap and a max-heap, sorting an int[][] by column, the fast-input skeleton. Done when you can type each in under a minute and explain every cost.
  2. Month 1 target: 30 problems — arrays, strings, hashing. Arrays (about 20): Two Sum, Best Time to Buy and Sell Stock, Maximum Subarray, Move Zeroes, Remove Duplicates from Sorted Array, Rotate Array, Sort Colors, Majority Element, Product of Array Except Self, Merge Sorted Array, Next Permutation, Find Pivot Index, Missing Number. Strings: Valid Palindrome, Valid Anagram, First Unique Character, Longest Common Prefix, Reverse Words, String Compression. Hashing: Contains Duplicate, Group Anagrams, Subarray Sum Equals K, Longest Consecutive Sequence, Intersection of Two Arrays. Done when 80% are solved without hints within 30 minutes each.
  3. Month 2 target: 30 problems — sorting and binary search. Implement merge sort and quick sort from memory, then count inversions; Merge Intervals, Kth Largest Element, sort strings by length then alphabetically, Largest Number. Binary search: Binary Search, Search Insert Position, First and Last Position, Sqrt(x), Search in Rotated Sorted Array, Find Minimum in Rotated Array, Find Peak Element, First Bad Version, Koko Eating Bananas, Capacity to Ship Packages, Split Array Largest Sum, Aggressive Cows. Done when you can write both binary search templates without off-by-one errors on the first try.
  4. Month 3 target: 30 problems — recursion, bits, maths. Recursion and backtracking: Fibonacci with memoization, Pow(x, n), Subsets, Subsets II, Permutations, Combination Sum, Generate Parentheses, Letter Combinations of a Phone Number. Bits: Single Number, Number of 1 Bits, Power of Two, Missing Number, Counting Bits, subsets with a bitmask. Maths: Count Primes, GCD and LCM, Reverse Integer, Palindrome Number, Happy Number, modular exponentiation. Done when you can draw the recursion tree of any of these and state its size.
  5. Keep a DSA log. One row per problem: problem, pattern (prefix sum, two pointers, hash lookup, binary search on answer, backtracking…), key trick (one sentence), mistake (what went wrong), and needed help? (yes / hint / no). Keep it in a spreadsheet or a notes file. Done when every solved problem has a row and you review the "mistake" column every Sunday.
  6. Re-solve on a schedule. Re-solve every problem where you needed help, or that took over 40 minutes, after 3 days and again after 2 weeks, from a blank file. Done when the second re-solve takes under 15 minutes and you can explain the idea aloud in two sentences.
  7. Write your own templates file. In a single Java file keep: binary search (both templates), the answer-search skeleton, sieve, gcd, modPow, merge sort, quickselect, subsets and permutations backtracking, Kadane, prefix sums. Re-type it from memory monthly. Done when it compiles first time and all methods have a short test in main.
  8. Mock interview. Pick three unseen problems (one array/hash, one binary search, one recursion). Set a 35-minute timer each, talk aloud: brute force, optimisation, complexity, dry run on an example, edge cases. Done when you finish two of the three in time with correct complexity statements.

When this module feels comfortable, move to Module 2: Core patterns (two pointers, sliding window, linked lists, stacks, queues, heaps, trees).
