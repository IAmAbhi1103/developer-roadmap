Queues and deques: BFS levels and sliding window maximum

A queue is first-in, first-out and drives breadth-first search (level by level); a deque works at both ends, and a monotonic deque gives the maximum of every sliding window in O(n).

A queue serves items in the order they arrived (FIFO: first in, first out), like a line at an IRCTC counter. You offer (enqueue) at the back and poll (dequeue) from the front. A deque (double-ended queue, said "deck") lets you add and remove at both ends, so it can act as a stack, a queue, or something in between. In Java both are interfaces; the implementation you use almost always is ArrayDeque.

Queue<Integer> q = new ArrayDeque<>();
q.offer(1);              // add at the back (add() also works, throws if it fails)
int head = q.peek();     // look at the front; null if empty
int x = q.poll();        // remove the front; null if empty (remove() throws instead)

Deque<Integer> d = new ArrayDeque<>();
d.offerFirst(1);  d.offerLast(2);       // add at either end
d.peekFirst();    d.peekLast();         // look at either end, null if empty
d.pollFirst();    d.pollLast();         // remove from either end, null if empty
d.addFirst(5);    d.removeLast();       // throwing versions

Common mistakes with queues in Java

  • Using LinkedList as a queue out of habit. It works but allocates a node per element; ArrayDeque is faster and lighter. (Use LinkedList only when you need to store null.)
  • Writing Queue<int[]> q and then forgetting that q.poll() returns null when empty. Always loop with while (!q.isEmpty()).
  • Using PriorityQueue when you want plain FIFO. It orders by priority, not arrival (see Heaps).

BFS template with levels

Breadth-first search (BFS) visits nodes in rings: first the start, then everything one step away, then two steps away, and so on. A queue gives exactly this order. To process one level at a time, take size = q.size() at the start of each round and handle exactly that many nodes; the nodes they add belong to the next level. The same code works on trees now and on graphs in Module 3 (graphs add a visited set).

public List<List<Integer>> levelOrder(TreeNode root) {
    List<List<Integer>> levels = new ArrayList<>();
    if (root == null) return levels;
    Queue<TreeNode> q = new ArrayDeque<>();
    q.offer(root);
    while (!q.isEmpty()) {
        int size = q.size();                    // nodes in the current level
        List<Integer> level = new ArrayList<>();
        for (int i = 0; i < size; i++) {
            TreeNode node = q.poll();
            level.add(node.val);
            if (node.left != null)  q.offer(node.left);
            if (node.right != null) q.offer(node.right);
        }
        levels.add(level);
    }
    return levels;
}

(TreeNode is defined in Binary trees.) Complexity: O(n) time; O(w) space where w is the widest level (up to n/2 in a complete tree). BFS finds the shortest path in an unweighted graph, which is why "minimum number of steps" problems use it. Flood fill and shortest-path-in-a-grid on a matrix are in Matrix.

Circular queue (array implementation)

Design Circular Queue (LeetCode 622): a fixed-size queue in an array where positions wrap around, so freed slots at the front are reused. Keep head (index of the front), size, and compute the tail as (head + size) % capacity.

class MyCircularQueue {
    private final int[] data;
    private int head = 0, size = 0;

    MyCircularQueue(int k) { data = new int[k]; }

    boolean enQueue(int value) {
        if (isFull()) return false;
        data[(head + size) % data.length] = value;
        size++;
        return true;
    }
    boolean deQueue() {
        if (isEmpty()) return false;
        head = (head + 1) % data.length;
        size--;
        return true;
    }
    int Front() { return isEmpty() ? -1 : data[head]; }
    int Rear()  { return isEmpty() ? -1 : data[(head + size - 1) % data.length]; }
    boolean isEmpty() { return size == 0; }
    boolean isFull()  { return size == data.length; }
}

Tracking size separately avoids the classic confusion where head == tail could mean either empty or full. All operations are O(1). This is also how ArrayDeque works inside.

Queue using two stacks, stack using queues

Implement Queue using Stacks (LeetCode 232): keep an in stack for pushes and an out stack for pops. When out is empty, move everything from in to out; that reverses the order, so the oldest item is on top.

class MyQueue {
    private final Deque<Integer> in = new ArrayDeque<>(), out = new ArrayDeque<>();

    public void push(int x) { in.push(x); }
    public int pop()  { move(); return out.pop(); }
    public int peek() { move(); return out.peek(); }
    public boolean empty() { return in.isEmpty() && out.isEmpty(); }

    private void move() {
        if (out.isEmpty()) while (!in.isEmpty()) out.push(in.pop());
    }
}

Each element moves at most once from in to out, so every operation is amortized O(1) (a single pop can cost O(n), but never repeatedly).

Implement Stack using Queues (LeetCode 225): with one queue, after pushing x rotate the queue size - 1 times so x comes to the front. Then pop and top are plain queue operations.

class MyStack {
    private final Queue<Integer> q = new ArrayDeque<>();

    public void push(int x) {
        q.offer(x);
        for (int i = 1; i < q.size(); i++) q.offer(q.poll());   // rotate x to the front
    }
    public int pop()  { return q.poll(); }
    public int top()  { return q.peek(); }
    public boolean empty() { return q.isEmpty(); }
}

push is O(n), the others O(1). The other trade-off (cheap push, costly pop) is also valid; interviewers want you to state the trade-off.

Sliding Window Maximum (LeetCode 239) with a monotonic deque

Find the maximum of every window of size k. A max-heap works in O(n log k), but a monotonic deque gives O(n). Keep indexes in the deque with values in decreasing order from front to back. The front is always the maximum of the current window. For each new element:

  1. Pop from the back every index whose value is less than or equal to the new value. They can never be a maximum again, because the new element is bigger and will stay in the window longer.
  2. Push the new index at the back.
  3. If the front index has slipped out of the window (front <= i - k), pop it from the front.
  4. Once i >= k - 1, the front is the answer for this window.
public int[] maxSlidingWindow(int[] nums, int k) {
    int n = nums.length;
    int[] res = new int[n - k + 1];
    Deque<Integer> dq = new ArrayDeque<>();         // indexes, values decreasing
    for (int i = 0; i < n; i++) {
        while (!dq.isEmpty() && nums[dq.peekLast()] <= nums[i]) dq.pollLast();
        dq.offerLast(i);
        if (dq.peekFirst() <= i - k) dq.pollFirst();   // front left the window
        if (i >= k - 1) res[i - k + 1] = nums[dq.peekFirst()];
    }
    return res;
}

Interview angle

Three things get asked: (1) the level-order loop with size = q.size(); (2) queue from two stacks with the amortized O(1) argument; (3) sliding window maximum, usually after you offer the heap solution, with "can you do O(n)?" as the follow-up. Say why the deque stores indexes (to expire old elements) and why smaller elements at the back are discarded.

Binary trees: terms and traversals

A binary tree is nodes with at most two children; DFS visits depth first (preorder, inorder, postorder) using recursion or an explicit stack, and BFS visits level by level using a queue.

A tree is a hierarchy: one root node at the top, and every other node has exactly one parent. In a binary tree each node has at most two children, called left and right. Folders in your laptop, a company org chart and the HTML DOM are trees. A node with no children is a leaf.

public class TreeNode {
    int val;
    TreeNode left, right;
    TreeNode(int val) { this.val = val; }
    TreeNode(int val, TreeNode left, TreeNode right) {
        this.val = val; this.left = left; this.right = right;
    }
}

Terminology

Depth of a node
Number of edges from the root down to the node. The root has depth 0.
Height of a node
Number of edges on the longest path from the node down to a leaf. A leaf has height 0. The tree's height is the root's height. (LeetCode's "maximum depth" counts nodes, so it is height + 1.)
Level
All nodes at the same depth.
Full binary tree
Every node has 0 or 2 children.
Complete binary tree
All levels are full except possibly the last, which is filled from the left. Heaps are complete trees (see Heaps).
Perfect binary tree
All internal nodes have 2 children and all leaves are on the same level. It has 2h+1 − 1 nodes for height h.
Balanced tree
For every node, the heights of its left and right subtrees differ by at most 1 (the LeetCode definition). A balanced tree has height O(log n); a skewed tree (each node one child) has height n.

Almost every tree algorithm costs O(n) time because it visits each node once, and O(h) space for the recursion stack, where h is the height: O(log n) if balanced, O(n) if skewed.

DFS traversals, recursive

Depth-first search (DFS) goes as deep as possible before backing up. The three classic orders differ only in when you handle the current node relative to its children:

OrderSequenceTypical use
Preordernode, left, rightCopy a tree, serialize, prefix expressions
Inorderleft, node, rightSorted order of a BST
Postorderleft, right, nodeDelete a tree, compute heights, anything that needs children's results first
 
void preorder(TreeNode node, List<Integer> out) {
    if (node == null) return;
    out.add(node.val);               // visit BEFORE the children
    preorder(node.left, out);
    preorder(node.right, out);
}
void inorder(TreeNode node, List<Integer> out) {
    if (node == null) return;
    inorder(node.left, out);
    out.add(node.val);               // visit BETWEEN the children
    inorder(node.right, out);
}
void postorder(TreeNode node, List<Integer> out) {
    if (node == null) return;
    postorder(node.left, out);
    postorder(node.right, out);
    out.add(node.val);               // visit AFTER the children
}

Iterative traversals with an explicit stack

Recursion uses the call stack; a tree of 100,000 nodes in a straight line can cause StackOverflowError. Interviewers also ask for iterative versions to see whether you understand what the call stack does.

Preorder. Push the root. Pop a node, record it, then push the right child and then the left child, so the left is popped first.

public List<Integer> preorderTraversal(TreeNode root) {
    List<Integer> out = new ArrayList<>();
    if (root == null) return out;
    Deque<TreeNode> stack = new ArrayDeque<>();
    stack.push(root);
    while (!stack.isEmpty()) {
        TreeNode node = stack.pop();
        out.add(node.val);
        if (node.right != null) stack.push(node.right);   // right first...
        if (node.left != null)  stack.push(node.left);    // ...so left pops first
    }
    return out;
}

Inorder (the careful one). Go left as far as you can, pushing every node on the way. When you cannot go left, pop (this is the next node in order), record it, then move to its right child and repeat. The pointer cur means "the next subtree to dive into".

public List<Integer> inorderTraversal(TreeNode root) {
    List<Integer> out = new ArrayList<>();
    Deque<TreeNode> stack = new ArrayDeque<>();
    TreeNode cur = root;
    while (cur != null || !stack.isEmpty()) {
        while (cur != null) {          // dive left, remembering the path
            stack.push(cur);
            cur = cur.left;
        }
        cur = stack.pop();             // leftmost unvisited node
        out.add(cur.val);
        cur = cur.right;               // then its right subtree
    }
    return out;
}

Dry run on the tree 2 / (1, 3): dive pushes 2, 1; pop 1, record, cur = null (1 has no right); pop 2, record, cur = 3; dive pushes 3; pop 3, record; stack empty and cur null, stop. Output 1 2 3.

Postorder. A neat trick: postorder (left, right, node) is the reverse of "node, right, left". Do a preorder that pushes left before right, collect the result, and reverse it.

public List<Integer> postorderTraversal(TreeNode root) {
    LinkedList<Integer> out = new LinkedList<>();
    if (root == null) return out;
    Deque<TreeNode> stack = new ArrayDeque<>();
    stack.push(root);
    while (!stack.isEmpty()) {
        TreeNode node = stack.pop();
        out.addFirst(node.val);                  // adding at the front = reversing
        if (node.left != null)  stack.push(node.left);
        if (node.right != null) stack.push(node.right);
    }
    return out;
}

All three iterative versions are O(n) time and O(h) space (O(n) for the result list).

Level-order and zigzag

Level-order BFS is in the queue article. Binary Tree Zigzag Level Order Traversal (LeetCode 103) alternates direction each level. Keep a boolean leftToRight; after building each level list, if it is false, call Collections.reverse(level) (or insert with level.add(0, val)), then flip the boolean. Same O(n) time.

Common mistakes

  • Forgetting the node == null base case, or checking node.left.val without a null check.
  • Using if (!stack.isEmpty()) instead of while in the iterative inorder loop.
  • Confusing height (edges) with depth/levels (nodes). Check which one the problem counts.
  • Declaring a leaf as "node with a null child". A leaf has both children null. This matters in Minimum Depth and Path Sum.

Interview angle

Know the three orders by heart, write inorder iteratively without notes, and state that recursion depth is the tree height. A frequent trick question: "which traversal of a BST gives sorted output?" (inorder). Also be ready for "reconstruct a tree from two traversals", covered in the LCA and views article.

Tree recursion: what does each node return?

Most tree problems are solved by defining one question per node, "what should this call return for its subtree?", and combining the answers from the left and right children; some also update a global best value on the way.

The trick with tree recursion is to stop tracing every call and instead trust a one-sentence contract. For example, "height(node) returns the height of the subtree rooted at node." Write the base case (usually null), assume the two recursive calls obey the contract, and combine their answers. Three shapes cover most problems.

  • Bottom-up (return a value): compute from the children, then return. Height, size, balanced, diameter, maximum path sum.
  • Top-down (pass information down): pass a parameter such as the current depth, a running sum, or allowed min/max bounds. Path sum, validate BST, count good nodes.
  • Global best (the diameter pattern): the function returns one thing to its parent (for example the height) but, while computing it, updates a separate field with the answer to the real question.
R solve(TreeNode node /*, top-down info */) {
    if (node == null) return /* identity value */;
    R left = solve(node.left /*, new info */);
    R right = solve(node.right /*, new info */);
    // combine left, right and node.val into the result for this subtree
    // optionally: update a global answer here
    return /* result */;
}

Maximum Depth of Binary Tree (LeetCode 104)

public int maxDepth(TreeNode root) {
    if (root == null) return 0;
    return 1 + Math.max(maxDepth(root.left), maxDepth(root.right));
}

Contract: returns the number of nodes on the longest root-to-leaf path. Complexity: O(n) time, O(h) space. A BFS that counts levels gives the same answer.

Diameter of Binary Tree (LeetCode 543): the global-max pattern

The diameter is the number of edges on the longest path between any two nodes; the path need not pass through the root. For each node, the longest path that bends at that node is leftHeight + rightHeight. But the function must return only the height (a path going up to the parent can use one side). So return height, and record the best bend in a field.

private int diameter = 0;

public int diameterOfBinaryTree(TreeNode root) {
    height(root);
    return diameter;
}

private int height(TreeNode node) {           // height in NODES of this subtree
    if (node == null) return 0;
    int left = height(node.left);
    int right = height(node.right);
    diameter = Math.max(diameter, left + right);   // path bending at this node
    return 1 + Math.max(left, right);              // what the parent needs
}

With height counted in nodes, left + right equals the number of edges on the bent path. Complexity: O(n) time, O(h) space. Remember the reset: if the method is called more than once, set diameter = 0 first.

Balanced Binary Tree (LeetCode 110)

Calling height separately at every node costs O(n²) in a skewed tree. Instead, return -1 as a sentinel meaning "unbalanced somewhere below", and bubble it up.

public boolean isBalanced(TreeNode root) {
    return check(root) != -1;
}

private int check(TreeNode node) {            // height, or -1 if unbalanced
    if (node == null) return 0;
    int left = check(node.left);
    if (left == -1) return -1;
    int right = check(node.right);
    if (right == -1 || Math.abs(left - right) > 1) return -1;
    return 1 + Math.max(left, right);
}

Complexity: O(n) time, O(h) space.

Same Tree, Symmetric Tree, Invert Tree

These three are "recurse on two trees at once" or "swap children".

// Same Tree (LeetCode 100)
public boolean isSameTree(TreeNode p, TreeNode q) {
    if (p == null || q == null) return p == q;        // both null -> true
    return p.val == q.val
        && isSameTree(p.left, q.left)
        && isSameTree(p.right, q.right);
}

// Symmetric Tree (LeetCode 101): left subtree must mirror the right one
public boolean isSymmetric(TreeNode root) {
    return root == null || mirror(root.left, root.right);
}
private boolean mirror(TreeNode a, TreeNode b) {
    if (a == null || b == null) return a == b;
    return a.val == b.val
        && mirror(a.left, b.right)                   // outer pair
        && mirror(a.right, b.left);                  // inner pair
}

// Invert Binary Tree (LeetCode 226)
public TreeNode invertTree(TreeNode root) {
    if (root == null) return null;
    TreeNode left = invertTree(root.left);
    TreeNode right = invertTree(root.right);
    root.left = right;
    root.right = left;
    return root;
}

All three are O(n) time and O(h) space. Note the trick p == q when at least one is null: it is true only when both are null.

Path Sum I and II (LeetCode 112, 113): top-down

Does a root-to-leaf path add up to target? Pass the remaining sum down. At a leaf, check whether the remaining value equals the leaf's value.

public boolean hasPathSum(TreeNode node, int remaining) {
    if (node == null) return false;
    if (node.left == null && node.right == null) return node.val == remaining;
    return hasPathSum(node.left, remaining - node.val)
        || hasPathSum(node.right, remaining - node.val);
}

For Path Sum II you must return all such paths. Keep a shared path list, add the node on the way in, and remove it on the way out (backtracking). Copy the list when you store it.

public List<List<Integer>> pathSum(TreeNode root, int targetSum) {
    List<List<Integer>> result = new ArrayList<>();
    dfs(root, targetSum, new ArrayList<>(), result);
    return result;
}

private void dfs(TreeNode node, int remaining, List<Integer> path,
                 List<List<Integer>> result) {
    if (node == null) return;
    path.add(node.val);                                  // choose
    if (node.left == null && node.right == null && node.val == remaining) {
        result.add(new ArrayList<>(path));              // COPY, path keeps changing
    } else {
        dfs(node.left, remaining - node.val, path, result);
        dfs(node.right, remaining - node.val, path, result);
    }
    path.remove(path.size() - 1);                        // un-choose
}

Complexity: O(n) time to visit; copying paths adds O(n) per stored path, so O(n²) worst case. Space O(h) plus the output.

Common mistake: storing the shared list itself

result.add(path) stores a reference to the same list that you keep modifying, so every answer ends up empty. Always new ArrayList<>(path).

Brief: Binary Tree Maximum Path Sum (LeetCode 124)

This is the diameter pattern with values instead of lengths. A path may start and end anywhere. The function returns the best downward path starting at the node (the node plus at most one child), ignoring negative branches with Math.max(0, …). The bent path through the node, node.val + left + right, updates the global best.

private int best = Integer.MIN_VALUE;

public int maxPathSum(TreeNode root) {
    gain(root);
    return best;
}

private int gain(TreeNode node) {
    if (node == null) return 0;
    int left = Math.max(0, gain(node.left));       // drop negative branches
    int right = Math.max(0, gain(node.right));
    best = Math.max(best, node.val + left + right);     // bend at this node
    return node.val + Math.max(left, right);            // one side only
}

Start best at Integer.MIN_VALUE, not 0, because all values may be negative. Complexity: O(n) time, O(h) space.

How to think about a new tree problem

  1. Write the contract: what does f(node) return?
  2. Decide the base case for null (0, true, an empty list, or null).
  3. Is the answer the return value (bottom-up), or does it need extra information from above (top-down parameters)?
  4. If the answer is a path that bends, return the one-sided value and update a global with the two-sided value.
  5. Test on a single node, a null tree, and a skewed tree.
