Heaps and PriorityQueue: how a binary heap works

A heap is a complete binary tree stored in an array where each parent is smaller (min-heap) or larger (max-heap) than its children, so the best element is always at index 0 and insert and remove cost O(log n).

Sometimes you do not need everything sorted; you only need the smallest (or largest) item, again and again, while new items keep arriving. Sorting each time costs O(n log n). A heap gives you the extreme item in O(1) and lets you add or remove in O(log n). The Java class is PriorityQueue. Typical uses: the K largest values, merging sorted streams, scheduling by priority, running medians, and Dijkstra's shortest path in Module 3.

The binary heap as an array

A binary heap is a complete binary tree (every level full except maybe the last, filled left to right), with the heap property: in a min-heap every parent is ≤ its children, so the root is the minimum; a max-heap is the reverse. Because the tree is complete, no pointers are needed; store it in an array level by level.

Note the heap is not fully sorted: 5 sits left of 3, and 9 is not smaller than 3. Only the parent-child relation is guaranteed.

Sift up and sift down

Insert: put the new value at the end of the array (the next free leaf), then sift up: while it is smaller than its parent, swap them. At most height = log n swaps.

Remove the root (poll): take the root as the answer, move the last array element to index 0, shrink the array, then sift down: swap with the smaller child while that child is smaller. Again at most log n swaps.

class MinHeap {
    private int[] a = new int[16];
    private int size = 0;

    void add(int x) {
        if (size == a.length) a = Arrays.copyOf(a, size * 2);
        a[size] = x;
        int i = size++;
        while (i > 0 && a[(i - 1) / 2] > a[i]) {          // sift up
            swap(i, (i - 1) / 2);
            i = (i - 1) / 2;
        }
    }

    int poll() {
        int top = a[0];                                      // caller checks size > 0
        a[0] = a[--size];
        int i = 0;
        while (true) {                                       // sift down
            int l = 2 * i + 1, r = 2 * i + 2, smallest = i;
            if (l < size && a[l] < a[smallest]) smallest = l;
            if (r < size && a[r] < a[smallest]) smallest = r;
            if (smallest == i) break;
            swap(i, smallest);
            i = smallest;
        }
        return top;
    }

    int peek() { return a[0]; }

    private void swap(int i, int j) { int t = a[i]; a[i] = a[j]; a[j] = t; }
}

Complexity: add and poll O(log n), peek O(1), space O(n).

Building a heap in O(n)

Inserting n items one by one costs O(n log n). A faster way: put all items in the array, then sift down every non-leaf node from the last parent (index n/2 - 1) back to index 0. Most nodes are near the bottom and move very little: half of them are leaves (0 moves), a quarter move at most 1, and so on. The sum of work is O(n). This is heapify, and it is what new PriorityQueue<>(collection) does.

Common mistakes with PriorityQueue

  • Iterating or printing it and expecting sorted order. The iterator and toString() show the internal array order, which is only heap-ordered. Poll repeatedly to get sorted output.
  • The overflow comparator. (a, b) -> b - a overflows when the numbers are far apart (for example b = Integer.MAX_VALUE, a = -5), producing the wrong sign. Use Integer.compare(b, a) or Comparator.reverseOrder().
  • Mutating an object after adding it. The heap does not re-sort. Remove and re-add it, or push a new entry and ignore stale ones when polled.
  • Assuming it is stable. Equal-priority items come out in no guaranteed order.

Rule: elements must be comparable

A PriorityQueue of your own class needs the class to implement Comparable or a Comparator passed to the constructor. Otherwise offer throws ClassCastException. It also rejects null elements (NullPointerException). It is not thread-safe; use PriorityBlockingQueue for multiple threads.

Heap sort (brief)

Build a max-heap in O(n). Then swap the root with the last element, shrink the heap by one, and sift down the new root; repeat n times. The array ends sorted ascending. Complexity: O(n log n) time in all cases, O(1) extra space, not stable. It is rarely used in practice because quicksort and merge sort are faster on real hardware, but it shows how heaps work and is asked in theory interviews.

Recognise a heap problem

  • "Top K", "K largest/smallest/most frequent/closest".
  • "Repeatedly take the best remaining item" while items are added (scheduling, merging).
  • "Median of a stream" or any need for the min and the max of a changing set.
  • Greedy choices that need "the smallest end time" or "the cheapest next step".

Interview angle

Be able to give the index formulas, explain sift up and sift down, and say why heapify is O(n) while n inserts are O(n log n). A common question: "why can't a heap give you sorted iteration, and how is it different from a BST?" (a heap orders only parent versus child, finds the min in O(1), but searching is O(n)).

Heap problems: top K, merge K lists, median of a stream

To get the K largest items keep a min-heap of size K; to merge K sorted sources keep a min-heap with one entry from each; to track a median keep a max-heap for the lower half and a min-heap for the upper half.

These problems use the PriorityQueue from the previous article. The same few ideas appear again and again.

Kth Largest Element in an Array (LeetCode 215)

Keep a min-heap of size k holding the k largest values seen so far. The top of the heap is the smallest of them, which is the k-th largest. When a new value arrives, add it; if the size exceeds k, remove the smallest. The surprise to remember: for the K largest you use a min-heap, because you want to evict the smallest.

public int findKthLargest(int[] nums, int k) {
    PriorityQueue<Integer> heap = new PriorityQueue<>();     // min-heap
    for (int x : nums) {
        heap.offer(x);
        if (heap.size() > k) heap.poll();                   // drop the smallest
    }
    return heap.peek();
}

Dry run: nums = [3,2,1,5,6,4], k = 2. Heap after each step: {3}, {2,3}, then add 1 and remove 1 gives {2,3}, add 5 and remove 2 gives {3,5}, add 6 and remove 3 gives {5,6}, add 4 and remove 4 gives {5,6}. The top is 5. Complexity: O(n log k) time, O(k) space. Alternatives: sort in O(n log n); Quickselect (partition like quicksort, recurse into one side only) gives O(n) average but O(n²) worst case.

Top K Frequent Elements (LeetCode 347)

Count with a HashMap, then keep the K highest counts. Two good solutions:

// 1. Min-heap of size k on the counts: O(n log k)
public int[] topKFrequent(int[] nums, int k) {
    Map<Integer, Integer> freq = new HashMap<>();
    for (int x : nums) freq.merge(x, 1, Integer::sum);

    PriorityQueue<Map.Entry<Integer, Integer>> heap =
        new PriorityQueue<>(Comparator.comparingInt(Map.Entry::getValue));
    for (Map.Entry<Integer, Integer> e : freq.entrySet()) {
        heap.offer(e);
        if (heap.size() > k) heap.poll();               // evict the least frequent
    }
    int[] res = new int[k];
    for (int i = k - 1; i >= 0; i--) res[i] = heap.poll().getKey();
    return res;
}

// 2. Bucket sort on frequency: O(n)
public int[] topKFrequentBuckets(int[] nums, int k) {
    Map<Integer, Integer> freq = new HashMap<>();
    for (int x : nums) freq.merge(x, 1, Integer::sum);

    List<Integer>[] buckets = new List[nums.length + 1];   // index = frequency
    for (var e : freq.entrySet()) {
        int f = e.getValue();
        if (buckets[f] == null) buckets[f] = new ArrayList<>();
        buckets[f].add(e.getKey());
    }
    int[] res = new int[k];
    int idx = 0;
    for (int f = buckets.length - 1; f >= 1 && idx < k; f--) {
        if (buckets[f] == null) continue;
        for (int num : buckets[f]) {
            if (idx == k) break;
            res[idx++] = num;
        }
    }
    return res;
}

A frequency can be at most n, so n + 1 buckets are enough; scanning from the highest bucket downward collects the most frequent first. The heap version is O(n log k) time, O(n) space; the bucket version is O(n) time, O(n) space. Generic array creation (new List[...]) gives an unchecked warning in Java, which is normal here.

K Closest Points to Origin (LeetCode 973)

Distance is x² + y² (no need for the square root, and it avoids floating point). For the K closest keep a max-heap of size k, so the farthest of your candidates is on top and gets evicted.

public int[][] kClosest(int[][] points, int k) {
    PriorityQueue<int[]> heap = new PriorityQueue<>(
        (a, b) -> Integer.compare(dist(b), dist(a)));        // max-heap on distance
    for (int[] p : points) {
        heap.offer(p);
        if (heap.size() > k) heap.poll();                  // drop the farthest
    }
    return heap.toArray(new int[0][]);
}

private int dist(int[] p) { return p[0] * p[0] + p[1] * p[1]; }

Coordinates are limited to ±10,000 on LeetCode, so x² + y² fits in an int; use long if the limits were larger. Complexity: O(n log k) time, O(k) space.

Merge K Sorted Lists (LeetCode 23)

Put the head of every list in a min-heap. Repeatedly poll the smallest node, append it to the result, and push that node's next. The heap never holds more than K nodes.

public ListNode mergeKLists(ListNode[] lists) {
    PriorityQueue<ListNode> heap =
        new PriorityQueue<>(Comparator.comparingInt(n -> n.val));
    for (ListNode head : lists) {
        if (head != null) heap.offer(head);          // never add null nodes
    }
    ListNode dummy = new ListNode(0), tail = dummy;
    while (!heap.isEmpty()) {
        ListNode smallest = heap.poll();
        tail.next = smallest;
        tail = tail.next;
        if (smallest.next != null) heap.offer(smallest.next);
    }
    return dummy.next;
}

Complexity: O(N log K) time where N is the total number of nodes, O(K) extra space. Another valid O(N log K) idea is divide and conquer: merge lists in pairs using mergeTwoLists from linked lists. The same heap idea merges K sorted arrays or finds the K-th smallest in a sorted matrix.

Find Median from Data Stream (LeetCode 295): two heaps

The median is the middle value of the sorted data (or the average of the two middle values). Split the numbers into a lower half and an upper half. Keep the lower half in a max-heap (its top is the largest of the small numbers) and the upper half in a min-heap (its top is the smallest of the big numbers). Keep the sizes equal, or let the lower heap have one extra. Then the median is at the tops.

class MedianFinder {
    private final PriorityQueue<Integer> lower =
        new PriorityQueue<>(Comparator.reverseOrder());    // max-heap
    private final PriorityQueue<Integer> upper = new PriorityQueue<>();   // min-heap

    public void addNum(int num) {
        lower.offer(num);
        upper.offer(lower.poll());                // move the largest of lower to upper
        if (upper.size() > lower.size()) {        // rebalance: lower may have +1
            lower.offer(upper.poll());
        }
    }

    public double findMedian() {
        if (lower.size() > upper.size()) return lower.peek();
        return (lower.peek() + (long) upper.peek()) / 2.0;
    }
}

Adding 5, 2, 8, 1 step by step: after 5, lower = {5}, median 5; after 2, lower = {2}, upper = {5}, median 3.5; after 8, lower = {5, 2}, upper = {8}, median 5; after 1, lower = {2, 1}, upper = {5, 8}, median 3.5. Passing the number through lower and then upper guarantees every value in lower is ≤ every value in upper. Complexity: addNum O(log n), findMedian O(1), space O(n). The cast to long avoids integer overflow when adding two large int values.

Brief: Task Scheduler (LeetCode 621)

Tasks with the same letter must be at least n intervals apart. Greedy with a max-heap: in each cycle of n + 1 slots take up to n + 1 of the most frequent tasks, decrement their counts, and push the leftovers back. A closed form also exists: max(tasks, (maxFreq - 1) * (n + 1) + countOfMaxFreq). Heap version: O(T log 26), practically O(T).

Brief: Last Stone Weight, Reorganize String

Last Stone Weight (LeetCode 1046): max-heap, smash the two heaviest, push back the difference. Reorganize String (LeetCode 767): max-heap of letter counts; each step place the most frequent letter that differs from the previously placed one.

Choosing between a heap, sorting and quickselect

  • The data is static and you need the whole order: sort.
  • You need only the k-th element once: quickselect (O(n) average) or a size-k heap.
  • Data arrives as a stream, or k is much smaller than n: a size-k heap (O(n log k), O(k) memory).
  • Frequencies are bounded by n: bucket sort (O(n)).

Interview angle

"Kth largest" has four answers (sort, heap, quickselect, counting) and the interviewer wants you to compare them. Explain "why a min-heap for the largest K" in one sentence. For the median, draw the two heaps and the balancing rule. For streaming data, mention that memory is O(k), not O(n), for top-K.

Intervals: merge, insert, meeting rooms

Sort intervals by start time, then sweep once from left to right comparing each interval with the last one you kept; meeting rooms add a min-heap of end times or a sweep line of start and end events.

An interval is a range such as a meeting from 9 to 11, stored as int[] {start, end}. Two intervals overlap when each starts before the other ends: a.start < b.end && b.start < a.end. (Whether touching intervals like [1,2] and [2,3] overlap depends on the problem; check the statement. In Merge Intervals they do merge; in Meeting Rooms they do not conflict.)

The big idea: sort by start. After sorting, any interval that can overlap the current one must be next to it, so one pass is enough. The sort costs O(n log n) and is the dominant cost.

Arrays.sort(intervals, (a, b) -> Integer.compare(a[0], b[0]));   // by start
// Arrays.sort(intervals, Comparator.comparingInt(a -> a[0]));    // same thing

Merge Intervals (LeetCode 56)

Keep a result list. For each interval in sorted order: if the result is empty or the interval starts after the last kept interval ends, append it; otherwise it overlaps, so extend the last interval's end to max(lastEnd, end). Use max because the new interval may be fully inside the last one.

public int[][] merge(int[][] intervals) {
    Arrays.sort(intervals, (a, b) -> Integer.compare(a[0], b[0]));
    List<int[]> merged = new ArrayList<>();
    for (int[] cur : intervals) {
        if (merged.isEmpty() || merged.get(merged.size() - 1)[1] < cur[0]) {
            merged.add(cur);                                  // no overlap
        } else {
            int[] last = merged.get(merged.size() - 1);
            last[1] = Math.max(last[1], cur[1]);              // extend
        }
    }
    return merged.toArray(new int[0][]);
}

Input [[1,3],[8,10],[2,6],[15,18]] sorts to [[1,3],[2,6],[8,10],[15,18]]; 2 ≤ 3 so [1,3] becomes [1,6]; 8 > 6 starts a new one. Result [[1,6],[8,10],[15,18]]. Complexity: O(n log n) time, O(n) space for the output. The code mutates the input arrays; copy them if the caller must keep them.

Common mistake: comparator with subtraction

(a, b) -> a[0] - b[0] can overflow for large or negative values. Use Integer.compare(a[0], b[0]). And do not forget to sort first; without it the one-pass logic is wrong.

Insert Interval (LeetCode 57)

The list is already sorted and non-overlapping. Do three phases in one pass: (1) copy all intervals that end before the new one starts; (2) merge all intervals that overlap the new one into it by taking min start and max end; (3) copy the rest. No sorting needed.

public int[][] insert(int[][] intervals, int[] newInterval) {
    List<int[]> result = new ArrayList<>();
    int i = 0, n = intervals.length;
    while (i < n && intervals[i][1] < newInterval[0]) result.add(intervals[i++]);   // before
    while (i < n && intervals[i][0] <= newInterval[1]) {                          // overlap
        newInterval[0] = Math.min(newInterval[0], intervals[i][0]);
        newInterval[1] = Math.max(newInterval[1], intervals[i][1]);
        i++;
    }
    result.add(newInterval);
    while (i < n) result.add(intervals[i++]);                                        // after
    return result.toArray(new int[0][]);
}

Complexity: O(n) time, O(n) space.

Non-overlapping Intervals (LeetCode 435): greedy

Find the minimum number of intervals to remove so the rest do not overlap. Equivalent: keep the maximum number of non-overlapping intervals. The greedy rule is to sort by end and always keep the interval that finishes earliest, because it leaves the most room for the future. The proof of this exchange argument and the family of greedy problems are in Module 3.

public int eraseOverlapIntervals(int[][] intervals) {
    Arrays.sort(intervals, (a, b) -> Integer.compare(a[1], b[1]));   // by END
    int removed = 0, lastEnd = Integer.MIN_VALUE;
    for (int[] cur : intervals) {
        if (cur[0] >= lastEnd) lastEnd = cur[1];     // keep it
        else removed++;                              // overlaps: remove it
    }
    return removed;
}

Complexity: O(n log n) time, O(1) extra space.

Meeting Rooms I (LeetCode 252) and II (LeetCode 253)

I: can one person attend all meetings? Sort by start and check that each meeting starts at or after the previous one ends.

public boolean canAttendMeetings(int[][] intervals) {
    Arrays.sort(intervals, (a, b) -> Integer.compare(a[0], b[0]));
    for (int i = 1; i < intervals.length; i++) {
        if (intervals[i][0] < intervals[i - 1][1]) return false;   // overlap
    }
    return true;
}

II: the minimum number of rooms needed. Sort by start. Keep a min-heap of the end times of the rooms in use. For each meeting, if the earliest-ending room is free by now (heap.peek() <= start), reuse it (poll); then add this meeting's end. The final heap size is the number of rooms.

public int minMeetingRooms(int[][] intervals) {
    Arrays.sort(intervals, (a, b) -> Integer.compare(a[0], b[0]));
    PriorityQueue<Integer> endTimes = new PriorityQueue<>();
    for (int[] meeting : intervals) {
        if (!endTimes.isEmpty() && endTimes.peek() <= meeting[0]) endTimes.poll();
        endTimes.offer(meeting[1]);
    }
    return endTimes.size();
}

For [[0,30],[5,10],[15,20]]: [0,30] → heap {30}; [5,10]: 30 > 5 so no reuse, heap {10,30}; [15,20]: 10 ≤ 15 so reuse, heap {20,30}. Answer 2. Complexity: O(n log n) time, O(n) space.

Sweep line alternative

A sweep line turns each interval into two events: +1 at its start and −1 at its end. Sort all events by time (ending before starting when times tie, so touching meetings share a room) and keep a running count. The maximum count is the number of rooms. Sorting the starts and ends separately gives a compact version.

public int minMeetingRooms(int[][] intervals) {
    int n = intervals.length;
    int[] starts = new int[n], ends = new int[n];
    for (int i = 0; i < n; i++) { starts[i] = intervals[i][0]; ends[i] = intervals[i][1]; }
    Arrays.sort(starts);
    Arrays.sort(ends);
    int rooms = 0, maxRooms = 0, e = 0;
    for (int s = 0; s < n; s++) {
        if (starts[s] < ends[e]) rooms++;      // a new meeting begins before any ends
        else e++;                              // reuse: one meeting has ended
        maxRooms = Math.max(maxRooms, rooms);
    }
    return maxRooms;
}

Complexity: O(n log n) time, O(n) space. The sweep line idea also solves "maximum overlap", "employee free time" and the "car pooling" problem.

Interval List Intersections (LeetCode 986)

Two sorted lists of disjoint intervals. Use two pointers: the intersection of A[i] and B[j] is [max(starts), min(ends)], valid if start ≤ end. Then advance the pointer whose interval ends first (it cannot overlap anything further in the other list).

public int[][] intervalIntersection(int[][] A, int[][] B) {
    List<int[]> res = new ArrayList<>();
    int i = 0, j = 0;
    while (i < A.length && j < B.length) {
        int lo = Math.max(A[i][0], B[j][0]);
        int hi = Math.min(A[i][1], B[j][1]);
        if (lo <= hi) res.add(new int[] {lo, hi});
        if (A[i][1] < B[j][1]) i++; else j++;        // drop the one that ends first
    }
    return res.toArray(new int[0][]);
}

Complexity: O(m + n) time. This is the "two arrays" shape of two pointers.

Recognising interval problems

  • Words: meetings, schedules, ranges, bookings, "overlap", "merge", "free time".
  • First move: sort by start (to merge or find conflicts) or by end (to pick the maximum number of non-overlapping ones).
  • "How many at the same time?" means heap of end times or sweep line.

Matrix problems: directions, spiral, rotate, search

A matrix is an array of arrays addressed by row and column; most problems need careful boundary handling, a direction array for neighbours, and small tricks such as transpose-then-reverse or treating the grid as one sorted line.

A matrix (grid) in Java is int[][] grid with m = grid.length rows and n = grid[0].length columns. The cell grid[r][c] is row r, column c. Indexes run from 0 to m - 1 and 0 to n - 1. Always read the constraints: can the matrix be empty, one row, one column, or non-square? Most matrix bugs are off-by-one errors on boundaries.

Direction arrays and boundary checks

To visit the four neighbours (up, right, down, left) loop over a small array of row and column offsets instead of writing four copies of the code.

int[][] dirs = {{-1, 0}, {0, 1}, {1, 0}, {0, -1}};    // up, right, down, left
// for 8 directions add the diagonals: {-1,-1}, {-1,1}, {1,1}, {1,-1}

for (int[] d : dirs) {
    int nr = r + d[0], nc = c + d[1];
    if (nr < 0 || nr >= m || nc < 0 || nc >= n) continue;   // out of bounds
    // use grid[nr][nc]
}

Check the bounds before reading the cell, or you get ArrayIndexOutOfBoundsException. A flat index id = r * n + c converts a cell to one number, and r = id / n, c = id % n converts back.

Spiral Matrix (LeetCode 54)

Return all elements in spiral order. Keep four boundaries top, bottom, left, right. Walk the top row left to right, the right column top to bottom, the bottom row right to left, the left column bottom to top, shrinking a boundary after each side. The two inner checks stop you from walking a row or column twice when one is left over.

public List<Integer> spiralOrder(int[][] matrix) {
    List<Integer> out = new ArrayList<>();
    int top = 0, bottom = matrix.length - 1;
    int left = 0, right = matrix[0].length - 1;
    while (top <= bottom && left <= right) {
        for (int c = left; c <= right; c++) out.add(matrix[top][c]);
        top++;
        for (int r = top; r <= bottom; r++) out.add(matrix[r][right]);
        right--;
        if (top <= bottom) {                       // a bottom row still exists
            for (int c = right; c >= left; c--) out.add(matrix[bottom][c]);
            bottom--;
        }
        if (left <= right) {                       // a left column still exists
            for (int r = bottom; r >= top; r--) out.add(matrix[r][left]);
            left++;
        }
    }
    return out;
}

For [[1,2,3],[4,5,6],[7,8,9]] the output is 1 2 3 6 9 8 7 4 5. Complexity: O(m·n) time, O(1) extra space besides the output. Spiral Matrix II (LeetCode 59) fills an n×n grid with 1..n² using the same four boundaries.

Rotate Image (LeetCode 48)

Rotate an n×n matrix 90 degrees clockwise in place. Two simple steps: transpose (swap matrix[i][j] with matrix[j][i], turning rows into columns), then reverse each row.

public void rotate(int[][] matrix) {
    int n = matrix.length;
    for (int i = 0; i < n; i++) {
        for (int j = i + 1; j < n; j++) {          // only above the diagonal
            int t = matrix[i][j];
            matrix[i][j] = matrix[j][i];
            matrix[j][i] = t;
        }
    }
    for (int[] row : matrix) {
        for (int l = 0, r = n - 1; l < r; l++, r--) {
            int t = row[l]; row[l] = row[r]; row[r] = t;
        }
    }
}

Complexity: O(n²) time, O(1) space. For anticlockwise rotation, reverse the rows first and then transpose (or transpose and reverse the columns). If you start the inner loop at j = 0, you swap every pair twice and end up with the original matrix.

Set Matrix Zeroes (LeetCode 73)

If a cell is 0, set its whole row and column to 0. The simple way uses two boolean arrays (O(m + n) space). For O(1) space, use the first row and first column of the matrix itself as the markers: matrix[i][0] = 0 means "row i must be zeroed", matrix[0][j] = 0 means "column j must be zeroed". Two extra booleans remember whether the first row and first column themselves contained a zero.

public void setZeroes(int[][] matrix) {
    int m = matrix.length, n = matrix[0].length;
    boolean firstRowZero = false, firstColZero = false;
    for (int j = 0; j < n; j++) if (matrix[0][j] == 0) firstRowZero = true;
    for (int i = 0; i < m; i++) if (matrix[i][0] == 0) firstColZero = true;

    for (int i = 1; i < m; i++)                 // record zeros in the markers
        for (int j = 1; j < n; j++)
            if (matrix[i][j] == 0) { matrix[i][0] = 0; matrix[0][j] = 0; }

    for (int i = 1; i < m; i++)                 // apply, skipping row 0 and col 0
        for (int j = 1; j < n; j++)
            if (matrix[i][0] == 0 || matrix[0][j] == 0) matrix[i][j] = 0;

    if (firstRowZero) for (int j = 0; j < n; j++) matrix[0][j] = 0;
    if (firstColZero) for (int i = 0; i < m; i++) matrix[i][0] = 0;
}

Complexity: O(m·n) time, O(1) space. The order matters: handle the first row and column last, or the markers get overwritten before use.

Search a 2D Matrix (LeetCode 74): one binary search

Each row is sorted and the first number of a row is greater than the last of the previous row, so the whole matrix is one sorted list in row-major order. Binary search over indexes 0 .. m*n - 1 and convert an index with row = mid / n, col = mid % n (binary search is in Module 1).

public boolean searchMatrix(int[][] matrix, int target) {
    int m = matrix.length, n = matrix[0].length;
    int lo = 0, hi = m * n - 1;
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;
        int v = matrix[mid / n][mid % n];
        if (v == target) return true;
        if (v < target) lo = mid + 1; else hi = mid - 1;
    }
    return false;
}

Complexity: O(log(m·n)) time, O(1) space.

Search a 2D Matrix II (LeetCode 240): staircase

Here rows are sorted and columns are sorted, but rows do not continue from each other. Start at the top-right corner. If the value is bigger than the target, the whole column below is bigger, so move left. If it is smaller, the whole row to its left is smaller, so move down. Every step removes a row or a column.

public boolean searchMatrix(int[][] matrix, int target) {
    int r = 0, c = matrix[0].length - 1;          // top-right corner
    while (r < matrix.length && c >= 0) {
        int v = matrix[r][c];
        if (v == target) return true;
        if (v > target) c--;                      // discard this column
        else r++;                                 // discard this row
    }
    return false;
}

Complexity: O(m + n) time, O(1) space. The bottom-left corner works the same way; top-left and bottom-right do not, because both choices increase (or both decrease) the value.

Brief: diagonal traversal and flood fill

  • Diagonal Traverse (LeetCode 498): cells on one diagonal share r + c. Walk each diagonal and reverse the direction on every other one. O(m·n).
  • Flood Fill (LeetCode 733) and Number of Islands (LeetCode 200): from a start cell, visit all connected cells with the same value using DFS or BFS and the dirs array, marking visited cells (by changing the value or using a boolean grid). This is the bridge to graph search; the full treatment is in Module 3.
public int[][] floodFill(int[][] image, int sr, int sc, int color) {
    int original = image[sr][sc];
    if (original != color) fill(image, sr, sc, original, color);   // avoids infinite loop
    return image;
}

private void fill(int[][] img, int r, int c, int original, int color) {
    if (r < 0 || r >= img.length || c < 0 || c >= img[0].length) return;
    if (img[r][c] != original) return;
    img[r][c] = color;                       // doubles as the "visited" mark
    fill(img, r + 1, c, original, color);
    fill(img, r - 1, c, original, color);
    fill(img, r, c + 1, original, color);
    fill(img, r, c - 1, original, color);
}

Complexity: O(m·n) time, O(m·n) recursion depth in the worst case.

Common mistakes

  • Swapping m and n, so rows and columns are mixed up in a non-square grid.
  • Reading matrix[0].length on an empty matrix.
  • Flood fill with the new colour equal to the old one: infinite recursion.
  • Copying a matrix with clone() and expecting a deep copy; it copies only the outer array, so rows are shared.

Interview angle

Matrix questions test care more than cleverness. Say the dimensions and edge cases first (1×1, one row, one column), name your four boundaries or direction array, and test with a 3×3 and a 2×3 grid. Be ready for the in-place and O(1) space follow-ups (rotate image, set matrix zeroes).
