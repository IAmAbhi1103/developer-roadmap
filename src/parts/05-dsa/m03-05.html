Topological sort: Kahn's algorithm and DFS, Course Schedule

A topological order lists the vertices of a directed acyclic graph so that every edge u → v has u before v; Kahn's algorithm builds it with a queue of zero in-degree vertices, the DFS method reverses the finishing order, and if not all vertices can be placed the graph has a cycle.

You cannot wear shoes before socks, build module B before module A if B depends on A, or take Algorithms before its prerequisite Data Structures. These are dependencies, and a topological sort turns them into one valid order. It exists exactly when the directed graph has no cycle (a DAG). If tasks A and B depend on each other, no order is possible. A DAG usually has many valid orders; any one is accepted unless the problem asks for the smallest.

Method 1: Kahn's algorithm (BFS with in-degrees)

The in-degree of a vertex is the number of edges pointing into it, that is, the number of unfinished prerequisites. A vertex with in-degree 0 has no prerequisites and can go next.

  1. Compute the in-degree of every vertex.
  2. Put all vertices with in-degree 0 into a queue.
  3. Remove a vertex from the queue and append it to the order. For each edge u → v, decrease the in-degree of v; if it becomes 0, enqueue v.
  4. Repeat until the queue is empty. If the order contains all V vertices, it is a topological order. If it has fewer, the remaining vertices sit on or behind a cycle: cycle detected.

Problem — Course Schedule I and II (LeetCode 207, 210)

There are numCourses courses labelled 0..n−1. Each pair [a, b] in prerequisites means "to take a, you must first take b", an edge b → a. Course Schedule I asks: can you finish all courses (is there no cycle)? Course Schedule II asks for one valid order, or an empty array if impossible.

import java.util.ArrayDeque;
import java.util.ArrayList;
import java.util.Arrays;
import java.util.Deque;
import java.util.List;

public class CourseSchedule {
    // Course Schedule II: returns a valid order, or an empty array if there is a cycle
    public static int[] findOrder(int numCourses, int[][] prerequisites) {
        List<List<Integer>> g = new ArrayList<>();
        for (int i = 0; i < numCourses; i++) g.add(new ArrayList<>());
        int[] indegree = new int[numCourses];
        for (int[] p : prerequisites) {
            g.get(p[1]).add(p[0]);                 // edge: prerequisite p[1] → course p[0]
            indegree[p[0]]++;
        }
        Deque<Integer> queue = new ArrayDeque<>();
        for (int i = 0; i < numCourses; i++) {
            if (indegree[i] == 0) queue.add(i);    // courses with no prerequisites
        }
        int[] order = new int[numCourses];
        int count = 0;
        while (!queue.isEmpty()) {
            int u = queue.poll();
            order[count++] = u;                    // "take" the course
            for (int v : g.get(u)) {
                if (--indegree[v] == 0) queue.add(v);   // its last prerequisite is done
            }
        }
        return count == numCourses ? order : new int[0];
    }

    // Course Schedule I: can all courses be finished?
    public static boolean canFinish(int numCourses, int[][] prerequisites) {
        return findOrder(numCourses, prerequisites).length == numCourses;
    }

    public static void main(String[] args) {
        int[][] pre = {{1, 0}, {2, 0}, {3, 1}, {3, 2}};
        System.out.println(Arrays.toString(findOrder(4, pre)));       // [0, 1, 2, 3]
        int[][] cyc = {{1, 0}, {0, 1}};
        System.out.println(canFinish(2, cyc));                        // false
    }
}

Dry run for the four-course example: in-degrees are [0, 1, 1, 2]. Queue [0]. Take 0: in-degree of 1 and 2 become 0 → queue [1, 2]. Take 1: course 3 drops to 1. Take 2: course 3 drops to 0 → enqueue. Take 3. Order [0, 1, 2, 3], count 4 = n → valid. For the cycle [[1,0],[0,1]] both courses start with in-degree 1, the queue is empty from the beginning, count 0 < 2 → impossible.

Complexity: O(V + E) time, O(V + E) space.

Method 2: DFS and reverse post-order

Run DFS; when a vertex is finished (all its outgoing neighbours are done), push it on a stack. The finishing order puts a vertex after everything it points to, so the reverse of the finishing order is a topological order. Detect cycles with the same three colours as in directed cycle detection.

import java.util.ArrayDeque;
import java.util.ArrayList;
import java.util.Deque;
import java.util.List;

public class TopoSortDfs {
    public static List<Integer> topoSort(List<List<Integer>> g) {
        int n = g.size();
        int[] state = new int[n];                         // 0 white, 1 grey, 2 black
        Deque<Integer> stack = new ArrayDeque<>();
        for (int s = 0; s < n; s++) {
            if (state[s] == 0 && !dfs(g, s, state, stack)) return List.of();  // cycle
        }
        return new ArrayList<>(stack);                    // stack top first = topological order
    }

    private static boolean dfs(List<List<Integer>> g, int u, int[] state, Deque<Integer> stack) {
        state[u] = 1;
        for (int v : g.get(u)) {
            if (state[v] == 1) return false;              // back edge: cycle
            if (state[v] == 0 && !dfs(g, v, state, stack)) return false;
        }
        state[u] = 2;
        stack.push(u);                                    // post-order: add after all descendants
        return true;
    }

    public static void main(String[] args) {
        int[][] edges = {{0, 1}, {0, 2}, {1, 3}, {2, 3}};
        System.out.println(topoSort(GraphBuilder.build(4, edges, true)));   // [0, 2, 1, 3]
    }
}

The order printed, [0, 2, 1, 3], differs from Kahn's but is also valid. Complexity: O(V + E).

Where else it appears

  • Parallel Courses: the number of Kahn "rounds" (levels) is the minimum number of semesters.
  • Alien Dictionary: compare adjacent words to get letter-order edges, then topologically sort the letters; a cycle means the dictionary is inconsistent.
  • Longest path in a DAG / critical path: process vertices in topological order and relax edges; this is O(V + E), even with negative weights.
  • Build tools: Gradle, Maven, Make, and Spring's bean creation order resolve dependencies this way.

Mistake: reversing the edge direction

[a, b] means "b before a", so the edge is b → a. Building a → b gives a valid-looking but reversed order, and it passes simple cycle tests. Write the comment "prerequisite → course" next to the line and check the example by hand.

Mistake: returning the partial order when there is a cycle

When count < n the array is only partly filled. Return an empty array (or false), as the problem asks, never the half-filled array.

Edge cases

  • No prerequisites: any order is valid; Kahn returns 0..n−1.
  • Self-dependency [0, 0]: in-degree of 0 is 1 and it can never reach 0 — a cycle, reported correctly.
  • Duplicate prerequisite pairs add the edge twice and increment the in-degree twice; that is consistent, because it is decremented twice too.
  • Disconnected pieces are handled automatically: every in-degree-0 vertex starts in the queue.

Interview angle

Say: "topological order exists iff the graph is a DAG; I use Kahn's algorithm, O(V + E); if I cannot place all vertices, there is a cycle." Mention the DFS alternative. Follow-ups: "return the lexicographically smallest order" (swap the queue for a PriorityQueue), "minimum semesters" (count Kahn levels) and "is the order unique?" (it is unique only if the queue never holds more than one vertex).

Dijkstra's shortest path algorithm

Dijkstra finds the shortest distance from one source to every vertex in a graph with non-negative edge weights by always finalising the closest unfinished vertex, using a min-heap of {distance, vertex} pairs; it runs in O((V + E) log V) and breaks when an edge is negative.

BFS finds the shortest path when every edge costs 1. When edges have different weights (kilometres, minutes, rupees), the path with the fewest edges is not the cheapest. Dijkstra's algorithm fixes this. It is behind route finding in maps, network routing (OSPF) and "cheapest way to do X" problems. The restriction: all weights must be ≥ 0.

The idea

Keep a best-known distance dist[v] for each vertex, starting at infinity (0 for the source). Repeatedly take the unfinished vertex with the smallest distance — that distance is now final — and relax its outgoing edges: for an edge u → v with weight w, if dist[u] + w < dist[v], update dist[v]. Why is the smallest distance final? Any other path to that vertex would have to leave the finished region through some vertex with an equal or larger distance and then add a non-negative weight, so it cannot be shorter. This argument is exactly where non-negative weights are needed.

A PriorityQueue picks the smallest distance in O(log n). Java's PriorityQueue has no "decrease key", so the standard trick is lazy deletion: when a distance improves, push a new entry, and when you poll an entry whose distance is larger than the current dist[u], it is stale — skip it.

Template

import java.util.ArrayList;
import java.util.Arrays;
import java.util.List;
import java.util.PriorityQueue;

public class Dijkstra {
    // g.get(u) holds {neighbour, weight}; returns shortest distance from src to every vertex
    public static int[] shortestPaths(List<List<int[]>> g, int src) {
        int n = g.size();
        int[] dist = new int[n];
        Arrays.fill(dist, Integer.MAX_VALUE);
        dist[src] = 0;
        PriorityQueue<int[]> pq = new PriorityQueue<>((a, b) -> Integer.compare(a[0], b[0]));
        pq.add(new int[]{0, src});                       // {distance, vertex}
        while (!pq.isEmpty()) {
            int[] cur = pq.poll();
            int d = cur[0], u = cur[1];
            if (d > dist[u]) continue;                   // stale entry: a better one was processed
            for (int[] edge : g.get(u)) {
                int v = edge[0], nd = d + edge[1];
                if (nd < dist[v]) {                      // relax
                    dist[v] = nd;
                    pq.add(new int[]{nd, v});
                }
            }
        }
        return dist;                                     // MAX_VALUE means unreachable
    }

    public static void main(String[] args) {
        // A=0, B=1, C=2, D=3
        int[][] edges = {{0, 1, 2}, {0, 2, 4}, {2, 1, 1}, {1, 3, 1}, {2, 3, 5}};
        List<List<int[]>> g = GraphBuilder.buildWeighted(4, edges, true);
        System.out.println(Arrays.toString(shortestPaths(g, 0)));
    }
}
[0, 2, 4, 3]

Complexity. Each edge can add at most one entry to the heap, so the heap holds up to E entries and each push/poll costs O(log E) = O(log V) (since E ≤ V²). Total O((V + E) log V), usually written O(E log V) for connected graphs. Space: O(V + E). With a Fibonacci heap it is O(E + V log V), but nobody uses that in interviews.

To get the path itself, store parent[v] = u whenever you relax v, then walk back from the target as in BFS. To stop early when you only need one target, return as soon as that vertex is polled with a non-stale entry.

Problem 1 — Network Delay Time (LeetCode 743)

A signal is sent from node k in a network of n nodes (labelled 1..n). times[i] = {u, v, w} means the signal takes w time to go from u to v. Return the time until all nodes have received the signal, or −1 if some node cannot be reached. The time for everyone is the largest shortest-distance.

import java.util.ArrayList;
import java.util.Arrays;
import java.util.List;
import java.util.PriorityQueue;

public class NetworkDelayTime {
    public static int networkDelayTime(int[][] times, int n, int k) {
        List<List<int[]>> g = new ArrayList<>();
        for (int i = 0; i <= n; i++) g.add(new ArrayList<>());   // nodes are 1..n
        for (int[] t : times) g.get(t[0]).add(new int[]{t[1], t[2]});

        int[] dist = new int[n + 1];
        Arrays.fill(dist, Integer.MAX_VALUE);
        dist[k] = 0;
        PriorityQueue<int[]> pq = new PriorityQueue<>((a, b) -> Integer.compare(a[0], b[0]));
        pq.add(new int[]{0, k});
        while (!pq.isEmpty()) {
            int[] cur = pq.poll();
            if (cur[0] > dist[cur[1]]) continue;
            for (int[] e : g.get(cur[1])) {
                int nd = cur[0] + e[1];
                if (nd < dist[e[0]]) {
                    dist[e[0]] = nd;
                    pq.add(new int[]{nd, e[0]});
                }
            }
        }
        int answer = 0;
        for (int v = 1; v <= n; v++) {
            if (dist[v] == Integer.MAX_VALUE) return -1;     // someone never receives it
            answer = Math.max(answer, dist[v]);
        }
        return answer;
    }

    public static void main(String[] args) {
        int[][] times = {{2, 1, 1}, {2, 3, 1}, {3, 4, 1}};
        System.out.println(networkDelayTime(times, 4, 2));   // 2
    }
}

From node 2: node 1 at time 1, node 3 at time 1, node 4 at time 2. The largest is 2. Complexity: O((V + E) log V).

Problem 2 — Path With Minimum Effort (LeetCode 1631), briefly

You walk from the top-left to the bottom-right of a height grid. The effort of a route is the largest absolute height difference between consecutive cells on it. Minimise the effort. This is Dijkstra on a grid where the "distance" of a route is the maximum edge instead of the sum. The greedy argument still works because the maximum never decreases as the route grows.

import java.util.Arrays;
import java.util.PriorityQueue;

public class MinimumEffort {
    private static final int[][] DIRS = {{1, 0}, {-1, 0}, {0, 1}, {0, -1}};

    public static int minimumEffortPath(int[][] h) {
        int rows = h.length, cols = h[0].length;
        int[][] effort = new int[rows][cols];
        for (int[] row : effort) Arrays.fill(row, Integer.MAX_VALUE);
        effort[0][0] = 0;
        PriorityQueue<int[]> pq = new PriorityQueue<>((a, b) -> Integer.compare(a[0], b[0]));
        pq.add(new int[]{0, 0, 0});                          // {effort, row, col}
        while (!pq.isEmpty()) {
            int[] cur = pq.poll();
            int eff = cur[0], r = cur[1], c = cur[2];
            if (r == rows - 1 && c == cols - 1) return eff;  // first arrival is optimal
            if (eff > effort[r][c]) continue;                // stale entry
            for (int[] d : DIRS) {
                int nr = r + d[0], nc = c + d[1];
                if (nr < 0 || nc < 0 || nr >= rows || nc >= cols) continue;
                int ne = Math.max(eff, Math.abs(h[r][c] - h[nr][nc]));   // max, not sum
                if (ne < effort[nr][nc]) {
                    effort[nr][nc] = ne;
                    pq.add(new int[]{ne, nr, nc});
                }
            }
        }
        return 0;
    }

    public static void main(String[] args) {
        int[][] heights = {{1, 2, 2}, {3, 8, 2}, {5, 3, 5}};
        System.out.println(minimumEffortPath(heights));      // 2
    }
}

Route 1 → 3 → 5 → 3 → 5 has differences 2, 2, 2, 2, so the effort is 2. Complexity: O(m · n · log(m · n)). Cheapest Flights Within K Stops (LeetCode 787) looks like Dijkstra but adds a limit on the number of edges; the clean solution is a limited Bellman-Ford.

Why Dijkstra fails with negative edges

Take edges A → B (4), A → C (5) and C → B (−3). Dijkstra finalises B at distance 4 (it is the smallest after A), but the route A → C → B costs 5 − 3 = 2. The assumption "once the smallest is chosen, nothing can improve it" is false, because a later edge can reduce a total. A re-insertion version can sometimes repair the answer, but it can become very slow, and with a negative cycle (a loop whose total weight is negative) it never ends, because every lap lowers the distance again. For negative edges use Bellman-Ford.

Mistake: skipping the stale-entry check

Without if (d > dist[u]) continue; the result is still correct, but the same vertex is expanded many times and the running time can degrade toward O(V · E). The check costs one comparison; always include it.

Mistake: integer overflow with MAX_VALUE

Wrong: MAX_VALUE + w wraps around to a negative number

int nd = dist[u] + w;            // dist[u] could be Integer.MAX_VALUE
if (nd < dist[v]) { ... }        // the negative value wins

Right: only relax from reached vertices (as polled entries are), or use long

int d = cur[0];                  // distance of a polled, reached vertex
int nd = d + w;                  // safe unless the sum itself exceeds 2^31 - 1
// for huge weights use long[] dist and Long.MAX_VALUE as infinity

Mistake: comparing heap entries by subtraction

A comparator like (a, b) -> a[0] - b[0] overflows for large distances and corrupts the heap order. Use Integer.compare (or Long.compare).

Edge cases

  • Unreachable vertices keep the "infinity" value; check for it before using or printing the distance.
  • Zero-weight edges are fine. Parallel edges and self-loops are harmless (a non-negative self-loop never improves anything).
  • Undirected graph: add each edge in both directions. A single negative undirected edge is already a negative cycle.
  • If all weights are equal use plain BFS; if weights are only 0 and 1 use 0-1 BFS; both are faster.

Real-project usage

Maps and delivery apps (Swiggy, Zomato, Ola) compute routes with Dijkstra-like search, usually A* (Dijkstra plus a distance-to-goal estimate) on a road graph with travel times as weights. Network routers run it to compute forwarding tables.

Interview angle

Say the three facts: greedy on the smallest tentative distance, correct only for non-negative weights, O((V + E) log V) with a binary heap. Explain lazy deletion and why there is no decrease-key in PriorityQueue. Be ready for "what if there is a negative edge?" (Bellman-Ford) and "what if you need only one target?" (stop when it is polled). Also be able to modify the relaxation (max instead of sum, or multiply probabilities) — it shows you understand why it works.

Bellman-Ford: negative edges and limited-edge paths

Bellman-Ford relaxes every edge V − 1 times to compute single-source shortest paths even with negative edge weights, detects a reachable negative cycle with one extra pass, and runs in O(V · E); a version with k + 1 rounds solves "at most k edges" problems such as Cheapest Flights Within K Stops.

Dijkstra needs non-negative weights. Some real graphs have negative edges: a refund, a discount, a currency exchange that gains money. Bellman-Ford is slower but handles them, and it can also tell you when the answer does not exist because a negative cycle (a cycle whose weights add to less than zero) lets you reduce the cost forever by going round again.

The idea

A shortest path without a cycle uses at most V − 1 edges (a path through V vertices has V − 1 edges). Round 1 of "relax every edge" makes all paths of 1 edge correct, round 2 makes all paths of up to 2 edges correct, and so on. After V − 1 rounds every shortest path is correct. If a V-th round still improves some distance, then an unbounded improvement is possible, so a negative cycle is reachable from the source.

It does not use an adjacency list at all; the natural input is an edge list, one of the three representations from the graph basics article.

import java.util.Arrays;

public class BellmanFord {
    private static final int INF = Integer.MAX_VALUE;

    // edges[i] = {u, v, w}; returns distances, or null if a negative cycle is reachable
    public static int[] shortestPaths(int n, int[][] edges, int src) {
        int[] dist = new int[n];
        Arrays.fill(dist, INF);
        dist[src] = 0;
        for (int round = 1; round < n; round++) {            // V - 1 rounds
            boolean changed = false;
            for (int[] e : edges) {
                int u = e[0], v = e[1], w = e[2];
                if (dist[u] != INF && dist[u] + w < dist[v]) {   // relax; skip unreached u
                    dist[v] = dist[u] + w;
                    changed = true;
                }
            }
            if (!changed) break;                               // early exit: already stable
        }
        for (int[] e : edges) {                                // one more pass: any change?
            if (dist[e[0]] != INF && dist[e[0]] + e[2] < dist[e[1]]) return null;
        }
        return dist;
    }

    public static void main(String[] args) {
        int[][] edges = {{0, 1, 4}, {0, 2, 5}, {1, 2, -3}, {2, 3, 2}};
        System.out.println(Arrays.toString(shortestPaths(4, edges, 0)));
        int[][] bad = {{0, 1, 1}, {1, 2, -2}, {2, 1, 1}};      // cycle 1→2→1 costs -1
        System.out.println(shortestPaths(3, bad, 0));
    }
}
[0, 4, 1, 3]
null

Dry run on the first graph: round 1 relaxes in list order: 1 = 4, 2 = 5, then edge 1→2 gives 4 − 3 = 1, then 3 = 3. Round 2 changes nothing, so the loop stops. Note that vertex 2 got the improved value 1 in the same round because we updated the array in place; that only speeds convergence and keeps the guarantee.

In the second graph, vertices 1 and 2 form a cycle of total weight −1. Each lap lowers the distance, so after V − 1 rounds the extra pass still finds an improvement and returns null.

Complexity: O(V · E) time — V − 1 rounds, each scanning E edges — and O(V) extra space. Compare with Dijkstra's O((V + E) log V): Bellman-Ford is far slower on big graphs, so use it only when negative weights or an edge limit require it. The queue-based version, often called SPFA, is faster on average but has the same worst case.

Problem — Cheapest Flights Within K Stops (LeetCode 787)

There are n cities and flights {from, to, price}. Find the cheapest price from src to dst with at most k stops (at most k + 1 flights), or −1.

A "stops" limit is a limit on the number of edges, and the cheapest path may have more edges than a slightly pricier one that fits the limit — plain Dijkstra, which finalises vertices by cost alone, cannot enforce this. Bellman-Ford with exactly k + 1 rounds fits perfectly: after round i, dist[v] is the cheapest price using at most i flights. One detail is essential: in each round read from the previous round's array and write to a copy. Otherwise a flight updated in this round could be used again in the same round, and you would exceed the limit.

import java.util.Arrays;

public class CheapestFlights {
    public static int findCheapestPrice(int n, int[][] flights, int src, int dst, int k) {
        final int INF = Integer.MAX_VALUE;
        int[] dist = new int[n];
        Arrays.fill(dist, INF);
        dist[src] = 0;
        for (int i = 0; i <= k; i++) {                    // k stops → k + 1 flights → k + 1 rounds
            int[] next = dist.clone();                     // read old values, write new ones
            for (int[] f : flights) {
                int u = f[0], v = f[1], price = f[2];
                if (dist[u] != INF && dist[u] + price < next[v]) {
                    next[v] = dist[u] + price;
                }
            }
            dist = next;
        }
        return dist[dst] == INF ? -1 : dist[dst];
    }

    public static void main(String[] args) {
        int[][] flights = {{0, 1, 100}, {1, 2, 100}, {2, 0, 100}, {1, 3, 600}, {2, 3, 200}};
        System.out.println(findCheapestPrice(4, flights, 0, 3, 1));   // 700
        System.out.println(findCheapestPrice(4, flights, 0, 3, 2));   // 400
    }
}

With k = 1 the route 0 → 1 → 3 costs 700 (the cheaper 0 → 1 → 2 → 3 uses two stops and is not allowed). With k = 2 it costs 400. Complexity: O(k · E) time, O(V) space.

Detecting arbitrage with a negative cycle

Currency exchange rates can be turned into a graph: edge a → b with weight −log(rate). A cycle whose rates multiply to more than 1 has a negative total weight, so a negative cycle means an arbitrage opportunity. Bellman-Ford finds it. (Floating-point care is needed; this is a conceptual example for interviews.)

Mistake: relaxing from an unreachable vertex

Wrong: INF + w overflows to a negative number

if (dist[u] + w < dist[v]) dist[v] = dist[u] + w;

Right: guard with the infinity check

if (dist[u] != INF && dist[u] + w < dist[v]) dist[v] = dist[u] + w;

Mistake: updating in place in the "at most k edges" version

If you drop the clone() in Cheapest Flights, a chain of flights can be relaxed several times within one round, so the code behaves as if k were larger and returns a cheaper, illegal answer.

Exceptions and edge cases

  • A negative undirected edge is itself a negative cycle (go back and forth). Bellman-Ford is for directed graphs with negative edges.
  • A negative cycle that is not reachable from the source does not affect the answer; the check above ignores it because its vertices stay at infinity.
  • If a negative cycle is reachable, shortest distances to the vertices that can be reached through it are undefined (minus infinity); report the cycle, do not print numbers.
  • Weights large enough to overflow int need long.

Interview angle

Likely questions: "Dijkstra or Bellman-Ford?" (negative edges or an edge limit → Bellman-Ford), "why V − 1 rounds?" (a simple path has at most V − 1 edges), "how do you detect a negative cycle?" (an extra round that still improves). You rarely need to code it in a service-company round, but you must know the O(V · E) cost and the use cases.

Floyd-Warshall (all pairs) and 0-1 BFS

Floyd-Warshall computes the shortest distance between every pair of vertices with three nested loops in O(V³), trying each vertex k as an intermediate stop; 0-1 BFS finds single-source shortest paths in O(V + E) when every edge weighs 0 or 1, using a deque.

Floyd-Warshall: all-pairs shortest paths

Dijkstra and Bellman-Ford answer "how far is everything from one source?". Sometimes you need the distance between every pair — for example "find the city with the fewest neighbours within a distance threshold" or a lookup table of travel times. Running Dijkstra from every vertex costs O(V · E log V). Floyd-Warshall does it with a very short algorithm in O(V³) time and O(V²) space, and it works with negative edges as long as there is no negative cycle.

Idea (dynamic programming). Let dist[i][j] be the best known distance from i to j. Allow the vertices 0, 1, 2, … one at a time as intermediate stops. When vertex k becomes allowed, a path from i to j can either avoid k (keep dist[i][j]) or go through it (dist[i][k] + dist[k][j]). Take the smaller. After all k have been tried, the matrix is final.

import java.util.Arrays;

public class FloydWarshall {
    private static final int INF = 1_000_000_000;      // big, but INF + INF still fits in an int

    // edges[i] = {u, v, w} (directed); returns the n x n matrix of shortest distances
    public static int[][] allPairs(int n, int[][] edges) {
        int[][] dist = new int[n][n];
        for (int[] row : dist) Arrays.fill(row, INF);
        for (int i = 0; i < n; i++) dist[i][i] = 0;      // distance to itself is 0
        for (int[] e : edges) dist[e[0]][e[1]] = Math.min(dist[e[0]][e[1]], e[2]);

        for (int k = 0; k < n; k++) {                    // k MUST be the outermost loop
            for (int i = 0; i < n; i++) {
                for (int j = 0; j < n; j++) {
                    if (dist[i][k] + dist[k][j] < dist[i][j]) {
                        dist[i][j] = dist[i][k] + dist[k][j];
                    }
                }
            }
        }
        return dist;                                     // dist[i][i] < 0 → negative cycle
    }

    public static void main(String[] args) {
        int[][] edges = {{0, 1, 3}, {0, 2, 8}, {1, 2, 2}, {2, 3, 1}, {3, 0, 4}};
        for (int[] row : allPairs(4, edges)) System.out.println(Arrays.toString(row));
    }
}

Check one cell: the direct edge 0 → 2 costs 8, but 0 → 1 → 2 costs 3 + 2 = 5, so dist[0][2] = 5; and dist[0][3] = 5 + 1 = 6. Complexity: O(V³) time, O(V²) space. For V = 400 that is 64 million steps — fine; for V = 5,000 it is too slow. Use it when V is at most a few hundred.

  • Negative cycle: after the run, if any dist[i][i] < 0, a negative cycle exists.
  • Path recovery: keep a next[i][j] matrix and update it whenever dist[i][j] improves.
  • Transitive closure: replace the min-plus step by reach[i][j] |= reach[i][k] && reach[k][j] to learn who can reach whom.
  • Problems: Find the City With the Smallest Number of Neighbors at a Threshold Distance (LeetCode 1334) and many "all-pairs on a tiny graph" questions.

Mistake: putting k in the inner loop

The order of the loops is not cosmetic. The intermediate vertex k must be the outermost loop, because the correctness proof says "after iteration k, all shortest paths that use only vertices 0..k as intermediates are right". With k inside, the matrix is wrong.

Mistake: INF = Integer.MAX_VALUE in the matrix

dist[i][k] + dist[k][j] adds two infinities and overflows to a negative number, which then "wins" the comparison. Use a large value that is safe to add to itself (such as 109), or skip the update when either term is INF.

0-1 BFS: shortest path when weights are only 0 or 1

If every edge costs 0 or 1, you do not need a heap. Use a deque (double-ended queue). When you relax an edge of weight 0, the new vertex has the same distance as the current one, so push it at the front; when the weight is 1, push it at the back. The deque then always holds vertices in non-decreasing order of distance, the same job that the priority queue does in Dijkstra, in O(1) per operation. This is also called a "deque-based Dijkstra".

import java.util.ArrayDeque;
import java.util.Arrays;
import java.util.Deque;
import java.util.List;

public class ZeroOneBfs {
    // g.get(u) holds {neighbour, weight} with weight 0 or 1
    public static int[] shortestPaths(List<List<int[]>> g, int src) {
        int[] dist = new int[g.size()];
        Arrays.fill(dist, Integer.MAX_VALUE);
        dist[src] = 0;
        Deque<Integer> deque = new ArrayDeque<>();
        deque.addFirst(src);
        while (!deque.isEmpty()) {
            int u = deque.pollFirst();
            for (int[] e : g.get(u)) {
                int v = e[0], nd = dist[u] + e[1];
                if (nd < dist[v]) {
                    dist[v] = nd;
                    if (e[1] == 0) deque.addFirst(v);     // free move: process it next
                    else deque.addLast(v);                // cost 1: process it later
                }
            }
        }
        return dist;
    }

    public static void main(String[] args) {
        int[][] edges = {{0, 1, 1}, {0, 2, 0}, {2, 1, 0}, {1, 3, 1}, {2, 3, 1}};
        List<List<int[]>> g = GraphBuilder.buildWeighted(4, edges, true);
        System.out.println(Arrays.toString(shortestPaths(g, 0)));   // [0, 0, 0, 1]
    }
}

Complexity: O(V + E). A vertex can be pushed more than once if its distance improves, but each edge triggers at most one push per successful relaxation, so the total stays linear. Typical problems: grids where moving in one direction is free and turning costs 1 (Minimum Cost to Make at Least One Valid Path in a Grid, LeetCode 1368), "minimum obstacles to remove" (LeetCode 2290), and graphs where some edges are "free".

Exception: weights other than 0 and 1

0-1 BFS is correct only for edge weights 0 and 1. For small integer weights up to W you can split edges into unit edges (BFS with levels) or use buckets, but in an interview use Dijkstra instead.

Interview angle

Floyd-Warshall: "three loops, k outermost, O(V³), good for V up to a few hundred, handles negative edges but not negative cycles." 0-1 BFS: "Dijkstra with a deque — push front for weight 0 and back for weight 1 — in O(V + E)". Naming 0-1 BFS when a grid problem has "free" and "paid" moves is a strong signal.
