Segment tree: range queries with updates in O(log n)

A segment tree stores the answer for every power-of-two-style segment of an array in a binary tree, so a range query and a point update each touch only O(log n) nodes.

Optional This topic is for top product companies and contests. If your targets are service companies, skip it and come back later.

The problem it solves

You have an array and two kinds of operations that arrive in any order: query "the sum (or min, or max) of a[l..r]" and update "set a[i] to a new value". The two simple answers are both slow when there are many operations.

ApproachQueryUpdate
Loop over the rangeO(n)O(1)
Prefix sumsO(1)O(n) (rebuild)
Segment treeO(log n)O(log n)

With n and the number of operations both near 105, O(n) per operation is about 1010 steps, far too slow. The segment tree makes both O(log n).

How it works

The root represents the whole array [0, n-1]. Each node splits its range into two halves, left child and right child. A leaf is one element. Each node stores the combined answer (here the sum) of its range. In the array form, the children of node i are 2i and 2i+1 (the root is node 1), the same layout as a heap.

  • Build: recurse to the leaves, then fill each parent from its two children. O(n).
  • Point update: walk from the root to the leaf of index i (one child per level), set the leaf, then recompute the parents on the way back. O(log n).
  • Range query: for a node whose range is outside the query, return the identity (0 for sum); fully inside, return its stored value; partly overlapping, ask both children and combine. At most about four nodes per level are visited, so O(log n).

Complete Java implementation (range sum)

public class SegmentTree {
    private final int n;
    private final long[] tree;                 // tree[1] is the root; size 4n is always enough

    public SegmentTree(int[] a) {              // requires a.length >= 1
        n = a.length;
        tree = new long[4 * n];
        build(a, 1, 0, n - 1);
    }

    private void build(int[] a, int node, int l, int r) {
        if (l == r) {                          // leaf
            tree[node] = a[l];
            return;
        }
        int mid = l + (r - l) / 2;
        build(a, 2 * node, l, mid);
        build(a, 2 * node + 1, mid + 1, r);
        tree[node] = tree[2 * node] + tree[2 * node + 1];   // combine
    }

    /** Sets a[idx] = value. O(log n). */
    public void update(int idx, int value) {
        update(1, 0, n - 1, idx, value);
    }

    private void update(int node, int l, int r, int idx, int value) {
        if (l == r) {
            tree[node] = value;
            return;
        }
        int mid = l + (r - l) / 2;
        if (idx <= mid) update(2 * node, l, mid, idx, value);
        else update(2 * node + 1, mid + 1, r, idx, value);
        tree[node] = tree[2 * node] + tree[2 * node + 1];   // recompute on the way back
    }

    /** Sum of a[ql..qr], both ends included. O(log n). */
    public long query(int ql, int qr) {
        return query(1, 0, n - 1, ql, qr);
    }

    private long query(int node, int l, int r, int ql, int qr) {
        if (qr < l || r < ql) return 0;        // no overlap: identity for sum
        if (ql <= l && r <= qr) return tree[node];   // fully inside
        int mid = l + (r - l) / 2;
        return query(2 * node, l, mid, ql, qr)
             + query(2 * node + 1, mid + 1, r, ql, qr);
    }

    public static void main(String[] args) {
        SegmentTree st = new SegmentTree(new int[]{2, 5, 1, 4, 9, 3});
        System.out.println(st.query(1, 4));    // 5 + 1 + 4 + 9 = 19
        st.update(2, 10);                      // a[2] = 10
        System.out.println(st.query(1, 4));    // 5 + 10 + 4 + 9 = 28
    }
}

Changing it to min or max

Only two things change: the combine function and the identity returned for a non-overlapping range.

Sumleft + right0
MinimumMath.min(left, right)Long.MAX_VALUE
MaximumMath.max(left, right)Long.MIN_VALUE
GCDgcd(left, right)0
 
// in build and update:
tree[node] = Math.min(tree[2 * node], tree[2 * node + 1]);
// in query:
if (qr < l || r < ql) return Long.MAX_VALUE;     // identity for min
if (ql <= l && r <= qr) return tree[node];
int mid = l + (r - l) / 2;
return Math.min(query(2 * node, l, mid, ql, qr),
                query(2 * node + 1, mid + 1, r, ql, qr));

Lazy propagation (idea only)

What if updates apply to a range, such as "add 5 to every element in a[l..r]", and queries ask for a range sum? Updating every leaf is O(n). Lazy propagation stores a pending update on a node ("add 5 to my whole range") and does not push it to the children until a later query or update needs to go below that node. A node with a pending value can answer a fully-covered query by itself: new sum = old sum + 5 × (number of elements). Each operation stays O(log n). The cost is extra bookkeeping: a second array lazy[] and a push-down step before descending. It appears in hard problems ("range add, range sum"), rarely in standard interviews.

Problems that use it

  • Range Sum Query - Mutable (point update, range sum).
  • Range minimum with updates; counting elements in a range with a value condition.
  • The Skyline Problem, Count of Range Sum, Falling Squares (often with coordinate compression).

Common mistakes

  • Allocating 2 * n nodes in the recursive layout. That crashes with ArrayIndexOutOfBoundsException for many sizes; use 4 * n.
  • Returning 0 as the "no overlap" value for a min tree, which makes every min wrong.
  • Using int for sums of up to 105 values of up to 109; use long.
  • Building a tree on an empty array (n - 1 = -1). Guard it.

Interview angle

You will usually be asked "how do you answer range queries with updates?" The short answer: segment tree or Fenwick tree, O(log n) each. Explain the three node cases (outside, inside, partial) and the build/update/query costs. Coding it fully is expected only for top-tier product roles.

Fenwick tree (binary indexed tree) and the i & -i trick

A Fenwick tree keeps prefix sums with point updates in a single array and about ten lines of code; each index covers a block whose size is its lowest set bit, found with i & -i.

Optional A Fenwick tree (also called a binary indexed tree, BIT) supports the same "prefix sum with updates" job as a segment tree, but it is smaller and faster to write. It works for operations that can be undone (sum, XOR, counts); it is not suitable for min/max directly.

The idea: each index owns a block

Use 1-based indexes. Index i stores the sum of a block that ends at i and has length equal to the lowest set bit of i. The lowest set bit is i & -i because -i in two's complement is ~i + 1, which flips every bit above the lowest set bit and keeps that bit.

  • Prefix sum of 1..i: add tree[i], then set i -= i & -i (remove the lowest set bit), until i == 0. At most log n steps, one per set bit.
  • Point update at i: add the change to tree[i], then set i += i & -i (move to the next block that contains this index), until i > n. At most log n steps.
  • Range sum l..r: prefix(r) - prefix(l - 1).

Complete Java implementation

public class FenwickTree {
    private final int n;
    private final long[] tree;                 // 1-based; tree[0] is unused

    public FenwickTree(int n) {
        this.n = n;
        this.tree = new long[n + 1];
    }

    /** Builds from a 0-based array in O(n). */
    public FenwickTree(int[] a) {
        this(a.length);
        for (int i = 1; i <= n; i++) {
            tree[i] += a[i - 1];
            int parent = i + (i & -i);         // the next block that includes this one
            if (parent <= n) tree[parent] += tree[i];
        }
    }

    /** Adds delta to element at 1-based index i. O(log n). */
    public void add(int i, long delta) {
        for (; i <= n; i += i & -i) {
            tree[i] += delta;
        }
    }

    /** Sum of elements 1..i (prefix). O(log n). */
    public long prefix(int i) {
        long sum = 0;
        for (; i > 0; i -= i & -i) {
            sum += tree[i];
        }
        return sum;
    }

    /** Sum of elements l..r, 1-based, both ends included. */
    public long range(int l, int r) {
        return prefix(r) - prefix(l - 1);
    }

    public static void main(String[] args) {
        FenwickTree ft = new FenwickTree(new int[]{2, 5, 1, 4, 9, 3});
        System.out.println(ft.range(2, 5));    // 5 + 1 + 4 + 9 = 19
        ft.add(3, 9);                          // element 3 changes from 1 to 10
        System.out.println(ft.range(2, 5));    // 28
    }
}

A classic use: Count of Smaller Numbers After Self

Process the array from right to left. Map each value to a rank 1..m (coordinate compression: sort the distinct values). For each element, the number of smaller values already seen is prefix(rank - 1); then add(rank, 1). Total O(n log n). The same trick counts inversions.

public java.util.List<Integer> countSmaller(int[] nums) {
    int n = nums.length;
    int[] sorted = java.util.Arrays.stream(nums).distinct().sorted().toArray();
    FenwickTree ft = new FenwickTree(sorted.length);
    Integer[] result = new Integer[n];
    for (int i = n - 1; i >= 0; i--) {
        int rank = java.util.Arrays.binarySearch(sorted, nums[i]) + 1;   // 1-based rank
        result[i] = (int) ft.prefix(rank - 1);     // how many smaller values are to the right
        ft.add(rank, 1);
    }
    return java.util.Arrays.asList(result);
}

Rule: Fenwick indexes start at 1

With index 0 the loops never move: 0 & -0 == 0, so i += i & -i loops forever in add. Convert 0-based input to 1-based before calling.

Common mistakes

  • Calling add(0, x) (infinite loop) or prefix(-1) for l = 0 in a 0-based range.
  • Using int[] and overflowing on large sums; use long[].
  • Mixing the roles: query goes down with -=, update goes up with +=.

Interview angle

Say: "Prefix sums are O(1) per query but O(n) per update. A Fenwick tree balances both at O(log n) with very little code; I would use a segment tree if I needed min or max, or range updates." Explain i & -i as "the lowest set bit".
