Longest common subsequence and longest common substring

LCS fills a table dp[i][j] over prefixes of two strings: equal last characters extend the diagonal, otherwise take the better of dropping one character from either string; walk the table backwards to rebuild the answer.

String DP almost always uses two indexes, one per string (or two ends of one string). The state is "the answer for the first i characters of a and the first j characters of b". A subsequence may skip characters, a substring may not. LCS (LeetCode "Longest Common Subsequence") is the base of edit distance, palindromic subsequence, shortest common supersequence and many diff tools.

LCS: state and transition

  • State: dp[i][j] = length of the LCS of a[0..i) and b[0..j).
  • Transition: if a[i-1] == b[j-1], that character is in the LCS: dp[i][j] = dp[i-1][j-1] + 1. Otherwise one of the two characters is not used: dp[i][j] = max(dp[i-1][j], dp[i][j-1]).
  • Base cases: dp[0][j] = dp[i][0] = 0 (an empty string has no common subsequence). A new int[m+1][n+1] gives this for free.
  • Order: row by row, left to right (each cell reads up, left and up-left).
  • Answer: dp[m][n].
public static int lcsLength(String a, String b) {
    int m = a.length(), n = b.length();
    int[][] dp = new int[m + 1][n + 1];
    for (int i = 1; i <= m; i++) {
        for (int j = 1; j <= n; j++) {
            if (a.charAt(i - 1) == b.charAt(j - 1)) {
                dp[i][j] = dp[i - 1][j - 1] + 1;
            } else {
                dp[i][j] = Math.max(dp[i - 1][j], dp[i][j - 1]);
            }
        }
    }
    return dp[m][n];                           // O(m*n) time and space
}

Reconstructing the string

Start at dp[m][n] and walk back. If the characters match, that character belongs to the LCS: record it and move diagonally. Otherwise move toward the neighbour with the larger value (up or left). The characters come out in reverse, so reverse them at the end.

public static String lcsString(String a, String b, int[][] dp) {
    StringBuilder sb = new StringBuilder();
    int i = a.length(), j = b.length();
    while (i > 0 && j > 0) {
        if (a.charAt(i - 1) == b.charAt(j - 1)) {
            sb.append(a.charAt(i - 1));        // part of the LCS
            i--; j--;
        } else if (dp[i - 1][j] >= dp[i][j - 1]) {
            i--;                               // the value came from above
        } else {
            j--;                               // the value came from the left
        }
    }
    return sb.reverse().toString();
}

Several different LCS strings can exist with the same length; this code returns one of them. Reconstruction needs the full table, so the space-saving version (two rows) gives only the length.

Space optimisation

Only the previous row is needed, so keep two arrays of size n+1 and swap them. Time stays O(m·n), space drops to O(n). Pick the shorter string as the column dimension.

Longest common substring

Here the characters must be contiguous, so a mismatch breaks the run. Redefine the state: dp[i][j] = length of the common substring that ends exactly at a[i-1] and b[j-1]. If they match, dp[i][j] = dp[i-1][j-1] + 1; if not, dp[i][j] = 0. The answer is the maximum anywhere in the table, not the last cell.

public static int longestCommonSubstring(String a, String b) {
    int m = a.length(), n = b.length(), best = 0;
    int[][] dp = new int[m + 1][n + 1];
    for (int i = 1; i <= m; i++) {
        for (int j = 1; j <= n; j++) {
            if (a.charAt(i - 1) == b.charAt(j - 1)) {
                dp[i][j] = dp[i - 1][j - 1] + 1;
                best = Math.max(best, dp[i][j]);   // track the max cell
            }                                      // else stays 0: run is broken
        }
    }
    return best;                               // O(m*n) time; O(n) with one rolling row
}

Problems that are LCS in disguise

  • Shortest common supersequence length = m + n - LCS.
  • Minimum deletions/insertions to turn a into b: deletions m - LCS, insertions n - LCS (this is "delete operation for two strings").
  • Longest palindromic subsequence = LCS of a string and its reverse (see the palindromes article).
  • Uncrossed lines: the same as LCS on two integer arrays.

Off-by-one with the padded table

With a table of size (m+1) × (n+1), row i stands for the first i characters, so the character is a.charAt(i - 1). Writing a.charAt(i) throws StringIndexOutOfBoundsException on the last row.

Why the recurrence is correct

Look only at the last characters of the two prefixes. If they are equal, some best common subsequence can always use them as its final pair: matching them costs nothing, and it leaves the best problem for the shorter prefixes, so the answer is one more than the diagonal cell. If they differ, they cannot both be the last character of the common subsequence, so at least one of them is unused. Dropping the last character of a gives dp[i-1][j]; dropping the last character of b gives dp[i][j-1]; the answer is the larger. Because both cases only look at smaller prefixes, filling the table row by row is a valid order.

Recognise LCS by these signs: two sequences, the words "common", "align", "delete or insert to make equal", and elements that must keep their order but may skip. When the question is about one sequence (palindrome, increasing), try an interval or single-index DP instead.

Dry run: walking back for "abcde" and "ace"

Start at (i, j) = (5, 3), the bottom-right cell with value 3.

  1. a[4] = 'e' equals b[2] = 'e': record e, move to (4, 2).
  2. 'd' versus 'c' differ. Compare dp[3][2] = 2 (above) with dp[4][1] = 1 (left): above is not smaller, so move up to (3, 2).
  3. 'c' equals 'c': record c, move to (2, 1).
  4. 'b' versus 'a' differ. dp[1][1] = 1 is at least dp[2][0] = 0: move up to (1, 1).
  5. 'a' equals 'a': record a, move to (0, 0) and stop.

The recorded characters are e, c, a; reversed, they give ace.

The same idea top-down

If the table order feels hard, write the recursion first: f(i, j) is the LCS of the first i and j characters. Cache the results in an int[m+1][n+1] filled with −1.

static int f(String a, String b, int i, int j, int[][] memo) {
    if (i == 0 || j == 0) return 0;                       // an empty prefix
    if (memo[i][j] != -1) return memo[i][j];
    int res;
    if (a.charAt(i - 1) == b.charAt(j - 1)) {
        res = 1 + f(a, b, i - 1, j - 1, memo);
    } else {
        res = Math.max(f(a, b, i - 1, j, memo), f(a, b, i, j - 1, memo));
    }
    return memo[i][j] = res;                              // recursion depth up to m + n
}

For strings of length 1,000 the depth reaches about 2,000 frames, which Java's default stack usually handles; for much longer strings prefer the bottom-up table.

Two-row version in code

public static int lcsTwoRows(String a, String b) {
    if (b.length() > a.length()) { String t = a; a = b; b = t; }   // columns = shorter string
    int n = b.length();
    int[] prev = new int[n + 1], cur = new int[n + 1];
    for (int i = 1; i <= a.length(); i++) {
        for (int j = 1; j <= n; j++) {
            if (a.charAt(i - 1) == b.charAt(j - 1)) cur[j] = prev[j - 1] + 1;
            else cur[j] = Math.max(prev[j], cur[j - 1]);
        }
        int[] t = prev; prev = cur; cur = t;            // the finished row becomes "previous"
    }
    return prev[n];                                     // O(m*n) time, O(min(m, n)) space
}

If you need the string and cannot afford the full table, Hirschberg's algorithm recovers it in linear space by divide and conquer; it is a name worth knowing, but rarely coded.

One more classic: Delete Operation for Two Strings

Make two strings equal by deleting characters from either one; minimise the deletions. What remains must be a common subsequence, and the longest one keeps the most characters, so the answer is m + n - 2 * LCS. There is no new DP, only the formula.

public int minDistance(String a, String b) {
    int lcs = lcsLength(a, b);                 // from the code above
    return a.length() + b.length() - 2 * lcs;
}
// "sea" and "eat": LCS "ea" has length 2 -> 3 + 3 - 4 = 2 deletions

Edge cases

  • An empty string: row 0 and column 0 are zeros, so the answer is 0 with no special case.
  • Identical strings: the LCS is the string itself, and the table has the diagonal 1, 2, 3, ...
  • No common character: the table stays all zeros.
  • Memory: two strings of 5,000 characters need a 25-million-cell int table (about 100 MB). Use the two-row version when you only need the length.

Mistake: using the subsequence answer for a substring

Wrong: returns the last cell

// longest common substring of "abcdef" and "xabcy"
return dp[m][n];            // 0, because f and y differ and the run resets

Right: track the maximum while filling

best = Math.max(best, dp[i][j]);
return best;                // 3 ("abc")

Interview angle

State the recurrence in words ("if the last characters match, extend the diagonal; else drop one"), fill a small table on the whiteboard, and offer reconstruction without being asked. Mention the rolling-row optimisation and that it loses the ability to rebuild the string.

Edit distance, distinct subsequences, wildcard and regex matching

Edit distance uses the same two-prefix table as LCS but each cell takes the cheapest of insert, delete and replace; distinct subsequences and wildcard matching are variations on the same table.

Edit Distance (LeetCode 72)

Problem: the minimum number of operations (insert, delete, replace one character) to turn word1 into word2. This is the Levenshtein distance, used in spell checkers and fuzzy search.

  • State: dp[i][j] = edits to turn the first i characters of word1 into the first j of word2.
  • Transition: if the last characters are equal, no work: dp[i-1][j-1]. Otherwise 1 + min(dp[i-1][j-1], dp[i-1][j], dp[i][j-1]) — replace, delete from word1, or insert into word1.
  • Base cases: dp[i][0] = i (delete all), dp[0][j] = j (insert all).
  • Answer: dp[m][n].
public int minDistance(String w1, String w2) {
    int m = w1.length(), n = w2.length();
    int[][] dp = new int[m + 1][n + 1];
    for (int i = 0; i <= m; i++) dp[i][0] = i;     // delete i characters
    for (int j = 0; j <= n; j++) dp[0][j] = j;     // insert j characters
    for (int i = 1; i <= m; i++) {
        for (int j = 1; j <= n; j++) {
            if (w1.charAt(i - 1) == w2.charAt(j - 1)) {
                dp[i][j] = dp[i - 1][j - 1];
            } else {
                dp[i][j] = 1 + Math.min(dp[i - 1][j - 1],        // replace
                                Math.min(dp[i - 1][j],           // delete
                                         dp[i][j - 1]));         // insert
            }
        }
    }
    return dp[m][n];                           // O(m*n) time; O(n) with two rows
}

Reading the three neighbours

Diagonal = replace (or match), up = delete a character of word1, left = insert a character. Walking back from the corner and noting which neighbour gave the minimum prints the actual edit script.

Distinct Subsequences (LeetCode 115, brief)

Count how many subsequences of s equal t. State: dp[i][j] = number of ways the first i characters of s contain the first j of t. Base: dp[i][0] = 1 (the empty target is made one way). If s[i-1] == t[j-1] you can use it or skip it: dp[i][j] = dp[i-1][j-1] + dp[i-1][j]; otherwise only skip: dp[i-1][j].

public int numDistinct(String s, String t) {
    int n = t.length();
    long[] dp = new long[n + 1];               // dp[j] for the current prefix of s
    dp[0] = 1;                                 // empty t: exactly one way
    for (int i = 1; i <= s.length(); i++) {
        for (int j = n; j >= 1; j--) {         // reverse: dp[j-1] must still be the old row
            if (s.charAt(i - 1) == t.charAt(j - 1)) {
                dp[j] += dp[j - 1];
            }
        }
    }
    return (int) dp[n];                        // the problem guarantees the answer fits in int
}

For s = "rabbbit", t = "rabbit" the answer is 3 (choose which of the three b's to skip). Notice the reverse loop, the same rule as 0/1 knapsack. Complexity: O(m·n) time, O(n) space. Intermediate counts can exceed int, hence long.

Wildcard Matching (LeetCode 44, brief)

Pattern p may contain ? (any one character) and * (any sequence, including empty). State: dp[i][j] = does s[0..i) match p[0..j).

  • If p[j-1] is ? or equals s[i-1]: dp[i][j] = dp[i-1][j-1].
  • If p[j-1] is *: it matches empty (dp[i][j-1]) or swallows one more character (dp[i-1][j]).
  • Base: dp[0][0] = true; dp[0][j] is true only while the pattern so far is all stars.
public boolean isMatch(String s, String p) {
    int m = s.length(), n = p.length();
    boolean[][] dp = new boolean[m + 1][n + 1];
    dp[0][0] = true;
    for (int j = 1; j <= n; j++) {
        if (p.charAt(j - 1) == '*') dp[0][j] = dp[0][j - 1];
    }
    for (int i = 1; i <= m; i++) {
        for (int j = 1; j <= n; j++) {
            char pc = p.charAt(j - 1);
            if (pc == '*') {
                dp[i][j] = dp[i][j - 1] || dp[i - 1][j];
            } else if (pc == '?' || pc == s.charAt(i - 1)) {
                dp[i][j] = dp[i - 1][j - 1];
            }
        }
    }
    return dp[m][n];                           // O(m*n) time and space
}

Regular Expression Matching (LeetCode 10, idea)

Here . matches any one character and * means "zero or more of the previous element", so a star always pairs with the character before it. Same table, different star rule: when p[j-1] == '*', either use the star zero times (dp[i][j-2]) or, if s[i-1] matches p[j-2] (equal or .), use it once more (dp[i-1][j]). The first row needs care: a*b* can match the empty string, so dp[0][j] = dp[0][j-2] when p[j-1] is a star.

Wildcard star vs regex star

In wildcard matching * stands alone and matches any sequence. In regex * modifies the previous character. Mixing the two rules up is the most common bug in these problems.

Why the three neighbours are the three operations

Think of turning the first i characters of word1 into the first j characters of word2. Look at the last characters.

  • Equal: keep both, no cost. The problem becomes (i−1, j−1).
  • Replace the last character of word1 by the last character of word2: one operation, then solve (i−1, j−1).
  • Delete the last character of word1: one operation, then solve (i−1, j): now the shorter word1 must still become the whole word2 prefix.
  • Insert the last character of word2 at the end of word1: one operation, and that new character now matches, so solve (i, j−1).

Take the cheapest option. When the characters are equal you may skip the other options: matching is never worse than any edit, so the diagonal is safe. The base cases are intuitive: turning an empty string into j characters needs j inserts, and turning i characters into an empty string needs i deletes.

Space optimisation: one row and a saved diagonal

Each cell needs its up, left and up-left neighbours. With one array, dp[j] before the update is the "up" value, dp[j-1] is the "left" value (already updated), and the up-left value would be overwritten, so save it in a variable before you overwrite it.

public int minDistance1D(String a, String b) {
    int m = a.length(), n = b.length();
    int[] dp = new int[n + 1];
    for (int j = 0; j <= n; j++) dp[j] = j;              // row 0
    for (int i = 1; i <= m; i++) {
        int diag = dp[0];                                  // dp[i-1][0]
        dp[0] = i;                                         // dp[i][0]
        for (int j = 1; j <= n; j++) {
            int up = dp[j];                                // dp[i-1][j], before the overwrite
            if (a.charAt(i - 1) == b.charAt(j - 1)) dp[j] = diag;
            else dp[j] = 1 + Math.min(diag, Math.min(up, dp[j - 1]));
            diag = up;                                     // becomes dp[i-1][j-1] next time
        }
    }
    return dp[n];                                          // O(m*n) time, O(n) space
}

Regular expression matching in code

The idea above becomes the following. The star is read together with the character before it, so when p[j-1] is a star the previous pattern character is p[j-2]. (LeetCode guarantees that a star never starts the pattern, so j - 2 is valid.)

public boolean isMatch(String s, String p) {
    int m = s.length(), n = p.length();
    boolean[][] dp = new boolean[m + 1][n + 1];
    dp[0][0] = true;
    for (int j = 2; j <= n; j++) {                        // patterns like a*b* match ""
        if (p.charAt(j - 1) == '*') dp[0][j] = dp[0][j - 2];
    }
    for (int i = 1; i <= m; i++) {
        for (int j = 1; j <= n; j++) {
            char pc = p.charAt(j - 1);
            if (pc == '*') {
                dp[i][j] = dp[i][j - 2];                   // use the star zero times
                char prev = p.charAt(j - 2);
                if (prev == '.' || prev == s.charAt(i - 1)) {
                    dp[i][j] |= dp[i - 1][j];              // or one more copy
                }
            } else if (pc == '.' || pc == s.charAt(i - 1)) {
                dp[i][j] = dp[i - 1][j - 1];
            }
        }
    }
    return dp[m][n];                                       // O(m*n) time and space
}

Check with s = "aab" and p = "c*a*b": the first row becomes true at the stars (c* and then c*a* both match the empty string), the stars absorb the two a's, and b matches b. The result is true.

Interview angle

Edit distance is asked often. Explain why the three neighbours mean replace, delete and insert, give the base cases, and mention O(n) space. Distinct subsequences and the matching problems usually appear as "hard" follow-ups; naming the state and the star rule is already most of the answer.

Palindromic subsequence, longest palindromic substring, counting substrings

A substring palindrome grows from a centre, so expanding around each of the 2n-1 centres is O(n²) with O(1) space; a palindromic subsequence is an LCS with the reversed string or a DP over the two ends of an interval.

"Palindrome" problems split into two families. For substrings (contiguous), the palindrome property is local: s[i..j] is a palindrome if s[i] == s[j] and s[i+1..j-1] is a palindrome. For subsequences (skipping allowed), the table runs over the two ends of an interval.

Longest Palindromic Substring: expand around the centre

Every palindrome has a centre: one character (odd length) or the gap between two characters (even length). Try all 2n - 1 centres and expand outwards while both ends match.

public String longestPalindrome(String s) {
    int start = 0, maxLen = 0;
    for (int c = 0; c < s.length(); c++) {
        int odd = expand(s, c, c);             // centre on one character
        int even = expand(s, c, c + 1);        // centre between two characters
        int len = Math.max(odd, even);
        if (len > maxLen) {
            maxLen = len;
            start = c - (len - 1) / 2;         // works for both odd and even lengths
        }
    }
    return s.substring(start, start + maxLen);
}

private int expand(String s, int left, int right) {
    while (left >= 0 && right < s.length() && s.charAt(left) == s.charAt(right)) {
        left--;
        right++;
    }
    return right - left - 1;                   // length after the last successful step
}

Complexity: O(n²) time (each expansion is up to O(n), there are 2n-1 centres), O(1) space. For "babad" it returns "bab" ("aba" is also valid). Manacher's algorithm does it in O(n), but it is rarely required.

The DP alternative for substrings

State: isPal[i][j] = is s[i..j] a palindrome. Transition: s[i] == s[j] && (j - i < 3 || isPal[i+1][j-1]) (lengths 1 to 3 need no inner check). The order matters: row i depends on row i+1, so loop i from n-1 down to 0 and j from i up.

boolean[][] isPal = new boolean[n][n];
for (int i = n - 1; i >= 0; i--) {              // i goes down: row i+1 is already done
    for (int j = i; j < n; j++) {
        isPal[i][j] = s.charAt(i) == s.charAt(j)
                && (j - i < 3 || isPal[i + 1][j - 1]);
    }
}
// isPal[i][j] now answers "is s[i..j] a palindrome?" in O(1). Time and space O(n^2).

Use the table when you need many palindrome queries (for example Palindrome Partitioning); use expand-around-centre when you need one answer, because it uses O(1) space.

Palindromic Substrings: count them (LeetCode 647)

Count every substring that is a palindrome, counting equal substrings at different positions separately. With the expand idea, each successful step of the loop is one more palindrome, so count them directly.

public int countSubstrings(String s) {
    int count = 0;
    for (int c = 0; c < s.length(); c++) {
        count += countAround(s, c, c);         // odd-length palindromes
        count += countAround(s, c, c + 1);     // even-length palindromes
    }
    return count;
}

private int countAround(String s, int l, int r) {
    int found = 0;
    while (l >= 0 && r < s.length() && s.charAt(l) == s.charAt(r)) {
        found++;                               // s[l..r] is a palindrome: count it
        l--;
        r++;
    }
    return found;
}

For "aaa" the answer is 6 (three of length 1, two of length 2, one of length 3). Complexity: O(n²) time, O(1) space.

Longest Palindromic Subsequence (LeetCode 516)

Now characters may be skipped. Two equivalent solutions:

  1. LCS with the reverse. A palindrome reads the same both ways, so the longest palindromic subsequence of s is the LCS of s and reverse(s). Reuse the LCS code.
  2. Interval DP. dp[i][j] = length of the longest palindromic subsequence inside s[i..j]. If s[i] == s[j], both ends join: 2 + dp[i+1][j-1]. Otherwise drop one end: max(dp[i+1][j], dp[i][j-1]). Base: dp[i][i] = 1.
public int longestPalindromeSubseq(String s) {
    int n = s.length();
    int[][] dp = new int[n][n];
    for (int i = n - 1; i >= 0; i--) {
        dp[i][i] = 1;                          // a single character
        for (int j = i + 1; j < n; j++) {
            if (s.charAt(i) == s.charAt(j)) {
                dp[i][j] = 2 + dp[i + 1][j - 1];   // when j = i+1 this reads dp[i+1][i] = 0
            } else {
                dp[i][j] = Math.max(dp[i + 1][j], dp[i][j - 1]);
            }
        }
    }
    return dp[0][n - 1];                       // O(n^2) time and space
}

For "bbbab" the answer is 4 ("bbbb"). A related result: the minimum insertions to make a string a palindrome is n - longestPalindromeSubseq.

Forgetting the even-length centres

Expanding only from (c, c) misses "abba" and "aa". Always run both (c, c) and (c, c + 1).

Iteration order in interval DP

The cell dp[i][j] reads dp[i+1][...], so i must go from n-1 down to 0. A normal top-down row loop reads cells that are still zero and gives wrong answers without any exception.

How to recognise and choose

Ask two questions. First: contiguous or not? A substring palindrome is checked from the inside out, so expanding from a centre fits. A subsequence palindrome uses both ends of an interval, so use a table with the interval [i, j] as the state. Second: one answer or many queries? For one answer, the O(1)-space expansion is enough. When a later step asks "is s[i..j] a palindrome?" many times (Palindrome Partitioning), build the boolean table once.

Dry run of expand-around-centre

"babad". At centre c = 1 (a), the odd expansion starts with left = right = 1. The characters match, so left = 0 and right = 2: b equals b, so left = −1 and right = 3, and the loop stops because left is out of range. The length is right - left - 1 = 3 - (-1) - 1 = 3. The start is c - (len - 1) / 2 = 1 - 1 = 0, so the substring is "bab".

"cbbd". At c = 1 the even expansion starts with (1, 2): b equals b, so left = 0, right = 3: c versus d differ, stop. The length is 3 - 0 - 1 = 2 and the start is 1 - (2 - 1) / 2 = 1 - 0 = 1 (integer division), so the substring is "bb". The same start formula works for odd and even lengths.

Palindrome Partitioning II: minimum cuts

Cut a string so that every piece is a palindrome and use as few cuts as possible. State: cuts[j] = fewest cuts for s[0..j]. If s[i..j] is a palindrome, the prefix s[0..i-1] plus this last piece costs cuts[i-1] + 1 (or 0 when the whole prefix is one palindrome). The palindrome table is built in the same loops.

public int minCut(String s) {
    int n = s.length();
    boolean[][] pal = new boolean[n][n];
    int[] cuts = new int[n];                       // cuts[j] = min cuts for s[0..j]
    for (int j = 0; j < n; j++) {
        cuts[j] = j;                               // worst case: a cut before every character
        for (int i = 0; i <= j; i++) {
            if (s.charAt(i) == s.charAt(j) && (j - i < 2 || pal[i + 1][j - 1])) {
                pal[i][j] = true;
                cuts[j] = (i == 0) ? 0 : Math.min(cuts[j], cuts[i - 1] + 1);
            }
        }
    }
    return cuts[n - 1];                            // O(n^2) time and space
}
// "aab": cuts = [0, 0, 1] -> one cut gives "aa" | "b"

The version that lists all partitions (Palindrome Partitioning) uses backtracking from the backtracking template, with the table giving the palindrome check in O(1).

Valid Palindrome II: one deletion allowed

Two pointers from the ends move inward. At the first mismatch you may delete either the left or the right character and check that the rest is a palindrome. This is O(n) and needs no table.

static boolean validPalindrome(String s) {
    int l = 0, r = s.length() - 1;
    while (l < r) {
        if (s.charAt(l) != s.charAt(r)) {
            return isPal(s, l + 1, r) || isPal(s, l, r - 1);   // skip one side
        }
        l++; r--;
    }
    return true;
}

static boolean isPal(String s, int l, int r) {
    while (l < r) {
        if (s.charAt(l++) != s.charAt(r--)) return false;
    }
    return true;
}

Beyond O(n²): Manacher's algorithm

Manacher's algorithm finds the longest palindromic substring in O(n) time by reusing the palindrome radii already found inside a bigger palindrome (mirror positions). It is a known result and worth naming in an interview when asked "can you do better than O(n²)?". Coding it is rarely expected. The expand-around-centre solution is the answer to give and write.

Palindromes and LCS: what carries over and what does not

The longest palindromic subsequence equals the LCS of a string and its reverse. This does not carry over to substrings. The longest common substring of s and its reverse can be a string that is not a palindrome, because it may come from two different places in s. For example, s = "aacabdkacaa" has the reverse "aacakdbacaa", and the common substring "aaca" has length 4, but the longest palindromic substring of s has length 3 ("aca"). A fix exists (check that the indices line up), but expansion is simpler.

Edge cases

  • Empty string: longestPalindrome("") returns an empty string; the loop does not run. Check the problem for whether it can happen.
  • One character: the answer is that character, and countSubstrings is 1.
  • All characters equal ("aaaa"): the whole string is a palindrome, and the count is n(n+1)/2. This is the worst case for expansion (O(n²) real work).
  • Several answers of the same length: the code keeps the first found because of the strict len > maxLen. State which one you return if asked.
  • Case and non-letters: "Valid Palindrome" (125) filters to letters and digits and ignores case; the substring problems here do not.

Mistake: the base case of the interval table

Wrong: j starts at i, so dp[i][i] is overwritten

for (int i = n - 1; i >= 0; i--)
    for (int j = i; j < n; j++)
        dp[i][j] = (s.charAt(i) == s.charAt(j)) ? 2 + dp[i + 1][j - 1]
                 : Math.max(dp[i + 1][j], dp[i][j - 1]);   // i==j gives 2, reads i+1

Right: set dp[i][i] = 1, then start j at i + 1

for (int i = n - 1; i >= 0; i--) {
    dp[i][i] = 1;
    for (int j = i + 1; j < n; j++) { /* transition as before */ }
}

Interview angle

Longest Palindromic Substring is a top-ten question. Give the O(n²), O(1)-space expansion first and say why it has 2n − 1 centres. Mention the table version for repeated queries and Manacher as the O(n) option. For subsequences, explain the two ways (LCS with the reverse, or the interval DP) and the iteration order (i going down). A follow-up like "minimum insertions to make a palindrome" is just n - longestPalindromeSubseq.

Other DP shapes to recognise: stocks, intervals, trees, bitmasks

Four shapes appear often enough to know by sight: DP with a small set of states (stocks), interval DP (try the last or first action in a range), DP on trees (return a pair from DFS), and bitmask DP (a set of up to about 20 items as an integer).

You will not meet these every day, but a good interview answer starts with naming the shape. This article shows one compact example each. The aim is recognition and the core recurrence, not every variant.

1. DP with states: stock buy and sell

Sometimes the position in the array is not enough; you also need a small piece of extra information, such as "do I hold a share right now". Keep one variable per state and update them together. Best Time to Buy and Sell Stock with Cooldown (after selling you must wait one day) has three states:

  • hold = best profit if I own a share at the end of today.
  • sold = best profit if I sold today.
  • rest = best profit if I own nothing and did not sell today.
public int maxProfit(int[] prices) {
    int hold = Integer.MIN_VALUE / 2;          // cannot own a share before buying
    int sold = 0, rest = 0;
    for (int p : prices) {
        int prevSold = sold;
        sold = hold + p;                       // sell the share I held
        hold = Math.max(hold, rest - p);       // keep holding, or buy (only from rest)
        rest = Math.max(rest, prevSold);       // do nothing, or finish the cooldown
    }
    return Math.max(sold, rest);               // never end holding a share
}

Complexity: O(n) time, O(1) space. The family also includes "at most k transactions" (add a transaction-count dimension: dp[k][hold?]) and "with a fee". The method is always: list the states, write how each can be reached from yesterday's states.

2. Interval DP: burst balloons, matrix chain

State is a range dp[l][r]; the transition tries every split point k inside the range; and you fill ranges by increasing length. The key idea in Burst Balloons is to choose the last balloon burst in a range, because then its neighbours are fixed (the range borders), which makes the two halves independent.

public int maxCoins(int[] nums) {
    int n = nums.length;
    int[] a = new int[n + 2];                  // pad both ends with 1
    a[0] = 1; a[n + 1] = 1;
    for (int i = 0; i < n; i++) a[i + 1] = nums[i];
    int[][] dp = new int[n + 2][n + 2];        // dp[l][r]: best for balloons strictly between l and r
    for (int len = 2; len <= n + 1; len++) {
        for (int l = 0; l + len <= n + 1; l++) {
            int r = l + len;
            for (int k = l + 1; k < r; k++) {  // k is the LAST balloon burst between l and r
                dp[l][r] = Math.max(dp[l][r],
                        dp[l][k] + dp[k][r] + a[l] * a[k] * a[r]);
            }
        }
    }
    return dp[0][n + 1];                       // O(n^3) time, O(n^2) space
}

Other interval DPs: Matrix Chain Multiplication (dp[i][j] = min over k of dp[i][k] + dp[k+1][j] + cost), minimum cost to cut a stick, palindrome partitioning II, and the longest palindromic subsequence from the previous article. Typical complexity is O(n³).

3. DP on trees: House Robber III

The state belongs to a tree node. Run a post-order DFS and let each call return a small array of answers for its subtree. In House Robber III you cannot rob a parent and its child; each node returns {best if robbed, best if not robbed}.

public int rob(TreeNode root) {
    int[] r = dfs(root);
    return Math.max(r[0], r[1]);
}

// returns {robThisNode, skipThisNode}
private int[] dfs(TreeNode node) {
    if (node == null) return new int[]{0, 0};
    int[] left = dfs(node.left);
    int[] right = dfs(node.right);
    int rob = node.val + left[1] + right[1];                       // children must be skipped
    int skip = Math.max(left[0], left[1]) + Math.max(right[0], right[1]);
    return new int[]{rob, skip};               // O(n) time, O(h) recursion space
}

Same shape: diameter of a binary tree, maximum path sum, and binary tree cameras (three states per node). Remember that TreeNode is the LeetCode class; define it yourself when running locally.

4. Bitmask DP (idea)

When you must remember which of up to about 20 items have been used, encode the set as an int mask: bit i set means item i is used. The state is dp[mask][last]. For the travelling salesman problem, dp[mask][i] = shortest path that visits exactly the cities in mask and ends at city i; the transition adds one unvisited city: dp[mask | (1 << j)][j] = min(..., dp[mask][i] + dist[i][j]). There are 2n·n states and each has n transitions, so O(2n·n²) time. It is feasible for n up to about 20 and shows up in "assign tasks to workers", "smallest sufficient team", and "partition into k equal subsets".

DP pitfalls and a debugging checklist

Most wrong DP answers come from the same five places: base cases, iteration order, integer overflow, the memo's "not computed" marker, and recursion depth — check them in that order.

When a DP solution fails, the idea is usually fine and the setup is wrong. Go through this list before rewriting anything.

1. Wrong or missing base cases

Ask: "what is the answer for the empty input?" and "what is the answer for the smallest non-empty input?". Typical errors: counting problems need dp[0] = 1 (one way to make nothing), while min-cost problems need dp[0] = 0 and everything else "infinity". Edit distance needs dp[i][0] = i, not 0. Maximum problems with negative numbers cannot start from 0 either: use the first element or Integer.MIN_VALUE.

2. Wrong iteration order

A cell must be computed after every cell it reads. Rules of thumb:

  • Prefix DP and grid DP: increasing indexes.
  • Interval DP: increasing length, or i descending with j ascending.
  • 0/1 knapsack in 1D: capacity descending. Unbounded: ascending.
  • Coin change II: coins in the outer loop (combinations); swapping the loops counts permutations.

3. Using int where long is needed

Counting DPs grow fast: unique paths on a 30 × 30 grid is already above 1016, which overflows int (max about 2.1 × 109). Java does not throw on overflow; it wraps silently to negative numbers. Also watch "infinity": Integer.MAX_VALUE + 1 becomes the most negative int. Use a safe sentinel such as amount + 1 (coin change), or Integer.MAX_VALUE / 2, or check dp[x] != INF before adding.

Wrong: infinity overflows

int INF = Integer.MAX_VALUE;
dp[w] = Math.min(dp[w], dp[w - c] + 1);   // INF + 1 becomes negative!

Right: skip unreachable states

if (dp[w - c] != INF) {
    dp[w] = Math.min(dp[w], dp[w - c] + 1);
}

When the problem says "return the answer modulo 109 + 7", apply % MOD after every addition and use long for products.

4. Memo array initial values

In top-down DP the memo needs a marker for "not computed yet". If valid answers can be 0, then new int[n] (all zeros) cannot tell "computed as 0" from "not computed" and you recompute forever, which turns O(n·m) back into exponential. Fill with -1 (Arrays.fill, or in a loop for 2D arrays), or use Integer objects and test for null. If answers can be negative, pick a different marker or a parallel boolean[] seen.

int[][] memo = new int[m][n];
for (int[] row : memo) java.util.Arrays.fill(row, -1);   // -1 = not computed
// in the recursion:  if (memo[i][j] != -1) return memo[i][j];

5. Recursion depth

Top-down DP on a linear state with n = 105 or more nests that many calls and ends in StackOverflowError; the default Java stack handles roughly ten thousand frames for a simple method (the exact limit depends on frame size and JVM settings). Fix: convert to bottom-up, or run the solver in a Thread with a bigger stack size as a last resort in contests. For n up to about a thousand, recursion is fine.

6. Other classic slips

  • Answer in the wrong place: LIS and longest-common-substring answers are the max over all cells, not the last cell.
  • Mutating shared state: reusing the input as the table, then needing the original values later.
  • Off-by-one between 0-indexed strings and 1-indexed tables: use charAt(i - 1).
  • Aliasing in 2D memo: Arrays.fill(memo, new int[n]) fills every row with the same array.
  • Greedy by mistake: if "take the best-looking choice" fails on a small example, you need DP.

Debugging routine

  1. Write the brute-force recursion and check it on tiny inputs.
  2. Print the DP table for a 3-4 element example and compare it by hand with the recursion.
  3. Check base rows and columns first, then the first interior cell, then the last.
  4. Test the extremes: empty input, one element, all equal, all negative, the largest allowed n.

Interview angle

After you finish a DP, say out loud: "base cases are..., order is... because..., answer is at..., complexity O(...)". It shows the interviewer you check the places where DP usually breaks.
