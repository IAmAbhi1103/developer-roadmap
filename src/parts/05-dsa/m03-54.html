Tries: TrieNode, insert, search and startsWith

A trie (prefix tree) stores strings character by character along tree edges, so insert, search and prefix checks cost O(L) for a word of length L, independent of how many words are stored.

Suppose you store a dictionary of words and keep getting questions like "is app a word?" and "does any word start with app?". A HashSet<String> answers the first in O(L) (hashing reads the string) but cannot answer the second without scanning every word. A trie (say "try", from retrieval) answers both in O(L). The root is empty; each edge is a character; a node is marked when a word ends there. All words that share a prefix share the same path.

Implement Trie (LeetCode 208)

Three methods: insert(word), search(word) (the exact word was inserted) and startsWith(prefix) (some inserted word begins with it). Both lookups walk the same path; the only difference is the final check, "is the end flag set".

class Trie {
    private static class Node {
        Node[] next = new Node[26];            // children for 'a'..'z'
        boolean isWord;                        // a word ends at this node
    }

    private final Node root = new Node();

    public void insert(String word) {
        Node cur = root;
        for (int i = 0; i < word.length(); i++) {
            int idx = word.charAt(i) - 'a';
            if (cur.next[idx] == null) cur.next[idx] = new Node();
            cur = cur.next[idx];
        }
        cur.isWord = true;
    }

    public boolean search(String word) {
        Node node = find(word);
        return node != null && node.isWord;    // path exists AND a word ends here
    }

    public boolean startsWith(String prefix) {
        return find(prefix) != null;           // path exists
    }

    private Node find(String s) {              // follow the path, or null if it breaks
        Node cur = root;
        for (int i = 0; i < s.length(); i++) {
            cur = cur.next[s.charAt(i) - 'a'];
            if (cur == null) return null;
        }
        return cur;
    }
}

Example: after inserting "apple", search("apple") is true, search("app") is false (the path exists but no word ends at the second p), and startsWith("app") is true. Inserting "app" then makes search("app") true.

Complexity: insert, search and startsWith are each O(L). Space is O(total characters × alphabet size) in the worst case for the array version — up to 26 references per node.

A HashMap-based node

import java.util.HashMap;
import java.util.Map;

class TrieMap {
    private static class Node {
        Map<Character, Node> next = new HashMap<>();
        boolean isWord;
    }
    private final Node root = new Node();

    public void insert(String word) {
        Node cur = root;
        for (char ch : word.toCharArray()) {
            cur = cur.next.computeIfAbsent(ch, k -> new Node());   // create when missing
        }
        cur.isWord = true;
    }
    // search and startsWith follow the same path with cur.next.get(ch)
}

Useful extras on a node

  • Count of words through a node (int pass, incremented on insert): answers "how many words start with this prefix" in O(L).
  • Store the whole word at the end node (String word): lets a DFS collect words without rebuilding the string, as in Word Search II.
  • Frequency or score: for autocomplete ranking.

Delete (brief)

Deleting a word is done recursively. Walk to the end of the word and clear isWord. On the way back up, remove a child link only if that child has no children and is not the end of another word. Many interview problems skip deletion; a simpler approach is to clear only the flag and leave the nodes in place.

// inside class Trie (Node as above); returns true if the caller should unlink this node
private boolean delete(Node node, String word, int depth) {
    if (depth == word.length()) {
        if (!node.isWord) return false;        // the word was never stored
        node.isWord = false;
        return isEmpty(node);                  // unlink only if no children remain
    }
    int idx = word.charAt(depth) - 'a';
    Node child = node.next[idx];
    if (child == null) return false;           // path missing: nothing to delete
    boolean unlink = delete(child, word, depth + 1);
    if (unlink) {
        node.next[idx] = null;
        return !node.isWord && isEmpty(node);   // keep going up while nodes are useless
    }
    return false;
}

private boolean isEmpty(Node n) {
    for (Node c : n.next) if (c != null) return false;
    return true;
}

When to choose a trie

  • Many prefix queries on a fixed dictionary: autocomplete, spell check, IP routing tables (binary tries).
  • Problems that grow a candidate word letter by letter and want to cut off dead prefixes early (Word Search II).
  • Matching a pattern with wildcards over many words.

If only exact and prefix membership are needed and the data is small, a HashSet of prefixes is perfectly acceptable. Choose the trie when you need to walk the structure (listing, wildcards, pruning a search).

Common mistakes

  • Returning true from search when the path exists but isWord is false (it only holds a prefix of a stored word).
  • Using c - 'a' on uppercase letters or digits, which gives an index outside 0-25 and throws ArrayIndexOutOfBoundsException. Check the input alphabet.
  • Creating a new node on search or startsWith. Only insert may create nodes.

Interview angle

Expected: draw the tree for three words, name the end-of-word flag, give O(L) per operation, and explain array vs map children. A follow-up is the memory cost: 26 references per node is wasteful for sparse data, so use a map or compress single-child chains (a radix tree).

Trie problems: wildcard search, replace words, common prefix, autocomplete

Most trie problems are the basic trie plus one idea: branch at a wildcard, stop at the first end-of-word, stop where a node has several children, or DFS the subtree below a prefix.

All examples reuse the same node shape: Node[] next = new Node[26] and boolean isWord. Each snippet shows only what changes.

Design Add and Search Words (LeetCode 211)

addWord(word) as usual; search(word) where . matches any one letter. A normal letter follows one child; a . must try every child, so the search becomes a DFS with an index into the word.

class WordDictionary {
    private static class Node {
        Node[] next = new Node[26];
        boolean isWord;
    }
    private final Node root = new Node();

    public void addWord(String word) {
        Node cur = root;
        for (char ch : word.toCharArray()) {
            int i = ch - 'a';
            if (cur.next[i] == null) cur.next[i] = new Node();
            cur = cur.next[i];
        }
        cur.isWord = true;
    }

    public boolean search(String word) {
        return dfs(root, word, 0);
    }

    private boolean dfs(Node node, String word, int pos) {
        if (node == null) return false;
        if (pos == word.length()) return node.isWord;
        char ch = word.charAt(pos);
        if (ch != '.') {
            return dfs(node.next[ch - 'a'], word, pos + 1);
        }
        for (Node child : node.next) {         // wildcard: try every existing child
            if (child != null && dfs(child, word, pos + 1)) return true;
        }
        return false;
    }
}

Complexity: addWord is O(L). search is O(L) without wildcards; with wildcards the worst case is O(26L) in theory, but bounded in practice by the number of nodes in the trie, so about O(total characters stored).

Replace Words (LeetCode 648)

Given a dictionary of roots (cat, bat, rat) and a sentence, replace every word by the shortest root that is its prefix. Insert the roots; for each word walk down and stop at the first node where isWord is true.

public String replaceWords(java.util.List<String> dictionary, String sentence) {
    Trie trie = new Trie();                    // Trie from the previous article
    for (String root : dictionary) trie.insert(root);
    StringBuilder out = new StringBuilder();
    for (String word : sentence.split(" ")) {
        if (out.length() > 0) out.append(' ');
        out.append(trie.shortestRoot(word));
    }
    return out.toString();
}

// add inside class Trie:
String shortestRoot(String word) {
    Node cur = root;
    for (int i = 0; i < word.length(); i++) {
        cur = cur.next[word.charAt(i) - 'a'];
        if (cur == null) return word;          // no root is a prefix: keep the word
        if (cur.isWord) return word.substring(0, i + 1);   // first (shortest) root
    }
    return word;
}

For "the cattle was rattled by the battery" with roots cat, bat, rat, the result is "the cat was rat by the bat". Complexity: O(total dictionary characters + sentence length).

Longest Common Prefix with a trie

The simple solution compares strings (O(total characters) with no trie). With a trie the common prefix is the path from the root that has exactly one child at every step and is not a word end. It is a good way to understand tries; for the single-query problem the plain loop is better.

// after inserting every string into the trie:
public String commonPrefix() {
    StringBuilder sb = new StringBuilder();
    Node cur = root;
    while (true) {
        int children = 0, only = -1;
        for (int i = 0; i < 26; i++) {
            if (cur.next[i] != null) { children++; only = i; }
        }
        if (children != 1 || cur.isWord) break;   // a branch or a word end stops the prefix
        sb.append((char) ('a' + only));
        cur = cur.next[only];
    }
    return sb.toString();
}

Plain alternative: take the first string as the prefix and shorten it until every other string startsWith it. O(S) time where S is the total number of characters, O(1) extra space.

Autocomplete: words with a prefix

Walk down the prefix, then DFS the subtree to collect words. Store a count or a ranking on end nodes to return the top suggestions (Design Search Autocomplete System uses the number of times a sentence was typed).

public java.util.List<String> withPrefix(String prefix) {
    java.util.List<String> result = new java.util.ArrayList<>();
    Node cur = root;
    for (char ch : prefix.toCharArray()) {
        cur = cur.next[ch - 'a'];
        if (cur == null) return result;        // no word has this prefix
    }
    collect(cur, new StringBuilder(prefix), result);
    return result;
}

private void collect(Node node, StringBuilder path, java.util.List<String> out) {
    if (node.isWord) out.add(path.toString());
    for (int i = 0; i < 26; i++) {
        if (node.next[i] != null) {
            path.append((char) ('a' + i));     // choose
            collect(node.next[i], path, out);
            path.deleteCharAt(path.length() - 1);   // un-choose (backtracking)
        }
    }
}

Because children are visited in letter order, the results are in alphabetical order. For a real product, cache the top-k suggestions on each node, update them on insert, and rank by frequency; large systems also shard the trie. That design discussion belongs to system design; here the trie is the in-memory index.

Other prefix problems

  • Map Sum Pairs: store a value at the end node and keep a running sum on each node along the path, or DFS the subtree.
  • Maximum XOR of two numbers: a binary trie over the 31 bits; for each number, walk preferring the opposite bit. O(31·n).
  • Longest Word in Dictionary: insert all words and DFS only through nodes that are word ends.
  • Search Suggestions System: sort the products, then binary search for the prefix; or use a trie with up to three suggestions per node.

Recognising a trie problem

Look for: a dictionary of words plus prefix queries; a search that builds a word one letter at a time and can be cut off when no word has that prefix; or a bit-by-bit choice over integers (XOR). If there are only a few exact lookups, a HashSet is simpler.

Dry run: wildcard search

Add bad, dad and mad to a WordDictionary. The root has three children: b, d and m; each leads through a to d, which is a word end. Now search b.d.

  1. dfs(root, "b.d", 0): b is a normal letter, so follow the single child b.
  2. At position 1 the character is .. Try every child of this node. Only a exists, so call dfs(a-node, "b.d", 2).
  3. At position 2 the character is d; follow that child. Now pos == word.length(), and isWord is true there, so the answer is true.

Search .ad instead: at position 0 the wildcard tries b, d and m in turn, and the first branch already succeeds. Search b..d: the path breaks because a word of length 4 does not exist, and the recursion returns false when a child is missing or the end flag is not set. Searching . alone returns false unless the dictionary has a one-letter word.

Map Sum Pairs: a running sum on every node

Insert key-value pairs, then return the sum of the values of all keys with a given prefix. Store a sum on every node of a key's path. When a key is inserted again, add only the difference from its old value, so keep a side map of current values.

class MapSum {
    private static class Node {
        Node[] next = new Node[26];
        int sum;                               // sum of values of all keys through this node
    }
    private final Node root = new Node();
    private final java.util.Map<String, Integer> values = new java.util.HashMap<>();

    public void insert(String key, int val) {
        int delta = val - values.getOrDefault(key, 0);   // re-inserting overwrites the old value
        values.put(key, val);
        Node cur = root;
        for (char ch : key.toCharArray()) {
            int i = ch - 'a';
            if (cur.next[i] == null) cur.next[i] = new Node();
            cur = cur.next[i];
            cur.sum += delta;
        }
    }

    public int sum(String prefix) {
        Node cur = root;
        for (char ch : prefix.toCharArray()) {
            cur = cur.next[ch - 'a'];
            if (cur == null) return 0;         // no key has this prefix
        }
        return cur.sum;                        // O(L) per query
    }
}

Insert ("apple", 3), then ("app", 2): sum("ap") is 5. Insert ("apple", 5) again: the delta is 2, so sum("ap") becomes 7.

Maximum XOR of two numbers: a binary trie

Treat each non-negative int as a string of 31 bits and insert it into a trie with only two children per node (0 and 1). For each number, walk down from the top bit and at every level prefer the child with the opposite bit, because a 1 in a higher position beats any combination of lower bits. The path you follow is the number that gives the largest XOR with the current one. Total time is O(31 · n).

public int findMaximumXOR(int[] nums) {
    int[][] next = new int[nums.length * 31 + 1][2];   // next[node][bit]; 0 means "no child"
    int nodes = 1;                                     // node 0 is the root and never a child
    for (int x : nums) {
        int cur = 0;
        for (int b = 30; b >= 0; b--) {
            int bit = (x >> b) & 1;
            if (next[cur][bit] == 0) next[cur][bit] = nodes++;
            cur = next[cur][bit];
        }
    }
    int best = 0;
    for (int x : nums) {
        int cur = 0, val = 0;
        for (int b = 30; b >= 0; b--) {
            int bit = (x >> b) & 1;
            int want = bit ^ 1;                        // the opposite bit gives a 1 in the XOR
            if (next[cur][want] != 0) {
                val |= 1 << b;
                cur = next[cur][want];
            } else {
                cur = next[cur][bit];                  // forced: only the same bit exists
            }
        }
        best = Math.max(best, val);
    }
    return best;
}
// [3, 10, 5, 25, 2, 8] gives 28, from 5 XOR 25

An array-based trie like this one avoids creating thousands of node objects and is faster in Java, at the cost of readability.

Edge cases

  • Empty word or prefix: startsWith("") is true when the trie is not empty (the root exists), and search("") is true only if the empty string was inserted. Decide what the problem wants.
  • A word that is a prefix of another ("app" and "apple"): the common-prefix loop must stop at the end flag, which is why it checks cur.isWord.
  • Wildcard at the end or only wildcards: the DFS still works, since it ends with a check of isWord at depth equal to the length.
  • Characters outside a–z: ch - 'a' gives a bad index and ArrayIndexOutOfBoundsException. Validate, or use a HashMap node.
  • Overwriting a key in Map Sum: add the difference, never the new value again.

Mistake: forgetting to undo the choice in the autocomplete DFS

Wrong: the path keeps growing

path.append((char) ('a' + i));
collect(node.next[i], path, out);
// no deleteCharAt: later words get extra letters

Right: choose, explore, un-choose

path.append((char) ('a' + i));
collect(node.next[i], path, out);
path.deleteCharAt(path.length() - 1);

Interview angle

Add and Search Words is the common one: say that exact letters follow one edge, a wildcard fans out to all children, and give the worst case honestly (bounded by the size of the trie). For autocomplete, expect the design follow-up: store the top three suggestions on each node, or sort candidates by frequency. For Maximum XOR, explain "opposite bit first, greedy from the top bit" and why a higher bit always outweighs all lower bits.

Word Search II: trie plus backtracking

Word Search II searches for many words in one grid by putting all words in a trie and running one DFS from each cell, walking the trie in step with the grid, so dead prefixes are cut off at once.

Problem (LeetCode 212): given a grid of letters and a list of words, return all words that can be formed by walking through adjacent cells (up, down, left, right) without reusing a cell within one word. The earlier Word Search problem handles one word; running it once per word is far too slow for many words, because each run repeats work on shared prefixes.

The idea

  1. Insert every word in a trie. Store the full word in the node where it ends (node.word), so no path rebuilding is needed.
  2. For each cell, start a DFS with the trie root. At each step move into the child for the cell's letter. If there is no such child, no word has this prefix: stop immediately.
  3. If the new node has a word, add it to the result and clear it (node.word = null) so the same word is not reported twice.
  4. Mark the cell as visited while exploring its neighbours, then restore it (the usual backtracking step).

Java solution

import java.util.ArrayList;
import java.util.List;

class Solution {
    private static class Node {
        Node[] next = new Node[26];
        String word;                           // non-null when a word ends here
    }

    public List<String> findWords(char[][] board, String[] words) {
        Node root = new Node();
        for (String w : words) {               // build the trie
            Node cur = root;
            for (char ch : w.toCharArray()) {
                int i = ch - 'a';
                if (cur.next[i] == null) cur.next[i] = new Node();
                cur = cur.next[i];
            }
            cur.word = w;
        }
        List<String> result = new ArrayList<>();
        for (int r = 0; r < board.length; r++) {
            for (int c = 0; c < board[0].length; c++) {
                dfs(board, r, c, root, result);
            }
        }
        return result;
    }

    private void dfs(char[][] b, int r, int c, Node parent, List<String> result) {
        char ch = b[r][c];
        if (ch == '#') return;                 // already used on this path
        Node node = parent.next[ch - 'a'];
        if (node == null) return;              // no word has this prefix: prune
        if (node.word != null) {
            result.add(node.word);
            node.word = null;                  // avoid duplicates
        }
        b[r][c] = '#';                         // mark visited
        if (r > 0) dfs(b, r - 1, c, node, result);
        if (c > 0) dfs(b, r, c - 1, node, result);
        if (r < b.length - 1) dfs(b, r + 1, c, node, result);
        if (c < b[0].length - 1) dfs(b, r, c + 1, node, result);
        b[r][c] = ch;                          // restore (backtrack)
    }
}

With the grid above and words ["oath", "pea", "eat", "rain"] the result is ["oath", "eat"] (in discovery order).

Complexity

Let M × N be the grid and L the longest word. Each DFS can go at most L deep and branches into at most 3 new directions after the first step, so the worst case is about O(M·N·4·3L-1). The trie makes the real cost much smaller, because the walk stops where no word continues. Space: the trie takes O(total characters of all words) nodes, plus O(L) recursion depth.

Optimisation: prune empty branches

Once a word is found, its nodes may be useless. If a node has no children and no word, remove it from its parent, so later DFS calls stop earlier. This matters for tests with large grids of one repeated letter. A simple way is to keep a child counter and unlink on the way back:

// at the end of dfs, after restoring the cell:
if (isLeafWithoutWord(node)) {
    parent.next[ch - 'a'] = null;              // nothing left below this node
}
// isLeafWithoutWord: node.word == null and all node.next[i] are null
// (use a "childCount" field to make this check O(1))

Mistakes in this problem

  • Searching word by word (a new DFS per word): works on small inputs and times out otherwise.
  • Forgetting to restore b[r][c] after the recursive calls, which corrupts the grid for other paths.
  • Not clearing node.word, so a word reachable in two ways appears twice in the output.
  • Using a String path built by concatenation at every step; store the word in the node instead.

Why the trie helps

Word Search I tries to match one word. If you run it for each of w words, a prefix such as "oat" is walked again for "oath", "oats" and "oaten". The trie merges all words that share a prefix into one path, so a single walk through the grid tests all of them at once. More important, the walk stops the moment the current path is not a prefix of any word. Without the trie you would have to check each word separately to learn that a dead end is dead for all of them. The cost depends on the grid and the length of the words, not on how many words there are.

Dry run on a 2 × 2 grid

  1. Start at (0,0) o: the root has a child o, so go on. Mark the cell. Neighbours: up and left do not exist; down is e, but the o node has no child e, so return at once; right is a, which is a child.
  2. At (0,1) a: left (0,0) is marked #; down is (1,1) t, which is a child and carries the word "oat". Add "oat" to the result and set the field to null. Restore the cells on the way back.
  3. Start at (0,1) a: the root has no child a, so prune immediately. This is the saving: no word starts with a.
  4. Start at (1,0) e: the root has a child e. Its neighbours are (0,0) o and (1,1) t. The e node has only the child a, so both fail.
  5. Start at (1,1) t: no word starts with t.

The result is ["oat"]. "eat" is not found because its a at (0,1) is diagonal to the e at (1,0); moves are only up, down, left and right.

Pruning with a leaf check, in code

The version above never removes nodes. With many words and a grid of repeated letters, the DFS keeps walking branches whose words were already found. Removing a node once its subtree is empty fixes this. Here is the DFS with the pruning in place (the trie building and the outer loop are the same).

private void dfs(char[][] b, int r, int c, Node parent, List<String> result) {
    char ch = b[r][c];
    if (ch == '#') return;                     // used on the current path
    int idx = ch - 'a';
    Node node = parent.next[idx];
    if (node == null) return;                  // no word has this prefix
    if (node.word != null) {
        result.add(node.word);
        node.word = null;                      // report each word once
    }
    b[r][c] = '#';
    if (r > 0) dfs(b, r - 1, c, node, result);
    if (c > 0) dfs(b, r, c - 1, node, result);
    if (r < b.length - 1) dfs(b, r + 1, c, node, result);
    if (c < b[0].length - 1) dfs(b, r, c + 1, node, result);
    b[r][c] = ch;                              // backtrack
    if (node.word == null && isLeaf(node)) {
        parent.next[idx] = null;               // this branch can never produce a word again
    }
}

private boolean isLeaf(Node n) {
    for (Node child : n.next) if (child != null) return false;
    return true;                               // keep a childCount field to make this O(1)
}

The pruning is done after restoring the cell, so the board is never left corrupted. Because the pruned node's parent may then also become a leaf, the effect travels up the recursion: a path that only led to found words disappears completely.

Edge cases

  • Duplicate words in the list: both inserts reach the same end node, and node.word = null after the first find means the word is reported once.
  • A word longer than the number of cells can never be found; the DFS dies out without an error.
  • 1 × 1 board: the neighbour checks (r > 0, r < b.length - 1) all fail and only a one-letter word can match.
  • The sentinel '#' works because the letters are lowercase; if the board can contain '#', use a boolean[][] visited instead.
  • Words that are prefixes of each other ("oa" and "oath"): the end flag is on the inner node, and the DFS reports "oa" and keeps going to look for "oath".
  • Recursion depth is at most the longest word, which is short in the usual constraints, so StackOverflowError is not a concern.

Mistake: checking the end flag before moving into the child

Wrong: the word check is one step late

if (parent.word != null) { result.add(parent.word); }   // parent, not node
Node node = parent.next[ch - 'a'];
if (node == null) return;
// a one-letter word on the last cell is never added

Right: move first, then test the new node

Node node = parent.next[ch - 'a'];
if (node == null) return;
if (node.word != null) { result.add(node.word); node.word = null; }

Interview angle

The interviewer wants to hear "one trie, one DFS, prune when the prefix is missing". Say why the trie helps: all words sharing a prefix are explored together, and a failed prefix cuts off every word below it. Compare it with the one-word-at-a-time approach and state the complexity honestly as exponential in the word length.

Interview questions — Dynamic programming and tries

How do you recognise a dynamic programming problem?

Look for two properties: overlapping subproblems (the same smaller question is asked many times) and optimal substructure (the best answer is built from best answers of smaller parts). Typical wording: "minimum/maximum", "count the number of ways", "is it possible", over choices, with a brute force that tries all subsets or paths. If greedy fails on a small counter-example, DP is the usual next step.

What is the difference between memoization and tabulation?

Memoization is top-down: write the recursion and cache each result so it is computed once. It only visits states that are reachable and is easy to write, but uses recursion depth. Tabulation is bottom-up: fill a table from the base cases in an order that satisfies dependencies. It has no stack risk and allows space optimisation (rolling rows). Both have the same time complexity for the same state space.

Walk me through the steps for solving any DP problem.

Define the state precisely ("dp[i] = ..."), write the transition from smaller states, set the base cases, choose an iteration order so dependencies are ready, and say where the answer is (last cell, or max over cells). Then check complexity and see whether a row or two variables are enough.

Why does the 1D 0/1 knapsack loop run from high capacity to low?

Because dp[w] must read dp[w - wt] from the previous item's row. A forward loop would already have updated dp[w - wt] for the current item, so the item could be used several times. Backward iteration keeps the lower cells untouched. Unbounded knapsack wants reuse, so it goes forward.

for (int w = W; w >= wt; w--) dp[w] = Math.max(dp[w], dp[w - wt] + val);
In Coin Change II, why must the coin loop be outside?

With coins outside and amounts inside, each coin is "introduced" once, so each combination is counted in one fixed order: it counts combinations. Swapping the loops lets any coin follow any other at each amount, so 1+2 and 2+1 both count: it counts permutations (that is the Combination Sum IV problem).

Explain the O(n log n) LIS algorithm. Is the tails array the LIS?

tails[k] is the smallest possible last value of an increasing subsequence of length k+1. It stays sorted. For each number, binary search the first tail that is at least as large (for strict increase) and replace it; if none exists, append. The length of the array is the LIS length, but the array itself is not necessarily a real subsequence. Time O(n log n), space O(n).

Longest common subsequence versus longest common substring: what changes in the DP?

Both use dp[i][j] over prefixes and extend the diagonal on a match. For the subsequence, a mismatch takes max(up, left) and the answer is the last cell. For the substring, a mismatch resets the cell to 0 (the run is broken) and the answer is the maximum over the whole table.

How do you reconstruct the LCS string, not just its length?

Keep the full table. Start at dp[m][n]. If the two characters match, add the character and go diagonally. Otherwise move to the neighbour (up or left) with the larger value. The characters come out reversed, so reverse the result. The two-row space optimisation cannot do this.

Explain the three moves in edit distance.

If the last characters match, take dp[i-1][j-1]. Otherwise 1 plus the minimum of the diagonal (replace), the cell above (delete from the first word) and the cell to the left (insert into the first word). Base cases: dp[i][0] = i and dp[0][j] = j. O(m·n) time.

How do you find the longest palindromic substring, and what is its complexity?

Expand around each of the 2n-1 centres (n single characters and n-1 gaps), growing while the ends match, and track the best. That is O(n²) time and O(1) space. A DP table isPal[i][j] gives the same time but O(n²) space. Manacher's algorithm reaches O(n) but is rarely expected.

How is the longest palindromic subsequence related to LCS?

It equals the LCS of the string and its reverse, because a palindrome reads the same both ways. The minimum number of insertions to make a string a palindrome is then n - LPS.

Why can a DP on a 40 × 40 grid of path counts give a negative number?

The counts exceed the range of int (about 2.1 billion) and Java wraps around silently instead of throwing. Use long, or take the result modulo the value the problem gives, applying the modulo after every addition. Similar bugs come from adding 1 to Integer.MAX_VALUE used as infinity.

What is a trie and when would you use it instead of a HashSet?

A trie stores words along a tree of characters, with an end-of-word flag. Insert, search and startsWith are O(L). Use it when you need prefix queries, listing all words under a prefix, wildcard search, or pruning a search once no word has the current prefix. A HashSet is simpler for exact lookups only.

Why does Word Search II use a trie instead of searching each word separately?

One DFS over the grid, guided by the trie, searches all words at once and shares work between words with the same prefix. When the next letter has no trie child, the DFS stops, which prunes whole groups of words. Searching word by word repeats the same grid walks and is too slow for large word lists.

Compare TrieNode[26] and HashMap children.

The array gives O(1) indexed access with no hashing, but uses 26 references per node even when sparse. A map uses memory only for existing children and handles any alphabet, but each access costs more. For lowercase interview problems use the array; for Unicode or mixed content use a map.

Cheat sheet — Dynamic programming and tries

  • DP = recursion + cache overlapping subproblems and optimal substructure; same answer asked many times.
  • Five questions state, transition, base cases, iteration order, where the answer is.
  • Memo vs table memo is top-down and lazy; the table is bottom-up and allows rolling arrays.
  • 1D prefix DP dp[i] = f(dp[i-1], dp[i-2]) becomes two variables; for example house robber max(dp[i-1], dp[i-2] + x).
  • Coin change (min) dp[0] = 0, others amount + 1; dp[a] = min(dp[a-c] + 1).
  • Coin change II (ways) coins outer, amounts inner, dp[a] += dp[a-c]; swap loops and you count permutations.
  • LIS O(n²): dp[i] ends at i, answer is the max. O(n log n): tails array plus lower bound (strict).
  • Grid DP dp[r][c] from up and left; fill the first row and column or pad with zeros; shrink to one row.
  • Maximal square 1 + min(up, left, up-left) on cells that are 1.
  • 0/1 knapsack 1D capacity loop from high to low; each item used once.
  • Unbounded knapsack capacity loop from low to high; unlimited use (rod cutting, coin change).
  • Subset sum family dp[0] = true or 1; partition needs an even total; target sum: P = (total + target) / 2.
  • LCS match: diagonal + 1; else max(up, left); answer in the corner; walk back to rebuild the string.
  • Longest common substring mismatch resets to 0; the answer is the maximum cell.
  • Edit distance match: diagonal; else 1 + min(replace, delete, insert); base dp[i][0] = i.
  • Palindromes expand around 2n-1 centres for substrings; LPS = LCS(s, reverse s); interval DP loops i downwards.
  • Other shapes stock states, interval DP by length, tree DP returning a pair, bitmask DP for n up to about 20.
  • Pitfalls base cases, loop order, long for counts and a safe infinity, memo marker -1, recursion depth.
  • Trie node = children + end flag; insert/search/startsWith O(L); search checks the flag, startsWith does not.
  • Wildcard trie search on . loop over all children with DFS.
  • Word Search II trie of words, DFS from each cell, prune on a missing child, store the word at the end node, null it after finding it.
  • Trie vs HashSet the trie wins for listing, wildcards and pruning; the HashSet wins for simplicity.
