Write from memory (1): binary search, lower bound, merge sort, partition

Four short routines appear inside dozens of problems; learn each one until you can type it without thinking, with the loop bounds and the update rules correct.

A template is not for copy-pasting; it is a small program you can write in two minutes while explaining it. Bugs in these routines are almost always off-by-one errors in the bounds, so each template below states its invariant (the sentence that is true at every loop step). If you remember the invariant, the code follows.

Binary search (exact match)

Invariant: if the target exists, it is inside [lo, hi] (both ends included).

static int binarySearch(int[] a, int target) {
    int lo = 0, hi = a.length - 1;
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;          // never (lo + hi) / 2: it can overflow
        if (a[mid] == target) return mid;
        if (a[mid] < target) lo = mid + 1;
        else hi = mid - 1;
    }
    return -1;                                 // O(log n) time, O(1) space
}

Lower bound and upper bound

Lower bound = the first index with a[i] >= target. Upper bound = the first index with a[i] > target. Both return n if no such index exists. Invariant: the answer is inside [lo, hi], where hi = n is allowed, and the loop uses lo < hi. This one routine solves "first occurrence", "last occurrence" (upper bound minus 1), "count of x" (upper minus lower), "insert position" and, with a predicate, "binary search on the answer".

static int lowerBound(int[] a, int target) {    // first i with a[i] >= target
    int lo = 0, hi = a.length;                  // hi = n: "not found" is a valid answer
    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;
        if (a[mid] < target) lo = mid + 1;      // mid is too small: answer is to the right
        else hi = mid;                          // mid might be the answer: keep it
    }
    return lo;
}

static int upperBound(int[] a, int target) {    // first i with a[i] > target
    int lo = 0, hi = a.length;
    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;
        if (a[mid] <= target) lo = mid + 1;    // the only change: <= instead of <
        else hi = mid;
    }
    return lo;
}
// count of target = upperBound(a, t) - lowerBound(a, t)
// smallest x in [lo, hi] for which feasible(x) is true (feasible is false...true)
static int firstTrue(int lo, int hi, java.util.function.IntPredicate feasible) {
    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;
        if (feasible.test(mid)) hi = mid;      // mid works: try smaller
        else lo = mid + 1;                     // mid fails: need bigger
    }
    return lo;                                 // assumes the answer exists in [lo, hi]
}

Merge sort

Split in half, sort each half, merge two sorted halves. Invariant: after sort(lo, hi), the range [lo, hi) is sorted. Use <= when taking from the left half to keep the sort stable.

static void mergeSort(int[] a) {
    mergeSort(a, new int[a.length], 0, a.length);
}

private static void mergeSort(int[] a, int[] tmp, int lo, int hi) {   // sorts [lo, hi)
    if (hi - lo < 2) return;                   // 0 or 1 element is already sorted
    int mid = lo + (hi - lo) / 2;
    mergeSort(a, tmp, lo, mid);
    mergeSort(a, tmp, mid, hi);
    int i = lo, j = mid, k = lo;
    while (i < mid && j < hi) {
        tmp[k++] = (a[i] <= a[j]) ? a[i++] : a[j++];   // <= keeps equal items in order
    }
    while (i < mid) tmp[k++] = a[i++];
    while (j < hi)  tmp[k++] = a[j++];
    System.arraycopy(tmp, lo, a, lo, hi - lo);
}
// O(n log n) time in every case, O(n) extra space, stable

The same split-and-merge skeleton counts inversions (count pairs while merging) and solves "count of smaller numbers after self" and "reverse pairs".

Quick sort partition and quickselect

Lomuto partition: pick the last element as pivot; i marks the end of the "smaller than pivot" zone. Invariant: a[lo..i-1] < pivot, a[i..j-1] >= pivot.

static void quickSort(int[] a, int lo, int hi) {         // sorts [lo, hi] inclusive
    if (lo >= hi) return;
    int p = partition(a, lo, hi);
    quickSort(a, lo, p - 1);
    quickSort(a, p + 1, hi);
}

static int partition(int[] a, int lo, int hi) {
    int r = lo + (int) (Math.random() * (hi - lo + 1));  // random pivot avoids O(n^2) on sorted input
    swap(a, r, hi);
    int pivot = a[hi], i = lo;
    for (int j = lo; j < hi; j++) {
        if (a[j] < pivot) swap(a, i++, j);               // grow the "smaller" zone
    }
    swap(a, i, hi);                                      // pivot goes to its final place
    return i;
}

static void swap(int[] a, int x, int y) { int t = a[x]; a[x] = a[y]; a[y] = t; }

// Quickselect: k-th smallest (0-based k) in average O(n)
static int quickSelect(int[] a, int k) {
    int lo = 0, hi = a.length - 1;
    while (lo <= hi) {
        int p = partition(a, lo, hi);
        if (p == k) return a[p];
        if (p < k) lo = p + 1; else hi = p - 1;
    }
    return -1;                                 // not reached when 0 <= k < n
}

Complexity: quick sort is O(n log n) on average, O(n²) in the worst case (made unlikely by a random pivot), O(log n) expected stack, not stable. Quickselect is O(n) average, O(n²) worst. With many equal values Lomuto degrades; the three-way partition (Dutch national flag) fixes that.

Bugs I see most often

  • Mixing the two loop styles: lo <= hi with hi = mid never ends.
  • Computing (lo + hi) / 2 for large arrays: overflow gives a negative index.
  • Using lower bound's hi = n - 1 and then missing the "greater than all" answer.
  • Merge sort that allocates a new array in every call (correct but slow; pass one temp array).

Practice drill

On a blank sheet, write all four routines and test each with an empty array, one element, all equal, and the target smaller than everything and larger than everything.

Write from memory (2): BFS, DFS, Dijkstra, union-find, topological sort, a DP

These six templates cover most graph and DP problems; each is about ten to twenty lines, and the details to remember are the visited marking, the queue discipline and the loop order.

All graph templates use an adjacency list List<List<Integer>> g (or List<int[]> for weighted edges) with nodes numbered 0..n-1. Imports: java.util.*.

BFS (shortest path in an unweighted graph)

Mark a node when you add it to the queue, not when you remove it; otherwise a node can be queued many times.

static int[] bfs(List<List<Integer>> g, int src) {
    int[] dist = new int[g.size()];
    Arrays.fill(dist, -1);                     // -1 = not visited
    Deque<Integer> q = new ArrayDeque<>();
    dist[src] = 0;
    q.add(src);
    while (!q.isEmpty()) {
        int u = q.poll();
        for (int v : g.get(u)) {
            if (dist[v] == -1) {               // first time we see v: this is the shortest way
                dist[v] = dist[u] + 1;
                q.add(v);
            }
        }
    }
    return dist;                               // O(V + E)
}
// Grid version: replace g.get(u) by the 4 neighbours (r+dr[k], c+dc[k]) inside the bounds.

DFS (recursive and iterative)

static void dfs(List<List<Integer>> g, int u, boolean[] seen) {
    seen[u] = true;
    for (int v : g.get(u)) {
        if (!seen[v]) dfs(g, v, seen);
    }
}

static void dfsIterative(List<List<Integer>> g, int src) {
    boolean[] seen = new boolean[g.size()];
    Deque<Integer> stack = new ArrayDeque<>();
    stack.push(src);
    while (!stack.isEmpty()) {
        int u = stack.pop();
        if (seen[u]) continue;                 // a node can be pushed twice; skip repeats
        seen[u] = true;
        for (int v : g.get(u)) {
            if (!seen[v]) stack.push(v);
        }
    }
}
// O(V + E). Use the iterative form when the depth can reach about 10^5.

Dijkstra

Edges are int[]{to, weight} with non-negative weights. The priority queue holds {node, distance}; when a stale entry is polled (its distance is worse than the best known), skip it. This is called lazy deletion.

static long[] dijkstra(List<List<int[]>> g, int src) {
    long[] dist = new long[g.size()];
    Arrays.fill(dist, Long.MAX_VALUE);
    dist[src] = 0;
    PriorityQueue<long[]> pq = new PriorityQueue<>((x, y) -> Long.compare(x[1], y[1]));
    pq.add(new long[]{src, 0});
    while (!pq.isEmpty()) {
        long[] top = pq.poll();
        int u = (int) top[0];
        if (top[1] > dist[u]) continue;        // stale entry: a shorter path was already found
        for (int[] e : g.get(u)) {
            int v = e[0];
            long nd = dist[u] + e[1];
            if (nd < dist[v]) {
                dist[v] = nd;
                pq.add(new long[]{v, nd});
            }
        }
    }
    return dist;                               // O((V + E) log V); unreachable stays Long.MAX_VALUE
}

The comparator uses Long.compare, not subtraction, to avoid overflow.

Union-find (DSU)

Path compression plus union by size gives almost constant time per operation (inverse Ackermann). union returns false when the two nodes are already connected, which is exactly the "cycle detected" signal.

static class UnionFind {
    int[] parent, size;
    int components;

    UnionFind(int n) {
        parent = new int[n];
        size = new int[n];
        components = n;
        for (int i = 0; i < n; i++) { parent[i] = i; size[i] = 1; }
    }

    int find(int x) {
        while (parent[x] != x) {
            parent[x] = parent[parent[x]];     // path halving: flatten as we climb
            x = parent[x];
        }
        return x;
    }

    boolean union(int a, int b) {
        int ra = find(a), rb = find(b);
        if (ra == rb) return false;            // already in the same set
        if (size[ra] < size[rb]) { int t = ra; ra = rb; rb = t; }
        parent[rb] = ra;                       // attach the smaller tree under the larger
        size[ra] += size[rb];
        components--;
        return true;
    }
}

Topological sort (Kahn's algorithm)

Count incoming edges (in-degree). Start with all nodes of in-degree 0; removing a node lowers its neighbours' in-degree. If fewer than n nodes come out, the graph has a cycle.

static int[] topoSort(int n, List<List<Integer>> g) {
    int[] indeg = new int[n];
    for (int u = 0; u < n; u++) for (int v : g.get(u)) indeg[v]++;
    Deque<Integer> q = new ArrayDeque<>();
    for (int i = 0; i < n; i++) if (indeg[i] == 0) q.add(i);
    int[] order = new int[n];
    int count = 0;
    while (!q.isEmpty()) {
        int u = q.poll();
        order[count++] = u;
        for (int v : g.get(u)) {
            if (--indeg[v] == 0) q.add(v);     // all prerequisites of v are done
        }
    }
    return count == n ? order : new int[0];    // empty array means a cycle; O(V + E)
}

A basic DP (coin change, minimum coins)

One DP you can write blind is enough to start any other: state, base, transition, order, answer.

static int coinChange(int[] coins, int amount) {
    int[] dp = new int[amount + 1];            // dp[a] = fewest coins to make amount a
    Arrays.fill(dp, amount + 1);               // amount + 1 acts as infinity (no overflow when +1)
    dp[0] = 0;                                 // zero coins make amount 0
    for (int a = 1; a <= amount; a++) {
        for (int c : coins) {
            if (c <= a) dp[a] = Math.min(dp[a], dp[a - c] + 1);
        }
    }
    return dp[amount] > amount ? -1 : dp[amount];   // O(amount * coins) time, O(amount) space
}

Template bugs to watch

  • BFS: marking visited when polling instead of when adding. It still gives answers, but the queue can grow to O(E) duplicates.
  • Dijkstra: using it with negative edges (wrong answers) or skipping the stale-entry check (slow).
  • Topological sort: forgetting the cycle check count == n.
  • Union-find: forgetting that find must be called on both inputs before comparing roots.

Interview angle

Interviewers often ask for one of these "from scratch" as a warm-up, and then ask you to adapt it (BFS with a state, Dijkstra with a stop limit). A clean template means all your time goes into the adaptation.
