IP addresses, MAC addresses and special addresses

An IPv4 address is a 32-bit logical address written as four decimal bytes, split into a network part and a host part by the subnet mask (CIDR prefix); a MAC address is the 48-bit hardware address of a network card, used only on the local link.

IPv4 address format

An IP address identifies a network interface so that packets can be routed to it. IPv4 addresses are 32 bits long, written as four numbers from 0 to 255 separated by dots (dotted decimal), each number being one byte (octet). Example: 192.168.10.77 is 11000000.10101000.00001010.01001101. There are 232 = 4,294,967,296 possible addresses, far fewer than the number of devices today. That shortage is why NAT and IPv6 exist (next articles).

Every IP address has two parts: the network ID (which network) and the host ID (which device inside it). Routers look only at the network part. The subnet mask tells where the split is: bits that are 1 in the mask belong to the network; bits that are 0 belong to the host.

Classful addressing (historical)

Early IPv4 fixed the split by the first bits of the address. This is now historical, but interviews still ask for it.

ClassFirst octetDefault maskHosts per network Use
A1–126255.0.0.0 (/8)16,777,214Very large networks

E240–255n/an/aReserved / experimental

Class A starts with bit 0, B with 10, C with 110, D with 1110. The first octet 127 is reserved for loopback, which is why class A shows 1–126. The problem: a company needing 300 addresses got a class B with 65,534, wasting thousands.

CIDR: classless addressing

CIDR (Classless Inter-Domain Routing, 1993) removed the fixed classes. Any prefix length from 0 to 32 is allowed and is written after a slash: 192.168.10.0/24 means the first 24 bits are the network. CIDR gives right-sized blocks and allows route aggregation (one routing entry for many networks), which keeps internet routing tables small.

The private range 172.16.0.0/12 covers 172.16.0.0 to 172.31.255.255 only. A common slip is to treat all of 172.x.x.x as private. Any address that is not private or special is a public address, unique across the internet and assigned through registries and ISPs.

Your Spring Boot app uses these every day. server.address=127.0.0.1 accepts connections only from the same machine, while binding to 0.0.0.0 accepts them from any interface. In Docker you must bind to 0.0.0.0 inside the container, or published ports will not reach the app.

MAC address vs IP address

A MAC address (Media Access Control) is a 48-bit address, written as six hex pairs such as 3C:22:FB:9A:10:E4. The first three bytes are the manufacturer's OUI; the rest identify the card. It is burned into the NIC by the maker (it can be overridden in software) and used only for delivery on the local link.

You need both because the IP address says where in the world the host is (routing needs the structure), and the MAC address says which card on this wire. ARP connects the two (article on ARP, DHCP and ICMP).

Static vs dynamic, public vs private

A static IP is configured by hand and never changes; servers use it. A dynamic IP is leased from a DHCP server and may change; laptops and phones use it. A cloud elastic IP is a public static address you attach to an instance.

Mistake: "my IP address" means one thing

A laptop at home has a private IP like 192.168.1.23, while websites see the public IP of your router (or your ISP's NAT). Searching "what is my IP" shows the public one; ipconfig (Windows) or ip addr (Linux) shows the private one.

Interview: "What is the difference between IP and MAC?"

  • Logical vs physical, layer 3 vs layer 2, end-to-end vs hop-by-hop.
  • IP changes when you change networks; MAC stays with the card.
  • Then add: ARP finds the MAC for a known IP on the local network.

Subnet masks and worked subnetting examples

Subnetting splits one network into smaller ones by moving the network/host border to the right; the network address is the IP ANDed with the mask, the broadcast address sets all host bits to 1, and usable hosts = 2h − 2 where h is the number of host bits.

Mask, prefix and host bits

A subnet mask is 32 bits: all 1s for the network part followed by all 0s for the host part. The prefix length is the count of 1s. So /26 = 26 ones + 6 zeros = 11111111.11111111.11111111.11000000 = 255.255.255.192. With h host bits, a subnet has 2h addresses. Two are reserved: the all-zeros host part (the network address, the name of the subnet) and the all-ones host part (the broadcast address). So usable hosts = 2h − 2.

Mask octet values are always one of 0, 128, 192, 224, 240, 248, 252, 254, 255 (the running sum of 128, 64, 32, 16, 8, 4, 2, 1).

Method in four steps

  1. Write the mask and find the interesting octet: the one that is neither 255 nor 0.
  2. Block size = 256 − (mask value in that octet). Subnets in that octet start at multiples of the block size.
  3. The network address is the largest multiple of the block size that is ≤ the IP's octet. (Equivalent to IP AND mask.)
  4. The broadcast address = next network address − 1. Usable range = network + 1 to broadcast − 1.

Worked example 1: 192.168.10.77/26

Mask: /26 = 255.255.255.192. The interesting octet is the fourth (192). Block size = 256 − 192 = 64. Subnets start at 0, 64, 128, 192. The value 77 lies between 64 and 127, so:

  • Network address: 192.168.10.64
  • Broadcast address: next network (128) − 1 = 192.168.10.127
  • Usable range: 192.168.10.65 to 192.168.10.126
  • Usable hosts: 26 − 2 = 62

Check with binary. The last octet of 77 is 01001101. AND with 11000000 gives 01000000 = 64. Set the six host bits to 1: 01111111 = 127. Both match.

Worked example 2: 172.16.45.200/20

Mask: /20 = 20 ones = 255.255.240.0. The interesting octet is the third. Block size = 256 − 240 = 16. Third-octet subnets start at 0, 16, 32, 48, … The value 45 lies between 32 and 47, so the network starts at 32.

  • Network address: 172.16.32.0
  • Broadcast address: next network 172.16.48.0, minus 1 = 172.16.47.255
  • Usable range: 172.16.32.1 to 172.16.47.254
  • Host bits: 32 − 20 = 12, so usable hosts = 212 − 2 = 4,096 − 2 = 4,094

Worked example 3: splitting a /24 into four subnets

Split 192.168.1.0/24 into 4 equal subnets. 4 = 22, so borrow 2 bits from the host part: the new prefix is /26 (mask 255.255.255.192, block size 64, 62 hosts each).

Variable-length subnet masks (VLSM)

Equal subnets waste space when needs differ. VLSM gives each subnet the smallest prefix that fits. Say you need 100, 50, 20 and 2 hosts from 192.168.1.0/24. Allocate the biggest first:

The blocks do not overlap: 0–127, 128–191, 192–223, 224–227. Space from .228 to .255 is left for growth.

Quick tools

  • Same network? Two hosts are in the same subnet if IP AND mask gives the same result for both. If not, traffic goes through the default gateway.
  • Wildcard mask = inverse of the mask (/26 → 0.0.0.63); used in router ACLs.
  • Supernetting is the reverse of subnetting: combine 192.168.0.0/24 and 192.168.1.0/24 into 192.168.0.0/23 (route aggregation).

Exceptions to "minus 2"

  • A /31 has two addresses and no network or broadcast: allowed on point-to-point links (RFC 3021).
  • A /32 is a single host route, used for loopbacks and security-group rules.
  • Cloud providers reserve extra addresses per subnet (AWS keeps five in each subnet), so always check before sizing a VPC subnet.

Mistake: forgetting the network and broadcast addresses

A /24 has 256 addresses but 254 usable hosts. Asking for "usable hosts" and answering 256 (or 2h) is the most common subnetting error. Also check that you subtract 1 for the broadcast, not add 1.

Interview: "Find the network and broadcast of 10.1.1.130/25"

  • /25 = 255.255.255.128, block size 128, 130 lies in 128–255.
  • Network 10.1.1.128, broadcast 10.1.1.255, hosts .129–.254, 126 usable.
  • Say the method aloud: mask, block size, multiple, broadcast, count.

NAT and IPv6

NAT lets many devices with private IPs share one public IP by rewriting addresses and ports at the router, which delayed IPv4 exhaustion; IPv6 solves the shortage properly with 128-bit addresses.

The problem

IPv4 has about 4.3 billion addresses, and the free pool ran out at the top level in 2011 (regional registries followed). Yet a home has a dozen devices, and a company thousands. The fix was to reuse the private ranges in every home and office and put a translator at the edge.

How NAT works

NAT (Network Address Translation) runs on your router. Hosts inside use private IPs. When one sends a packet out, the router replaces the private source IP with its own public IP and records the mapping in a NAT table. When the reply returns, the router looks up the table and swaps the address back. The most common form is PAT (Port Address Translation, also called NAT overload or NAPT): many hosts share one public IP and are told apart by the source port.

DirectionSource (IP:port)Destination (IP:port)
Laptop → router192.168.1.23:50321142.250.0.1:443
Router → internet203.0.113.7:40001142.250.0.1:443
Reply → router142.250.0.1:443203.0.113.7:40001
Router → laptop142.250.0.1:443192.168.1.23:50321

(Addresses in 203.0.113.0/24 are reserved for documentation; the server address above is a placeholder.) The NAT table row is: 192.168.1.23:50321 ↔ 203.0.113.7:40001.

Types of NAT

  • Static NAT: one private IP maps permanently to one public IP (to expose a server).
  • Dynamic NAT: private IPs take addresses from a pool of public ones.
  • PAT: many private hosts to one public IP using ports. The usual home setup.
  • Port forwarding: a fixed rule "public port 8080 goes to 192.168.1.50:8080" so outsiders can reach a server behind NAT.
  • CGNAT: your ISP does a second NAT, so you do not even have a public IP.

Pros

  • Saves public IPv4 addresses
  • Hides internal addresses; unsolicited inbound traffic is dropped by default
  • Change ISP without renumbering the inside

Cons

  • Breaks end-to-end connectivity; hosting from home needs port forwarding
  • Complicates peer-to-peer apps, VoIP and some protocols (they need NAT traversal)
  • Router must keep state, and adds a small delay
  • It is not a firewall, only a side effect that looks like one

IPv6

IPv6 uses 128-bit addresses: 2128 ≈ 3.4 × 1038 of them. It is written as eight groups of four hex digits separated by colons: 2001:0db8:0000:0000:0000:ff00:0042:8329. Two shortening rules apply: drop leading zeros in a group, and replace one run of all-zero groups with ::. So the address becomes 2001:db8::ff00:42:8329.

Special IPv6 addresses: ::1 is loopback, :: is the unspecified address, fe80::/10 is link-local (every interface has one), fc00::/7 is unique local (the private equivalent) and 2000::/3 is global unicast. IPv6 and IPv4 cannot talk directly, so the world runs dual stack (both at once) and uses tunnelling or translation for transition. Browsers prefer IPv6 when it works.

Real projects

Inside a VPC or a Kubernetes cluster you use private IPv4 ranges and NAT only at the edge (a NAT gateway lets private servers reach the internet for updates without being reachable inbound). See DevOps · Module 2 for how this looks in practice. When you see a connection error from an app, localhost may resolve to the IPv6 ::1 while the server only listens on IPv4 127.0.0.1.

Interview: "How does NAT work and why do we need IPv6?"

  • NAT rewrites private source IP and port to a public one and remembers it in a table.
  • IPv4 has only 232 addresses; NAT postponed the problem, IPv6 removes it.
  • Mention header simplification and no broadcast; say adoption is gradual, dual stack.

ARP, DHCP, ICMP and routing basics

ARP maps an IP address to a MAC address on the local network, DHCP hands out IP settings automatically in four steps (Discover, Offer, Request, Acknowledge), ICMP carries error and diagnostic messages (ping, traceroute), and routers forward packets using routing tables.

ARP: from IP to MAC

To send a frame on Ethernet you need the destination MAC, but applications only know the IP. ARP (Address Resolution Protocol) bridges the gap on IPv4 networks.

  1. Your PC wants to reach 192.168.1.1. It checks its ARP cache first.
  2. On a miss it broadcasts an ARP request to FF:FF:FF:FF:FF:FF: "Who has 192.168.1.1? Tell 192.168.1.23."
  3. Every host on the LAN receives it; only the owner of 192.168.1.1 replies, with a unicast ARP reply containing its MAC.
  4. Your PC stores the pair in its cache (for a short time) and sends the frame.

If the destination is on another network, the PC ARPs for the default gateway's MAC, not the far host's. Use arp -a to view the cache. ARP has no authentication, which makes ARP spoofing possible (security article). IPv6 replaces ARP with NDP.

DHCP: automatic configuration

DHCP (Dynamic Host Configuration Protocol) gives a joining host an IP address, subnet mask, default gateway and DNS servers, so nobody configures them by hand. It runs over UDP: client port 68, server port 67. The exchange is remembered as DORA:

The first message is a broadcast from source 0.0.0.0 to 255.255.255.255, because the client has no address yet. The Request is also broadcast so that other DHCP servers learn their offers were declined. The address is a lease: the client tries to renew at about half the lease time and gives it up on shutdown or expiry. If no server answers, a host picks a 169.254.x.x address. In a large network a DHCP relay agent on the router forwards the broadcasts to a central server.

ICMP: the network's error reporter

ICMP (Internet Control Message Protocol) is a layer 3 companion of IP. It has no ports and carries no application data; it reports problems and supports diagnostics.

ICMP messageTypeUsed for
Echo request / reply8 / 0ping
Destination unreachable3No route, port closed, fragmentation needed but not allowed

ping sends echo requests and measures the round trip. traceroute (tracert on Windows) discovers the path: it sends probes with TTL 1, then 2, then 3. Each router decrements the TTL (time to live) and drops the packet when it reaches 0, replying "time exceeded". The sender learns each router in turn.

$ ping -c 3 example.com
PING example.com (203.0.113.10): 56 data bytes
64 bytes from 203.0.113.10: icmp_seq=0 ttl=57 time=21.4 ms
64 bytes from 203.0.113.10: icmp_seq=1 ttl=57 time=20.9 ms
64 bytes from 203.0.113.10: icmp_seq=2 ttl=57 time=22.1 ms
--- 3 packets transmitted, 3 received, 0% packet loss

(Sample output with documentation addresses; real times vary.) Many servers and firewalls drop ICMP, so a failed ping does not prove a server is down.

Routing basics

A router's routing table lists destination prefixes, the next hop and the outgoing interface. For each packet it chooses the longest prefix match: the most specific route wins. The entry 0.0.0.0/0 is the default route, matching anything that nothing else matches.

DestinationNext hopInterface
192.168.1.0/24directly connectedeth0
10.0.0.0/8192.168.1.254eth0
0.0.0.0/0203.0.113.1 (ISP)eth1

A packet for 10.2.3.4 matches both 10.0.0.0/8 and the default route; the /8 is more specific and wins. Routes are static (hand-written) or dynamic, learned through routing protocols: inside an organisation OSPF; between internet providers BGP. You only need the names at interview level.

Edge cases

  • If DHCP gives two hosts the same address by mistake you get an IP conflict; both lose connectivity intermittently.
  • A rogue DHCP server (a plugged-in home router) can hand out wrong gateways. Switches can block this with DHCP snooping.
  • Packets with TTL 0 are discarded; this also stops routing loops from circulating forever.

Interview: "DHCP steps" and "how does traceroute work?"

  • DORA with broadcast on Discover and Request, UDP 67/68, lease and renewal.
  • Traceroute: increasing TTL, "time exceeded" from each hop, built on ICMP.
  • ARP: broadcast request, unicast reply, cache; used for the gateway when off-network.
