Interview questions — OOP theory

1. What is OOP? How is it different from procedural programming?

OOP organises a program as objects that combine data and behaviour, built on encapsulation, abstraction, inheritance and polymorphism. Procedural code is organised as functions acting on shared data, top-down. OOP gives better data protection, reuse and maintainability for large, changing programs. Java is not purely OOP because it has primitive types.

2. What is the difference between a class and an object?

A class is a blueprint that defines fields and methods; an object is an instance of that class with its own state, created with new and stored on the heap. One class can produce many objects. A reference variable is not an object; it points to one.

3. What are the four pillars of OOP?

Encapsulation (hide data behind methods), abstraction (expose only what matters, hide how), inheritance (reuse and extend a parent's features, is-a) and polymorphism (one call, many behaviours). Some lists add "object, class, message passing", but these four are the standard answer.

4. What is encapsulation? How do you achieve it in Java?

Bundling data with the methods that use it and restricting direct access. Make fields private and expose public methods (getters, validated setters, behaviour methods). The class controls its own invariants, e.g. balance never negative, and can change its internals without affecting callers.

5. What is abstraction? How do you achieve it?

Showing only essential behaviour and hiding implementation details. In Java: interfaces and abstract classes. Callers use PaymentMethod.pay() without knowing whether it is UPI or card.

6. Abstraction vs encapsulation?

Abstraction is a design-level idea: hide complexity, show a contract (what). Encapsulation is an implementation-level technique: hide and protect data inside a class (how it is guarded). Abstraction uses interfaces and abstract classes; encapsulation uses private fields and access modifiers. Example: the List interface is abstraction; ArrayList keeping its array private is encapsulation.

7. What types of inheritance does Java support?

With classes: single, multilevel and hierarchical. Multiple and hybrid inheritance are not allowed for classes, but a class can implement many interfaces, giving multiple inheritance of type.

8. Why does Java not support multiple inheritance of classes?

To avoid the diamond problem (ambiguity about which parent's method and which copy of state to inherit) and the added complexity. Interfaces provide multiple inheritance of type without instance state.

9. What happens when two interfaces have the same default method?

If a class implements both, it is a compile error unless the class overrides the method. Inside it you can choose with InterfaceName.super.method(). Rules: a class method wins over an interface default; a more specific sub-interface default wins over its parent's.

10. What is polymorphism? Compile-time vs runtime?

One name, many behaviours. Compile-time (static) polymorphism is method overloading, decided by the compiler from argument types. Runtime (dynamic) polymorphism is method overriding, decided by the JVM from the actual object, through a parent-type reference. Java has no user-defined operator overloading.

11. Method overloading vs method overriding?

Overloading: same name, different parameters, same class (or inherited), resolved at compile time, return type and access can vary. Overriding: same signature in a subclass, resolved at runtime; return type same or covariant, access same or wider, checked exceptions not broader; not possible for static, private or final methods. Use @Override to let the compiler check.

12. Can we overload or override static, private and final methods? The main method?

Overload: yes for all, including main (the JVM still starts with main(String[])). Override: static methods are hidden, not overridden; private methods are invisible to the subclass; final methods cannot be overridden (compile error).

13. What is the difference between static and dynamic binding?

Static (early) binding is resolved by the compiler: private, static and final methods, constructors, and overload selection. Dynamic (late) binding is resolved at runtime from the object's class: overridden instance methods. Fields are always bound statically by the reference type.

14. What is a covariant return type?

An overriding method may return a subtype of the parent method's return type. For example a parent method returning Animal can be overridden by one returning Dog. This also lets clone() be overridden to return your own type.

15. Abstract class vs interface?

Abstract class: single inheritance, can hold instance state, constructors, any access level, abstract and concrete methods; models "is-a" with shared code. Interface: a class can implement many, no instance state (only constants), no constructors; methods are public abstract, plus default and static (Java 8) and private (Java 9) methods; models a capability. Use an abstract class to share state and code, an interface for a contract and for multiple roles.

16. Can an abstract class have a constructor? Why?

Yes. You cannot instantiate it directly, but subclass constructors call it with super(...), so it can initialise the fields it declares. Abstract classes can also have no abstract methods at all.

17. Why were default methods added to interfaces? Can an interface have state?

To evolve interfaces without breaking existing implementations, e.g. adding Collection.stream() and List.sort() in Java 8. An interface has no instance state; its fields are implicitly public static final constants.

18. What is a functional interface?

An interface with exactly one abstract method (it may also have default and static methods). It can be implemented with a lambda expression. @FunctionalInterface makes the compiler enforce the rule. Examples: Runnable, Comparator, Function.

19. What is a constructor? What if I write none? Constructor vs method?

A constructor initialises a new object; it has the class's name and no return type. If you write none, the compiler adds a default no-argument one; if you write any, it does not. Unlike a method it is called by new, cannot be inherited, overridden, static, final or abstract, and the first line is this(...) or super(...) (implicitly super()).

20. Types of constructors? Does Java have a copy constructor?

Default (compiler-provided), no-argument, parameterized. Java has no built-in copy constructor like C++; you write one yourself: Student(Student other), which is also a safe way to copy objects instead of clone().

21. Can a constructor be private? Why would you?

Yes. It prevents outside instantiation. Used for singletons, utility classes (only static members), and classes created through static factory methods or builders.

22. this vs super?

this refers to the current object (separates fields from parameters, calls another constructor with this(...), can be returned for chaining). super refers to the parent part (calls parent constructor, parent's overridden method or hidden field). Neither is usable in static code.

23. Why does Java have no destructor?

Memory is reclaimed by the garbage collector, so manual deallocation is not needed. finalize() is deprecated and unreliable. For other resources implement AutoCloseable and use try-with-resources.

24. Static vs instance members?

Static members belong to the class and have one shared copy, accessed through the class name; static methods have no this and cannot directly use instance members. Instance members belong to each object. Static blocks run once at class loading.

25. Explain the access modifiers.

private: same class only. Default (no keyword): same package. protected: same package plus subclasses in other packages. public: everywhere. A top-level class can only be public or package-private.

26. Association vs aggregation vs composition vs dependency?

Dependency: uses another class temporarily (method parameter). Association: general long-term link between independent objects (teacher–student). Aggregation: has-a where the part can exist without the whole (department–teachers). Composition: strong has-a where the part cannot exist without the whole (house–rooms). Strength grows from dependency to composition.

27. Why prefer composition over inheritance?

It gives looser coupling, avoids fragile base classes and exposing unwanted inherited methods, allows swapping behaviour at runtime, and is not limited by single inheritance. Use inheritance only for a true, stable is-a relationship.

28. What are coupling and cohesion?

Coupling is the degree of dependence between classes; cohesion is how related the members of one class are. Good design has low coupling (use interfaces and dependency injection) and high cohesion (each class does one job).

29. Explain SOLID.

S: a class has one reason to change. O: open for extension, closed for modification. L: subclasses must be substitutable for their parents. I: many small interfaces beat one fat one. D: depend on abstractions, not concrete classes. See System Design · Module 1.

30. Give an example that violates the Liskov Substitution Principle.

Penguin extends Bird where Bird has fly() and Penguin.fly() throws an exception: code written for any Bird breaks. Also Square extends Rectangle, where setting the width changes the height. Fix by remodelling the hierarchy (FlyingBird) or using composition.

31. DIP vs dependency injection vs IoC?

DIP is the principle that high-level code depends on abstractions. Dependency injection is the technique of passing the dependency in from outside (usually via the constructor). IoC is the broader idea that a framework controls object creation and calls your code; Spring's container is an IoC container that performs DI.

32. Shallow copy vs deep copy?

A shallow copy copies field values, so reference fields point to the same inner objects as the original (Object.clone() does this). A deep copy also copies the referred objects, so the copy is fully independent. Prefer a copy constructor over clone().

33. How do you create an immutable class? Why is String immutable?

Final class, private final fields, no setters, set everything in the constructor, defensive copies for mutable fields. String is immutable for the string pool (sharing), security (class names, file paths, credentials can't be altered after validation), cached hash codes and thread safety.

34. final vs finally vs finalize?

final is a modifier (constant variable, non-overridable method, non-extendable class). finally is a block that runs after try/catch for cleanup. finalize() is an old Object method called by the GC; deprecated for removal, do not use.

35. What is the equals/hashCode contract?

Equal objects must have equal hash codes; equals must be reflexive, symmetric, transitive, consistent and false for null. Unequal objects may share a hash code. Override both together, or hash-based collections misbehave. See Core Java · Module 7.

36. What is a marker interface?

An interface with no methods that flags a class for the JVM or a library: Serializable, Cloneable, RandomAccess. Annotations now do much of this, but a marker interface also gives a type the compiler can check.

37. How do you write a thread-safe singleton?

Private constructor plus a static accessor. The best simple choices are an enum singleton or the initialization-on-demand holder class (lazy and thread-safe). Double-checked locking works only with a volatile field. Reflection, serialization and cloning can break plain class singletons; enums resist them.

38. What are the types of inner classes?

Static nested, member inner (non-static), local (inside a method) and anonymous. Non-static inner classes hold a reference to the outer instance and can use its private members; local and anonymous classes can capture only effectively final variables.

39. Why is main() static?

The JVM calls it before any object exists, so it must be callable on the class itself. It is public so the JVM can reach it, and void since the JVM uses no return value.

40. Predict the output. 
class A { A() { System.out.print("A "); } }
class B extends A { B() { System.out.print("B "); } }
class C extends B { C() { System.out.print("C "); } }
// new C();

Prints A B C. Parent constructors run first, because each constructor starts with a call to its parent's. If a parent method that the child overrides is called from the parent constructor, it sees the child's fields still at their default values (0, null).

Cheat sheet — OOP theory

  • Class blueprint of fields and methods; object an instance on the heap, made with new.
  • Constructor same name, no return type; compiler adds a default one only if you write none; not inherited.
  • this / super current object / parent part; this(...) or super(...) must be the first line.
  • No destructor in Java; the GC reclaims memory; use try-with-resources for resources.
  • Static belongs to the class, one copy; no this in static code.
  • Access private < default < protected < public.
  • Encapsulation private fields plus controlled methods; protects state.
  • Abstraction expose what, hide how; interfaces and abstract classes.
  • Abstraction vs encapsulation design contract vs data protection inside a class.
  • Inheritance extends; is-a; single, multilevel, hierarchical for classes; multiple only via interfaces.
  • Diamond problem avoided by single class inheritance; default-method clash must be overridden, use X.super.m().
  • Polymorphism compile-time = overloading; runtime = overriding with a parent reference.
  • Overloading same name, different parameters; return type alone is not enough.
  • Overriding same signature; return same or covariant; access same or wider; checked exceptions not broader; not for static, private or final.
  • Binding static for private, static, final, constructors and overload choice; dynamic for overridden instance methods; fields use the reference type.
  • Abstract class state, constructors, any access, one parent only; for shared code.
  • Interface contract; constants only; default, static (8) and private (9) methods; many allowed; for capabilities.
  • Abstract class constructor allowed; called through super(...).
  • Relationships dependency < association < aggregation < composition (strength).
  • Composition over inheritance looser coupling, runtime flexibility.
  • Low coupling, high cohesion interfaces plus dependency injection; one job per class.
  • SOLID SRP one reason to change; OCP extend, don't edit; LSP substitutable subtypes; ISP small interfaces; DIP depend on abstractions.
  • Shallow vs deep copy shared inner objects vs independent copies; prefer a copy constructor.
  • Immutable class final class, private final fields, no setters, defensive copies.
  • final / finally / finalize modifier / cleanup block / deprecated GC hook.
  • equals and hashCode override together; equal objects share a hash code.
  • Singleton private constructor, static accessor; enum or holder idiom is thread-safe.
  • Inner classes static nested, member inner, local, anonymous.
  • main is static the JVM needs it before any object exists.

Practice — OOP theory

  1. Pillars by hand (easy). Write a BankAccount class that shows encapsulation (private balance, validated deposit and withdraw). Then say each of the four pillars aloud in 20 seconds with its own example, recording yourself if you can. Done when each answer has a definition, an analogy and one Java line, and takes no longer than 20 seconds.
  2. Abstraction and polymorphism. Build a Notifier interface with EmailNotifier and SmsNotifier, and a NotificationService that sends through a List<Notifier>. Done when adding a PushNotifier needs no change to NotificationService.
  3. Overloading vs overriding. Write a class with print(int), print(long), print(Integer), print(Object) and print(int...). Predict, then run, the output for print(5), print('a'), print(5L) and print("x"). Done when you can explain every result with the three resolution phases (print('a') prints the int overload, by widening char to int).
  4. Binding trap. Reproduce question 1 and question 4 of the polymorphism article, predict the outputs on paper first, then check. Done when you can explain why the field, the static method and the constructor call behave as they do.
  5. Diamond with default methods. Create two interfaces with the same default method and a class that implements both. Observe the compile error, then fix it with X.super.method(). Done when the class compiles and prints a combined result.
  6. Abstract class or interface? Model Employee (shared name, id and salary logic) with FullTimeEmployee and Contractor, plus a Payable capability that unrelated classes such as Vendor also have. Done when you can defend in two sentences why one is an abstract class and the other an interface.
  7. Relationships. Draw a class diagram for an online shop with one example each of association, aggregation, composition and dependency (for instance Customer–Order, Category–Product, Order–OrderLine, OrderService uses PaymentGateway). Done when each arrow type is justified by lifetime or usage.
  8. SOLID refactor (hard). Take a 100-line class that calculates fees, prints a report and saves to a database, with an if/else on student type. Refactor it to follow SRP, OCP and DIP. Done when the report format, the fee rules and the storage can each change without editing the others. Depth: System Design · Module 1.
  9. Copying and immutability. Implement a shallow clone() of an object with a mutable list, show the shared-state bug, then fix it with a copy constructor. Finally make the class immutable with defensive copies. Done when changing the copy never changes the original, and a modifying call on the immutable class's list throws UnsupportedOperationException.
  10. Singleton and inner classes. Write an enum singleton and a holder-idiom singleton, then try to break the second one with reflection. Add a static nested and a member inner class to one outer class and instantiate both. Done when you can say why the enum cannot be broken and why the inner class needs an outer instance.
