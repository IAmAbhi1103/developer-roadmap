Interview questions — Computer networks

1. What are the seven layers of the OSI model?

From top to bottom: Application, Presentation, Session, Transport, Network, Data Link, Physical (mnemonic: All People Seem To Need Data Processing). Application is where HTTP and DNS live, Transport has TCP and UDP and ports, Network has IP and routing, Data Link has Ethernet, MAC addresses and switches, and Physical is bits on the wire. The PDUs are data, segment, packet, frame and bit.

2. How is the TCP/IP model different from OSI?

TCP/IP has four layers: Application (OSI 5–7), Transport, Internet and Link (OSI 1–2). OSI is a theoretical reference model with seven layers; TCP/IP was built from working protocols and is what the internet uses. We still use OSI numbers as vocabulary, such as "layer 7 load balancer".

3. What is encapsulation?

Each layer wraps the data from the layer above with its own header: application data gets a TCP header (segment), then an IP header (packet), then an Ethernet header and trailer (frame), and finally becomes bits. The receiver removes the headers in reverse (decapsulation). MAC addresses change at every hop; IP addresses stay the same end to end.

4. Difference between a hub, a switch and a router?

A hub (layer 1) repeats bits to all ports. A switch (layer 2) learns MAC addresses and forwards frames only to the right port, inside one network. A router (layer 3) uses IP addresses and routing tables to forward packets between different networks and separates broadcast domains.

5. Bandwidth vs latency vs throughput?

Bandwidth is the maximum capacity of the link, latency is the delay for data to cross it (RTT is there and back), and throughput is the rate you actually achieve after loss, overhead and congestion. Throughput is always at most bandwidth. More bandwidth does not reduce latency.

6. MAC address vs IP address?

A MAC is a 48-bit hardware address at layer 2, used for delivery on the local link and rewritten on every hop. An IP address is a logical layer 3 address (32-bit IPv4, 128-bit IPv6) used for routing across networks and changes when you change networks. ARP maps an IP to a MAC on the local network.

7. Find the network address, broadcast address and usable hosts of 192.168.10.77/26.

/26 = 255.255.255.192, block size 256 − 192 = 64. 77 falls in the block starting at 64. Network: 192.168.10.64. Broadcast: 192.168.10.127. Usable range: .65 to .126. Host bits = 6, so usable hosts = 26 − 2 = 62.

8. How does NAT work?

The router replaces the private source IP (and port) of outgoing packets with its public IP and a unique port, and remembers the mapping in a NAT table. Replies are matched in the table and translated back. With many hosts sharing one public IP using ports, it is called PAT. It saves IPv4 addresses but breaks end-to-end connectivity.

9. Why do we need IPv6?

IPv4 has only about 4.3 billion addresses and they have run out. IPv6 has 128-bit addresses (about 3.4 × 1038), a simpler fixed header, no broadcast, built-in autoconfiguration and no need for NAT.

10. What is ARP and how does it work?

ARP finds the MAC address for a known IPv4 address on the local network. The host broadcasts "who has this IP?", the owner replies with its MAC by unicast, and the result is cached. For off-network destinations the host ARPs for the default gateway. ARP is unauthenticated, so it can be spoofed.

11. Explain DHCP (DORA).

A new host broadcasts DISCOVER; a server replies with OFFER (an address and lease); the host broadcasts REQUEST to accept; the server confirms with ACK, also supplying the mask, gateway and DNS servers. It uses UDP ports 68 (client) and 67 (server), and the address is leased and renewed.

12. How do ping and traceroute work?

Ping sends ICMP echo requests and waits for echo replies to measure reachability and RTT. Traceroute sends packets with TTL 1, 2, 3 and so on; each router that drops a packet at TTL 0 replies "time exceeded", revealing the path hop by hop.

13. What is the difference between a port and a socket?

A port is a 16-bit number identifying a process on a host (0 to 65,535; well-known 0–1023, registered 1024–49151, ephemeral 49152–65535). A socket is an endpoint: IP address + port + protocol. A TCP connection is identified by the 4-tuple (source IP, source port, destination IP, destination port), so many clients can use the same server port.

14. Explain the TCP three-way handshake. Why three steps?

Client sends SYN (seq = x); server replies SYN-ACK (seq = y, ack = x + 1); client sends ACK (ack = y + 1). Both sides have now announced and had acknowledged their initial sequence numbers; the server's SYN and ACK are combined, which is why it is three rather than four. It also prevents old duplicate SYNs from opening false connections.

15. How is a TCP connection closed? What is TIME_WAIT?

Each direction closes separately: FIN, ACK, then the other side's FIN, ACK (four steps; the middle two can combine). The side that closed first waits in TIME_WAIT for 2 × MSL (60 seconds on Linux) so a lost final ACK can be resent and delayed packets from the old connection die out before the 4-tuple is reused.

16. How does TCP provide reliable delivery?

Sequence numbers number the bytes, the receiver sends cumulative ACKs, and the sender retransmits on timeout or after three duplicate ACKs (fast retransmit). A checksum detects corruption, and the receiver reorders out-of-order segments and drops duplicates.

17. Flow control vs congestion control?

Flow control protects the receiver: it advertises a receive window and the sender may not exceed it (sliding window). Congestion control protects the network: the sender keeps a congestion window that grows by slow start then additive increase, and shrinks (halves, or resets to 1 after a timeout) on loss. The sender uses min(cwnd, rwnd).

18. TCP vs UDP — differences and examples?

TCP is connection-oriented, reliable, ordered, with flow and congestion control, a byte stream and a 20-byte header: HTTP, SSH, email, databases. UDP is connectionless, best-effort, unordered, message-based, with an 8-byte header and low latency: DNS, DHCP, video calls, games. Choose TCP for correctness, UDP for timeliness.

19. What is QUIC and why does HTTP/3 use it?

QUIC is a UDP-based transport with built-in TLS 1.3, reliability and congestion control implemented in user space. It gives a faster handshake (1 RTT, or 0 on resumption), independent streams so one lost packet does not block others, and connection migration across networks.

20. What is the difference between HTTP/1.1, HTTP/2 and HTTP/3?

HTTP/1.1 is text, one request at a time per connection, with HOL blocking. HTTP/2 is binary, multiplexes streams over one TCP connection and compresses headers (HPACK) but still suffers TCP-level HOL blocking. HTTP/3 runs on QUIC over UDP, removing that problem and speeding up setup.

21. What does "HTTP is stateless" mean? How do we keep state?

The server does not remember earlier requests; each must be self-contained. State is added with cookies (a session ID the server maps to stored data), tokens such as JWT sent in the Authorization header, or data in a database/Redis. Session cookies should be HttpOnly, Secure and SameSite.

22. 401 vs 403, 301 vs 302, 502 vs 504?

401: not authenticated (no or bad credentials); 403: authenticated but not permitted. 301: permanent redirect (cacheable); 302: temporary. 502: a proxy received an invalid response from the upstream server; 504: the upstream did not answer in time.

23. GET vs POST, and what are idempotent methods?

GET reads, is safe, cacheable and has parameters in the URL; POST sends data in the body to create or trigger actions and is not idempotent. An idempotent method gives the same result if repeated: GET, PUT, DELETE, HEAD. Retrying a POST can create duplicates, so use idempotency keys for payments.

24. How does HTTPS work? What is in the TLS 1.3 handshake?

After the TCP handshake, the client sends ClientHello with ciphers and a key share; the server replies with ServerHello and its key share, plus its certificate and a signature; the client verifies the chain to a trusted CA and the hostname; both derive the same symmetric key and exchange Finished messages. Data is then sent with symmetric encryption. TLS 1.3 needs one round trip and offers forward secrecy.

25. Why does TLS use both symmetric and asymmetric encryption?

Asymmetric cryptography solves trust and key agreement over an open network but is slow; symmetric encryption (AES, ChaCha20) is fast but needs a shared secret. TLS uses asymmetric methods to authenticate the server and agree on a secret, then symmetric encryption for the data.

26. What is a digital certificate and a CA?

A certificate binds a public key to a domain name and is signed by a Certificate Authority that browsers trust. The browser checks the signature chain up to a trusted root, the validity dates, revocation and the hostname. Without that check, anyone could claim to be your bank.

27. How does DNS resolution work?

The browser and OS check their caches, then ask the recursive resolver. On a miss, the resolver asks a root server (which refers it to the TLD server), then the TLD server (which refers it to the authoritative server), and the authoritative server returns the record. Answers are cached for the TTL. Client-to-resolver is recursive; resolver-to-servers is iterative. DNS uses UDP/TCP port 53.

28. What happens when you type a URL and press Enter?

URL parse and HSTS; caches; DNS resolution; TCP handshake; TLS handshake; HTTP request; CDN/load balancer; Spring Boot filters, controller, service; database query; response back; the browser builds the DOM, CSSOM and render tree, does layout and paint; then fetches assets and API data. See the walkthrough article for the full 3–4 minute version.

29. Forward proxy vs reverse proxy?

A forward proxy sits in front of clients and sends their requests out (filtering, caching, hiding clients). A reverse proxy sits in front of servers and receives requests for them (load balancing, TLS termination, caching, protection). Nginx is typically a reverse proxy.

30. What is a SYN flood and how is it mitigated?

An attacker sends many SYNs (often with spoofed sources) and never completes the handshake, filling the server's half-open connection queue so real clients cannot connect. Mitigations: SYN cookies (no state kept until the final ACK), larger backlog, rate limiting and upstream DDoS filtering.

Cheat sheet — Computer networks

  • OSI (7→1) Application, Presentation, Session, Transport, Network, Data Link, Physical (All People Seem To Need Data Processing)
  • TCP/IP Application, Transport, Internet, Link
  • PDUs data → segment (TCP) / datagram (UDP) → packet → frame → bits
  • Devices hub = L1 bits, switch = L2 MAC, router = L3 IP, firewall = L3–L7
  • Addresses MAC (48 bit, per hop), IPv4 (32 bit, end to end), IPv6 (128 bit), port (16 bit)
  • Bandwidth / latency / throughput capacity / delay / achieved rate
  • Subnet formulas hosts = 2h − 2; block size = 256 − mask octet; broadcast = next network − 1
  • Prefix quick table /24 = 254 hosts, /25 = 126, /26 = 62, /27 = 30, /28 = 14, /30 = 2
  • Private ranges 10/8, 172.16/12, 192.168/16; loopback 127.0.0.1; link-local 169.254/16
  • NAT / PAT rewrite private IP:port to public IP:port, table lookup on reply
  • ARP IP → MAC on the LAN (broadcast request, unicast reply)
  • DHCP DORA, UDP 67/68, gives IP, mask, gateway, DNS
  • ICMP ping = echo request/reply; traceroute = increasing TTL, "time exceeded"
  • Port ranges 0–1023 well-known, 1024–49151 registered, 49152–65535 ephemeral
  • Key ports 22 SSH, 25 SMTP, 53 DNS, 80 HTTP, 443 HTTPS, 3306 MySQL, 5432 PostgreSQL, 8080 Spring Boot
  • TCP handshake SYN → SYN-ACK → ACK (1 RTT); teardown FIN, ACK, FIN, ACK; TIME_WAIT = 2 × MSL
  • TCP reliability sequence numbers, cumulative ACK, retransmit on timeout or 3 dup ACKs
  • Flow vs congestion rwnd (receiver) vs cwnd (network); slow start → AIMD; loss: halve, timeout: 1
  • TCP vs UDP reliable/ordered/20 B header vs best-effort/8 B header; DNS, DHCP, calls = UDP
  • HTTP stateless request/response; status 1xx–5xx; 401 not logged in, 403 forbidden; 502 bad gateway, 504 timeout
  • Idempotent methods GET, PUT, DELETE, HEAD (POST is not)
  • Cookie flags HttpOnly (no JS), Secure (HTTPS only), SameSite (CSRF)
  • HTTP versions 1.1 text and one request at a time; 2 multiplexing and HPACK; 3 QUIC over UDP
  • TLS 1.3 ClientHello+key share → ServerHello+cert+Finished → Finished; 1 RTT, forward secrecy
  • DNS path caches → resolver → root → TLD → authoritative; records A, AAAA, CNAME, MX, NS, TXT
  • URL walkthrough parse/HSTS → DNS → TCP → TLS → HTTP → LB/CDN → app → DB → response → render
  • Security firewall = rules; forward proxy hides clients, reverse proxy hides servers; VPN = encrypted tunnel; HTTPS + certificates beat MITM

Practice — Computer networks

  1. Layer sorting (easy). Without notes, write the seven OSI layers and place these items on them: HTTP, TLS, TCP, IP, Ethernet, switch, router, cable, ARP, DNS. Check against the OSI article. Done when you get at least nine of ten right.
  2. Subnet by hand (easy). For 10.20.30.200/27 and 172.20.130.9/19, write the mask, block size, network address, broadcast address, usable range and number of hosts. Done when each answer matches the method in the subnetting article (for the first: block size 32, network 10.20.30.192, broadcast 10.20.30.223, 30 hosts).
  3. VLSM plan (medium). Split 192.168.5.0/24 into subnets for 60, 28, 10 and 2 hosts. Give prefix, network, range and broadcast for each, and prove that no ranges overlap. Done when all four fit and the leftover space is listed.
  4. Packet capture (medium). Install Wireshark. Capture while running ping example.com, then loading an HTTPS page. Filter by dns, arp, icmp and tcp.flags.syn==1. Find: the DNS query and answer, the SYN, SYN-ACK, ACK trio, and the TLS ClientHello with its SNI. Done when you can point to each step of the URL walkthrough in the capture.
  5. Command-line tour (easy). Run ipconfig or ip addr, arp -a, nslookup or dig for a domain (note the TTL, then run again), traceroute or tracert, and netstat -an or ss -tan. Done when you can explain every column you see, including at least one connection in each of the ESTABLISHED, LISTEN and TIME_WAIT states.
  6. Java sockets (medium). Extend the echo server from the ports article to handle many clients using one thread per client (or a thread pool), and add a UDP version with DatagramSocket. Done when three clients talk to the server at once, and you can say which of them shows connection state and which does not.
  7. Inspect HTTP (easy). Use curl -v https://example.com and the browser DevTools Network tab. List the request line, three request headers, status line and three response headers, and find the negotiated HTTP version and TLS version. Done when you can explain each header's purpose.
  8. Break and fix (hard). Run your Spring Boot app on port 8080 twice to trigger Address already in use; then connect to a closed port and a firewalled port and compare "connection refused" with a timeout. Finally serve the app over HTTPS with a self-signed keystore and watch curl reject it until you pass --cacert. Done when you can explain each error from the TCP and TLS mechanics.
  9. The 4-minute answer (hard). Record yourself answering "what happens when you type a URL and press Enter?" for your own project, with your own service names. Time it: aim for 3 to 4 minutes, with all 14 stages in order. Then answer five follow-ups from the walkthrough article without notes. Done when you hit the time and the order without reading.
