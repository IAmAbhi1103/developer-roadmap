Computer networks is the part of CS fundamentals that explains how two machines far apart talk to each other. Every time your Spring Boot API answers a React page, a dozen protocols work together: DNS finds the server, TCP carries the bytes reliably, TLS encrypts them, and HTTP gives them meaning. Interviewers love this subject because one question, "what happens when you type a URL and press Enter?", tests all of it at once.

Network basics: LAN, WAN, topologies and the three speed words

A network is a set of devices connected so they can exchange data; networks are grouped by size (LAN, MAN, WAN), and their quality is described by bandwidth, latency and throughput, which are three different things.

What a network is

A computer network is two or more devices (nodes or hosts) connected by a medium (copper cable, fibre, radio waves) so that they can share data and resources. The nodes follow agreed rules called protocols. A protocol defines the message format, the order of messages and what to do on errors. HTTP, TCP and IP are all protocols.

Data does not travel as one big lump. It is cut into small pieces called packets. Each packet carries the sender and receiver addresses and travels independently. This is packet switching, the idea behind the internet. The older telephone network used circuit switching: a dedicated path was reserved for the whole call. Packet switching shares the links among many users and is much more efficient for bursty computer traffic, but packets can arrive late, out of order or not at all. Handling that is the job of the upper layers (TCP).

The internet is a "network of networks": thousands of independently run networks (each called an autonomous system) joined by routers and agreeing to forward each other's packets. An intranet is a private network for one company that uses the same technology. A VPN (later in this module) extends a private network over the public internet.

Almost every modern LAN is a star (devices to a switch or Wi-Fi access point). The internet core is a partial mesh, which is why traffic can route around a failed link. A full mesh of 5 nodes needs 5 × 4 / 2 = 10 links.

Bandwidth, latency and throughput

These three are the most confused words in networking.

Bandwidth
The maximum rate a link can carry, measured in bits per second (Mbps, Gbps). It is the width of the pipe.
Latency
The delay for data to travel from sender to receiver, measured in milliseconds. Often quoted as RTT (round-trip time): there and back. It is the length of the pipe.
Throughput
The rate you actually achieve, after protocol overhead, packet loss and congestion. Throughput is always at most the bandwidth.
Jitter
Variation in latency from packet to packet. It hurts voice and video calls.
Packet loss
The percentage of packets that never arrive. TCP resends them, which lowers throughput.

Latency has four parts: transmission delay (packet size ÷ bandwidth, the time to push the bits onto the wire), propagation delay (distance ÷ signal speed, limited by the speed of light in the medium), queuing delay (waiting in router buffers) and processing delay (routers reading headers). Worked example: a 1,500-byte packet is 12,000 bits. On a 100 Mbps link the transmission delay is 12,000 / 100,000,000 = 0.00012 s = 0.12 ms. Propagation from Mumbai to a server in the US takes tens of milliseconds regardless of how fast your link is.

Tip: a fat pipe is not a short pipe

Upgrading from 100 Mbps to 1 Gbps makes a big download faster but does almost nothing for a chatty app that makes many small round trips to a far-away server. For those, reduce the number of round trips (keep-alive, HTTP/2, a CDN, caching) instead of buying bandwidth.

Interview: "Bandwidth vs latency vs throughput"

  • Bandwidth = capacity, latency = delay, throughput = real achieved rate.
  • Use the pipe or highway analogy: width, length, cars actually passing per minute.
  • Name the four delay components; mention that throughput ≤ bandwidth.

Network devices: hub, switch, router, modem, access point, NIC

A hub repeats bits to everyone, a switch forwards frames by MAC address inside a LAN, and a router forwards packets by IP address between networks; modems, access points and NICs connect devices to the medium.

The devices and their layers

Each device works at a layer of the OSI model (next article). A device only looks at headers of its own layer and below. That is why a switch cannot read IP addresses (in its basic form) and a router does not care about HTTP.

Hub vs switch

A hub is a dumb repeater. A frame arriving on one port is copied to every other port, so all hosts share one collision domain (two hosts sending at once corrupt each other's data) and everyone sees everyone's traffic. Hubs are obsolete.

A switch keeps a MAC address table (also called the CAM table). When a frame arrives, the switch records "source MAC X is on port 3". Then it looks up the destination MAC. If it knows the port, it forwards the frame only there. If the destination is unknown, or is the broadcast address, it floods the frame out of every port except the one it arrived on. Each switch port is its own collision domain, so modern switched Ethernet has no collisions. But all ports of a switch are still in one broadcast domain unless you split it with VLANs.

Router and default gateway

A router has an interface in each network it joins and a routing table: a list of "to reach network N, send to next hop H". It reads the destination IP of each packet, picks the most specific matching route (longest prefix match) and forwards the packet, decrementing the TTL. Routers do not forward broadcasts, so each router interface is a separate broadcast domain.

Your laptop does not know the whole internet. It knows only its own network. For any destination outside that network it sends the packet to the default gateway, the router's IP on your LAN (often 192.168.1.1 at home). Your home "router" box is really several devices in one: a modem or ONT, a router with NAT, a switch with a few LAN ports, a Wi-Fi access point, a DHCP server and a small firewall.

Domains and the cheat rule

  • Collision domain: the set of devices whose frames can collide. Hubs extend it; switch ports and routers split it.
  • Broadcast domain: the set of devices that receive a layer 2 broadcast. Hubs and switches extend it; only routers (or VLANs) split it.

A quick rule: hubs forward bits, switches forward frames, routers forward packets. Switch = within a network, router = between networks.

Exception: layer 3 switches

A "layer 3 switch" is a switch with routing built into the hardware. It can route between VLANs at wire speed. So "switches work at layer 2" is the textbook rule, not a law.

Interview: "Difference between a switch and a router?"

  • Switch: layer 2, MAC addresses, connects devices inside one LAN.
  • Router: layer 3, IP addresses, connects different networks, splits broadcast domains.
  • Add the MAC table, flooding and the default gateway to show depth.

The OSI model: seven layers

The OSI model splits network communication into seven layers (Physical, Data Link, Network, Transport, Session, Presentation, Application), each doing one job and talking only to the layer above and below it, so protocols can be designed, replaced and debugged independently.

Why layers?

Sending a web page across the world involves electrical signals, addressing, routing, reliability, encryption and an application protocol. One giant protocol doing all this would be impossible to build or change. So the problem is cut into layers. Each layer offers a service to the layer above and uses the service of the layer below. Rules: a layer talks to the same layer on the other machine through its own protocol (a peer relationship), and the layers can change without breaking each other (swap Wi-Fi for Ethernet and HTTP does not notice).

The OSI (Open Systems Interconnection) model was published by ISO in the 1980s as a reference model. The internet actually runs on the simpler TCP/IP model, but OSI numbering and vocabulary ("layer 2 switch", "layer 7 load balancer") is used everywhere.

Mnemonics

Top to bottom (7 → 1): All People Seem To Need Data Processing (Application, Presentation, Session, Transport, Network, Data link, Physical). Bottom to top (1 → 7): Please Do Not Throw Sausage Pizza Away.

What each layer does, in plain words

Layer 1, Physical
Turns bits into signals: voltage, light pulses, radio waves. Defines cables, connectors and bit rates. No addresses here.
Layer 2, Data Link
Moves a frame between two directly connected devices using MAC addresses. Adds a checksum (the FCS) to detect corruption. Ethernet and Wi-Fi live here. Switches work here.
Layer 3, Network
Moves a packet from source host to destination host across many networks using IP addresses and routing. Best effort: no guarantee of delivery.
Layer 4, Transport
Delivers data between processes on two hosts using port numbers. TCP adds reliability, ordering, flow and congestion control; UDP adds only ports and a checksum.
Layer 5, Session
Sets up, maintains and tears down a long-running dialogue between two applications, with checkpoints. In practice this is folded into applications.
Layer 6, Presentation
Translates between application data and network format: character encoding, serialisation, compression, encryption.
Layer 7, Application
The protocols your programs speak: HTTP, DNS, SMTP. This is not the application itself (Chrome); it is the protocol Chrome uses.

A real example, layer by layer

You open a page in Chrome. At layer 7 it forms an HTTP request. At layer 6 the request is encrypted by TLS and the text is UTF-8. At layer 5 a TLS session is kept alive between the two ends. At layer 4 TCP cuts the data into segments and adds port numbers (your ephemeral port to 443). At layer 3 IP adds the source and destination IP addresses. At layer 2 Ethernet adds your MAC and the router's MAC. At layer 1 the frame becomes electrical or radio signals. The receiver does the reverse, bottom to top.

Layers 5 and 6 are fuzzy in real life

TCP/IP has no separate session or presentation layers; applications handle that work (TLS, JSON encoding, cookies for sessions). Where TLS "sits" is a classic debate: it is commonly drawn at layer 6, but it is also described as sitting between 4 and 7. Say "presentation, roughly" and move on; no interviewer will fail you for this.

Mistake: calling every PDU a "packet"

The PDU (Protocol Data Unit) has a name per layer: bits, frames, packets, segments (datagrams for UDP), data. Using the right word is an easy way to look prepared. In casual talk "packet" is used for everything, and that is fine outside exams.

Interview: "Explain the OSI model"

  • Name all seven layers in order with the mnemonic, then give one protocol per layer.
  • State the PDU and address type for layers 2, 3 and 4: frame/MAC, packet/IP, segment/port.
  • Explain why layering exists: independence, easier debugging, standard interfaces.
  • Mention that the internet uses TCP/IP, which has four (or five) layers.

TCP/IP model and encapsulation

The TCP/IP model merges OSI into four layers (Link, Internet, Transport, Application); as data goes down the stack each layer wraps it with its own header (encapsulation), and the receiver unwraps it in reverse (decapsulation).

The TCP/IP model

The TCP/IP model (also the "internet protocol suite" or DoD model) came first and is what the internet really uses. It has four layers. Many books split the bottom layer into two and draw a five-layer model; both are accepted.

Encapsulation and decapsulation

When you send data, each layer takes what the layer above gave it (the payload), adds its own header (and sometimes a trailer) and passes the result down. This is encapsulation. The receiver strips headers one by one on the way up: decapsulation.

Typical header sizes: Ethernet header 14 bytes plus a 4-byte FCS trailer; IPv4 header 20 bytes minimum; TCP header 20 bytes minimum; UDP header 8 bytes. The maximum payload of an Ethernet frame is the MTU (Maximum Transmission Unit), usually 1,500 bytes. After subtracting 20 (IP) and 20 (TCP), a TCP segment carries at most 1,460 bytes of data. This figure is the MSS (Maximum Segment Size). A 5,000-byte HTTP response is therefore split into four segments (1,460 + 1,460 + 1,460 + 620).

What changes hop by hop

As a packet crosses routers, the link layer header is thrown away and rebuilt at every hop: the MAC addresses always describe just the current link. The IP addresses stay the same from source to destination (unless NAT rewrites them). The TCP header and the data are not touched by routers at all.

Rule: MAC is hop-by-hop, IP is end-to-end

The layer 2 destination is the next device on the path (often the default gateway). The layer 3 destination is the final host. A switch reads the first, a router reads the second.

Edge case: fragmentation

If an IPv4 packet is larger than the MTU of a link, a router may split it into fragments that the destination reassembles. TCP avoids this by choosing an MSS that fits. Path MTU discovery finds the smallest MTU along the path. In IPv6, routers never fragment; only the source does.

What each layer's header contains

A header is a small block of fields the receiving side needs to do its job. Each layer looks only at its own header and treats everything after it as opaque payload.

The names of the units are worth remembering: application data, then a segment (TCP) or datagram (UDP), then a packet (IP), then a frame (Ethernet), then bits. In casual talk people say "packet" for all of them; in an interview use the exact words.

How the receiver knows what comes next

Every header carries a small field that names the protocol of the payload, so the receiver can pick the right parser at each step. This is called demultiplexing.

Ethernet EtherType0x0800 / 0x86DDPayload is IPv4 / IPv6
IPv4 protocol (IPv6 next header)6 / 17 / 1Payload is TCP / UDP / ICMP

So a frame arrives, the network card checks the destination MAC, the OS reads EtherType and passes the packet to the IP code, which reads the protocol number and passes the segment to TCP, which uses the port (and the source address and port) to find the right socket. The Java program that called accept() on that socket finally receives the bytes.

A worked example with numbers

Your browser sends a 500-byte HTTP request over IPv4 and Ethernet. TCP adds 20 bytes (520), IP adds 20 (540), Ethernet adds 14 for the header and 4 for the trailer (558 bytes on the wire, ignoring the preamble). The useful data is 500 out of 558 bytes, so the overhead is about 10 percent. For a tiny payload such as a 1-byte keystroke, the overhead is far worse: Ethernet also requires a minimum frame size of 64 bytes, so short frames are padded. This is one reason small chatty messages are wasteful and why servers batch data.

For a large response, the sender cuts the data into pieces of at most the MSS. With the usual 1,500-byte MTU the MSS is 1,460 bytes, but when TCP timestamps are in use the option takes 12 more bytes, so many connections really carry 1,448. VPNs and tunnels add their own header and lower the MTU. If the MSS is not adjusted, large packets get dropped or fragmented and connections seem to hang on big transfers while small requests work. This is a classic network puzzle that engineers solve by lowering the MTU or clamping the MSS.

Where your Java code sits

Your code lives at the top. java.net.http.HttpClient, Spring's RestClient and a controller method work with HTTP, the application layer. java.net.Socket and ServerSocket give you a TCP connection and a stream of bytes, the transport layer. You never build IP or Ethernet headers yourself; the operating system's network stack and the network card do that. This is why a Spring Boot developer can ignore most of the model, and why the model still helps when a deployment fails.

Using the model to troubleshoot

  • Link: no Wi-Fi or cable link, wrong VLAN. Symptom: nothing works at all.
  • Internet: wrong IP, subnet or gateway; a firewall dropping ICMP. Test with ping and traceroute.
  • Transport: port closed or blocked, connection refused or timed out. Test with telnet host port or nc -vz host port.
  • Application: the connection works but the response is a 404 or 500. Test with curl -v and read the logs.

Work from the bottom up: if ping fails, there is no point reading the application log. DNS, which turns a name into an IP before any of this starts, is covered in DNS, and the seven-layer view in the OSI model.

Mistake: calling everything a "packet"

A TCP unit is a segment, an IP unit is a packet and an Ethernet unit is a frame. Interviewers listen for this. Also remember that NAT and firewalls can look at ports, so "routers never touch layer 4" holds only for plain routing.

Note: QUIC and the layers

QUIC (used by HTTP/3, see HTTP versions) runs on top of UDP in the application's own code, so it fits the Transport row only loosely. Models are guides, not laws.

Interview: "What is encapsulation?"

  • Each layer adds its header; give the order: data → segment → packet → frame → bits.
  • The receiver reverses it. Name what each header adds: ports, IPs, MACs.
  • Mention MTU/MSS and that MAC addresses are rewritten at every hop.

20-second answer: "TCP/IP has four layers: Application, Transport, Internet, Link. Sending data goes down the stack: the app data gets a TCP header with ports to form a segment, an IP header with addresses to form a packet, and an Ethernet header and trailer with MAC addresses to form a frame, then it becomes bits. The receiver strips the headers in reverse. MAC addresses change at every hop; IP addresses stay end to end. A typical MTU of 1,500 gives an MSS of 1,460."
