Interview questions — Operating systems

What is an operating system and what does it do?

An OS is the software between programs and hardware. It has three jobs: it manages resources (CPU, memory, disk, network) among many programs, it provides abstractions (process, file, socket) that hide hardware details, and it provides protection so one program cannot damage another or the system. Its core, the kernel, runs in privileged mode.

What is the difference between kernel mode and user mode?

The CPU has a mode bit. In kernel mode code may run every instruction and access all memory and devices. In user mode only safe instructions and the process's own memory are allowed; a privileged instruction causes a trap. The split protects the system: a bug in a user program kills only that program, while a bug in kernel code can crash the machine.

What is a system call? What happens when a program calls read()?

A system call is the controlled way for a user program to ask the kernel for a service. The library puts the call number and arguments in registers and executes a trap instruction. The CPU switches to kernel mode and jumps to the kernel entry point, which checks arguments and permissions, does the work (possibly blocking the process while the disk reads) and returns to user mode. Examples: fork, exec, open, read, write, mmap, socket.

Monolithic kernel vs microkernel?

A monolithic kernel (Linux) runs almost all services, including drivers and file systems, in kernel space: fast, but a faulty driver can crash everything. A microkernel keeps only scheduling, memory and IPC in the kernel and runs the rest as user-space servers: more reliable and modular, but slower because of message passing. Windows NT and macOS are hybrids.

What is a process? Explain the process states.

A process is a program in execution, with its own address space (text, data, heap, stack), a PID and resources. States: new (being created) → ready (waiting for the CPU) → running (on the CPU) → terminated. From running it can go back to ready (time slice over), or to waiting (blocked on I/O or an event), and from waiting it goes to ready, never directly to running.

What is a PCB and what does a context switch do? Why is it costly?

The Process Control Block is the kernel's record for a process: PID, state, program counter, registers, scheduling data, memory-management info (page-table pointer), open files and accounting. A context switch saves the running process's CPU state in its PCB and loads the next process's state, including switching the address space. It does no useful work itself, and it also leaves the CPU caches and TLB cold for the new process, which is the larger hidden cost. Thread switches inside one process are cheaper because the address space stays.

What are zombie and orphan processes?

A zombie has finished, but its parent has not yet called wait(), so its PCB entry (PID and exit status) stays in the table; it uses no CPU. It is cleared when the parent waits, or when the parent dies and init adopts and reaps it. An orphan is a running child whose parent has exited; init (PID 1) adopts it. You cannot kill a zombie with kill -9; its parent must reap it.

How many processes exist after this code runs: fork(); fork(); printf("Hi");?

Four processes exist in total (the original plus 3 new), so "Hi" is printed 4 times. The first fork makes 2 processes; each of them executes the second fork, making 4. In general n sequential forks give 2n processes. fork returns 0 in the child and the child's PID in the parent.

What are the ways processes communicate (IPC)?

Two models. Shared memory: a region mapped into both processes; the fastest, but you must synchronise access. Message passing: through the kernel; simpler and safe, with data copying. Mechanisms: unnamed pipes (related processes, one-way), named pipes (FIFOs), message queues, shared memory, sockets (also across machines), and signals (notifications without data, like SIGTERM).

Process vs thread: what is the difference?

A process has its own address space and resources and is isolated; a thread is an execution unit inside a process. Threads of one process share code, data, heap and open files, and each has its own stack, registers and program counter. Threads are cheaper to create and switch and communicate through shared memory, but a bug or crash in one thread can take down the whole process and shared data needs synchronization. Processes are heavier but strongly isolated and need IPC to talk.

User threads vs kernel threads. How do Java threads map?

Kernel threads are managed and scheduled by the OS, so they can run in parallel on several cores and one blocking does not block the others. User threads are managed by a library; they switch quickly, but the kernel sees only one, so one blocking call can stall all. Models: many-to-one, one-to-one, many-to-many. A Java platform thread is one-to-one with an OS thread; Java 21 virtual threads are many-to-few, scheduled by the JVM on a small set of carrier threads.

Define turnaround time, waiting time and response time. Preemptive vs non-preemptive?

Turnaround = completion − arrival. Waiting = turnaround − burst (time in the ready queue). Response = first CPU time − arrival. A non-preemptive scheduler lets a process keep the CPU until it blocks or ends (FCFS, plain SJF); a preemptive one can take the CPU away on a timer or a higher-priority arrival (SRTF, Round Robin, preemptive priority). Preemptive gives better response but costs more context switches and needs care with shared data.

What is the convoy effect? Why is SJF optimal but not practical?

In FCFS, short processes queue behind one long CPU-bound process. With bursts 24, 3, 3 arriving together, FCFS gives an average wait of 17; shortest-first gives 3. SJF minimises average waiting time, but the next CPU burst is not known (only predicted by an exponential average of past bursts) and long jobs can starve. SRTF is its preemptive form and does better still.

How does the time quantum affect Round Robin?

If the quantum is very large, RR behaves like FCFS. If it is very small, the CPU spends too much time on context switches. A good quantum is much larger than the switch time, and most CPU bursts (about 80%) should finish inside one quantum. RR gives good response time and has no starvation, because no process waits more than (n − 1) × q for its next turn, but its average turnaround time is usually higher than SJF.

What are starvation, aging and priority inversion?

Starvation is a process waiting indefinitely because others always go first (low priority, or a long job behind endless short ones). Aging raises the priority of a waiting process over time so it eventually runs. Priority inversion is when a high-priority process waits for a lock held by a low-priority one that a medium-priority process keeps preempting; the cure is priority inheritance.

Explain the Multilevel Feedback Queue scheduler.

MLFQ has several queues with decreasing priority and increasing quantum. New processes enter the top queue; one that uses its full quantum is demoted, while one that gives up the CPU early for I/O stays high. So short and interactive jobs finish quickly and CPU-bound jobs sink, without the OS knowing burst times. Aging or periodic priority boosts stop starvation. A multilevel queue, in contrast, fixes each process in one queue forever.

What is a race condition? What are the requirements of the critical-section problem?

A race condition is when the result depends on the interleaving of threads accessing shared data, e.g. count++ is load, add, store, so two threads can lose an update. The critical-section solution must give mutual exclusion (one at a time), progress (processes outside the critical section cannot block the decision of who enters next) and bounded waiting (no one waits forever). Tools: atomic instructions (test-and-set, compare-and-swap), locks, semaphores, monitors.

Mutex vs semaphore: what is the difference?

A mutex is a lock with an owner: only the thread that locked it may unlock it. It enforces mutual exclusion on a critical section. A semaphore is an integer counter with wait and signal, with no ownership, so any thread can signal; it is used for signalling and for limiting access to N identical resources. A binary semaphore has values 0 or 1; a counting semaphore ranges 0 to N (for example 10 free connections). Short rule: mutex to protect data, semaphore to coordinate events and counts.

What is a monitor? How does Java relate?

A monitor is a language-level construct that combines a lock with condition variables: only one thread can be inside at a time, and threads can wait for a condition and be signalled. In Java, every object has a monitor; synchronized enters it, and wait(), notify(), notifyAll() are the condition operations. ReentrantLock with Condition offers several condition queues.

Solve the producer–consumer problem.

Use a bounded buffer with three semaphores: empty = N (free slots), full = 0 (filled slots) and mutex = 1. Producer: wait(empty); wait(mutex); insert; signal(mutex); signal(full). Consumer: wait(full); wait(mutex); remove; signal(mutex); signal(empty). The counting semaphores must be waited on before the mutex, or both sides can deadlock. In Java, use a BlockingQueue with put and take.

Explain the dining philosophers problem and a solution.

Five philosophers share five chopsticks and each needs both neighbours' chopsticks to eat. If all pick up their left chopstick at once, each waits for the right one forever: a circular wait, hence deadlock. Fixes: allow at most 4 at the table; pick up both chopsticks or none; have odd and even philosophers pick in opposite order; or number the chopsticks and always pick the lower number first (breaks circular wait). Even a deadlock-free scheme must still avoid starvation.

What is deadlock? What are the four necessary conditions?

Deadlock is a state where a set of processes each hold a resource and wait for one held by another in the set, so none can proceed. All four must hold: mutual exclusion (a resource is non-sharable), hold and wait (a process holds some resources while waiting for more), no preemption (resources cannot be taken away) and circular wait (a cycle of processes each waiting for the next). Break any one and deadlock cannot occur.

How can deadlock be handled? Explain the Banker's algorithm.

Four strategies: prevention (break one Coffman condition, e.g. impose a lock order), avoidance (never enter an unsafe state), detection and recovery (find a cycle, then abort processes or preempt resources) and ignoring it (the ostrich approach). The Banker's algorithm is avoidance: each process declares its maximum need; a request is granted only if Request ≤ Need, Request ≤ Available and the state after the grant is safe, meaning some order exists in which every process can finish (found with the Work/Need test). It needs advance knowledge of maximum demands, so real systems rarely use it.

Deadlock vs starvation vs livelock?

In deadlock a group is blocked forever, using no CPU, each waiting for another. In starvation one process waits indefinitely while the system keeps working (low priority, unfair lock). In livelock, processes keep running and reacting to each other but make no progress, like two people repeatedly stepping aside in a corridor; CPU use is high. Fixes: lock ordering or timeouts, aging or fair locks, random back-off.

Internal vs external fragmentation. What is compaction?

Internal fragmentation is unused space inside an allocated block (fixed partitions, the last page of a process). External fragmentation is free memory split into small holes that cannot satisfy a request even though the total is enough (variable contiguous allocation). Compaction moves processes together to merge the holes; it needs dynamic relocation and is expensive. Paging removes external fragmentation.

Explain paging. How is a logical address translated? What is a TLB?

Logical memory is cut into fixed-size pages and physical memory into frames of the same size. The page table maps page number to frame number. A logical address splits into (page number, offset); the physical address is frame × page size + offset. With 4 KB pages, address 9000 is page 2, offset 808; if page 2 is in frame 7, the physical address is 7 × 4096 + 808 = 29480. The TLB is a small hardware cache of page-table entries: a hit saves the extra memory access. With 10 ns TLB, 100 ns memory and an 80% hit ratio, EAT = 0.8 × 110 + 0.2 × 210 = 130 ns.

Paging vs segmentation?

Paging uses fixed-size pages chosen by the OS and hidden from the programmer; it has no external but some internal fragmentation. Segmentation uses variable-size segments that match logical parts (code, stack, heap), addressed as (segment, offset) with base and limit; it suits sharing and protection but suffers from external fragmentation. Modern systems use paging (sometimes with segments on top).

What is virtual memory and what happens on a page fault?

Virtual memory gives each process a large private address space while only the used pages sit in RAM and the rest stay on disk (swap), so programs can exceed RAM and more of them can run. On a page fault (valid bit 0) the hardware traps; the OS checks the access is legal (otherwise it kills the process), finds a free frame (or evicts a victim, writing it out if dirty), reads the page from disk while another process runs, updates the page table, and restarts the faulting instruction. Faults are costly: at 8 ms service time and 200 ns memory, one fault per 1,000 accesses makes the average access about 41 times slower.

Compare FIFO, LRU and Optimal page replacement. What is Belady's anomaly?

FIFO evicts the oldest page, LRU the least recently used, Optimal the page needed farthest in the future (impossible to implement, used as a benchmark). On the string 7 0 1 2 0 3 0 4 2 3 0 3 2 1 2 0 1 7 0 1 with 3 frames they give 15, 12 and 9 faults. Belady's anomaly is when more frames cause more faults; FIFO shows it on 1 2 3 4 1 2 5 1 2 3 4 5 (9 faults with 3 frames, 10 with 4). LRU and Optimal are stack algorithms and never show it. Real systems approximate LRU with the clock (second-chance) algorithm.

What is thrashing and how do you prevent it?

Thrashing is when processes spend more time paging than computing because they lack enough frames for their active pages, so CPU utilisation collapses. It gets worse if the scheduler admits more processes to raise utilisation. Prevention: the working-set model (keep the sum of working-set sizes within available frames and suspend a process otherwise), page-fault-frequency control, local replacement, and adding RAM. Symptoms on a server: heavy swap in/out, high I/O wait, low user CPU.

A Java service in a container gets OOMKilled although the heap is only 80% full. Why?

The container limit covers the whole process, not just the heap: metaspace, thread stacks, code cache, direct buffers and GC structures all count. When the total passes the cgroup limit, the kernel's OOM killer sends SIGKILL (exit code 137). It is different from a Java OutOfMemoryError, which is thrown when the JVM's own heap is full. Fix: leave headroom, for example set -XX:MaxRAMPercentage to about 70–75 instead of -Xmx equal to the limit, and watch the total RSS.

Cheat sheet — Operating systems

  • OS jobs resource manager, abstraction, protection.
  • Kernel / user mode mode bit; privileged instructions only in kernel mode; syscalls are the only door in.
  • Process memory layout text, data, heap (grows up), stack (grows down).
  • Process states new → ready ⇄ running → terminated; running → waiting → ready.
  • Context switch save/load registers and PC via the PCB, switch address space; pure overhead plus cold cache and TLB.
  • fork / exec / wait fork returns 0 in the child; n forks give 2^n processes; zombie = not reaped; orphan = adopted by init.
  • IPC pipe, named pipe, message queue, shared memory (fastest, needs sync), socket, signal.
  • Thread shares code, data, heap, open files; owns stack, registers, PC.
  • Scheduling formulas TAT = CT − AT; WT = TAT − BT; RT = first run − AT.
  • FCFS simple, convoy effect. SJF min average wait, needs burst prediction, starves long jobs. SRTF preemptive SJF.
  • Priority starvation fixed by aging; priority inversion fixed by priority inheritance.
  • Round Robin quantum q; large q = FCFS, tiny q = overhead; wait for next turn at most (n − 1) × q.
  • MLQ vs MLFQ fixed queues vs processes demoted/promoted by behaviour.
  • Critical section needs mutual exclusion, progress, bounded waiting.
  • Atomic hardware test-and-set, compare-and-swap; spinlock = busy wait, only for very short sections.
  • Mutex vs semaphore mutex has an owner (lock); semaphore has a counter and no owner (signalling, N resources).
  • Semaphore ops wait: decrement and block if negative; signal: increment and wake one.
  • Producer–consumer empty = N, full = 0, mutex = 1; wait on the counting semaphore before the mutex.
  • Dining philosophers naive pick-left deadlocks; fix with lock ordering, at most 4 seated, or pick both.
  • Coffman conditions mutual exclusion, hold and wait, no preemption, circular wait.
  • Deadlock handling prevention, avoidance (Banker's), detection and recovery, ignore (ostrich).
  • Banker's Need = Max − Allocation; safe if an order exists where Need ≤ Work; Work += Allocation.
  • Fragmentation internal = inside a block; external = scattered holes; compaction or paging fixes external.
  • Paging address = (page, offset); physical = frame × page size + offset; offset is unchanged.
  • EAT with TLB h × (ε + m) + (1 − h) × (ε + 2m); 80% hits, 10 ns, 100 ns gives 130 ns.
  • Virtual memory demand paging, valid bit, page fault = trap, load page, restart instruction; EAT = (1 − p) × m + p × fault time.
  • Page replacement FIFO 15, LRU 12, OPT 9 on the standard string with 3 frames; Belady: FIFO only.
  • Thrashing more paging than computing; cure with working set, fewer processes, more RAM.
  • Disk scheduling FCFS, SSTF (starvation), SCAN (elevator), C-SCAN, LOOK; I/O by polling, interrupt or DMA.
  • Backend links thread pools, HikariCP as a semaphore, container memory limit and OOMKilled (137), file-descriptor limits.

Practice — Operating systems

  1. Trace system calls. On a Linux shell run strace -c ls and strace -e trace=openat,read,write cat /etc/hostname. Done when you can name the system call behind each line and say which ones switch to kernel mode and why. Then write a one-line shell pipeline with | and explain which IPC mechanism it uses.
  2. Count the processes. Without running it, say how many times "Hi" prints for fork(); fork(); fork(); printf("Hi"); (done when you answer 8 and can explain 2n). Then draw the process tree and mark which processes get 0 from fork.
  3. Draw the state diagram. From memory, draw the five-state diagram and label every arrow. Done when you can say for each of these events which arrow it uses: time slice expires, disk read starts, disk read completes, process calls exit().
  4. Scheduling by hand. Processes (arrival, burst): P1 (0, 5), P2 (1, 3), P3 (2, 8), P4 (3, 6). Draw the Gantt chart and compute average waiting and turnaround time for FCFS and non-preemptive SJF. Check: FCFS gives average WT 5.75 and TAT 11.25; SJF gives average WT 5.25 and TAT 10.75. Then do SRTF and Round Robin (q = 4) and compare.
  5. Race condition in Java. Write two threads that each do counter++ one million times and observe a total below 2,000,000. Fix it three ways: synchronized, ReentrantLock and AtomicInteger (see Core Java · Module 6). Done when all three print 2,000,000 on ten runs in a row. Explain in two sentences why volatile alone does not fix it.
  6. Producer–consumer with semaphores. Implement the bounded buffer with java.util.concurrent.Semaphore (empty, full, mutex), with two producers and two consumers, and 20 items in total. Done when every item is consumed exactly once and the program ends. Then swap the order of mutex.acquire() and empty.acquire() in the producer and observe the hang with jstack.
  7. Create and fix a deadlock. Write the two-lock deadlock, capture a thread dump with jstack and find the "Found one Java-level deadlock" section. Fix it with lock ordering, then with tryLock(timeout) and a random back-off. Done when both versions complete 1,000 transfers between two accounts running in opposite directions.
  8. Banker's algorithm. Use the example state (Available (3,3,2); Allocation and Max from the Banker's article). Check whether P4's request (3,3,0) can be granted. Check: it is within Need and exceeds nothing in Available, but after pretending to grant it Available is (0,0,2) and no process can finish, so it is unsafe and must wait. Then run the safety algorithm on your own 4-process, 3-resource example and list the safe sequence.
  9. Paging and replacement. (a) With 1 KB pages and page table 0→3, 1→7, 2→1, 3→4, translate logical addresses 1500, 2100 and 3071. Check: 7644, 1076 and 2047. (b) Reference string 1 2 3 2 4 1 5 2 1 2 3 4 with 3 frames: count faults for FIFO, LRU and Optimal. Check: 9, 9 and 7. (c) Re-run the Belady string 1 2 3 4 1 2 5 1 2 3 4 5 with 3 and 4 frames under FIFO and under LRU, and show that only FIFO gets worse.
  10. Disk scheduling and a memory investigation. Head at 50, cylinders 0 to 199, requests 82, 170, 43, 140, 24, 16, 190: compute total movement for FCFS and SSTF. Check: 642 and 208. Then start any Spring Boot app in Docker with --memory=256m and -Xmx256m, watch it get OOMKilled, and fix it by using -XX:MaxRAMPercentage=70. Done when you can explain every extra memory area the JVM uses beyond the heap.
